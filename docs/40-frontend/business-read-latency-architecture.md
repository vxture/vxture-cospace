# 业务交互延迟：会话、授权与概要读取

日期：2026-11-14。基线：v0.7.40 / d426abf。本轮实现覆盖公共请求链路、目录查询和场景概要，尚未发布生产；未取得带身份的生产分段耗时。

## 根因

业务请求原先都要调用平台成员应用授权：令牌交换 → 签名验证 → product-access。默认 transport 每次创建，公钥验证器无法复用缓存。工作区订阅虽有缓存，但远程读取占用全局锁，不同工作区也可能互相等待。

前端固定每 30 秒确认，顺序为 GET session → POST session → subscription。同源静态资源也等待确认。大板块切换已使用 SPA，但目录 hook 和抽屉各自重新读取，重复经过公共门禁。

概要有候选时读取少量保存文件，无候选时扫描全部作业。标题用 candidate_ref 是否存在决定，“尚未返回”被当成“没有候选”，因此出现“最近构建 → 当前候选”的跳变。

## 实现后的职责

| 层级 | 正常读取 | 失效边界 |
| --- | --- | --- |
| 本站会话 | 本地 HttpOnly 会话和令牌验证 | 平台给出的 next_check_at、令牌到期、退出、认证错误 |
| 工作区订阅 | 有限内存缓存 | 原有 TTL、签名通知的持久化 generation |
| 用户应用授权 | 用户及凭证绑定的短期决定 | 默认 30 秒、令牌到期、generation 变化、手动重新检查 |
| 场景权限 | 每个接口检查产品资源 ACL | 当前策略立即参与下一次后端判断 |
| 前端查询 | 当前身份作用域内合并请求，15 秒内复用 | 数据修改、会话恢复、权限失效、身份变化 |
| 场景概要 | 场景索引及可重建标量投影 | 依赖文件变化、最新作业变化、归属变化 |

平台继续拥有订阅和商业授权；产品没有新增商业限额判断。页面缓存和概要数据库不作为权限依据。

## 授权决定及撤销语义

PlatformSubscriptions 持有一个长期 transport 和公钥 verifier。相同作用域的在途请求共用结果，远程 I/O 不持有全局缓存锁；不同租户不因同一网络锁串行。

成员授权 key 包含 issuer、product、subject、org、workspace、用户 token 的 SHA-256。不会把一个成员的允许结果提供给同工作区其他成员。缓存不持久化，不保存 token 原文；最多 512 项。允许和拒绝均可短期缓存，查询错误不返回过期允许结果。

默认 COSPACE_PLATFORM_ACCESS_CACHE_SECONDS=30，范围 0–30。缓存寿命不超过用户令牌剩余寿命。此设置明确改变原先逐请求远程撤权确认的语义：**没有通知时，平台决定在本地最多复用 30 秒；不承诺下一次业务请求立即感知平台撤权。** 在途远程请求及事件传播仍有实际耗时。

签名 webhook 更新 SQLite 中的 generation，所有使用同一持久卷的进程在后续请求中检查该版本。事件在远程读取期间到达时，结果不能写入允许缓存。grant.invalidated 在平台侧主要用于资源共享失效，不能据此声称每次成员撤权都会推送；30 秒 TTL 是当前缺少完整推送协议时的失效上界。

需要原有逐请求远程检查的环境可设置 COSPACE_PLATFORM_ACCESS_CACHE_SECONDS=0。此时仍保留 verifier 复用、在途合并和锁改进。手动“重新检查”使用 Cache-Control: no-cache 绕过成员决定缓存，避免刚恢复应用授权仍被旧拒绝阻挡。工作区订阅继续按其原有 TTL 和通知规则刷新。

## 前端会话协调

服务端公开 confirmation_max_age_s，由 next_check_at 计算；重试未恢复时为 0。浏览器用 performance.now() 和发起请求时刻计算截止时间，网络等待不能延长会话确认有效期。

有效窗口内不因切换板块、抽屉、焦点变化重新确认。到期后业务 API 等待同一个确认 Promise。正常只 POST session，再读取订阅；仅在 POST 403、可能发生跨标签登录轮换时，额外 GET session 更新 CSRF 后再 POST 一次，无循环恢复。

只对 /api/ 业务请求应用确认门禁，静态资源不等待。业务写入不自动重放。身份、组织或工作区变化后，旧请求结果不能继续进入当前业务；未保存工作沿用已有恢复机制。

## 应用查询缓存

WorkspaceQueries 在 AuthBoundary 内长期存在，跨模块共用目录和概要查询。内存 store 随用户、组织、工作区及 CSRF 轮换而隔离，无 localStorage 数据持久化。

相同 key 的并发读取合并；成功结果 15 秒内重开可立即使用。过期重新读取时保留同作用域已有值。权限失效、数据变更及会话恢复事件清理数据并提高 generation，旧请求即使晚于新请求完成也不能覆盖新状态。读取失败清除旧值，避免把缓存当成持续授权。

此缓存覆盖目录和概要，其他业务接口仍各自读取；它们同样受公共后端授权优化保护。没有引入全站永久数据缓存或后台无限轮询。

## 场景概要读模型

jobs 根目录新增 scene-read-model.sqlite3，包括 jobs 的场景/时间索引和 summaries 标量投影。无候选时用固定索引查询最近作业，抽屉查询不遍历作业目录；无几何数组读取，无构建或轮询副作用。

作业保存完成后 register 更新索引并使该场景投影失效；语义候选的 staging 提交路径也登记。当前候选、最近构建是独立引用，可以指向不同作业；UI 两个标题固定，不按加载结果切换。

投影记录 selection、job、manifest、view-task 的文件指纹（mtime_ns、ctime_ns、size、inode），查询时校验依赖、最新作业和场景归属。冷读保留原有清单 SHA 和归属校验。外部直接修改已有依赖文件会触发重读；通过正式写路径新增作业会更新索引。

成果文件仍为事实来源。文件替换和 SQLite 更新属于跨介质操作，不宣称原子提交。服务启动时利用既有作业遍历重建索引和清理投影，修复保存后更新索引前的崩溃窗口。外部绕过正式写路径新增作业需重启对账；不能只复制目录就期待索引即时更新。数据库错误显式暴露，不返回陈旧投影掩盖故障。

概要投影只保存显示字段与内部归属绑定，不保存凭证、几何或 ACL 决定。每次 HTTP 查询依然先通过本地会话、平台门禁和场景权限。

## 观测与验收

业务响应增加 Server-Timing，仅包含固定片段名和毫秒数：rp_session、platform_gate、token_exchange、platform_signature、application_access、entitlements、scene_summary、total。嵌套耗时不可直接相加；未出现的远程片段表示本次未执行该读取，不代表平台请求恒定为零。无 Cookie、token、URL、用户资料输出。

回归重点：并发请求合并、不同租户无网络全局锁、token/成员隔离、TTL 到期、签名事件跨实例失效、事件与查询竞争、手动恢复拒绝、概要暖读无目录扫描、依赖变化、当前候选和最近构建分离、启动重建、前端旧响应隔离和 CSRF 恢复。

生产验收应比较同场景 A→B→A、不同场景、有效期内与到期后的请求瀑布，分别记录会话等待和业务服务耗时。目标是有效窗口内重复操作没有冗余中央授权请求，概要暖查询无需全目录扫描；具体毫秒和 p95 必须实测，不能以单元测试推断线上收益。

## 发布与回退

通过 feature PR 和五项 GitHub 检查后发布镜像，按 worker02 /srv/md0/cospace 的生产 Environment 审核部署。没有本地源码上传路径。

可通过 access cache 配置 0 恢复成员逐请求检查；完全回退使用上一个发布镜像。新增 SQLite 是可重建读模型，不改变成果文件格式，旧版不依赖该文件。上线后先观察授权失败率、会话恢复、Server-Timing 和连续切换体验，再评价最终效果。
