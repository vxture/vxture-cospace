# 数据管理阶段发布 v0.19.0

日期：2026-11-25。生产基线 v0.18.0。本说明界定 D01–D04 阶段发布范围，不预写生产成功；实际提交、检查、镜像、审批与部署结果以 GitHub 流水线为准。

## 发布范围

平台数据管理增加业务项目视角：统一目录投影既有采集资料、参考资料、空间成果及处理记录，支持项目 / 场景筛选、显式管理归属和基础数据标记。业务项目与技术来源目录分开，允许项目关联场景，不迁移既有输入和发布成果。

项目资料和工作区共用资料可独立上传、保留原件，按同工作区项目授予固定版本参考 / 下载权限。接收项目显式关联，显示外部引用；源项目显示已共享。撤销、到期和权限变化在访问时复核，不承诺收回已下载的副本。引用不自动成为构建输入、空间基准或发布成果。

参考原件追加版本保留旧字节、旧授权与审计；接收项目比较已授权版本后显式升级。来源与引用追溯只显示当前可见范围；实际处理血缘核对保存的输入绑定、构建、模型 manifest 与固定发布元数据，不加载完整模型、不轮询或触发导出。

独立原件支持可恢复归档。全工作区有效授权及未解除引用均阻止归档；撤销授权不等于解除引用。归档和新授权 / 引用 / 登记 / 追加共用写事务，避免检查后产生新依赖。场景成果继续使用已有生命周期管理，不复制治理引擎。数据管理与语义本体页头不再显示全局项目检索，目录自身保留业务项目筛选。

本版不包括跨工作区共享、自动坐标应用、通用数据湖或新的独立管理平台，也不增加商业额度实现。

相对 v0.18.0 的累计提交还包含已合并的本体模块提取、依赖闭包交换与消费校验，以及后续宿主收敛和导航修正。最终入口继续由 CoSpace 承载，保留可复用模块；查看 / 编辑 / 发布仍为操作流程，不恢复流程菜单或额外独立管理入口。

## 数据与兼容性

新增项目、登记、原件、历史版本、授权、引用、升级及归档审计保存在 preview-directory 下的 business-projects.sqlite3；表按需创建。旧技术项目、场景资料、固定发布文件及既有服务保留。首次上线不批量替用户登记归属、不自动共享、不改写历史形成时间。

目录可能因个别旧记录不可读取显示部分可用；缺失或损坏的血缘证据显示未核实，不能呈现为完整成功。治理全工作区依赖检查仅披露是否存在阻断，不泄露不可见接收项目及全局计数。来源管理权限与接收项目参考权限分别核验。

备份脚本已将 business-projects.sqlite3 纳入逐库 SQLite checkpoint，包括原件 / 历史 BLOB 和审计。部署前沿用 180 秒备份门禁、quick_check、旧镜像记录，备份留在 worker02 私有目录。该备份不是跨库原子快照，也不替代模型及固定发布目录的资产备份。

## 发布与验收

仅经 feature PR、五项必需检查和 squash merge 进入 main；核对同一 main 提交的 quality-gate、build、test-coverage、audit、gitleaks 成功后创建未使用的 v0.19.0 标签。GitHub 从该提交构建镜像，核验 OCI version / revision。production Environment reviewer 批准后部署到 vx-worker-02 的 /srv/md0/cospace，不上传本地源码包。

部署后核对 checkpoint 完成、服务健康、VERSION / 镜像提交、前端静态资源、认证配置，以及匿名数据目录 / 项目 / 原件 / 共享 / 血缘 / 升级 / 治理接口拒绝访问。认证正向验收只在明确标注的合成项目中操作，不改动现有业务资料；浏览器会话不可用时如实记录限制。本地验收与生产验收分开记录。

阶段联调证据见[数据管理整体联调](../validation/数据管理阶段联调-D01-D04-2026-11-25.md)。检查或生产审批未完成前不能标记为已上线。

已知检查基线：main 的 Sonar previous_version 门禁仍报告三条 2026-11-07 的 pythonsecurity:S8707 告警，涉及 ifc_inspection.digest、ifc_workspace.read_json / load_mesh 的离线 CLI 路径数据流。v0.18.0 同样失败，两个文件相对该生产标签未修改。本次不将历史告警静默标记已解决、豁免或通过；PR 的增量 Sonar 与五项必需检查分别核验。离线工具须继续在可信目录与参数下运行，历史告警保留为独立安全治理事项。

## 回退约束

优先发布修复版本。旧 v0.18.0 不理解新增资料、共享、版本与归档语义，不能宣称旧镜像可继续安全写入新数据管理记录。

确需回退时先停止数据管理相关写入，隔离新目录、原件及共享访问，受控备份当前数据库、原件历史、审计与固定发布目录，保留 checkpoint 和旧镜像证据。无法验证隔离和拒绝写入时保持流量隔离，走修复版本，不直接恢复旧服务对外写入。

经确认的回退提交仍须新标签、GitHub 构建及 production 审核。保留现有库和固定发布文件，不删除新表、不用发布前旧库覆盖上线后的记录，不在线覆盖 SQLite / WAL。既有固定服务按原权限继续核验；重新启用数据管理需恢复支持新语义的版本并复核授权、引用和归档状态。
