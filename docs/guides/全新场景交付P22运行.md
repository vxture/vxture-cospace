## 从零操作顺序

1. 数据管理 → 新建场景，填名称和说明。一个真实场景只建一个场景空间；后续数据仍导入此处。
2. 导入资料 → 准备 PLY → 选择真实文件，填写局部坐标、轴语义和来源，确认原文件为米。
3. 检查并准备 → 查看点数、外观和来源 → 确认坐标与来源声明 → 确认并登记。服务器重新检查原文件与资料包。
4. 资料详情 → 执行预检 → 整理到批次。创建批次，明确勾选资料、保存成员、预检并封存。
5. 用于构建 → 核查当前场景、输入及封存批次 → 发起构建。运行记录展示实际阶段及已保存产物。
6. 双视图就绪后，核对本次模型，写说明并确认“未完成精度验收”，再选择候选。纯几何可以直接走此流程；语义本体、对象、关系和台账按用途补充。
7. 前往确认发布 → 发布所选候选 → 再次确认。打开固定版本在新标签查看人视图／智能体视图；也可下载固定离线包。
8. 同场景更新：导入后续资料、新批次、新构建、核对并发布第二版。失败先核查原资料，再“使用原资料重新构建”，历史失败保留。
9. 新发布核对可用后，在旧发布“版本与技术详情 → 管理分发 → 退役版本”，选择替代版本并写原因。新消费者采用新版；既有离线消费者仍需显式换版。

不要为了跟随本手册重新发布现有候选。当前已有完整两版及退役证据，可直接查看。

## 本机重启

仅在确认8786服务已停止后执行。保留同一业务根目录和模拟issuer端口，auth-output每次使用一个尚不存在的新目录：

```powershell
.venv/Scripts/python.exe -X utf8 -m experiments.scripts.serve_empty_journey_demo --root var/validation/p22-001 --auth-output var/validation/p22-auth-next-001 --port 8786 --accounts-port 19122 --resume
```

--resume保留场景、权限、配置与成果；会话单独新建，需要重新登录。禁止用不带--resume的启动方式覆盖原目录。8784／8785为前批次，保留运行。

如需重新做全新空流程，给--root和--auth-output各指定全新的独立目录，省略--resume，并选未占用的服务／模拟身份端口。标准授权工作台serve_platform_workbench的--initial现为可选，空业务根目录不再要求已有模型；平台、权限和场景创建配置仍须显式提供。
