# 智能体只读交付核对运行

日期：2026-10-27。合成实验CLI，只读诊断，不授予运行、交付或修复权限。

当前CLI生成cospace.test-delivery-audit/0.2，增加批次、观察区间、单调耗时、来源指纹及关联摘要，见[上下文契约](../../contracts/schemas/delivery-generation-v0.1.md)与[验证记录](../validation/交付报告上下文验证-2026-10-27.md)。保存读取仍兼容0.1，旧报告不补造缺失时间。可用`python -m experiments.scripts.delivery_audit_evidence --output experiments/runs/p2-delivery-context-001`生成独立新版证据；不传--output沿用原输出目录，会重写旧证据，保留历史时须明确另选目录。

在仓库根目录执行：

```powershell
.venv/Scripts/python.exe -m experiments.scripts.delivery_audit --files 'D:/local-data/agent-files' --journal 'D:/local-data/recovery-test' --binding 'D:/local-data/binding.json' --limit 100
```

三个路径为示例，须替换为已有实验资料。binding.json为完整固定版本binding对象；不能用包清单整体代替。输入和输出均不含私钥。报告输出stdout，可保存到库外证据目录，不写回被核对库。

退出码0表示本次观察完整且无待处理发现；2表示有发现、观察不完整或参数错误。0不表示签名、时效、撤回、机器人或正式交付验收通过。查看findings的code、component、next_action并结合components原始诊断，不删除残留文件或改变数据库模式。

无需准备持久库的复跑：

```powershell
.venv/Scripts/python.exe -m pytest tests/test_delivery_audit.py -q --tb=short
.venv/Scripts/python.exe -m experiments.scripts.delivery_audit_evidence
```

证据程序会写临时合成库并注入恢复中断，再保存四阶段报告至experiments/runs/p2-delivery-audit-001。固定证据文件会重写，需要保留历史时另存或调整输出目录。它是写临时数据的实验程序，区别于上述只读CLI。

设计见[说明](../architecture/智能体只读交付核对设计-v0.1.md)，结果见[验证记录](../validation/智能体只读交付核对验证-2026-10-27.md)。
