# 固定试用入口与平台接入

本机固定入口：[CoSpace试用](http://127.0.0.1:8790/workbench/layout.html)。当前明确使用本地模拟平台，登录“模拟工作区所有者”。真实平台身份待配置，不是生产部署。

## 日常启停

在仓库根目录执行；当前实例已初始化并封存软件版本，无须重复initialize／seal：

```powershell
.venv/Scripts/python.exe -X utf8 -m experiments.scripts.trial_workbench status --config deploy/config/trial-workbench.example.json
.venv/Scripts/python.exe -X utf8 -m experiments.scripts.trial_workbench stop --config deploy/config/trial-workbench.example.json
```

确认stopped后可在终端重新启动。仅为了本地程序消费演练设置mock fixture路径；文件中的密钥不输出、不提交或随业务包导出：

```powershell
$env:COSPACE_MOCK_SERVICE_CONFIG = (Resolve-Path 'var/trial-state/mock-service.json').Path
.venv/Scripts/python.exe -X utf8 -m experiments.scripts.trial_workbench run --config deploy/config/trial-workbench.example.json
```

服务占用锁阻止第二实例；固定端口被占用、软件／依赖／配置与release不一致时拒绝启动。不要通过删除锁绕过检查。新软件先完成测试，保留旧release收据，再由维护者显式seal新的版本。mock每次启动使用新会话，需重新登录。

| 路径 | 内容 |
| --- | --- |
| var/trial/runtime | 场景、资料、批次、任务、模型、双视图、发布 |
| var/trial/policy | 场景Workspace绑定与用户权限审计 |
| var/trial/setup | 来源、Workspace场景配置、程序消费场景授权 |
| var/trial-state | 软件release、实例状态、会话及本地mock凭据，业务包不包含 |
| var/trial-evidence-cold-001 | 冷恢复前保留的原目录，禁止混入当前运行根 |

停服会排空HTTP；异常退出时Windows Job结束子进程。重启后未完成构建标记为interrupted，再由原场景重试，不伪装已成功。当前试用仅Windows单机loopback，不暴露公网。

## 核心操作与交接清单

1. 登录所有者 → 数据管理 → 新建一个真实场景的“场景空间”。
2. 导入明确格式的资料 → 执行预检 → 整理到批次 → 保存成员 → 预检封存。
3. 用于构建 → 发起构建 → 看本次逐帧轨迹与点块 → 等待固定模型和两类视图完成。
4. 核对本次模型 → 确认未完成精度验收 → 前往发布 → 确认固定版本。
5. 空间预览检查人／智能体视图；态势服务下载固定离线包或让独立程序查询。
6. 不同版本明确指定发布ID；退役旧版后新请求被拒绝，不能偷偷跳到新版。
7. 停服 → 备份 → 核对摘要 → 保留原根 → 原路径恢复 → 重新登录并重复一次构建发布。

以上清单已做本机自动化演练；仍待另一名工程师独立操作并签收，不能据此声称人工交接完成。

## 独立程序消费

可信管理员维护var/trial/setup/consumer-access.json：audience为目标产品代码，grants逐项列出caller产品与space_id。无条目即拒绝；程序自身还须持有平台为同Workspace签发的service票据。该配置没有Client Secret。

本次当前固定版本客户端样例是output/playwright/p26-trial-current-client.json，绑定固定发布、模型与摘要、坐标和Workspace。p26-trial-client.json保留指向已退役旧版，用于验证不会自动换版。调用产品自行配置环境变量COSPACE_CONSUMER_CLIENT_ID及COSPACE_CONSUMER_CLIENT_SECRET（真实平台中是调用方自身客户端，不能借CoSpace浏览器凭据）。

```powershell
.venv/Scripts/python.exe -X utf8 -m experiments.scripts.query_online_publication --config output/playwright/p26-trial-current-client.json --point 0 0 0 --mode historical --max-age-s 60 --accept-unverified-time --output output/playwright/my-query-new.json
```

坐标0,0,0仅示范格式，返回unknown也合法；实际模型查询点见output/playwright/p26-trial-point.json。输出必须尚不存在。退出码0为已校验历史结果，3为服务明确拒答并保存拒答内容，2为通信／权限／契约错误。令牌不落盘，不刷新，下一次调用重新换票。

当前样本没有可信观测UTC：operational请求必定拒绝；historical也须显式接受时间未验证。结果仅表面候选／未知，不表示可通行、可导航或达到某精度等级。max_age_s不会把未知观测时间变成已满足新鲜度。

服务接口：POST /s2s/spaces/{space_id}/publications/{publication_id}/query。Header为Authorization: Bearer {平台service票据}及Content-Type: application/json；不带Cookie／Origin。请求示例：

```json
{
  "model_manifest_sha256": "替换为固定模型清单的64位SHA256",
  "frame_id": "first_lidar_anchor",
  "point_m": [0, 0, 0],
  "mode": "historical",
  "max_age_s": 60,
  "accept_unverified_time": true
}
```

完整请求／响应Schema在contracts/schemas/online-consumption-request-v0.1.schema.json及online-consumption-v0.1.schema.json。401为凭据缺失／无效，403为租户／场景授权或凭据混用，409为版本／坐标冲突、暂停或退役，422为请求格式，503为依赖不可用。观测时间未验证的业务拒答用HTTP 200＋status=refused，客户端必须检查status。

## 冷备份与恢复

先stop并确认stopped，所有构建均应终止并经重启处理未完成状态。输出使用新名字：

```powershell
.venv/Scripts/python.exe -X utf8 -m experiments.scripts.workbench_backup backup --root var/trial --output output/playwright/trial-next-backup.zip --actor local_operator --reason '试用交接'
```

另存打印的SHA-256。verify检查该外部摘要；恢复目标必须为原绝对路径且不存在。先检查路径，再把原根移至明确的证据目录保留，不能覆盖或合并。restore后使用相同trial配置run。

```powershell
.venv/Scripts/python.exe -X utf8 -m experiments.scripts.workbench_backup verify --archive output/playwright/trial-next-backup.zip --sha256 <另存的摘要>
.venv/Scripts/python.exe -X utf8 -m experiments.scripts.workbench_backup restore --archive output/playwright/trial-next-backup.zip --root var/trial --sha256 <另存的摘要>
```

会话、凭据、软件与依赖不在业务包内；保存state及环境的访问权限由部署方管理。当前只支持同机原路径，不能把ZIP改路径恢复到另一台主机。

## 切换真实平台前

P25缺少：COSPACE_OIDC_CLIENT_ID、COSPACE_OIDC_CLIENT_SECRET、COSPACE_ORIGIN、COSPACE_SESSION_KEY。issuer默认https://accounts.vxture.com。为CoSpace登记独立客户端、回调{origin}/auth/callback、登出{origin}/workbench/layout.html及实际产品代码／覆盖授权；会话密钥为Fernet密钥，由本机环境或受控秘密配置提供。

准备独立真实业务根、明确Workspace与用户授权，再将新trial配置mode设platform。不会从mock复制租户绑定，也不会在真实配置失败时降级登录。HTTPS外部地址需要部署方提供可信反向代理，后端仍只监听loopback。

运行check_platform_readiness只检查公开契约和环境变量名；真实验收还要验证登录／登出、Workspace隔离、成员撤权、刷新／状态接口及调用产品换票。当前四项缺失，不能标为真实接入成功。
