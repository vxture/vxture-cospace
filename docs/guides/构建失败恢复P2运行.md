# 构建失败恢复 P2 运行

同一场景空间内，从构建中心的任务进入“构建流程”，选定具体失败或中断任务。

1. 需要沿用原资料时，点击“使用原资料重新构建”。后台重新检查原资料和原批次准入修订，通过后进入新任务；原失败记录保留。
2. 如果提示提交结果未确认，点击“核对提交结果”。刷新后也先核对，不会自动提交。找到任务则进入该任务；尚未找到时可用同一请求重新提交，服务端去重。
3. 资料停用／归档、文件缺失／变化时，通过“核查原资料”定位数据管理；批次变化时通过“核查原批次”核查。系统不自动恢复资料、不解除批次门禁。
4. 确需采用另一份资料或新批次修订时，点击“更换资料或批次”，在任务页显式选择并发起一次新的构建；它不冒用原任务的批次身份。
5. 新任务成功后仍须人工核对并另行确认发布。可通过父任务链接和重试记录追溯；失败或中断不会替换历史固定发布。

成果读取失败或同源校验失败时，页面保留任务ID，暂不允许核对或发布。先刷新核查；确需重新构建则显式更换资料／批次发起新任务，不把已成功任务静默改为失败。

浏览器的会话存储用于保留请求ID，不保存身份令牌。存储不可用时不能发起该恢复操作；清除存储、关闭会话或换设备后须通过场景任务历史核查。权限仍由服务端当前身份与场景策略判定。
