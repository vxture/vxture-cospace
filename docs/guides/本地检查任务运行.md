# 本地检查任务运行

日期：2026-10-26。仅synthetic_check/0.1固定检查执行器，不运行SLAM、不生成候选或新真值，不改变当前服务发布。

## 准备及命令

先按[受控导入手册](本地受控导入运行.md)获得committed数据集，并配置同一个专用PostgreSQL和数据根目录。执行uv sync --locked、uv run --locked alembic upgrade head升级到0003_check_jobs；含任务历史的数据库拒绝降级删除。

```powershell
uv run --locked python -m apps.cli.jobs --root var/input submit --dataset dataset-实际ID --actor engineer
uv run --locked python -m apps.cli.jobs --root var/input run job-实际ID --revision 0
uv run --locked python -m apps.cli.jobs --root var/input status job-实际ID
uv run --locked python -m apps.cli.jobs --root var/input report job-实际ID
```

submit只登记queued任务，run认领并在当前CLI进程监督下执行一次worker子进程。没有后台队列或常驻调度，终端停止会影响监督。run返回failed时CLI退出码2；数据库异常不能按成功处理，应先status核对。

可用submit --timeout 120 --log-limit 8388608设置上限；timeout只支持1..120整数秒，日志限制1024..8388608字节。生产入口不能传任意命令、脚本或执行器。请求规范见[任务Schema](../../contracts/schemas/check-job-v0.1.schema.json)。运行前核对数据集、参数、源码/Schema/uv.lock摘要、实际Python版本及关键依赖版本；指纹改变需新建任务。

queued任务可用cancel job-实际ID --revision 0取消；取消与认领条件竞争仅允许一个成功。running、succeeded或failed不允许取消。首批一个job只有一个attempt，不提供重试或恢复命令；重新检查需创建新job，旧记录仍保留。

## 报告与留痕

正常路径queued → running → succeeded；预检、执行、输入或输出失败转failed。job和attempt状态、事件在数据库事务中提交，产物先在数据根jobs/<job>/<attempt>形成，再封存到artifacts/<artifact>。

成功产物登记validation_report.json、context.json和worker.log的大小与SHA256；artifact.json绑定job、attempt、spec摘要和封存时点。产物目录也保留本次复制的input作为执行留痕，其正式输入完整性以原dataset清单和摘要为准；这些副本不是另一份权威数据集。report命令重新验证已登记产物的摘要。

报告带输入dataset摘要、任务spec摘要、job/attempt身份、合成包校验结果，candidate_created=false、truth_created=false，并明确未执行SLAM、现场质量、重定位、采用及发布。原输入包的真值版本仅作为被检查来源，不是本任务生成的新版本。

失败时status给stage、code与attempt_id；本地attempt目录保存有界日志，执行器非零退出、超时或日志超限另外保存execution.json（退出码、截断标记及结束时间）。尚未提供失败日志网络查询或字段级诊断。

## 恢复与运行边界

子进程只运行固定模块，不接收数据库URL等父进程业务环境变量；仅保留启动所需的系统变量。应用将输入复制到attempt目录，worker只按约定读副本、写本次报告；没有OS只读挂载、权限隔离、容器、CPU/内存配额或防恶意源码执行能力，不能称为安全沙箱。

父进程对当前固定Python子进程监控wall timeout和日志管道，终止后等待退出；固定执行器不生成下级进程。本轮不承诺未来算法进程树终止或GPU资源回收。主进程崩溃、机器重启及自动接管尚未验收；不得基于心跳超时自行修改任务或重跑。

文件封存后数据库提交失败可能留下running状态及孤立产物；report接口拒绝读取为成功结果。保留现场并核对，I4再提供人工恢复及重试。当前已封存内容通过摘要检测修改，不提供签名、断电持久性或OS权限不可变承诺。

本轮不新增网络任务写接口或任务工作台。下一增量I3才将任务、输入和诊断接入只读工作台。

## 只读任务工作台

API启动前将COSPACE_DATA_ROOT设为CLI导入与任务使用的同一根目录，再启动apps.api.managed:managed_app。访问/workbench/#jobs，刷新任务列表、查看任务并核对固定输入或成功报告。当前场景由顶部“场景ID”字段决定，无需激活发布；切换场景会重置任务区。

临时演示可用./experiments/stack/run-workbench-demo.ps1 -Jobs启动。脚本生成独立数据库及var/cospace-workbench-demo-本次标识数据根，包含真实执行成功、排队、取消及明确注入的demo_failure任务；不把演示失败冒充真实超时。容器停止后运行文件默认保留在被忽略的var中，核对后按本次精确目录清理，不操作其他数据根。
