# 成果使用状态管理运行

H3a在“数据管理”管理资料停用/归档/恢复、候选归档/恢复。原成果内容和既有固定发布保持不变。

## 页面操作

1. 按[真实样本流程手册](真实样本流程运行手册.md)启动本机服务，Launcher → 构建 → 数据管理。
2. 在成果目录选择空间及资料/模型候选，点击“管理使用状态”。面板显示可用、已停用或已归档、修订、引用统计和操作历史。
3. 检查目标操作的限制。灰色按钮下会显示当前选择、活动批次、活动任务或来源缺口等原因。
4. 点击可用操作，核对前后状态和保留内容，填写“操作原因”，再确认。取消不提交。服务会重新检查修订和引用；报告发生变化时拒绝旧操作。
5. 完成后核对新状态、修订和历史。需复用时显式“恢复”；资料恢复为可用会重新预检，恢复失败应核查原文件。

原有激光资料可[直接打开](http://127.0.0.1:8767/workbench/layout.html#data?space=space-6fe7d4c455774cb2&artifact=input%3Ainput-d61dc8fd9f294e6a)。默认没有历史控制记录，面板显示可用/修订0。当前选择依赖该资料，因此归档阻断；停用操作会实际阻止后续新构建，请按工程需要使用。

## 状态含义

| 操作 | 生效 | 保留 |
| --- | --- | --- |
| 停用资料 | 直接和批次新构建均拒绝，含深链接/API；含该资料的草稿不能封存 | 原文件、批次成员、已准入任务及已有成果 |
| 归档资料 | 新构建拒绝，构建资料选择移出 | 历史目录、详情、来源及发布 |
| 归档候选 | 新选择、语义/业务/关系派生、新固定发布拒绝 | 候选预览、比较、已生成后续候选及其固定发布 |
| 恢复 | 返回原使用状态；归档前已停用的资料恢复后仍停用 | 原历史；不自动选择、派生或发布 |

归档当前候选须先通过已有核对流程选择替代候选。归档资料还须处理整理中/封存批次、活动任务及当前选择依赖。不要为消除提示而随意切换候选；不确定时先保留现状并核查引用。

发布和离线包仍只有只读影响检查，尚无分发暂停操作。已有机器人端副本不受本次状态控制，不会远程消失。当前仍使用本机预览身份，未接入真实身份/空间ACL；状态可用不代表精度合格或允许机器人运行。

## 失败处理

409、网络失败或返回不一致时，旧操作区会清空。先点击“刷新使用状态”，读当前状态与历史后重新决定；响应丢失时操作可能已经提交，不要直接重复发送。刷新失败也不保留旧按钮；切换成果或空间会关闭旧确认框。

资料恢复失败：用现有资料预检检查原文件，恢复封存文件或将新内容重新登记；不改写历史模型。来源缺口、损坏账本和活动任务问题需先处理再重新检查；保存的running不等于已确认进程存活。

同运行区一次只启动一个服务。运行区锁文件是协作锁，不要在服务运行时删除或替换；控制账本与批次库、任务记录一起备份。读取历史不迁移旧成果，也不创建默认账本。

## 隔离完整验证

已有H1验收副本时，在项目根目录执行，新output目录必须不存在：

```powershell
.venv/Scripts/python.exe -X utf8 -m experiments.scripts.verify_preview_control --source var/validation/batches-h1-001 --output var/validation/control-h3a-new
```

脚本复制H1 runtime，启动临时HTTP服务，进行两类样本的状态变更、门禁、恢复及真实重建，最后自动停止临时服务。**它会写入指定新副本，并发起两个真实构建**；不是只读健康检查。源runtime及原var/nyu仅做摘要核对，不提交状态变更。需要源封存资料、已有H1样本和本机预览依赖；它不是全新机器数据准备脚本。

```powershell
.venv/Scripts/python.exe -X utf8 -m pytest tests/test_preview_control.py -q --tb=short
```

契约见[状态与接口](../../contracts/schemas/preview-artifact-control-v0.1.md)，完整结果见[H3a验证](../validation/成果受控状态变更-H3a-2026-11-02.md)。浏览器证据固定在独立验证副本执行，不能将固定测试ID的写脚本运行在原演示区。
