# 本地受控导入运行

当前仅支持cospace.synthetic-bundle/0.2的小型合成包。仅本机CLI，不提供网络写入口；导入不运行算法、不生成候选或新真值、不注册或激活服务。

先配置专用PostgreSQL的COSPACE_DATABASE_URL，凭据不写入仓库。根目录执行uv sync --locked和uv run --locked alembic upgrade head，迁移到0002_dataset_imports；已用Alembic管理的0001可向上升级。含导入记录时拒绝降级删除，未使用Alembic的旧库仍需另行审定接管。

准备import-request.json（SHA256替换为源package.json原始字节的实际摘要）：

```json
{
  "schema_version": "cospace.import/0.1",
  "scene_id": "synthetic-equipment-corridor",
  "data_kind": "synthetic",
  "source_description": "内部手工合成设备间与走廊样例",
  "purpose": "synthetic_check",
  "usage_conditions": "not_assessed",
  "idempotency_key": "indoor-import-001",
  "expected_manifest_sha256": "替换为64位小写SHA256"
}
```

PowerShell可用(Get-FileHash examples/indoor-spatial/package.json -Algorithm SHA256).Hash.ToLowerInvariant()取得摘要。请求格式见[Schema](../../contracts/schemas/import-request-v0.1.schema.json)，不得自动改写源清单以掩盖不匹配。

```powershell
uv run --locked python -m apps.cli.imports --root var/input ingest examples/indoor-spatial --request import-request.json --actor engineer
uv run --locked python -m apps.cli.imports --root var/input status import-实际ID
uv run --locked python -m apps.cli.imports --root var/input dataset dataset-实际ID
```

运行目录var被忽略，也可指定外部专用目录。源目录与存储根不能重叠；拒绝路径越界、链接/Windows重解析点、大小超限及大小写碰撞。最多100份资料（含源清单）、单份8MiB、总计32MiB。只复制清单声明的文件，忽略未声明源文件；保留原package.json作为资产，dataset.json是内部保留文件名。

同一场景及幂等键绑定完整请求：相同请求返回原记录，无论源目录是否后来变化；不同清单摘要或声明返回idempotency_conflict。进行中返回receiving/validating，失败返回rejected，不隐式重试；新操作使用新键。查看dataset会重新核验封存内容，丢失或损坏不会返回合格结果。

当前文件封存采用同一数据根内目录rename，数据库随后事务提交可见引用。数据库提交中断可能保留validating和不可见孤立目录；没有自动恢复、自动清理或重试。保留现场，依据import_id核对，不能把孤立目录手工改成committed。后续I4增加恢复命令。

文件没有OS层只读或防篡改权限，依赖摘要检测变更；不能当作对恶意本机进程的安全隔离。没有断电持久性演练。actor是声明，未认证。当前失败诊断仅返回stage/code及import_id，文件/字段细化待后续任务诊断增量；数据库异常输出不暴露URL或SQL参数。
