## 恢复

当前p23-001正在服务，不能把演练包覆盖回去。实际恢复时先停服，记录明确原路径，将原目录移至一个明确的新证据位置保留。核对路径后再移动，不能移动其他批次。目标必须不存在：

```powershell
.venv/Scripts/python.exe -X utf8 -m experiments.scripts.workbench_backup restore --archive output/playwright/p23-complete-backup.zip --root var/validation/p23-001 --sha256 9c0639ce6f167b2bec66a0cfcf0ba3c7b425d862e75a8e5b124597071c2c05c9
```

命令不会代替操作者删除原目录，也不会合并当前成果。该完整包包含两版发布及当前选择；后续新增工作需另做新备份，勿用旧包覆盖新工作。首轮单发布包p23-cold-backup.zip及source-evidence-001仍保留作为第一次恢复的证据。

恢复后仍用同一模拟issuer端口19123。auth-output指定一个未存在的新目录，恢复业务／权限，不恢复会话：

```powershell
.venv/Scripts/python.exe -X utf8 -m experiments.scripts.serve_empty_journey_demo --root var/validation/p23-001 --auth-output var/validation/p23-auth-next-001 --port 8787 --accounts-port 19123 --resume
```

重新登录后检查：场景身份、资料／批次、任务／历史发布、原包摘要、查看者与未授权权限。再按原资料 → 批次用于构建 → 发起构建 → 人工核对 → 确认发布操作；不能仅以服务能启动判断恢复成功。

## 标准平台工作台的布局

真实平台凭据仍从原环境配置提供，不随业务包导出。标准启动器新增可选--sessions，将会话目录放在业务根目录之外，例如：

```powershell
.venv/Scripts/python.exe -X utf8 -m experiments.scripts.serve_platform_workbench --runtime var/business/policy --sample var/business/runtime --sources-config var/business/setup/sources.json --workspace-scenes-config var/business/setup/workspace-scenes.json --sessions var/platform-auth/sessions --port 8787
```

上述配置、策略和目录需由部署方先提供，不会自动生成生产账户。省略--sessions保持旧行为，但会话留在policy/sessions时冷备份将拒绝，需要先安排独立会话目录。不要把认证目录拷入business/runtime冒充业务资料。

备份不包含软件、Python／Node依赖、操作系统ACL、环境变量或Client Secret。恢复不改变issuer／Workspace权限模型。生产身份、跨机迁移、精度及实机能力仍待单独验收。
