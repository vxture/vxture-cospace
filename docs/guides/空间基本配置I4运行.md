# 空间基本配置 I4 运行

日期：2026-11-03。首页默认使用已确认的全景方案；原双栏版通过 `?home=split` 保留。认证沿用平台独立RP，未改登录协议。

## 页面操作

1. 打开[本机工作台](http://127.0.0.1:8769/workbench/layout.html)，点击登录，在明确标识的本地模拟平台选择管理员。
2. 空间预览卡片点击“空间配置”，或从右上角配置与管理进入业务配置并选择空间。
3. 修改空间名称、用途描述，填写修改原因后保存。空间目录显示新信息，修改历史保留操作者、时间及前后值。
4. 如需恢复，填写原名称/描述和恢复原因再次保存。恢复是新的修订，历史仍保留。

查看者A和工程师B可以读取自己获授权空间的基本配置，字段只读。修改需要该空间管理权限；其它空间不因知道URL即可读取。选择器与目录只列有权限的空间。

多人修改产生修订冲突时，页面保留未保存输入并提示重新读取。先自行保留需要的文字，再点击“重新读取配置”，核对最新值后重新填写。刷新会丢弃未保存输入。

## 本机运行与复验

复用[I3运行](空间业务权限I3运行.md)启动器，选择不存在的独立运行目录；8769当前演示仅写副本，原 `var/nyu` 不参与写入。配置数据库随样本目录持久保存；实际平台还需登记CoSpace客户端、配置凭据和稳定会话密钥。

```powershell
.venv/Scripts/python.exe -X utf8 -m experiments.scripts.serve_platform_workbench_mock --runtime var/validation/space-settings-i4-demo-rerun --port 8769
.venv/Scripts/python.exe -m pytest tests/test_space_settings.py tests/test_platform_business.py tests/test_preview_spaces.py tests/test_preview_space_flow.py tests/test_preview_workflow.py tests/test_space_access.py -q --tb=short

pnpm --dir apps/workbench run build
```

启动前先停止占用8769的旧演示进程；不要停止原8767工程服务或8768登录验证服务。验收工具使用新的输出目录，自动启动并停止临时服务，执行真实服务重启；只保存脱敏轨迹和结果，不归档会话库或密钥。
