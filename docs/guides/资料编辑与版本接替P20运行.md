# P20：编辑资料与发布版本接替

适用：已有来源收据的严格PLY。保持同一资料，保存修改历史；影响发布解释时生成新模型／发布，退役旧发布。

## 1. 编辑与构建

1. 数据管理选择场景空间，打开原资料右侧详情，点击“编辑坐标说明”。
2. 核对受影响的批次、任务和发布数量，编辑局部坐标系、轴语义或适用范围，填写原因并保存。
3. 资料仍是原来一行；“坐标说明修改历史”可查看操作者、时间、原因和前后值。原文件不变。
4. 重新预检。原封存批次代表当时输入，重新整理并封存明确引用当前修订的批次。
5. 前往构建中心，明确选择资料及新批次后构建。旧任务保留历史解释；新任务固定此次修订，等待模型及两类视图完成。
6. 人工核对本次候选并选择，进入态势服务发布所选候选。新版本先完成浏览、查询或离线消费核查。

名称、备注等显示信息沿既有编辑功能处理，不需要因此重建模型。坐标说明修改不会自动触发构建、发布或退役。

## 2. 接替旧发布

1. 在态势服务找到旧发布，展开“版本与技术详情”→“管理分发”→“退役版本”。
2. 原因类型选择“新版本替代”，选择同场景已发布且分发中的新版本，填写原因并确认。
3. 旧发布显示“已退役”、原因及替代入口；新查询、资产读取和离线下载停止。新发布继续可用。
4. 查看管理历史保留的来源、操作者和版本关系。消费方显式切换，系统不把旧版URL静默变成新版。

若已确认旧版错误，可选择“错误版本”先退役，无需等待新版本；新版本完成后通过“补充替代版本”登记接替关系。旧版保持退役，不提供一般“恢复”操作。临时“暂停分发”仍可恢复，含义不同。

## 3. 出现失败时

- 编辑冲突：重新读取说明与历史，再核对保存，避免覆盖别人的修订。
- 构建失败：旧发布状态不自动改变，按失败任务流程检查并重新构建。
- 新发布完成但退役失败：刷新旧版使用状态，核对历史及替代关系后重试；不能将新发布成功当成旧版已退役。
- 旧版退役后消费者未更新：提供替代版本，要求其明确更新。已下载、安装或缓存的副本无法通过服务端退役远程删除。
