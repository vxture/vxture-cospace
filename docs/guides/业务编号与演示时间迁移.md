# 业务编号与演示时间迁移

日期：2026-11-11

设计依据：[版本编码](../30-design/version-identification.md)、[服务发布工作区](../30-design/service-publication-workspace.md)。

## 本次实现

业务运行根目录新增 `business-versions.sqlite3`。场景 S 六位随机号由 SQLite 全局唯一约束与冲突重试分配，构建 B、发布 B-P、独立资料 D-V、规则 O-V 持久化补号，至少两位并自然扩展。服务端读取接口与新建发布返回可读编码，保留所有技术 ID、原清单和摘要。几何不变的关联候选、表达派生沿来源 B 映射。无法核实的来源不伪造编号。

原资料登记没有可靠版本接替链，本批按独立 D-V01 登记，不凭名称猜测资料版本关系。规则 O-V 是展示映射，保留原语义版本与 SHA256；不同 Workspace 的规则作用域独立识别。基本信息 R 采用真实保存修订，0 显示历史快照。关联的完整集合修订仍需后续专用存储，不将候选数量伪装成 R。

版本映射随业务备份保留。现有签名文件、`model.json`、发布清单、下载包和 URL 不重写；历史包暂不携带新增展示码，通过服务端映射识别。新建发布支持 request_id 幂等重放，候选与修订不一致拒绝复用。

## 演示时间

只对已有成功构建生成四环节演示时间；未开始、失败和中断状态不虚构完成或核对。已有机器开始／结束、真实人工核对与发布时间保持原值。缺失的准备时间按创建前 20 分钟、检查按创建前 5 分钟估算；机器时间缺失时使用已知事件边界。无人工核对记录时以首次发布作为估算上界；无发布时按机器完成后 5 分钟估算。所有环节连续且按时间递增；矛盾记录跳过，不强行调整真实事件。

估算仅保存到独立 presentation 记录，标注依据、生成时间与 estimated，不写入原审计字段，不作为质量验收或真实构建性能的证据。页面展示开始、完成、耗时及“估算”，分钟以下显示“不足1分钟”。重复运行保留既有演示时间，不随刷新漂移。

## 操作

先保存业务备份和原清单摘要，再在**经过 GitHub 检查、生产审批部署后的镜像内**执行：

```sh
docker exec cospace-app python -m experiments.scripts.migrate_business_versions \
  --runtime /data/runtime --demo-times
```

不加 `--demo-times` 只补业务编号。执行输出场景、资料、构建、发布数量与新增演示时间条数，不输出凭据或原始资料。禁止上传本地源码直接执行生产迁移。

完成后重跑验证幂等，检查各场景内 B/P、随机 S 唯一、四环节边界连续、原 JSON 和交付包摘要不变，以及页面显示。数据库随现有冷备份一起保存；回退应用时保留映射，不能删除后重新分配。线上部署状态和实际迁移数量应记录在本批验证文档中。
