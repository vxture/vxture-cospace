# 采集批次与历史版本 P7

数据管理以一个场景空间为边界，串起 **资料 → 采集批次 → 构建任务 → 模型与双视图候选 → 固定发布**。批次是资料的整理与构建来源，不是新的场景，也不等同于模型版本。

## 操作

1. 在数据管理选择场景空间。不同物理场景分别管理，同一场景后续采集或导入进入自己的新批次。
2. 从资料详情点击“整理到批次”，或打开“采集批次”页签。创建批次、填写说明和操作原因。
3. 勾选本次资料并保存成员。从资料详情带入的勾选仅是待保存选择，创建批次本身不会自动保存成员。
4. 核对后封存批次。封存后成员不可修改；后续采集或补充资料新建批次。批次详情展示固定成员、修订和成员摘要。
5. 点击成员旁的“资料与预检”检查资料，或者“用于构建”进入构建中心；场景、资料、批次一起交接。经过预检或构建子页切换仍保留本次批次。
6. 显式发起构建。构建任务记录准入时的批次修订，固定模型后派生人视图与智能体视图。成功仍需核对和确认发布。
7. 在批次详情查看构建记录；点击“查看批次版本”仅显示明确绑定本批次的候选。刷新或关闭版本详情仍保留筛选。用“全部版本”回到场景历史。

“场景版本”表的来源列展示任务实际记录的批次、提交修订与资料。旧任务没有批次绑定时显示“未记录批次绑定”，不会依据相同资料补认归属。批次后续停用也不改写历史准入修订。

同一资料可以属于多个批次。直接从资料发起构建而未携带批次时，需要显式选择包含该资料的已封存批次；系统不自动挑选。整理中或停用批次不能发起新构建。停用保留历史成果，不撤回已有发布和离线包。

读取来源失败显示“来源记录暂不可用”，不能据此判断历史任务没有批次。切换场景后清除旧详情；其他场景的批次引用会被拒绝。
