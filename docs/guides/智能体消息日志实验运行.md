# 智能体消息日志实验运行

日期：2026-10-27。仅Windows合成J2开发实验；没有正式交付、旧库迁移或恢复解除入口。

从仓库根目录运行：

```powershell
.venv/Scripts/python.exe -m pytest tests/test_recovery_journal.py -q --tb=short
.venv/Scripts/python.exe -m experiments.scripts.recovery_journal_evidence
```

证据程序在临时目录创建独立J2库，验证五处提交边界并保存结果到experiments/runs/p2-recovery-journal-001；不保存随机私钥。scenario.json含合成证明原字节、公共测试信任配置及提交凭据，均无真实授权。运行目录为固定证据位置，重复执行会重写该次输出，历史需要保留时先另存结果或调整程序中的输出目录。

开发接口位于experiments/scripts/recovery_journal.py：显式JournalStore.bootstrap创建全新目录，JournalStore打开现有库，accept必须给intent_id，receipt只读查结果，export_intent读取原消息记录。构造时传入测试trust、Policy和可选JournalLimits；没有将这些接口接入R1 CLI或平台API。

遇到recovery_required时保留现场，本批不提供处理未决intent的方法。重复相同ID只能读取已完成结果；未完成不会自动重放。当前对象出现SQL/IO故障后锁存storage_error；应先诊断，不能删除库、改上下文或新建库规避撤回和高水位。

结构与故障边界见[实现说明](../architecture/智能体消息留存与原子提交实现-v0.1.md)，验收证据见[验证记录](../validation/智能体消息留存与原子提交验证-2026-10-27.md)。下一批J3再实现受控恢复。
