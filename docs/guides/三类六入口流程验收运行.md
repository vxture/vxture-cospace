# 三类六入口流程验收运行

目标：在不改变原运行资料、选择和发布的前提下，从两类已有真实封存输入重新生成完整流程，并让工程师在空间预览中看清当前空间的实际阶段。

## 页面使用

1. 打开空间预览，在真实工程空间卡片点击“查看流程”。面板位于筛选器下方。
2. 查看当前候选、匹配发布及七个阶段。七阶段归入六模块，离线消费仍属态势服务。
3. 通过“下一步”或阶段入口定位资料、候选、固定本体、空间关联或发布。固定空间在新标签页打开。
4. 切换空间会清除旧报告；刷新失败时隐藏旧的阶段和操作链接。修复记录后重新刷新。

“项目进度”表示已实现能力，“流程状态”表示这个空间的保存记录。原空间尚未补业务和关系时会显示待完成，不能因为独立验收样本通过就显示原空间已完成。

离线消费显示“未核验”，这是服务观察边界；实际安装、激活与恢复应在消费端确认。当前参考流程不代替质量验收或发布权限。

## 可复跑验收

从项目根目录运行，先按[真实样本流程运行手册](真实样本流程运行手册.md)准备本机Python依赖、封存输入及初始模型。使用允许来源配置中的`os1-single-frame`和`nyu-office-short`，源数据只读。每次指定全新输出目录：

```powershell
.venv/Scripts/python.exe -X utf8 -m experiments.scripts.verify_preview_workflow --output var/validation/workflow-g1-new
```

运行器创建独立runtime、临时loopback HTTP服务及真实构建子进程，逐项执行：

登记及去重 → 预检 → 真实构建 → 固定本体草稿校验 → 对象候选 → 固定测试台账绑定 → 关系候选 → 人工核对声明与选择 → 固定发布 → HTTP对象/点/范围查询 → 离线0.4安装/激活 → 删除原下载路径后另一进程恢复 → 新候选未发布的历史隔离检查。

每类样本声明四个测试对象、一项测试台账绑定、三条关系；这些语义是流程测试，不是现场设备识别或归属结果。NYU使用已有轨迹，激光保持传感器局部单帧坐标。

安装与恢复在两个独立进程中禁用Python socket创建和create_connection，恢复只读取独立SQLite消费库，结果逐字段对照真实HTTP。不是操作系统网络隔离或真实机器人上机验证。

失败非零退出，输出目录保留供排查，修复后换新目录重跑。通过时有acceptance.json、original-before.json、server.log、两类样本的workflow.json、请求/结果、独立消费库和exported-evidence.zip。acceptance.json包含48项检查及模型/发布/包摘要。

若需浏览已生成的隔离样本：

```powershell
.venv/Scripts/python.exe -X utf8 -m experiments.scripts.verify_preview_workflow --serve --output var/validation/workflow-g1-new --port 8768
```

前端API默认8767；直接使用8768会出现前后端运行区不一致。需要独立前端构建时设置VITE_MODEL_PREVIEW_URL后重新构建，或在确认原服务无活动任务后停止原服务，让隔离服务临时使用8767，检查后恢复。不要让两个服务同时写相同运行区。`--serve`会初始化内置规则及已有任务管理器，应仅用于此工具生成的独立runtime，不是只读健康检查。

## 错误处理

| 现象 | 处置 |
| --- | --- |
| 输出目录已存在 | 换一个新的目录，保留旧证据 |
| 来源停用或封存文件缺失 | 检查deploy/config/preview-sources.json及路径，不替换旧来源绑定 |
| 构建失败 | 看runtime/preview-builds中的任务和build.log |
| 当前候选无匹配发布 | 核对候选后显式固定发布，不改用历史发布掩盖缺口 |
| 流程读取409 | 检查选择、候选及成员绑定，刷新；勿直接编辑固定快照 |
| 消费状态未核验 | 到独立消费库查status，并显式restore，不从下载量推导完成 |
