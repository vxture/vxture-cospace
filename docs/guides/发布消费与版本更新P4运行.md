# 发布消费与版本更新 P4 运行

始终先选一个场景空间。它拥有自己的资料、模型、双视图、历史固定发布和消费包；客户归属使用平台 Workspace。

1. 数据管理登记资料并预检，交给构建中心。构建完成后核对本次候选，显式选择并确认发布。纯空间浏览不要求先填写本体与台账。
2. 态势服务定位该固定发布，“打开固定版本”在独立标签页显示真实三维场景。右上切换图标显示人视图或智能体视图；右侧概览可显式选择历史固定发布。刷新保留 URL 中的固定发布，不自动取最新版。
3. 在空间预览底部展开“查看场景流程”，查看当前选择、匹配发布及下一步。本体与关联缺项标记“可选增强／未补充”，消费端状态标记“未核验”。收起后保持当前场景。
4. 在固定发布行下载离线包，展开“本地消费”。按显示的发布ID和 SHA256 执行初始化、安装、status、activate、restore。初始化仅针对新目录；已有消费库先查看 status，显式使用当前 revision，不能照抄旧序号。
5. 安装只保存包，不切换版本。激活才更改消费库当前引用。每次 CLI 是独立进程，后续查询必须显式 restore；恢复校验已安装字节和保存引用，不增加修订。下载 ZIP 可以移走，已安装内容仍在消费库。
6. 新资料重建或重派生得到新候选后，重新核对发布。第二版安装后第一版继续有效；显式 activate 第二版才切换。回切旧版同样是一次新的消费修订。服务端选择、固定发布与设备消费版本分别管理。
7. 新任务失败不会覆盖历史发布。暂停分发会阻止该发布新读取、查询和下载；已持有离线包无法远程撤回。恢复须在态势服务显式操作，不会替换发布文件或设备当前引用。

只使用实际状态和证据：网页不读取机器人消费库，也不会根据下载次数显示“已安装”或“已激活”。精度、时效与真实机器人调用仍待对应验收。

## 重放完整本机验收

在项目根目录执行，输出目录必须不存在：

```powershell
.venv/Scripts/python.exe -X utf8 -m experiments.scripts.verify_release_consumption --output var/validation/release-consumption-p4-rerun-001
```

脚本使用原 NYU 短序列，创建新的独立场景、两次真实模型／双视图构建、人工核对记录和固定发布。它通过本地模拟平台认证真实 HTTP 路由，并启动禁用网络的独立消费进程检查安装、显式换版、恢复、旧会话和回切。失败仅注入独立测试工作进程，不修改源文件。服务自动关闭，报告保存在 `acceptance.json`；`http-trace.json` 记录路由和结果，不保存认证密钥。

默认原工程文件必须保持不变；不要将输出目录指向 `var/nyu`、现有业务运行区或消费库。重放是本机流程验收，不能代替真实平台或机载端验证。
