# 采集批次与成果追溯运行

入口：Launcher → 构建 → 数据管理 → **采集批次**。先选择工作空间。列表只按工程空间匹配，尚无真实用户授权。

## 操作闭环

1. 在“登记资料”登记允许的封存输入；已有资料可直接使用，批次不会重新导入或复制原始文件。
2. “创建批次”，填写名称、来源和说明。公开数据选“导入样本”；选择现场采集仅保存声明，不代表设备已接入。
3. “查看批次”，在整理中选择已有资料，填写操作说明后“保存成员”。更改成员尚未保存时不能封存。
4. 重新填写说明，“预检并封存”。服务重新核对全部资料，失败保持整理中和原修订，不会留下半封存记录。
5. 从固定成员“用于构建”，构建中心自动带上资料和批次，提交时携带读取的批次修订。构建生成独立候选，不自动选择或发布。
6. 回到批次，查看几何任务、关联候选及固定发布；失败和中断也会保留。固定发布继续走原人工核对与发布流程。
7. 需要停止后续资料构建时，填写原因“停用批次”。恢复后返回原状态；旧任务、候选、发布、ZIP及消费端版本保留。

封存成员不能修改。新增采集或补充资料建新批次。相同资料可属于多个批次，构建须明确选择一个已封存的批次。未纳入任何批次的历史资料兼容旧构建入口，但一旦纳入批次，省略batch_id会被服务端拒绝。

冲突提示表示其他操作已改变修订，旧的操作面板会清除。点击“刷新批次”，查看历史及新状态再操作，不重复提交旧修订。批次详情中的构建状态是保存记录，实时任务进程请到构建中心；发布完整性请到成果目录检查。

## 可复跑的隔离验收

按[真实样本流程运行手册](真实样本流程运行手册.md)准备本机资料和依赖，然后使用全新输出目录：

```powershell
.venv/Scripts/python.exe -X utf8 -m experiments.scripts.verify_preview_workflow --with-batches --output var/validation/batches-h1-new
```

该命令是写入独立测试区的完整验收，不是健康检查。沿OS1单帧与NYU短序列跑原六入口流程，另测批次整理、封存、遗漏批次拒绝、来源继承、停用保留历史、显式恢复和旧修订拒绝。真实HTTP＋两套实际构建＋离线跨进程恢复，总计66项。验收自动停止临时服务，保留acceptance.json、原管理文件摘要、独立runtime及消费库供排查。

首次创建批次才生成`preview-inputs/acquisition-batches.sqlite3`；备份需包含此数据库与原输入、候选、发布文件。本批没有自动清理、移动原始资料或回收包；不要直接编辑固定记录。

状态定义及下一批范围见[契约](../../contracts/schemas/preview-batch-v0.1.md)，本机验证见[H1记录](../validation/采集批次与成果追溯-H1-2026-11-02.md)。
