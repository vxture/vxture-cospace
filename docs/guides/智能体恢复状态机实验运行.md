# 智能体恢复状态机实验运行

日期：2026-10-27。仅供Windows本地合成开发试验；不用于正式设备或已有J2/v1数据迁移。

从仓库根目录执行：

```powershell
.venv/Scripts/python.exe -m pytest tests/test_recovery_state.py -q --tb=short
.venv/Scripts/python.exe -m experiments.scripts.recovery_state_evidence
```

证据程序在临时目录创建user_version=3的RecoveryStore，注入未决消息，依次begin、plan、resume、再规划和提交。验证撤回、到期幂等和提交回滚三个场景，输出到experiments/runs/p2-recovery-state-001。输出固定目录会重写本次场景/环境文件；需要保留独立历史时先另存或调整证据程序输出目录。

接口位于experiments/scripts/recovery_state.py。显式bootstrap要求新目录；普通打开绝不迁移J2库。正常接收仍使用J2的accept与intent_id；恢复调用begin_recovery、resume_recovery、plan_recovery、commit_recovery，诊断使用recovery_result。

begin、resume和完成都会改变代次；操作后打开新对象。旧对象、旧计划或恢复期间打开的消费对象不会自动刷新。恢复结束后从新对象读取结果，再重新装配测试时间与会话；重开不会延长原离线时限。

缺消息、验签失败、历史不一致或无法解释的撤回保持阻断，当前没有忽略、跳过、强制完成或管理员清库命令。没有平台API、维护权限系统或R1命令接入；调用权限仅依赖当前本地受信开发环境，不能称为生产运维入口。

设计见[实现说明](../architecture/智能体恢复状态机实现-v0.1.md)，证据见[验证记录](../validation/智能体恢复状态机验证-2026-10-27.md)。
