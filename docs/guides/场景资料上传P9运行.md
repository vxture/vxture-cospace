# 场景资料上传 P9 运行

目标：把本机已有、受支持的采集资料交给具体场景空间，继续进入预检、模型和双视图构建。使用、构建、定义三类六入口保持原结构。

## 页面操作

1. 打开[8770数据管理](http://127.0.0.1:8770/workbench/layout.html#data?space=space-ea727be75c1049db&tab=inputs)，重新登录“模拟管理员”。当前仍为本地模拟平台身份。
2. 先选对应物理场景；不同场景的数据分别管理。
3. 点击“导入资料”。“已配置来源”仍为默认入口；本机资料改选“上传资料包”。
4. 选择下述打包工具生成的ZIP，填写资料名称，点击“上传并登记”。服务端验证通过后定位资料详情，保存格式、包摘要和操作者。
5. 在资料详情执行预检；通过后点击“用于构建”，确认资料与当前场景，显式“发起构建”。
6. 查看模型冻结、人视图与智能体视图三个阶段；继续按[P8操作主线](场景端到端流程P8运行.md)人工核对、固定发布及消费。

同一场景重复上传**同一ZIP字节内容**会定位原资料，保留原名称。连接中断时结果可能已提交，重试相同包可复用记录。上传成功不自动创建批次、提交构建、选择候选或发布；批次仍按实际采集轮次显式整理。

## 打包方法

使用已通过现有适配器检查的封存目录，输出路径必须不存在且位于来源目录之外：

```powershell
# RGB-D：快照需有report.json/raw，轨迹需与快照匹配
.venv/Scripts/python.exe -X utf8 -m experiments.scripts.pack_input_upload --snapshot <封存快照目录> --tracking <匹配tracking.json> --output <新资料包.zip>

# 激光：短样本目录需有sample.json与sample.bag
.venv/Scripts/python.exe -X utf8 -m experiments.scripts.pack_input_upload --snapshot <激光短样本目录> --output <新资料包.zip>
```

这是受支持适配器的封装，不能直接把任意RGB-D、PLY、LAS、COPC或ROS bag改扩展名后上传。原始外部样本应先经过对应抽样／封存步骤。

限制：ZIP最大128 MiB、展开后192 MiB、每场景上传展开内容512 MiB。不支持断点续传、自动清理保留内容和通用格式识别。坐标、配准、精度、导航与机器人实机可用性另行验证。

## 重放检查

后端与前端：

```powershell
.venv/Scripts/python.exe -X utf8 -m pytest tests/test_input_uploads.py tests/test_preview_registration.py tests/test_preview_preflight.py tests/test_preview_inputs.py tests/test_platform_business.py -q
pnpm --dir apps/workbench run build
```

在端口空闲、输出目录不存在时，对本轮既有上传资料执行真实HTTP复用及业务进程重启检查：

```powershell
.venv/Scripts/python.exe -X utf8 -m experiments.scripts.verify_input_uploads --sample var/validation/input-upload-p9-2026-11-04-001/runtime --output var/validation/input-upload-p9-new-replay --cases output/playwright/p9-main/cases.json --port 8776
```

参数 `--stay-open` 可保留本地模拟服务用于浏览器验收。该脚本只重传两套原包、核对已有资料／模型与重启持久性，不重新构建、选择或发布。

参见[上传契约](../../contracts/schemas/input-upload-v0.1.md)、[P9验收](../validation/场景资料上传-P9-2026-11-04.md)。
