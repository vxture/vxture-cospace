# 交付报告归档与选择运行

日期：2026-10-27。本地合成实验，推荐本机NTFS独立输出目录，见[设计](../architecture/交付报告受控生成与选择-v0.1.md)。在仓库根执行，路径为示例，须替换：

```powershell
.venv/Scripts/python.exe -m experiments.scripts.delivery_generate --files D:/local-data/agent-files --journal D:/local-data/recovery-test --binding D:/local-data/binding.json --output D:/local-reports/agent-audit --limit 100
```

输出目录不能包含或位于源根、binding文件内。CLI会创建输出目录，stdout回执包含report_key、摘要、字节数、report_id及诊断状态。退出0表示观察完整无待处理项；2可能保存了问题报告，也可能出错，须区分receipt和error。保存失败后先核对目录，不能盲重试或删现场。

最终文件不手工修改；更新数据后生成新批次。不覆盖同键文件，硬链接不支持时拒绝而非复制回退。进程退出可能留下.writing临时文件，本批不自动清理，临时文件不能被选择。未验收物理断电或网络盘。

配置现有[托管工作台](本地工作台与迁移运行.md)：

```powershell
$env:COSPACE_DELIVERY_ARCHIVE = 'D:/local-reports/agent-audit'
pnpm --dir apps/workbench run build
.venv/Scripts/python.exe -m uvicorn apps.api.managed:managed_app --factory --host 127.0.0.1 --port 8000
```

仍需原手册中的专用PostgreSQL和COSPACE_DATABASE_URL；原临时演示脚本也会继承新配置。本批无迁移。单文件COSPACE_DELIVERY_REPORT独立可选，未配置时原单文件按钮返回503，不影响目录按钮。

输入scene/release，点击“读取 / 刷新报告列表”，明确选择报告，核对版本及用途后点“读取所选批次”。刷新列表清空选择，生成后须刷新才能看到新批次。列表最多50份目标报告、目录最多200项；超限另行规划目录，不通过页面自动删除。读取失败不回退其他报告，也不表示底层状态可运行。
