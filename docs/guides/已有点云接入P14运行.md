## 准备新资料包

格式要求见[PLY契约](../../contracts/schemas/pointcloud-input-v0.1.md)。首版单位必须是米；不可从文件名猜单位、坐标或配准关系。先确认这些声明，再调用工具。以下命令的输出目录和 ZIP 必须尚不存在；更换后缀可以生成新试验副本。

```powershell
.venv/Scripts/python.exe -X utf8 -m experiments.scripts.prepare_pointcloud_input --cloud var/samples/multi-1-os1-lidar-1s-001/first-frame.ply --output var/samples/os1-declared-pointcloud-p14-002 --points 12884 --frame-id os1_16/os_sensor --axes sensor_x sensor_y sensor_z --scope sensor_local --source-manifest var/samples/multi-1-os1-lidar-1s-001/sample.json --source-member-sha256 9534f75319427fd0a91a5a16aa951ef6b28f9474c233fcd097ecc6ca48c9cd18 --kind derived_single_frame --description "采样ROS消息派生的首帧；米制按上游约定，未配准，精度未验收"
.venv/Scripts/python.exe -X utf8 -m experiments.scripts.pack_input_upload --snapshot var/samples/os1-declared-pointcloud-p14-002 --format ply_pointcloud --output var/samples/os1-declared-pointcloud-p14-002.zip
```

工具只复制原点云，写入声明和来源摘要，不修改原文件。不知道坐标时先补资料；不要填写猜测的坐标声明。也可按生成的 JSON Schema 自行准备严格清单。

## 数据管理到交付

1. 选择已有 OS1 场景空间，点击“导入资料 → 上传资料包”；选择现成 `var/samples/os1-declared-pointcloud-p14-001.zip` 可检查重复上传。
2. 资料详情中确认“已有空间成果”、12,884 点、米制局部坐标；执行预检。
3. 按导入轮次整理到批次，明确保存成员后预检并封存；通过“用于构建”携带输入与批次修订进入构建中心。
4. 点击“发起构建”。模型固定完成后，两类视图独立生成；检查同源摘要。上传或构建不会自动选择版本。
5. 核对候选，确认未完成精度验收，再前往态势服务确认发布。发布保存固定文件，不覆盖历史。
6. 打开固定版本（独立标签页），或下载离线交付包。在“本地消费”中查看带准确发布和包摘要的安装／激活／恢复命令。

缺少单位等声明的包会在登记前拒绝。同一场景重复上传同一包定位原登记，不按新名称覆盖记录；改显示说明使用 P13 编辑入口。
