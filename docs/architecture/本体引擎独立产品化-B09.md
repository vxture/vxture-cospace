# 本体引擎独立产品化 B09

本体引擎管理可复用的通用概念、领域定义、依赖、规则及其版本。接入产品持有场景、实例、几何、现场证据与消费选择。CoSpace 继续从「公共资源 → 语义本体」访问原工作台；独立产品有自己的安装、配置与身份适配入口。三层语义架构保持不变，产品拆分不改变任何已固定的定义或成果。

| 批次 | 交付范围 | 验收条件 |
| --- | --- | --- |
| B09a 可移植编制接口 | 将编制读模型、命令、送审快照和固定版本解析移入独立 Python 包；CoSpace 仅装配可信身份、权限和存储。 | 独立 wheel 以注入的模板、存储和权限策略完成草稿到发布；不同角色和作用域隔离；CoSpace 的原 HTTP、界面和引用回归通过。 |
| [B09b 独立宿主与系统配置](本体引擎独立宿主-B09b.md) | 可单独启动的编制宿主，支持持久化、替换身份适配，分组和顺序归系统配置管理。 | 从空目录安装，重启后继续审批和读历史版本；环境配置与业务数据分开，备份和恢复可演练，不复制宿主账号或商业权益。 |
| B09c 定义与实例交换 | 先固定原生定义闭包的导入预检、冲突处理和导出；独立验证实例包，再为行业标准选取可无歧义映射的子集。 | 原生往返保留精确版本与摘要；同标识同版本不同内容显式拒绝；标准格式不能表达的约束明确报告，不静默近似或导入为已发布。 |
| B09d 独立工作台与版本验收 | 复用现有 DS 组件装配独立产品 Shell；查看、编辑和发布清晰分离，配置入口独立。 | 不挂载 CoSpace 验证安装、升级、回退和历史闭包；业务导航不随数据增长，宿主适配和发布独立验收。 |

B09a 只抽取通用工作台接口。工作台从同一个事务快照生成草稿、校验、比较和审批栏，避免读取途中更新导致修订不一致。模板库可以由另一宿主注入；目录可以显示模块各自的最新发布，固定读取仍返回目标版本自己的依赖闭包。权限由宿主注入，存储格式、HTTP 路径、浏览器页面、审批记录和生产配置保持兼容。

接口见 [编制与版本契约](../../contracts/schemas/ontology-authoring-v0.1.md)，独立安装见 [Python 包说明](../../packages/ontology/kernel/README.md)。本批不包含独立账号、实例仓库、标准格式互转、配置迁移或生产发布。
