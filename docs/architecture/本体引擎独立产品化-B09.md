# 本体模块独立性与宿主集成 B09

当前架构在 B09e 收敛为一个可复用模块，由 CoSpace 作为正式宿主运行。用户继续从「公共资源 → 语义本体」进入，使用平台身份和同一份业务数据。内核、公共界面组件与接口契约保持独立；当前不维护第二套工作台、登录、定义库或自动同步链。

本体模块管理通用概念、领域定义、依赖、约束及固定版本。CoSpace 持有场景、实例、几何、现场证据和采用选择。三层语义体系以及既有发布引用均保持有效。

| 批次 | 已保留能力 | 当前状态 |
| --- | --- | --- |
| B09a 可移植编制接口 | 草稿、校验、差异、送审快照、审批、发布和固定闭包读取；宿主注入身份、授权与事务端口。 | 由 CoSpace 业务 API 直接调用同一内核。 |
| B09b 存储与系统配置 | 可替换 SQLite 编制与分组适配器；保留已有数据库格式、文件名和 CoSpace 兼容导入。 | 适配器归 `kernel/adapters`；独立 HTTP 宿主及令牌配置已撤下。 |
| [B09c 定义与实例交换](../../contracts/schemas/ontology-exchange-v0.1.md) | 精确闭包导出、导入预检及草稿暂存，多闭包实例校验与有限 OWL 类层级投影。 | 保留模块和 CLI 能力；CoSpace 尚未新增交换 HTTP 接口。 |
| B09d 独立工作台验收 | 已验证内核和公共组件可以离开 CoSpace 场景运行。 | 独立浏览器应用、登录、专属构建和发行链已撤下，历史实现保留在 Git。 |
| [B09e 单宿主收敛](本体模块宿主集成-B09e.md) | 一个正式入口、一套公共组件、一份业务数据；独立性用模块及包级验收保障。 | 当前架构。 |

目录可以展示各模块自己的最新发布；读取某个固定版本时，必须返回该版本自己的依赖闭包。身份和权限由 CoSpace 在服务端绑定，浏览器不得声明 actor/scope。系统分组配置继续归 CoSpace 配置管理，场景实例继续由消费侧持有。

未来有第二个实际产品接入，或有明确的独立交付、部署和运维需求时，再设计集中服务或独立宿主。当前不把服务化、第二套账号和数据同步列为后续必做批次。

接口见 [编制与版本契约](../../contracts/schemas/ontology-authoring-v0.1.md)，包级使用见 [Python 包说明](../../packages/ontology/kernel/README.md)。
