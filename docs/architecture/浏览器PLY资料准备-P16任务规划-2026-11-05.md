# P16：浏览器 PLY 资料准备

日期：2026-11-05。状态：三个小批已实现并完成本机样本验收。见[P16验收](../validation/浏览器PLY资料准备-P16-2026-11-05.md)及[操作指引](../guides/浏览器PLY资料准备P16运行.md)。下文保留批准的范围。

## 目标与流程

在当前场景的数据管理“导入资料”中增加“准备 PLY”：选择原始PLY → 填写米制局部坐标及来源说明 → 本机检查 → 确认声明并登记 → 复用P15预检、批次、构建、发布和消费。

同一物理场景继续使用同一场景空间。准备不自动建场景、转换坐标、选择候选或发布。不增加服务或持久准备任务。

## P16.1 格式与来源

- 仍只支持P14的binary little endian、float32 XYZ、可选uchar RGB、单vertex，无mesh/多余属性。最大32MiB、100万点、8KiB头、单行1024字节；有限坐标且绝对值≤100万米。
- 浏览器从头部读取点数并检查负载长度与数值；后台重新执行现有解析。不能通过修改浏览器状态跳过后端约束。
- 单位固定m且需明确确认，不转换mm等单位。局部frame、三条轴语义、sensor_local/scene_local由用户填写，无猜测默认，无精度或场景对齐认证。
- 新包附加可选`source.json`，profile=`cospace.pointcloud-source/0.1`。保存原文件名、字节数、计算摘要、用户来源说明及坐标声明。该来源收据由浏览器生成，不伪造上游采集日志；kind固定existing_pointcloud，source_member_sha256等于所选原文件摘要，source_manifest_sha256等于source.json真实字节摘要。
- `pointcloud.json`新增可选source_receipt_path=`source.json`；显式存在时必须带收据且摘要／字段一致。历史P14清单保持兼容；旧清单不得带未声明收据。
- 登记actor及空间归属继续取服务端身份，收据不含租户、空间、操作者或本机路径。原文件字节封存在cloud.ply，坐标及来源声明改动形成新包，重复相同声明生成确定性包并复用原登记。

## P16.2 页面

- 沿用当前DS导入弹窗、场景上下文及窄屏滚动；第三个导入方式只有服务声明支持对应能力时可执行，旧能力响应不误开放。
- 本机检查完成后显示点数、颜色、字节数、摘要和坐标／来源复核，明确“尚未登记”；修改文件或声明使准备结果失效。
- 明确确认后才上传；失败保留同一准备包供重试，取消／换场景／卸载不处理旧响应。忙碌期防重复提交，按服务端回执核对场景和摘要。
- 详情及后续固定模型保留来源收据内容与摘要；只是声明，未核验现场坐标或采集来源。可通过现有事实接口看到来源说明。

## P16.3 验收

1. 后端：旧格式回归、可选收据绑定、缺失／多余／篡改收据、坐标与原文件摘要不一致、权限及场景隔离、重复导入和实时源变更拒绝。
2. 浏览器：本机XYZ与XYZRGB检查、错误布局／非有限值／截断／超限、必填和单位确认、修改后失效、取消与慢响应、旧能力、重复与失败重试、1440/390布局及资料详情不覆盖header。
3. 在P15运行区独立副本中用原OS1首帧PLY准备并登记；实际预检、固定模型及双视图、核对发布、下载，独立禁网进程核对同源查询与恢复。RGB-D/ROS及原PLY路线回归，不把同数据新声明当作现场变化。
4. 核对原运行区及历史发布摘要；保存实现、操作、验收及汇总文档。

不增加LAS/LAZ/PCD、ASCII PLY、配准、SLAM或点云精度研究；裸文件准备不等于任意点云通用导入。当前认证仍用本机模拟平台，真实账户联调和实机验收独立安排。
