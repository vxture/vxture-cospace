# 平台数据管理与项目关联设计 v0.3

日期：2026-11-24。状态：D00 设计已完成；D01 已实现项目与场景关联后端，页面和跨项目共享尚未接入。依据本次用户要求，将数据管理从场景资料工作面提升为平台数据资产目录，并增加项目关联及跨项目复用。本文取代 v0.2 中以单场景为主的数据管理入口设计；原有场景资料处理能力继续复用。

## 1. 定位与范围

数据管理统一回答：有什么数据、从哪里来、归谁管理、哪些项目可以使用、实际在哪里使用、使用的是哪个版本。

平台视角为当前组织和工作区授权范围内的 CoSpace 业务数据全貌；项目视角为该项目拥有、引用和产生的数据集合。两者查询同一份资源目录，不建立两套数据仓库。项目是业务组织维度，场景是具体空间及作业对象，二者均不等同于平台工作区。

覆盖采集资料、参考资料、可复用基础数据、固定数据集、空间模型与派生成果，以及关联的处理记录和血缘。语义本体仍由语义本体模块维护，本目录只关联固定定义；身份、系统参数、商业权益和运维日志归其原管理模块。

## 2. 当前实现与问题

| 核对位置 | 已有能力 | 需要修正 |
| --- | --- | --- |
| `shared-data-catalog.tsx` | 工作区目录、按场景筛选、检索和分页 | 无项目视角；默认筛选可能继承当前场景，入口范围不直观。 |
| `data-navigation.tsx` | 数据目录及场景作业导航 | 场景选择会改变导航条目；平台目录与具体场景工具混排。 |
| `packages/data/workspace_catalog.py` | 按权限聚合输入、附件、预检、批次、任务、候选、视图及发布记录 | 资源与处理记录混为同一数量；只有 `space_id` 过滤，没有资源身份、业务项目关联及共享授权。 |
| `packages/lifecycle/workspace_scenes.py` | 创建场景及可信工作区绑定 | 新场景默认归入同一「Workspace 场景目录」项目；不能把这个技术归档项目当作真实业务项目。 |
| `packages/lifecycle/preview_scope.py` 及来源校验 | 既有记录的场景、项目绑定校验 | 历史 `project_id` 被多条来源链固定引用，不能为改变页面分组而批量重写。 |

原目录还会列出“按需导出、尚未生成”的离线交付入口。新目录必须区分实际数据成果和服务操作入口：未生成交付包不计入资产数量。部分元数据读取失败须保留明确的不完整状态，不能将缺失误判为空数据。

## 3. 核心关系：归属、授权、引用分别记录

```text
组织 / 工作区
 ├─ 业务项目 ─ 场景关联
 └─ 数据资源 ─ 固定资源版本 ─ 内容或成果引用
       ├─ 管理归属：项目，或工作区共用
       ├─ 共享授权：允许哪些项目、以何种权限使用
       └─ 使用关联：哪个项目 / 场景、实际用了哪个版本、用于什么
```

一份资源只有一个管理归属，可以有多个获授权项目和多个实际使用关联。共享授权只表示允许使用，使用关联才表示已经引用；二者不能合并成一个 `shared` 布尔字段。相同内容摘要允许底层去重，不据此合并来源身份、项目归属或使用许可。

| 对象 | 最小职责 |
| --- | --- |
| Project | 有稳定 ID、名称、工作区绑定、负责人及状态的业务项目。复用有明确业务含义的既有项目 ID；默认技术目录不自动转换为真实项目。 |
| ProjectSceneLink | 场景的业务项目关联及变更历史；首批一个场景只设一个当前主项目。关联变化不重写历史来源记录。 |
| DataResource | 稳定资源 ID、名称、资源类型、来源、管理归属、创建人及管理状态。归属可以为项目或工作区共用，二者互斥。 |
| DataVersion | 固定版本及可核验内容引用、格式、大小、坐标声明、时间覆盖和质量证据；未知字段显示未知，不补造摘要或精度。 |
| ResourceGrant | 资源向指定项目或当前工作区授予查看、下载、引用等权限，记录授予者、期限及撤销修订；不授予源数据编辑权。 |
| ResourceUse | 项目、可选场景、固定资源版本、用途和使用状态；涉及空间叠加时保存适用的配准或坐标转换引用。 |
| ProcessingRecord / LineageEdge | 处理任务、检查结果及版本之间的输入输出关系；处理记录不冒充文件或空间成果。 |

旧输入、构建、发布等记录仍由原模块持有，新目录用资源登记和关联指向它们。先建立稳定资源与版本映射；可重建的查询索引不代替真实业务记录，不引入资源双写成为两个事实来源。

## 4. 项目视角

数据管理的默认入口为当前工作区的“全部授权项目”，不静默继承上次作业场景。操作行选择项目，项目选择改变查询范围，侧栏结构保持不变。项目不作为必须进入的新页面或第二套侧栏。

选定项目后，数据范围包括本项目管理资源、从其他项目引用的资源、已经关联使用的工作区共用资源及本项目产生的成果。通过“关联方式”筛选本项目、外部引用和平台共用。尚未关联的可用共享资源通过“关联已有数据”抽屉检索，不混入当前项目的数据数量。

场景筛选位于所选项目之下，同时保留“项目级资料”选项，使没有场景绑定的数据可以管理。切换项目清除不适用的场景与对象选择，切换工作区清除原项目上下文。全平台默认列表只按资源去重；项目列表同一资源被多个场景使用仍只显示一次，详情列出各使用关联。

项目创建、成员和场景关联属于业务组织能力；资源分类字典、共享策略默认值及保留策略归配置管理。项目功能在平台身份与场景授权之上接入，不把技术目录列表当作项目授权。

## 5. 分类与导航

资源类型、基础用途、项目归属、共享范围和生命周期分别定义，不混成一棵分类树。“基础数据”表示可长期复用的基础用途，例如园区底图、控制网、既有建筑参考、标定和固定配置资料；具体资料仍保留采集或参考类型。基础用途与是否共享无必然关系。

| 导航组 | 条目 | 内容 |
| --- | --- | --- |
| 数据资源 | 全部数据 | 全部授权资源，包含待分类记录。 |
| 数据资源 | 基础数据 | 具有基础用途的资源集合。 |
| 数据资源 | 采集资料 | 点云、影像、传感日志、轨迹等原始采集资料。 |
| 数据资源 | 参考资料 | IFC / BIM、图纸、控制点、标定、外部台账等辅助资料。 |
| 数据资源 | 数据集 | 明确成员及固定版本的资料集合，不把临时勾选或文件夹当作已固定数据集。 |
| 数据资源 | 空间成果 | 已实际生成的模型、视图、质量报告及交付包等成果。 |
| 业务记录 | 引用记录 | 项目和场景实际使用数据的记录。 |
| 业务记录 | 处理记录 | 预检、转换、构建等任务及检查结果的可追溯记录。 |

这是一套目标导航。每项须在真实查询能力接通后开放，不先做空占位页。项目名、场景名、数据项和自建分组不堆入导航；导入、编辑、共享、构建、发布是对象操作。血缘图在所选资源详情中展开。

资料与预检、配套资料、点云、批次等现有场景工具从资源详情或场景操作进入，迁移期间保留旧直链。数据目录只使用一套 DS 板块导航，不额外增加项目树或顶部分类标签。

## 6. 共享标记与复用行为

| 标记 | 条件及含义 |
| --- | --- |
| 已共享 | 本项目管理的资源存在有效的对外授权；不表示已有其他项目使用。 |
| 外部引用 | 当前项目已引用其他项目管理的固定资源版本，显示允许披露的来源项目。 |
| 平台共用 | 工作区共用资源，并具备相应有效授权；不等于匿名公开或自动可用于全部项目。 |
| 被 N 个项目引用 | 实际有效使用项目数；按可见范围统计，不能泄露未授权项目或全局数量。 |

标记靠近数据名称，使用轻量标签；详情分别展示管理归属、共享授权和实际引用。无对外授权的普通本项目资源无需默认加“未共享”标签。已共享和被引用可以同时成立。

典型操作：A 项目上传控制网资料形成资源及版本 → 明确向 B 项目开放引用权限 → B 从“关联已有数据”选择版本与用途 → 必要时核对坐标和质量 → B 显示“外部引用”，A 显示“已共享”及可见的使用记录。流程不复制整套原文件，不改写 A 的归属，不自动替换 B 的空间基准或构建输入。

源资料变更产生新版本，已有引用保持固定，消费项目显式核对后升级。取消项目关联不删除源资源。撤销共享阻止新的受限访问和引用，保留历史引用审计，并标记当前授权状态；已固定服务的可用性按原服务契约核验，不能承诺无条件继续访问。存在引用时不允许直接物理删除，归档及回收按引用和保留规则处理。

首版只处理同一工作区内的跨项目复用。跨工作区交换另行设计，不从“已共享”标签推断跨租户权限。

## 7. 页面规范

页面结构固定为：公共页头 → 单行项目 / 场景与查询操作行 → 数据清单 → 分页。使用现有公共内容容器和 DS token，沿用 1536 / 1440 宽度控制及 80px 底部安全区。组件高度 32px、操作行文字 12px；行间距离由 gap 控制，不叠加多重 margin / padding。

清单包括序号、名称及标记、类型、管理归属与关联摘要、版本与更新时间、操作。序号及操作列均为 64px、居中且保留两侧留白；操作使用外框 32px、图形 24px 的三竖点汇聚按钮，菜单项为 icon + 文本，分隔线分组且无分组标题。低频筛选收入筛选面板，窄屏合理换行或横向滚动，不把操作行挤成多层大表头。

导入、关联已有数据和共享设置采用抽屉；需要大图作业的既有预览 / 编辑器继续使用专门工作面。列表不下载完整点云或模型，不把不可访问或未生成的数据画成可用成果。

## 8. 分批执行与验收

| 批次 | 本批交付 | 完成条件 |
| --- | --- | --- |
| D00 框架与盘点（本文） | 平台定位、项目与资源模型、分类、标记及旧实现缺口 | 明确归属、授权、引用的区别，确认历史绑定不被改写。 |
| D01 项目基础与历史映射 | 可信工作区内业务项目、场景主项目关联、项目查询及旧目录映射 | 两个真实业务测试项目可分别关联场景；默认技术目录保持“待关联业务项目”，迁移可重入且可追溯，不改旧构建和发布来源。 |
| D02 统一资源目录与项目视角 | 资源 / 版本登记和既有记录投影、项目 / 场景过滤、新导航与清单 | 平台资源去重、项目数据齐全；任务与未生成交付入口不计资产；部分失败明确可见；既有数据入口仍可使用。 |
| D03 基础数据与跨项目复用 | 项目级 / 共用资源、共享授权、固定版本使用关联、共享抽屉及标记 | A 向 B 共享并由 B 引用，C 无权访问；仅共享未引用、引用撤销、源升级和坐标不适配均有明确结果。 |
| D04 引用追溯与版本治理 | 使用记录、血缘、版本升级及归档影响检查 | 能回答来源、使用版本及受影响项目；旧服务不随源升级变化；引用中的源资料不能直接删除。 |

各批次只上线已完成的范围，依次执行，不把跨工作区共享、通用数据湖或第二套独立平台加入首版。D02 初期只能展示已具备真实语义的关联标记，D03 完成前不伪造共享状态。D01 的项目授权是后续数据访问的前置条件。

D01 当前接口及权限见[业务项目与场景关联契约](../../contracts/schemas/business-projects-v0.1.md)。显式关联记录单独持久化，旧 `/api/projects` 及来源 `project_id` 保持兼容；D02 从新接口读取业务项目，不将旧技术目录当作默认业务项目。页面尚未增加项目选择或管理入口。

场景主项目变化仅改变业务组织关联，资源管理归属须在 D02 单独登记并保留历史，不能随场景重新关联自动迁移。

端到端验收数据采用明确标注的园区合成资料：项目 A 为园区基础测绘、项目 B 为园区巡检应用、项目 C 为未获授权的对照项目。A 有控制网、参考模型和采集资料，B 有独立场景；验证共享、引用、版本更新及撤销全过程。真实旧资料的业务项目归属仅按明确证据或管理员选择建立，不按名称、时间或路径猜测。
