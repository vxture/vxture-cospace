# CoSpace 工作台界面布局设计 v0.2

本轮以 UI 设计原型确认页面布局。空间态势是业务使用的主要入口；构建、资料、本体和服务属于业务工作区；业务配置、账户和权限属于管理区域。当前没有计量、额度或计费页面。

## 参考与布局决策

参考项目：`D:/MyWebSite/vxtureagents/vx-agent-yucer`。

- `(app)/components/app-shell.tsx`：顶部稳定保留产品、Launcher、管理和账户入口。
- `(app)/components/domain-launcher.tsx`：Launcher 按功能域分组，使用链接进入业务页面。
- `(screen)/layout.tsx` 与 `national-screen`：大屏拥有自己的完整视口，不套用常规后台侧栏；折叠辅助信息，全屏与登录继续属于同一产品。
- `(app)/components/sign-in.tsx`：未登录时显示登录入口，并保留目标页面意图。

采用其信息架构与大屏原则。当前原型仍是独立 HTML/CSS/JS，尚未导入 Vxture Design System 包；后续迁入 React 页面时使用 DS 的 Shell、Panel、Menu、Form 和 Dialog 组件。

## 页面与入口

| 区域 | 页面 | 主要布局 |
| --- | --- | --- |
| 空间使用 | 空间态势 | 全幅深色空间视口；对象与图层、对象属性作为浮层；双视图切换；沉浸与全屏 |
| 业务使用 | 数据管理 | 资料目录、类别、准备状态与引用关系 |
| 业务使用 | 语义本体 | 类型、必要属性与本体版本 |
| 业务使用 | 构建中心 | 输入、预检、算法回放、校核阶段与状态 |
| 业务使用 | 服务与交付 | 人视图、智能体视图、在线服务与离线交付 |
| 管理 | 业务配置 | 空间名称、单位与坐标约定、默认本体、智能体交付模板、发布方式 |
| 管理 | 成员与角色 | 成员身份、工作空间角色与状态 |
| 管理 | 登录集成 | 第三方认证接入状态与配置责任 |
| 账户 | 个人账户 | 身份来源、所属工作空间、角色与退出 |

Launcher 分为「使用空间」「构建空间」「定义空间」三组。管理由顶部独立入口进入，账户由头像进入。

## 大屏交互

1. 桌面默认隐藏侧栏，底图占据除 64px 顶栏外的整个视口。
2. 对象树与属性面板浮在视口上方，不改变底图容器尺寸；可分别收起。
3. 沉浸模式隐藏顶栏和辅助信息，仅保留退出操作；Esc 可退出。
4. 浏览器全屏使用 Fullscreen API，并同步浏览器退出状态；拒绝时给予提示。
5. 窄屏保留完整底图范围，Launcher 与管理入口可访问。

## 第三方登录与账户边界

正式接入拟使用 OIDC Authorization Code + PKCE，产品服务端维护会话，通过 HttpOnly Cookie 关联浏览器。具体身份提供方、客户端、回调与注销行为待确定。第三方负责身份认证；CoSpace 的工作空间成员与角色仍由服务端授权。

UI 原型仅用 sessionStorage 记录「进入 UI 预览」状态，绝不是认证控制。现有 API 与功能演示未因本轮 UI 改造获得鉴权保护，正式实现必须覆盖页面和 API。未连接身份提供方时，第三方登录按钮展示接入说明，不伪造成功登录。

## 原型可操作范围

- 页面导航、Launcher、管理与账户菜单、对象选择、图层切换、浮层、沉浸展示可交互。
- 基本配置可保存为本浏览器 localStorage 草稿；场景与工作空间名称用于当前预览。
- 成员可添加临时草稿，刷新清除；不发送邀请，不创建账户，不变更真实权限。
- 业务页使用示例数据，构建和语义编辑入口仅展示流程说明；不执行真实任务。
- 空间图是 SVG 布局示意，尚未替换为真实三维数据或可操作的 Three.js 相机。

## 后续实现顺序

1. 确认大屏、Launcher、业务与管理布局。
2. 将布局迁入 React 路由与 Vxture DS，分离业务 Shell 和大屏 Shell。
3. 接入真实空间渲染与固定版本查询。
4. 接入第三方认证、服务端会话与工作空间授权，再接管理写入、校验和审计。
5. 逐步接入资料、本体、构建和双视图交付业务接口，不引入计量模块。
