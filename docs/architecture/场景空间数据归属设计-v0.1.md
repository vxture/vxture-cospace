# 场景空间数据归属设计 v0.1

六板块整理更新：[三类六板块场景空间总体整理](三类六板块场景空间总体整理-v0.1.md)已统一全宽框架、场景目录和跨模块上下文；语义本体保留共用定义边界，场景实例在空间关联中管理。60 项浏览器布局与导航检查通过；样本场景初始化和数据迁移仍未实施。

日期：2026-11-03

本设计修订此前“任意样本登记到当前空间”的产品口径。数据管理以真实三维场景为中心，场景空间是该场景的数据管理单元。

## 1. 归属层次

```text
平台 Workspace
├── 场景空间 A：一个具体三维场景
│   ├── 原始资料：多次采集、多种传感器、多种格式
│   ├── 构建任务与处理记录
│   ├── 历史模型版本：同一场景的连续演进
│   ├── 语义与空间关联：绑定对应模型/本体版本
│   └── 发布成果与人/智能体视图：来自确定版本
└── 场景空间 B：另一个具体三维场景，独立管理上述数据
```

Workspace 是客户边界，不对应单个人。场景空间复用现有 `space_id`，不另外新增一层“场景”实体或第二套空间 ID。

## 2. 拆分与归并规则

- 按实际场所、空间范围和业务管理边界划分场景空间，不按文件名或输入格式划分。
- 同一设备间及纳入管理范围的走廊，可以组成一个场景空间；同一场景的 RGB-D、激光、IMU、控制点、已有点云/BIM 和复测资料统一归入其中。
- 不同采集批次形成同一场景的不同资料记录。构建和修订可形成多个模型版本；发布成果明确绑定版本。
- 不同物理场景不作为同一场景空间的不同版本，也不混在一个场景空间测试输入适配。
- 新版本继承场景身份；复制文件或更换名称不等于创建新的物理场景。
- 需要校验资料的空间范围、坐标基准、采集来源及配准关系，不能根据文件后缀或传感器型号自动断定是否属于同一场景。

## 3. 预置样本的修订口径

预置单位应为“样本场景包”：场景名称、来源说明、可用输入资料、已知坐标/时间声明及使用限制。一个包描述一个场景，初始化到该场景对应的独立场景空间。包内可以包含多格式、多批次资料；模型版本和发布成果沿用此空间身份。

首批规划分别为 NYU 办公室样本场景与 OS1 局部采集样本场景。两者来自不同采集场景，不合并为一个空间的两个输入格式。OS1 当前仅有单帧局部构建能力，不能把该样本场景称为完整场所地图。

普通使用中，同一 Workspace 再次使用同一样本场景应定位其已有场景空间，并按内容去重；显式建立隔离测试副本属于单独的测试操作，不能成为默认初始化行为。

## 4. 当前实施与下一步

现有目录、输入、候选、发布和服务查询已按 `space_id` 组织及授权。数据管理页面统一显示“场景空间”，样本库明确显示当前目标空间名称，避免登记归属不清。

当前样本库仍为已有场景中的来源登记入口，尚未实现“样本场景包 → 创建/定位场景空间 → 绑定该场景来源 → 登记资料”的初始化流程；平台授权服务目前也未开放场景创建接口。本次不绕过平台权限直接生成业务空间，不宣称已实现物理场景归属的自动判定或服务端强约束。

下一步实施重点：

1. 定义样本场景包的稳定身份和来源清单，保持样本场景身份与采集资料版本分离。
2. 接入 Workspace 下创建/定位场景空间的授权入口，为 NYU、OS1 分别初始化独立空间。
3. 将来源许可与样本场景包绑定，登记时校验场景归属；来源启用不再被当作物理场景归属证明。
4. 验证同场景多资料/多版本、不同场景隔离、重复初始化复用空间及无权创建的异常分支。

现有“测试空间 A/B”等工程验证数据包含历史测试混用，不据名称自动迁移或删除。后续单独整理样本场景时保留已有引用和发布追溯。
