# 场景 IFC 参考资料接入设计 v0.1

2026-11-18。状态：实施规格，尚未上线。适用于需要把 IFC 设计资料用于场景参考、构件查阅和空间查询的业务人员。

## 用户在哪里操作

主入口：**空间关联 → 对象管理 → 参考资料 → 添加 IFC**。页面已有构件查询区，继续在同一位置查看结果，不另设业务板块。

「数据管理 → 配套资料」仍负责原文件登记。上传成功后可提供「用作场景参考」快捷入口，带着该场景的文件进入同一个流程，不重复上传，不自动开始解析。

## 业务和交互

| 步骤 | 用户看到和执行的动作 | 系统行为 |
|---|---|---|
| 1. 添加 | 「选择已有 IFC」或「上传 IFC」，确认场景和文件，点击「开始解析」 | 复用场景配套资料上传和去重；解析任务固定场景、文件和源摘要 |
| 2. 等待 | 「排队中」「解析中」；可以离开页面，回来继续看任务 | 后台运行；只显示真实阶段，不显示估计百分比；刷新不会重复创建任务 |
| 3. 检查 | 「待启用」或「解析失败」；成功可查看楼层、门、楼梯和几何缺项，失败提供原因及「重试」或「重新选文件」 | 校验原文件、目录、关系和几何成员；标注缺项；结果与当前参考版本并存 |
| 4. 启用 | 首次点「设为当前参考」；已有版本则用 DS 确认面板显示新旧版本及影响 | 确认后原子切换当前版本。后续构件浏览、查询和导出采用新版本；旧版本仍可查。若同时有人切换，提示刷新复核，不覆盖对方选择 |
| 5. 回退 | 「版本记录」显示文件、时间、状态及操作人；从历史版本选择「恢复为当前参考」并确认 | 复用切换逻辑，保留新旧资料及审计记录；无需重新解析 |

页面按「当前参考」「待处理」「版本记录」组织。有当前参考时优先展示可用构件，新解析任务放在「待处理」，不会挡住查阅。没有当前版本时，给出明确空态「还没有 IFC 参考资料」，有操作权限才显示添加入口。解析成功不等于启用，启用也不等于现场核验。

提示文字示例：

- 解析完成：「已提取 3 个楼层、7 扇门、2 部楼梯。预览后可设为当前参考。」
- 模型无空间声明：「该文件未提供房间或楼道声明。」
- 切换确认：「构件浏览、查询和导出将改用新版本。现有对象关联和已发布成果不会被自动迁移。」
- 成功状态：「设计资料 · 待核验」。

## 权限、结果和边界

- 原文件登记沿用 `data.manage`；构件读取沿用 `association.edit`。第一版发起解析、重试、启用与回退同时检查这两项场景能力，后端重验，界面按同一结果控制按钮。无权账号不能通过文件 ID、任务 ID 或版本 ID 跨场景读取；任务完成也不授予任何权限。
- 原文件与解析版本不可变。重复源文件复用已有上传；同一场景、原件摘要和解析器版本的并发任务去重，失败由用户显式重试。较新解析器的结果可并存，不能覆盖较旧版本。执行任务不改变当前参考。
- 当前参考只决定本场景的 IFC 浏览、查询和导出来源。已保存的构件引用继续保留原版次和构件标识，按其摘要解析；无法解析时显示待复核，不按名称或 GlobalId 私自改绑。旧查询、下载继续使用各自固定版本，不能误读新目录。
- 不自动对齐点云、重构场景、迁移关联、修改发布或更新动态状态。设计声明和本体映射、现场确认分别保留。应用自行判断设备通行与导航。

## 技术落点和次序

1. 复用场景附件服务与原件校验，增加按场景隔离的 IFC 解析任务、不可变产物和当前版本指针。把读接口接到版本解析器；已有静态绑定作为只读兼容来源，迁移时不中断已有场景，不继续用全局配置给业务人员开新场景。
2. IFC 原生解析运行在独立受限 worker，沿用 `inspect_ifc_structure`，不把解析器放进请求线程或公开上传服务。限制文件、队列、时长、内存和并发；只读输入和独立临时输出；完整校验后再提交，超时或重启可恢复，半成品不可见。原件和产物纳入现有留存、备份和恢复验证。
3. 工作台加上述入口、任务反馈、预览和版本切换。先通过集成环境端到端，再按正式发布流程上线；不以运维通过 SSH 注入 Anoeta 数据代替产品验收。

## 可执行验收

| 验收 | 通过条件 |
|---|---|
| 首次接入 | 有权限账号从网页上传 Anoeta 或选择其原件，解析后预览 3 楼层、7 门、2 楼梯，显式启用后读取、查询和导出一致；全过程无需 SSH |
| 重复和失败 | 同文件重复提交复用已有任务或结果；输入损坏、任务超时、worker 重启时，旧版本仍可用，刷新后状态正确，可重试 |
| 变更和回退 | 替换时呈现新旧差异和影响；并发切换拒绝覆盖；回退后恢复原目录摘要，构建、关联和发布记录不变 |
| 权限隔离 | 有权和无权账号分别验证目录、任务、切换和查询；上传后撤销权限，不能查看或启用 |
| 可复制 | Anoeta 通过后，Longyearbyen 用同样的网页流程完成，无场景特判；备份恢复后同一版本的构件与查询结果保持一致 |

先前准备的 Anoeta/Longyearbyen 运行资料包只作解析结果比对及运维预演，不作为正式上线路径。业务通过之后，现场事实验收仍按独立证据推进。

### 第 1 批实施记录

已实现：从场景附件登记解析任务、按原件摘要及解析器版本去重、独立解析入口、版本保留、显式启用/回退、并发版本检查、备份内容校验。`IfcWorkspace` 可在显式注入版本仓库时解析当前及先前启用的固定摘要，待启用版本不进入普通查询。未注入的环境继续使用已有静态绑定。

本地以真实 Anoeta 原件验证解析及启用后读取：168 个实体、173 条声明关系，含 3 层、7 门、2 楼梯。该操作验证后端生命周期，不是网页或部署验收。子进程启动器用于本地验证；生产还需接通独立 worker 的调度、容器资源和网络约束、HTTP 授权与工作台界面后再开放入口。
