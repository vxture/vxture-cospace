## 1. 定位与数据归属

将已提供的资料选成可重复使用的流程样本，入口为数据管理右上角「样本库」。Workspace 是客户边界；每个样本场景应先创建或定位独立场景空间，资料、构建结果和历史版本均属于该场景空间。

样本库复用服务端来源目录，不新增样本 workspace 或自动生成业务场景。同一样本场景在 Workspace 内默认复用其对应场景空间；跨空间重复仅用于显式隔离测试；同一场景的相同内容重复登记定位已有记录，不重复生成资料，不改原名称，不自动构建或发布。不同场景的登记独立，不将相同源文件当成跨场景可访问的业务记录。

预置指本机部署中已有的样本目录和封存文件，不代表已把整个原始数据集打包进入产品，也不代表已经完成再分发授权确认。当前前端的样本说明对应下列固定来源 ID 与格式；部署替换这些来源时需同步核对说明。

## 3. 当前登记入口与交互（场景包初始化待实现）

1. 选择有数据管理权限且与样本真实场景一致的场景空间，打开「样本库」；页面明确显示目标名称。不同场景不得通过此入口混入同一场景空间。
2. 读取服务端当前场景来源配置；仅匹配已知样本 ID 和格式，不把所有普通资料来源自动称为预置样本。
3. 样本卡片展示格式、规模、来源、用途和限制。管理员可看到当前场景尚未启用的已配置来源，并从「配置样本来源」进入既有来源配置；其他成员仅看到自己有权使用的启用来源。
4. 选择可用样本，确认资料名称，点击「使用此样本」。提交仍只含 `space_id`、`source_id`、`label`，浏览器不提交服务器文件路径。
5. 服务端按最新来源许可重新核验原文件及配套轨迹；成功后定位资料详情，继续通过「用于构建」进入既有链路。

样本库不自动启用被停用的来源，不改变已有来源许可。停用、换源、失去权限或文件校验失败时显示错误，不创建伪成功记录。切换场景时组件重建，并取消未完成的目录请求，防止旧样本选择沿用到新场景。

## 4. 定义与验证

本批只新增样本选择入口；登记对象与输入格式继续使用既有定义，不再增加一套样本资料业务模型。样本卡片规模是封存资料说明，登记后的实际检查结果以保存记录为准；样本名称不作为去重或版本依据。

使用 `python -m experiments.scripts.verify_sample_presets --output output/validation/sample-presets-2026-11-03.json`，读取真实封存文件，在临时目录验证两套样本校验、同场景去重、跨场景独立登记及重启读取，并对比原始 195 个工程记录的摘要。临时记录不进入当前工作区，不发起构建或发布。

另复用来源权限、来源停用和登记校验测试；浏览器检查样本库展示、停用来源禁选、来源配置入口及窄屏布局。当前 8769 为模拟身份服务，不能据此认定完成真实平台或机器人验收。

验证结果：两套真实样本在临时目录各登记到两个场景，共 4 条记录；同场景重复登记复用记录，重新加载后归属一致，未启动构建或发布，原始 195 个记录文件摘要不变。既有登记与来源权限回归 17 项通过，前端 TypeScript/Vite 构建通过。结果见 `output/validation/sample-presets-2026-11-03.json` 和 `output/validation/sample-presets-regression.txt`。8769 浏览器验证未修改当前场景的来源许可或已有资料。
