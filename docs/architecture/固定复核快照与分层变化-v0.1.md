# 固定复核快照与分层变化 v0.1

日期：2026-11-17。承接 SG3 标注、SG4 设计资料包与本体提案、SG5 变化影响核对。这是可重放的**复核输入快照**，不是已核实事实快照或正式服务发布。

## 1. 构成与职责

`cospace.ifc-review-snapshot/0.1` 固定场景/IFC 目录与原文件引用、完整设计资料包摘要、结构声明摘要、原坐标系、区域与连接标注、证据引用，以及可选的本体映射与提案摘要。Schema 位于 contracts/schemas/ifc-review-snapshot-v0.1.schema.json。快照最多 8 MiB，设计包沿用 32 MiB 预算及全部组件核对。

快照内保留原工作表与结构复核记录的规范内容摘要，标注原样保存；区域 ID 是工作表局部身份，IFC GlobalId 是来源身份，两者分开，不能据此建立正式稳定实体身份。本体仍是独立的固定版本文件；映射只生成类型提案，不改变源声明或确认连接。观测日志和回放上下文不嵌入本快照，实时报告改变也不改写它。

不扩展 SG0 synthetic 契约、不把 synthetic 改成 real，不引入第二套可编辑权威底图。原 annotation 与 structure_review 校验内核分别移到 spatial / construction，旧 CLI 入口保留；生成快照和旧标注命令复用相同校验。

## 2. 生成与读取

本地生成：

```text
python -m experiments.scripts.ifc_review_snapshot --bindings <本地受控绑定.json> --space <场景ID> --catalog-sha256 <目录摘要> --output-dir <新目录>
```

可加 `--worksheet` 载入已有工作表；省略时由当前已核对来源生成空表，所有门/楼梯任务保持待标注。可同时加 `--mapping <映射.json> --ontology <固定本体.json>`；两项缺一拒绝。输出 snapshot.json、design.bin，最后写 receipt.json（成员摘要、大小与来源）。目标目录必须不存在，拒绝覆盖。写入中断的目录不是完整导出，不自动补齐或安装。

生成先导出完整设计包，再从相同目录核对原 IFC 和相关网格、重建结构复核任务，验证工作表与原复核摘要和坐标系绑定；从固定结构和本体实际重算类型提案；最后重新导出设计包比对，发现来源/配置变化则拒绝返回结果。只有类型映射改变时包字节不变。

程序读取 `inspect_review_snapshot` 要求外部可信的快照 SHA-256、来源引用和实际 design_package 字节；有映射时还需固定 ontology_raw。它检查原始字节摘要、规范 JSON（拒绝重复键/额外空白）、严格 Schema、来源、结构/坐标一致性及完整资料包。随后从包内源声明建立标注校验上下文，复查区域几何、楼层、任务覆盖、依据引用、端点所在区域和楼梯端点顺序，并重算类型提案与摘要。

内部标注上下文只是为固定包重放而建立的投影，不冒充最初的结构复核记录。annotation_check_context 明确为 snapshot_source_projection；其中 worksheet/source_review 摘要指本次内部投影，原摘要独立保存在 snapshot.annotations。读取时不需要原 IFC 目录，但不因此声称已重新读取或认证原文件；原始记录摘要是追溯锚点，不能仅凭摘要重建原证据。

本体原文件另行保存，不能用快照内摘要替代原内容；缺少或不符即拒绝。无映射时不得夹带本体或提案摘要。返回的统计及 complete_annotation_ids 只表示标注结构与几何自洽；confirmed_connections 为空，evidence_content_verified、alignment_verified、ontology_bound、real_release_ready 始终 false。

## 3. 分层变化与复核影响

`compare_review_snapshots` 先完整检查两版，再比较。首批仅支持**同一固定设计包、目录和坐标系**；设计重提取、更换来源、跨版身份迁移不支持，应先走新的身份与对齐复核，不能把它解释成无变化。

```text
python -m experiments.scripts.ifc_review_changes --base <旧snapshot.json> --target <新snapshot.json> --base-sha256 <旧快照摘要> --target-sha256 <新快照摘要> --design-package <同一design.bin> --source <可信来源引用.json> --output <新变化报告.json>
```

有映射的版本分别提供 --base-ontology / --target-ontology。source 文件是 SourcePin 对象，不是整份导出 receipt；来源与摘要应来自可信调用上下文或另行保存的可信记录，不能把读取同一不可信包内的摘要当信任建立。

报告 `cospace.ifc-review-changes/0.1` 区分 areas、connections、evidence、types 的 added/removed/revised。证据摘要改变会传播到引用区域，再传播到这些区域的连接任务；区域删除或修改同时查看前后引用。本体上下文改变即使类型 ID 相同也要求语义复核。仅映射规则改变而实际类型结果未变，仍列 semantic_mapping_review。原复核/工作表摘要改变单独列 provenance_changed，避免相同内容下忽略依据上下文变化。

review_components 是待复核的类别，不是任务编排或重构许可。affected_area_ids 与 affected_source_entity_ids 分开输出，不混用局部标识与来源实体。只改类型不会要求 structural_connections，也不会重派生 IFC 几何。设计几何在此比较范围内固定，因此 design_geometry_changed=false；不包含观测变化，observation_changes_included=false。不推断现场物理变化、不继承稳定身份、不写入状态、不重构、不发布。

## 4. 安全、留存与后续

本轮是本地文件工具和内部方法，没有新增 HTTP、登录、审批或公开写入接口。workspace 方法的调用方仍须先做场景授权，本地 CLI 的无鉴权适配器只能用于有文件权限的操作者。绑定路径、本体、设计包、原始标注和现场资料均应留受控目录；数据导出不含凭证。摘要不含签名，不证明复核者身份或现场事实；读取成功不是审批通过。

上轮证据文件内容核对回执不作为可自报的审核标志嵌入快照，本轮不自动保留证据字节。证据缺失、单位和对应点未核实、区域/连接未填等仍是下一步事实采用的缺项。需要在受控复核、证据留存与审批机制成立后定义已采用事实快照及正式用途发布，不能仅更改这些 false 字段完成升级。
