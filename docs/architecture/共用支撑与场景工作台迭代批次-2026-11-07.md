# 共用支撑与场景工作台迭代批次

日期：2026-11-07。批次前缀 N，独立于既有 P、C、D 系列，避免混用进度。

用户确认方向：数据管理与语义本体是共用支撑，数据包含原始、过程、成果；场景选择前置于场景工作；左栏组织板块能力；页面内部横栏表达业务流程、当前阶段和未完成事项。三类六板块允许重新评估。

## 1. 产品边界与现状

共用支撑可独立进入，场景是可选筛选及返回上下文。场景工作必须有明确授权场景。共用目录不改变资产归属，不扩大访问权限，不意味着全平台公开，也不默认允许跨场景复用。

| 范围 | 能力 | 当前事实及差距 |
| --- | --- | --- |
| 共用支撑 | 数据管理 | 当前 InputDirectory 默认选择首个场景，按 space_id 读取资料与成果；尚无已验收的跨授权场景统一工作面 |
| 共用支撑 | 语义本体 | 已有共享模板及 Workspace 私有规则，见 workspace_authoring.py 与 P21；不再沿用早期“未实现 Workspace 私有本体”的结论 |
| 场景工作 | 构建中心 | 已有构建流程、任务、候选三个子视图 |
| 场景工作 | 空间关联 | 已有语义与几何、IFC 构件资料、对象与业务、对象间关系 |
| 场景工作 | 态势服务 | 已有固定发布与在线／离线交付；“发布与服务”为候选名称，待任务路径验证后统一调整 |
| 场景工作 | 空间预览 | 已有固定发布目录和独立三维页面；不强制填充多项侧栏 |

当前模块通用壳与数据页面各自维护场景目录。Launcher 和页面六模块横栏重复，且普通切换会继承 input、batch、job、publication，与原设计“普通切换只保留场景”不符。构建、关联已访问子视图在同场景保持挂载，但不能据此宣称跨模块、刷新草稿已保存。

产品模板继续参考 vx-agent-vxtpl，视觉沿用现有 DS。新布局实施前核对模板可用版本；无法取得时明确记录，不能把未经检查的模板约定当成事实。

## 2. 目标结构

工作台外壳统一提供产品身份、Workspace、功能入口；场景工作显示当前场景选择器，共用支撑显示范围／场景筛选。左栏是当前板块能力，主区是操作工作面，详情按需展开。全屏三维与构建画布保持专用布局。

功能入口按“共用支撑／场景工作”评审分区，六个能力暂不合并、不改稳定 route key。现有三类分组是过渡显示，不作为新业务归属。N3 完成任务路径评审后决定菜单分组和名称。

场景入口用于查找、创建、概况；顶部选择器用于工作中切换。完整深链直接进入目标，不经过额外选择页。创建场景入口提升到场景层，数据导入仍留在数据工作面。

数据左栏须区分数据生命周期与管理任务：原始／过程／成果是分类维度，资料、批次、任务产物、模型、视图、发布、交付等是具体对象；不以三类标签替换已有对象模型，不为同一产物创建第二套身份。

### N2 子批

1. N2.1：逐对象盘点 ID、原存储、归属、版本、授权、生命周期、来源与可复用条件。明确原始观测、已有模型、配套资料；过程包括已有批次、任务、检查及可访问中间产物；成果包括模型、双视图、固定发布及交付。缺失的持久化对象列为后续能力，不造虚假目录项。
2. N2.2：授权只读目录与过滤／分页／错误契约。评估服务端统一投影，避免浏览器向每个场景无界扇出；权限需按对象操作核对，不能只依赖可见场景目录。明确读取时间、部分失败、无权限、无记录的区别，筛选条件纳入 URL。
3. N2.3：接入共用工作面和本体独立入口。跨场景目录先完成查询与定位；导入、编辑、停用、删除仍走原对象授权。建立在无场景工作面进行写入时的归属选择规则。跨场景复用只开放有明确后端契约与权限的类型。

## 4. 上下文与数据不变量

- 普通板块切换仅保留场景；在共用支撑中它是筛选／返回上下文，不是资产归属声明。普通切换不带旧 tab、input、job、batch、artifact、publication 或本体固定引用。
- 显式业务交接携带目标需要的固定引用，并由服务端核对场景绑定与权限；URL 不是授权依据。若来源记录不符合目标条件，提示处理，不静默换成最新记录。
- 切换场景清除旧记录及临时选择，可保留当前能力与有效子功能；显式不可访问场景不替换为首个场景。Workspace 改变清理旧上下文并重新授权读取。
- 不自动修改任务、选择候选、替换本体引用、发布、退役或取消任务。未保存编辑需受保护；在迁移具体编辑器时实施，不能等最终验收才处理。
- 当前工作候选、当前查看固定发布和消费端实际启用版本分别表达。下载、预览、查询成功都不证明设备已安装启用。
- 数据统一管理不搬动历史目录、不改 ID、不复制业务权威记录；全局目录是授权投影。删除与停用需遵守引用影响与既有生命周期门禁。
- 共享模板只读、Workspace 私有规则可跨其场景引用；固定本体版本升级不自动迁移场景或历史发布。
- 平台继续拥有订阅与商业权益；本轮不引入产品侧商业额度。

## 5. 验收矩阵

| 路径／边界 | 必须观察到的结果 |
| --- | --- |
| 共用支撑独立进入 | 无场景可查授权数据／规则，筛选和返回上下文明确；没有可见场景也不阻断有权限的规则工作 |
| 空场景首次工作 | 创建场景、选择输入、预检、构建、核对、发布、使用可连续操作；无语义增强可完成 |
| 同场景第二版 | 明确跟进资料／任务；本次待处理与旧发布可用并列 |
| 历史发布直达 | 固定版本及其来源不被最近任务／候选替换 |
| 构建或视图失败 | 指向原任务恢复能力；切换页面不取消后台任务 |
| 可选语义增强 | 共用定义固定引用，关联实例形成场景候选，再核对发布 |
| 编辑与会话 | 切换、返回、过期恢复和刷新行为明确；无自动写操作重放 |
| 权限与隔离 | 查看者、工程师、规则维护者、管理者分别按能力测试；跨 Workspace、撤权、无权记录不泄露 |
| 空、错、部分失败 | 无记录不等于读取失败；无法确认不显示完成；可访问目录不等于可写 |
| 多标签和布局 | 每页 URL 独立；1440／919／390px 无全局横向溢出，键盘可操作导航及选择器 |

验证按改动影响选择：纯导航先做确定性上下文测试及 TypeScript／Vite；目录与授权补后端测试；界面迁移做真实浏览器路径；流程投影补目标绑定与状态组合测试。未改变算法、消费协议时不重复全套重建实验；写操作验证使用隔离数据。
