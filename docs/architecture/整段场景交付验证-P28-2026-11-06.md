# P28：整段场景资料到固定交付

目标是用一个可识别的办公室完整录制序列，验证现有流程能接住较完整的场景成果。继续使用 Workspace → 场景空间 → 资料／批次 → 模型版本 → 同源双视图 → 固定发布的结构。

## 本批范围

1. 从本机 NYU offices 选一个办公室目录；处理其中全部深度时间点，逐项记录配对、排除和原文件摘要，不再截取两秒或十帧。
2. 隔离 Python 3.12／Open3D 环境估计连续轨迹；复用已有参数和双向检查，不调整阈值。遇到断点停止，不桥接、不跳帧拼接、不用单位矩阵冒充位姿。
3. 只有所有有效配对连续通过，才输出首帧相机局部系的点云成果。固定 2cm 体素取真实观测点，不补洞、不推断空闲。该预处理发生在导入前。
4. 使用现有 PLY 已有成果路线：上传 → 预检 → 封存批次 → 固定模型／双视图 → 核对 → 发布 → 独立在线和离线消费。工作台的“1帧”表示一个输入点云文件，不能当成原始采集帧数；原录制帧数在预处理证据中记录。
5. 继续使用固定 8790 试用服务，在新场景空间验证；保留原场景、历史发布及外部原始文件。补重启和业务备份检查。

源数据与预处理报告的摘要关联用于本次可复现验证，不构成独立测量或签名认证。交接附件和应用固定发布分别校验绑定，避免将旁置报告误认为已嵌入发布包。

## 验收门槛

- 工具拒绝覆盖输出、校验源文件变化、拒绝不连续轨迹；失败不能生成可导入成功包。
- 配对清点能核对全部深度帧；有排除时明确数量和原因。
- 上传不自动构建或发布；批次、模型、两视图及发布固定同一资料和摘要。
- 两视图实际渲染、程序查询真实表面点，未观测点仍 unknown。
- 独立离线进程禁网安装和显式恢复；在线程序仍区分历史查看和无可信UTC的实时拒答。
- 同一8790服务重启后版本可读；旧成果未改写；业务备份可验证。

完整录制处理完成不等于房间完整覆盖。场景覆盖率保持未知；精度、回环／表面融合、机器人导航和真实平台联调不计入本批验收。
