# 园区本体实施批次与任务 v0.1

日期：2026-11-20。范围：公共资源—语义本体，保持独立产品边界。首批覆盖研发/办公型产业园、制造型工业园、仓储物流园；专业园区按同一基础扩展。

## 实施基线

已具备定义内核、精确依赖校验、8 个草案模块、目录查询、配置分组和归组、定义查看及导出。已接受的导航与页面规范继续沿用。当前尚无新本体编制、实例校验与正式发布能力，不把界面完成视为业务引擎完成。

三层职责固定：L1 为跨行业通用语义；L2 为多个行业/园区需求的可复用语义并集，按领域模块组合；L3 为消费方持有的场景实例。本体不依赖园区 ID、地图 SDK、场景数据库、宿主认证与商业权益。园区类型不是一棵互斥的本体分类树；同一综合园可以引用多个领域。

## B01 交付清单

- `packages/ontology/kernel/definitions.json`：保留 8 模块；新增建筑空间范围、管理范围、入驻指派、设施职责指派、资产记录 5 个概念及 9 个关系，共 42 概念、19 关系。`built_environment`、`operations` 升至 `0.2.0`，其他模块保持 `0.1.0`，均为草案。
- `examples/ontology/park-competency-questions.json`：12 个跨园区问题，标明语义引用、消费方必需输入、禁止推断及后续验收批次。用于需求追溯，不是查询执行器。
- `tests/test_ontology_park_semantics.py`：问题引用可解析、角色/对象类型分离、端点边界、版本升级、依赖闭包与归组保留回归。

当前 profile 能表达继承、必填标量属性、关系方向/端点，不能表达日期类型、基数、条件规则、时态和实例约束。B01 文本中的有效期与完整性要求属于语义规范，不能宣称已由内核执行。B02 明确编码，B03 实现执行。

## 后续扩展池

B02 工程交付：独立 Schema 与候选园区规则随内核打包，契约见 [实例契约](../../contracts/schemas/ontology-instances-v0.1.md)；三个合成实例及可复现生成器、23 项反例矩阵已落地，见 [B02 验证](../validation/园区本体-B02-2026-11-20.md)。Schema 检查不能替代 B03 引用、时态、基数与层级校验。

以能力问题驱动增加供配电网络、给排水、消防、环境、能耗、道路通行、设施运维的专业深度。生产工艺、危险介质、洁净环境、移动物流设备分别评估，不使用通用水泵/房间概念冒充专业模型。行业规范映射需记录标准版本、许可、映射强度与专业审核结论。

研发、生产、仓储、办公先作为空间用途指派，不把一次用途变化当成空间身份变化。园区范围、管理范围、行政区、法定宗地分别处理；未具备法定资料前不添加土地权属推断。资产记录管理员、设施责任组织、产权主体和平台权限不互相替代。

本阶段无需预先选择图数据库、RDF/OWL 推理引擎或地图供应商。后续通过适配器实现外部标准交换和存储集成，独立产品契约优先稳定。
