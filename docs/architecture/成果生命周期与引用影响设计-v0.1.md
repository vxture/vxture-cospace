日期：2026-11-02。归属：数据管理，联动构建中心、空间关联、态势服务及空间预览。三类六入口保持不变。

## 实施边界

H1已实现采集批次整理、封存、启停和固定来源追溯；H2实现只读引用影响检查。H3a已实现资料/候选状态写入、恢复、历史及新使用门禁，见[契约](../../contracts/schemas/preview-artifact-control-v0.1.md)。H3b已实现固定发布暂停/恢复、全路径分发门禁、管理历史和默认入口控制，见[分发契约](../../contracts/schemas/preview-publication-distribution-v0.1.md)。H3c已完成两类样本组合状态、缺口阻断、两次重启和断网消费恢复验收，见[记录](../validation/完整生命周期集成验收-H3c-2026-11-03.md)。

模型内容、来源事实与“是否允许新使用”分别管理。固定发布不可变，生命周期状态作为外部控制记录，不改写历史模型和离线包。归档表示停止新使用并保留历史，不表示压缩、移动文件、删除或回收存储。对资料停用不级联停用候选或发布。

P20补充（2026-11-05，已实施验收）：[新版本接替与旧版退役](资料坐标声明纠正-P20任务规划-2026-11-05.md)复用原分发门禁，保存退役原因、替代版本、服务端操作者及修订。正常替代先完成新版本；错误版可先退役，之后只补充替代。退役无一般恢复入口，临时暂停保留恢复。实际OS1重建发布后已退役旧版，新版可在线／禁网消费，见[P20验收](../validation/资料编辑与版本接替-P20-2026-11-05.md)。

## 影响检查

H2以同空间成果目录的已匹配引用遍历后续候选、发布和离线入口，补入保存构建尝试与批次成员。引用计数分别展示，不混算任务与成果。当前选择依赖、活动任务、活动批次及记录缺口具有明确阻断码，见[契约](../../contracts/schemas/preview-artifact-impact-v0.1.md)。

已存在的后续成果是需核对的影响，不自动成为全部操作的硬阻断。例如归档历史几何候选可保留其已生成语义候选和发布；停用资料不取消已准入构建。空间级来源不完整可能隐藏入向引用，先核查后操作，不将“未查到”当成“无引用”。

H2读取不形成跨文件事务；报告摘要只便于对照。保存的queued/running按活动任务处理，即便进程可能已退出；先经已有任务恢复流程核查，再重试影响检查。

## H3写入与门禁要求

1. 按空间及成果key持久保存控制记录、修订和追加历史。写请求显式带预期修订、检查摘要、操作及原因；工程服务默认预览身份，平台认证入口取服务端principal.subject。当前模拟身份验收不能代替生产身份源验收。
2. 写入前重新生成影响报告，摘要不符或阻断时拒绝，并返回需刷新信息。修订用CAS提交。跨存储锁顺序统一，状态提交与构建准入、候选选择和固定发布形成明确先后；只重算摘要而不锁定准入不足以防竞态。
3. 资料门禁覆盖直接构建和批次入口；批次成员保存不抹掉停用资料，封存/准入要识别不可用成员。候选门禁覆盖选择、语义/业务/关系派生和发布。历史查询与新使用分别处理。
4. 发布暂停必须覆盖完整服务面：`/publications/{id}/api/preview`、对象列表/详情、checklist、lineage、query、query-range、HTML入口、通配资产、offline.zip和offline.json。历史审计若需读取，另设受控路径；不能保留公共查询旁路。
5. 核查间接入口：空间目录/空间详情、发布列表、工作空间模型、缩略图和当前选择映射，不应把暂停发布继续作为默认可用入口；不能回退到任意历史发布。根静态挂载和资产缓存也纳入路径审查。
6. 恢复必须是独立显式动作、附原因和修订，不改变固定内容、不替用户切换候选、发布或消费版本。依赖缺口仍阻断；不能用恢复绕过已归档上游的新使用限制。

暂停控制之后发起的请求；在途响应和已持有字节无法追溯收回。消费端失效策略、租约和远程设备控制另行设计。H3仍不实施删除、存储回收或级联撤回。
