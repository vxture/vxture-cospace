# 智能体运行包完整性核对设计

日期：2026-10-27。状态：R1c首批只读核对实现；不授权删除、修复、恢复或实际机器人运行。

依据：[文件存储设计](智能体运行包文件存储与恢复设计-v0.1.md)。入口为CLI的files后端audit，独立PackageAudit避免调用会初始化数据库和目录的FilePackages构造器。

## 1 读取边界

必须已有runtime-files.sqlite3且user_version=1。SQLite以URI mode=ro打开并启用query_only，在读取事务内取得packages、active、installs的元数据快照，执行quick_check(1)。库缺失不创建，库损坏报错，不以空库或新schema替代。未完成热日志恢复导致只读打开失败时应停止核对，不能借audit执行修复。

扫描只涉及已登记清单声明内容、packages/staging/locks三个目录。文件读取复用路径与链接/重解析点检查，枚举不跟随链接，不执行额外文件；未登记目录只报告一级身份，不递归读取其内容。注册包目录内额外文件只列位置，不加载。根目录其他用户文件不纳入清理或完整性结论。

默认每表最多200行、每区域最多200个一级条目、每个注册包目录最多200个条目；可用limit调整到1..1000。元数据超限直接拒绝，不对部分注册表推断孤立内容；目录超限返回complete=false。单个成员继续遵守R0文件读取上限，quick_check本身不是严格CPU或耗时配额。

## 2 核对与分类

| 对象 | 检查/分类 |
|---|---|
| 注册包 | Schema、清单摘要、数据库/磁盘清单一致、来源回执关系、声明成员大小及摘要；通过标记verified，否则corrupt |
| 活动指针 | 包登记存在、包内容可读、场景一致、revision有效；不满足标记active_unusable |
| 安装记录 | ready、failed、interrupted与copying/verified/sealed分别列出；非终态不自动判断所有者死亡 |
| 未登记packages目录 | unregistered_content，只表示元数据快照未登记，可能仍在封存途中 |
| staging | 关联已知安装或未关联，均保留；即使ready安装遗留也不自动删除 |
| locks | lock_evidence；存在或修改时间均不是进程存活证明，不尝试锁定或创建锁文件 |
| 额外成员/异常目录类型 | 明确finding；权限不足、危险入口或扫描受限不伪报完整 |

核对不重新访问原来源，也不重做现场质量校核；它检查本地登记和字节一致性。没有签名或可信时间，不能抵御同时改写数据库及文件的管理员操作。

## 3 输出与并发解释

输出包含passed、complete、integrity_healthy、needs_attention、packages、active、installations、entries和findings。只有完整且无finding时passed=true；遗留目录可能导致passed=false但integrity_healthy=true。后者仅表示已登记包及活动引用本次检查通过，不表示可删除遗留内容或可用于机器人。

非终态安装的owner_status固定not_probed。恢复仍需用户显式调用现有recover-install并在其内部获取内核锁；audit不代替恢复检查。

元数据是同一事务快照，文件系统可同时变化，目录和摘要读取不是跨数据库/文件系统原子快照。报告必须携带这一限制；“未登记”“缺件”属于本次观察，后续写入完成可能改变结果。诊断不是垃圾回收凭据，不能拿旧报告直接删除文件。

CLI无finding退出0，诊断或核对失败退出2；数据库损坏返回既有local_error，未冻结统一SDK诊断格式。缺库、未知版本或元数据超限可能只有错误响应，不能把缺少列表理解为零问题。
