# P15：资料接入与构建交接

日期：2026-11-05。状态：已执行并完成本机验收。本文保留批准时的计划范围，实际结果以[P15验收](../validation/资料接入与构建交接-P15-2026-11-05.md)为准。

依据：[P14验收](../validation/已有点云接入-P14-2026-11-04.md)、[场景数据管理设计](场景数据管理设计-v0.2.md)及当前接入、准备摘要、批次准入与构建页面代码。规划依据为代码及既有证据审阅；后续执行已完成后端270项、最终专项74项（重叠）、浏览器131项、离线7项及前端编译。

## 1. 本批目标

**用户在一个场景空间中知道如何导入手头资料、当前缺什么，以及下一步应去哪。**

P14 已贯通第三种输入路线；P15 将已有能力整理成清晰、相互一致的产品操作。继续沿用 Workspace → 场景空间 → 资料／批次 → 模型版本 → 固定发布结构，以及“使用、构建、定义”三类六模块。

完成后，常用路径为：

```text
选择场景空间
  → 导入资料（上传资料包 / 已配置来源；同一个导入入口）
  → 资料详情（是什么、能做什么、需要什么、预检结果）
  → 进入构建中心（保留场景、资料及明确的批次引用）
  → 明确提交 → 固定模型 → 双视图
  → 沿用现有核对、发布和消费
```

## 2. 已确认的使用断点

|问题|代码依据|影响|本批处理|
|---|---|---|---|
|无配置来源的空场景，准备摘要引导先配置来源|`space_preparation.py` 的空目录分支；`data-intake.tsx` 按 enabled_source_count 推导阶段|上传本身不依赖配置来源，但页面给出额外前置步骤|分开判断上传入口与来源登记可用性；无配置来源仍可按权限上传|
|导入弹窗固定先打开已配置来源|`input-registration.tsx` 的 setMode('source')|无来源时先遇到空选择器，再寻找上传页签|有可用来源时保留来源方式；无可用来源且上传可用时进入上传方式；两种方式平级|
|上传页列出三种格式，但未按当前响应的 formats 显示支持范围|`input-upload.tsx` 仅核对 profile 后置 supported=true|新前端连接较旧后端时，文案可能宣称后端尚未支持的格式|从服务端能力响应生成当前可用路线；未知或读取失败明确显示|
|预检通过被当作资料已准备好，未解释批次条件|`space_preparation.py`、`scene_progress.py` 依据 check_status 与 lifecycle_state；`PreviewBatches.admit` 另核对批次|资料页提示可构建，到了构建页才发现批次未封存、停用或须明确选择|摘要和构建中心解释同一套批次条件；最后提交仍重新核验|
|更换构建资料时旧 batchId 可继续留在状态中|`build-jobs.tsx` 只对资料选择调用 setInputId；batchId 独立维护|旧批次可能残留，用户不知道为什么不能提交|换资料后核对批次归属，清除无效引用并给提示；明确传入的错误直链显示错误|
|用户能看到点数和坐标，却难判断这份资料会怎样处理|格式介绍散落于导入、详情及构建页面|容易将传感器单帧当成已配准场景，将已有点云导入当成重建算法|展示简短路线说明、必须信息和结果含义，统一语义|

以上是静态代码与 P14 证据可确认的行为。具体交互在实施时以独立环境复现，不将推测的失败算作已发生故障。

## 3. 业务类别、导入方式和技术路线

三者采用独立含义，避免增加重复选择：

- **资料类别**：原始采集资料、已有空间成果；参考资料保留设计位置，当前没有通用接入能力。
- **导入方式**：上传资料包、已配置来源。用户选一种方式；不强迫先选择类别再选择格式。
- **技术路线**：由实际适配器与校验结果确定；浏览器选择不能改变包内格式、坐标解释或场景归属。

|当前技术路线|资料类别|必需信息|实际处理与产物|
|---|---|---|---|
|NYU RGB-D＋已有轨迹|原始采集资料|图像封存清单、匹配已有轨迹|按既有位姿累积模型，再派生双视图；不生成新轨迹|
|ROS1 激光短样本|原始采集资料|受支持样本清单、日志及首帧声明|首帧局部模型，再派生双视图；未配准、未执行 SLAM|
|PLY＋显式坐标清单|已有空间成果|支持布局的点云、米制局部坐标、源摘要|保留坐标规范化为固定模型，再派生双视图；不自动对齐|

准备条件只表示现有路线具备提交依据，不表示精度、完整度、机器人或导航放行。

## 4. 页面调整

### 数据管理

- 保留已确认的全屏布局、品牌淡色背景、浮动场景侧栏及 header 下方的右侧资料详情。
- 顶部仍以“导入资料”为主要动作，“样本库”为辅助动作；不新增顶级模块或额外常驻操作面板。
- 导入弹窗明确显示当前场景，平级提供两种导入方式；格式说明随可用能力展示，长技术限制按需展开。
- 资料列表补充按类别筛选，保留格式和名称搜索；不为“参考资料”提供无法执行的入口。
- 右侧详情增加短说明：“此资料用于什么处理”“当前需处理的问题”“下一步”。已有坐标、时间、说明历史和技术信息按原层次展示，避免重复堆叠。
- 准备摘要收敛为“导入资料 → 检查整理 → 用于构建”；来源配置为一种接入方式的辅助管理，不是上传的共同前置步骤。

### 构建中心

- 当前场景、已选资料及路线在同一输入区域呈现，准确显示点数、图像帧数或单帧范围。
- 未纳入任何批次的资料可按现有规则直接提交；不为走流程自动新建或封存批次。
- 已纳入批次时，保留必须显式选择封存批次的规则；单个可用批次也给明确入口，多批次不静默挑选。
- “发起构建”旁解释当前阻断原因；资料不可用、批次未封存／停用、需选择批次、正在提交等分开表达。
- 重新预检、整理批次等返回入口携带同场景和资料引用。仅因切换资料残留的无效批次可清除；明确直链指定的跨场景或错误引用不得静默替换。

## 5. 数据与实现边界

### P15.1：接入能力与路线说明

1. 在后端现有适配器附近集中维护小型路线描述（稳定格式 ID、类别、短说明、必需资料、产物含义）。不是可执行算法注册平台。
2. 优先扩展现有上传能力／来源列表响应，按权限和实际装配返回能力。保留旧字段，新增字段可选，不新增持久业务实体或服务。
3. 前端按服务端 formats 与入口可用性生成展示；旧响应缺少描述时，仅对已声明支持的格式使用兼容文案。未知格式不启用猜测处理。
4. 来源目录为空、来源接口失败、上传接口不可用是不同情况；一种入口失败不能凭空宣称另一种也不可用。

验收：无配置来源仍可合法上传；不支持的格式不误展示为可用；切换场景不沿用旧能力或旧来源。

### P15.2：统一准备条件与批次交接

1. 将现有批次选择／状态判据提取为可复用的只读判断，构建准入继续在原锁和实时复核流程内执行；不依赖浏览器传回的“准备完成”标志。
2. 准备摘要只读登记、历史预检、使用状态和批次记录，不重新读取大数据文件、不启动或轮询 worker。
3. 区分“尚未预检”“上次预检失败”“已保存通过记录（提交重检）”“需选择封存批次”“批次待整理／已停用”“资料停用／归档”。
4. 资料准备与场景总体进度共享上述解释；已有候选、固定发布和消费端状态仍分别呈现。
5. 构建中心换资料时更新批次上下文；无权限、显式错误引用及陈旧修订保留错误反馈，不自动回退到其他资料或最新版本。

验收：资料页和构建页给出一致的下一步；摘要读取不改变记录；提交时资料或批次变化仍能拒绝，历史发布继续可读。

### P15.3：页面收敛与连续验收

1. 接入弹窗、分类筛选、详情说明及构建输入区使用现有 DS，不另建一套视觉语言。
2. 验证无配置来源空场景、直接构建、需选择批次、批次阻断、多批次及场景切换。
3. 在既有办公室及 OS1 场景内覆盖三条路线；新增版本保留源资料、模型、所选版本及发布的明确引用。
4. 走通一次实际资料导入 → 模型／双视图 → 核对发布 → 新标签页预览和下载；离线包由独立禁网进程验证来源与查询一致。

验收环境采用独立副本，端口执行时检查空闲后确定；不将规划中的新端口写成已启动服务。保留 P14 服务和历史成果。

## 6. 判据示例

|场景|页面应表达|操作结果|
|---|---|---|
|空场景，无配置来源，但上传获准|可以上传资料包|直接到上传方式，不要求先配置来源|
|只具预览权限|无资料管理操作权限|页面与直接 API 均执行现有权限检查|
|活动资料，上次预检通过，未纳入批次|可进入构建中心，提交时重检|支持原有直接构建路径|
|活动资料，属于一个封存批次|请选择／确认本次封存批次|明确传递批次 ID 与当前修订|
|活动资料，属于多个封存批次|需选择本次批次|不默认最近批次、不合并批次|
|仅属于整理中或停用批次|先整理封存或核查使用状态|禁止跳过批次要求|
|换资料，旧批次不包含新资料|旧批次选择已清除，重新确认|提交不能带错批次|
|明确直链指定不相符批次|目标资料与批次不匹配|不静默替换引用|
|显示准备完成后源文件被改动|原结论仅为历史预检|提交实时拒绝；原发布不变|
|能力或来源读取失败|入口信息暂不可用，可重试|不伪造空目录或已支持格式|

运行中任务是构建中心的实时执行状态，摘要最多显示已保存记录；不将只读准备摘要包装成资源调度保证。

## 7. 测试与交付

按 P15.1 → P15.2 → P15.3 顺序执行；各小批完成后验证，最终按业务动作验收。

- 后端：格式描述与适配器支持范围一致、授权、空来源上传、批次只读判据、多批次、修订变化、停用、文件变更、原三条路线及固定发布回归。
- 前端：能力响应兼容、入口独立故障、慢响应及场景切换、筛选和详情、资料与批次切换、重复提交及失败反馈。
- 浏览器：主线连续操作及上表异常；1440px／390px 布局、右侧详情不覆盖 header、新标签页固定发布预览。
- 原成果：执行前后索引摘要、原固定发布完整性；新的合法业务变化单列，不能将所有文件变化一概视作故障。
- 离线：实际下载包，独立禁网进程核对安装、激活、恢复、来源及点／未知／范围查询。
- 文档：能力／准备摘要字段变化、操作指引、验收日志及汇总；只报告实际完成项，不预设通过数量。
