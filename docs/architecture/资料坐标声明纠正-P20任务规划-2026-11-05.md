# P20：资料编辑、修改历史与成果版本接替

日期：2026-11-05。状态：用户批准后已实施，P20.1—P20.3验收通过。下文保留设计，执行证据见第8节。

本版替代此前“纠正坐标声明必须新增一份可见资料”的方案。保留原文件与必要历史，用户在原资料上编辑；已发布使用的成果通过新版本接替并退役旧版本。

## 1. 两条业务原则

1. **资料可编辑，修改有历史。** 同一份资料保持同一资料ID和列表项，保存谁、何时、为什么、改了什么；展开详情才查看历史，不因纠错增加资料卡片。
2. **发布成果固定，更新通过新版本。** 修改影响已发布且有使用的成果时，构建并核对新版本，发布接替后退役旧版本。旧版保留审计及来源，新请求停止使用旧版。

使用状态未知的已发布成果按需要保留固定版本处理，不以“没有使用记录”推断从未使用。不为此增加实时使用统计系统。

## 2. 当前进展与本批目标

场景空间 → 资料登记 → 固定模型 → 独立双视图 → 核对发布 → 在线／离线消费已有样本闭环。P17补齐预览，P18补齐当前RGB-D逐帧过程，P19补齐源图／深度与构建来源联动。

[P19验收](../validation/RGB-D资料预览与构建来源联动-P19-2026-11-05.md)与[机器汇总](../../output/playwright/flow-batch-p19-acceptance.json)已保存passed：255项后端、48项RGB-D客户端、271项分组浏览器／HTTP、7项离线汇总及编译通过；其他原客户端回归单列。这些是P19历史证据，P20独立验收见第8节。现场精度、设备接入与生产认证仍未完成。

P20只补齐一条实际操作：**编辑原资料 → 留下修改历史 → 判断影响 → 必要时重新构建 → 新发布接替 → 旧发布退役。**

## 3. 编辑与重建的判定

| 修改及已有成果情况 | 处理 |
| --- | --- |
| 名称、备注、用途等显示信息 | 原资料保存、记录修改，不触发重建或发布版本 |
| 影响处理或成果解释的坐标信息，尚无构建 | 原资料保存，新构建使用已保存修订 |
| 已有未发布构建 | 旧任务保留当时输入，标出待重建／不再适用；新任务生成更新结果，默认工作面转向明确选择的新结果 |
| 影响已发布成果，包括已使用或使用未知 | 不改写旧发布；构建、核对并发布新版本，再执行明确的接替与退役 |

坐标系标识或轴语义的调整可能影响下游解释，即使几何数字不变也要检查已发布引用。普通显示信息沿P13处理；固定成果中保存的坐标解释变化需要生成固定新版本。

首批仍限定有用户来源收据的严格PLY，允许修改局部坐标系标识、三轴语义和传感器／场景局部范围；原点云字节不变，单位固定米，场景对齐继续未核验。单位换算、旋转平移、配准、时钟和传感器标定另行设计。

## 4. 页面与操作

### 数据管理

沿用header下方的页面右侧资料详情；界面称“坐标说明”“编辑”和“修改历史”，不要求用户掌握“声明”概念。

- 在原资料上编辑，展示变化和受影响成果；原因必填，保存后留在同一详情。
- 修改历史按时间展示操作者、原因和前后值；与现有说明历史整合呈现，不增加独立模块。
- 需要重建时提供“前往构建”，携带资料ID及明确保存修订。保存本身不启动任务或发布。
- 已封存批次与已提交任务保留当时输入说明；修改后的资料按既有批次流程形成明确的封存引用，不将新说明静默写入旧封存记录。

### 构建与态势服务

新构建、双视图和人工核对复用已有流程。新发布具备可消费结果后，提供明确的“接替并退役旧版”操作，关联新旧发布ID及原因；按当前授权处理，不把编辑权限当作发布权限。

退役包括两种原因：“新版本替代”和“错误版本”。这是同一退役操作的原因，不增加两套流程。

- 正常替代：先完成新版本并核对，再接替、退役旧版；新构建失败时不自动退役原正常版本。
- 已确认错误：允许先停止旧版分发，再修正和重建，避免等待新版本期间继续使用错误成果。
- 旧版从日常可用列表及新使用入口移除，管理历史可查看退役原因、替代版本、当时输入与结果；历史访问不提供公共资产或下载旁路。
- 旧版直链说明退役情况及替代入口，不把对旧版的请求自动转为新版。消费者按明确版本切换，避免默默改变其数据。
- 接替／退役遇到部分失败时显示真实状态，可按同一次操作重试；新发布成功不冒充旧版已退役，旧版退役也不冒充所有消费者已切换。

## 5. 最少必要的底层记录

复用现有资料说明修订、固定输入、引用检查、构建和分发门禁；不另建资料分支系统或审批引擎。

| 记录 | 必要内容 |
| --- | --- |
| 资料及修改历史 | 稳定资料ID、修订号、修改前后值、服务端操作者、时间、原因 |
| 构建固定输入 | 资料ID、当时修订、原文件摘要、实际使用的坐标说明与摘要 |
| 发布与退役历史 | 原固定发布、新替代发布、退役原因、操作者、时间和处理结果 |

现有原始清单与收据保持固定；当前可编辑说明通过修订保存。构建时验证原字节，并在任务内固定本次有效说明与相匹配的清单／收据绑定。实际存储形式在P20.1落定，不能直接覆写旧源清单，也不能让旧任务在刷新时改用当前修订。离线包携带当时的固定说明和必要审计引用，不能要求联网读取当前资料才能消费。

不因说明修改重复存储点云；列表不新增资料记录。旧预检不能直接证明新修订可构建，预检及批次准入需与实际修订对应。旧批次、旧任务及旧发布的输入说明不变。

资料修改采用预期修订校验防止互相覆盖；重复提交不产生重复修订或重复退役。服务端验证Workspace／场景、权限及来源完整性。原文件损坏仍明确失败，不能通过编辑说明掩盖。

退役复用现有暂停分发所覆盖的查询、双视图资产和离线导出门禁，补齐退役原因和替代版本关系。现有暂停是可恢复的临时控制，不能只改文字就宣称退役完成；退役后的恢复须显式检查、授权和记录，不能由一般暂停恢复入口绕过。

已下载或安装的离线副本无法由服务端追溯删除。系统记录旧版已退役并提供替代版本，消费方需显式更新；本批不增加设备远程撤回或租约服务。

没有引用的错误中间产物可以作为后续清理对象；本批保留修改与任务历史，不实施自动删除和存储回收。错误记录不占正常工作入口。

| 小批 | 交付 | 验收重点 |

实施在独立验证运行副本进行，旧运行区不变；记录正常退役带来的控制状态变化与固定成果文件不变，不能把两者混为一谈。浏览器故障注入与真实后端构建／消费证据分开保存。

## 7. 完成定义

**用户能编辑同一份资料并查到修改历史；影响已发布使用的成果时，完成新版本构建与发布接替，旧版本退役且审计可追溯。**

本批只完成DM09的当前PLY说明编辑子项及关联版本接替，不扩展到通用坐标变换、实时设备控制、使用统计、自动清理或复杂审批。
