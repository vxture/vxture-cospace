# 机器人消费数据需求与行业对照 v0.1

日期：2026-11-20。状态：产品设计依据草案；本次查阅公开项目的官方文档源，不构成标准认证、机器人适配或现场验收。与《园区交付数据架构与B06范围》配套，先定义消费能力，再建设交付配置。

## 核心定位

本文完整保留机器人工作需求，用于行业参考，不能直接转为本平台交付承诺。CoSpace应提供、可接入及不负责的数据，统一以 [空间态势服务数据责任与交付边界](空间态势服务数据责任与交付边界-v0.1.md) 为准。机器人仅是消费方之一，产品服务对象不缩窄为机器人平台。

机器人工作所需数据由环境、机器人自身能力、任务和运行时观测共同构成，不能由一个静态园区数据包完全提供。本体解决术语、类型、关系和约束的一致表达；它不代替定位地图、通行证据、传感器、控制器或设施接口。

首批目标按轮式地面移动机器人设计，覆盖巡检、运输及跨楼宇协同。机械臂操作、足式移动、无人机各有额外能力和数据要求，不能用轮式导航配置宣称通用支持。产品底层保留通用数据合同，适配器绑定具体协议、版本、机器人族与实际验证范围。

## 行业公开体系的职责

| 参考 | 已核对的职责 | 对产品的启示 |
| --- | --- | --- |
| ROS REP-103 / REP-105 | 单位、轴向与机器人坐标框架约定；map 与 odom 分别承担长期参考及连续局部运动参考 | 静态模型坐标、机器人地图坐标、机器人机体/传感器坐标分别定义；变换方向、时刻和责任明确；地理 earth 并非所有本地任务的前提 |
| Nav2 Static / Obstacle / Inflation / Keepout | 静态地图输入、传感器障碍观测、与机器人尺寸相关的障碍代价及禁行区域处理 | 观测点云、定位地图、自由/占据/未知空间、代价地图和区域政策分开；运行时按具体机器人组合，未知不能默认为自由 |
| Open-RMF traffic editor / building map tools | 楼宇地图编制，交通模式与导航图输出；代码中分别表达门、电梯等设施 | 层级、楼层切换、交通图、门/梯及机器人适配分别建模；设施几何或标签不等于已接通控制 |
| VDA 5050 官方仓库 | 车队控制与移动机器人通信；任务节点/边/动作、地图标识/分发及状态；机器人继续承担定位、路线及动作执行 | 调度任务图不等于底层避障地图；任务与状态属于有时序的协议交互，不能只用静态文件替代；按目标厂商版本适配 |

这些体系解决不同问题，不存在由它们共同规定的一份“全机器人通用园区包”。ROS/Nav2/Open-RMF 的项目规范和 VDA 5050 协议地位也不混同。本次 VDA 官方 main 标注3.0.0，并明确正式 VDA PDF 优先；本设计只依据已读公开文档判断数据职责，实施时另选固定版本及厂商能力，不以 main 最新值作为兼容性合同。

## 按工作能力定义输入

| 机器人工作能力 | 环境/任务数据 | 机器人及运行时输入 | 验收关注 |
| --- | --- | --- | --- |
| 定位：我在哪里 | 定位用地图或参考特征、地图身份与版本、frame、原点/分辨率、标志物与校准依据 | 激光/视觉/GNSS/IMU/里程计等实际配置、传感器标定、实时变换、位姿及置信/不确定性 | 在目标环境可重复定位；地图匹配与时间同步；失效可识别。不同定位技术所需地图不同 |
| 通行：哪些地方可能经过 | 自由/占据/未知空间、覆盖证据、通道宽高、坡度/台阶/地面条件、禁行限速及方向规则 | 轮廓及载荷变化、转弯/制动能力、爬坡/越障与净空限制 | 给定机器人与条件下可用；设计几何不能冒充现场通行确认 |
| 规划与局部避障 | 全局通行地图、目标位置、区域政策；运行代价层的来源与规则 | 实时障碍传感、动态局部代价、规划/控制配置、速度与时效 | 动态障碍和未知处理；静态发布不保证未来通道无障碍 |
| 拓扑与车队交通 | 节点/边、方向、路线/走廊、等待/会车点、共享资源、楼层连接及交通规则 | 调度分配、占用/预约状态、机器人进度及车队适配 | 图中连通不等于几何可通；资源状态有时效；路径适配指定机器人 |
| 任务与巡检 | 目标对象、任务点/朝向、观察位姿或范围、检查项目、顺序、完成判据 | 可用传感器/载荷、动作接口、执行反馈与采集结果 | “设备点锚”不自动成为“机器人站位”；需验证视线、距离、到达与执行条件 |
| 门、电梯、充电与对接 | 设施身份、接口能力、停靠/等待点、入口与朝向、允许的交互流程 | 门/梯实际状态、控制确认、充电/对接反馈及厂商接口 | 设施可见、可调用、执行成功分别声明；通信地址不随公开地图泄露凭据 |
| 异常处理与持续运维 | 作业边界、恢复点、任务优先级、地图变更与失效政策 | 电量/故障/定位质量、心跳、新鲜度、停止/恢复反馈 | 缺数据/超时的处理责任明确；静态园区平台不代替机器人安全控制 |

上述为需求分析，不表示全部由 CoSpace 提供。底层控制、安全功能、传感器输入由机器人/集成系统负责；园区平台提供环境成果、对象语义、任务目标与设施资源描述，并通过授权适配器交换必要状态。

移动操作另需目标物体位姿及不确定性、抓取/操作位姿、机器人运动学与碰撞模型、工具/载荷、可达性与任务动作；无人机另需三维飞行空间、起降点、飞行约束、气象及飞控能力。均另立成果配置及验收，首批不预置为可用能力。

## 建议的数据图层与非图层资源

| 类型 | 建议成果 | 数据形态与边界 |
| --- | --- | --- |
| 定位参考 | 按算法选择的定位地图/特征集、标志物及frame绑定 | 不强求可视化；几何点云能否用于定位须由目标定位链路验证 |
| 通行几何 | 二维/三维自由、占据、未知及覆盖，通道和地面条件 | 不把现有 agent 表面单元直接转换为可通行自由空间 |
| 交通拓扑 | 路网节点/边、方向、楼层/入口连接、共享资源 | 关系图需附通行与机器人适用证据；本体供给/组成关系不能直接变为路线 |
| 区域政策 | 禁行、限速、单向、作业区、临时限制 | 携带范围、适用对象/机器人、有效期、来源与优先级 |
| 对象语义 | 设备、设施、区域及其固定定义、属性、关系、依据 | 本体消费重点；声明与现场核实分别表达 |
| 任务交互 | 目标点/位姿、观察位、等待/停靠点、动作参数、完成条件 | 区分对象几何、机器人目标和操作约束；目标引用固定对象版本 |
| 动态状态 | 障碍、封路、设施状态、资源预约、作业反馈 | 有时间戳和失效条件的流/API或窗口快照；不能随静态包永久有效 |
| 兼容与质量资源 | 机器人能力配置引用、协议适配、校准及测试记录 | 不强迫作为地图图层；机器人尺寸/运动能力改变后需重新评估适用性 |

## 交付配置必须声明能力

用成果清单和适用性声明替代笼统 robot_ready=true。以下名称为设计草案，尚非注册 schema/profile：

1. 对象语义查询配置：固定模型/对象索引 + 定义闭包 + 实例/关系/证据 + 校验边界。支持“是什么、有关联什么”，不提供导航或任务执行资格。B06 实现此配置。
2. 定位适配配置：在所选算法和机器人适配范围内提供定位地图、坐标绑定与验证记录，运行时定位仍由机器人完成。
3. 移动通行配置：补齐自由空间、覆盖、拓扑/区域政策、机器人能力匹配和目标环境验证；需声明依赖的运行时输入及失效处理。
4. 巡检/物流任务配置：在移动能力之上增加任务目标/站位、动作与设施适配、反馈/完成判据及验证。

四类配置不是所有机器人必须逐级购买或安装的层级；任务差异会导致不同依赖组合。车载地图已具备的机器人也可只消费语义或任务目标，但仍需验证它的地图/对象绑定，不能免除坐标对齐和兼容检查。

每项能力记录：用途、必需成果及固定版本、机器人/载荷适用条件、坐标与时间范围、运行时依赖、验证方法/结果/日期、已知缺失及超时/失效行为。状态区分未声明、不支持、数据已检查、目标机器人已验证、现场已验证，不能由文档存在自动晋级。未知或未验证是显式结果，不伪造成功。

室内局部 map 下可开展机器人工作，不要求先有经纬度；但园区模型到机器人 map 的变换必须核实。B07 的地理配准解决地理地图交接，不自动解决所有机器人定位、通行或控制问题。

## 对 B06 的直接调整

数据合同先明确“对象语义查询配置”，包括对象索引/命名空间、固定本体闭包、实例属性与显式关系、有效时间、人工依据、模型证据绑定、校验范围及缺失项；不把旧轻量类型定义替换成新本体，也不默认补齐通行图层。

现有离线基础包仅携带 agent 计算表达等限定成员。新语义成果即使携带模型点锚及摘要，没有实际点云字节时也必须标为模型证据引用；离线不能声称已重新核验完整几何。在线/离线一致是声明与依赖绑定一致，不等于所有运行时数据随包固化。

B06 不新增定位算法、自由空间重建、Nav2全栈部署、车队控制、门梯联动或机器人安全控制。架构和合同应允许后续适配以上配置，当前版本仍明确导航及任务执行未验证。实际机器人适配前记录厂商、机型、导航/调度协议版本、地图输入方式与任务要求，再选择对应配置。
