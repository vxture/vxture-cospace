# 故障恢复与受控重试验收清单

日期：2026-10-26。状态：待实现、待执行；本文件不是验证记录。依据：[恢复设计](故障恢复与受控重试设计-v0.1.md)。

## 1 故障矩阵

| 编号 | 注入或竞争 | 必须观察到的结果 |
|---|---|---|
| FR-01 | claim后、创建worker前强杀监督进程 | 锁释放后可核对无worker；恢复为interrupted，无成功报告 |
| FR-02 | 原子Job关联创建调用前、返回后且登记前强杀 | 调用前未创建worker；返回后已受Job约束，旧worker随所有者结束；不回退到先创建再加入 |
| FR-03 | 登记前后、执行许可前分别强杀 | 子进程按Job Object结束或受许可门禁阻止；未知身份不会自动放行 |
| FR-04 | worker执行期间强杀监督进程 | 操作系统终止所属worker；恢复重新确认退出；原输入和发布不变 |
| FR-05 | 只杀worker，监督进程仍存活；监督线程暂停 | 恢复因owner_alive阻塞；监督进程自行记录失败，无双重终态 |
| FR-06 | 封存前、rename后、DB提交前分别崩溃 | 半成品及孤立产物均不可消费；恢复保留证据；新attempt使用新目录 |
| FR-07 | DB成功提交后、CLI响应前断开 | 查询得到唯一成功attempt；旧revision重试冲突，不重复执行 |
| FR-08 | 延迟旧finish与recover、新run竞争 | 当前代次仅一个合法提交；旧fence返回stale_execution，不污染新状态 |
| FR-09 | 两个recover、两个retry、retry与cancel竞争 | 每种竞争按revision只有一个胜者；事件和attempt序号无重复 |
| FR-10 | PID复用、创建时间不符、其他Python进程 | 不把其他进程视作旧worker，不发送终止信号 |
| FR-11 | 无权限枚举、身份记录丢失、主机不符 | 返回明确unknown或host_mismatch，状态与revision不变 |
| FR-12 | 操作系统重启、残留登记和文件 | 核对host/boot和本机进程；仅可信重启证明才认定旧进程消失，未知则阻塞 |
| FR-13 | 重试前后删除/篡改dataset或改变环境 | 不修改原spec；不运行可变输入；提示新建任务或修复原快照 |
| FR-14 | 失败→重试→成功，多次中断 | attempt_no有序，旧诊断保留；报告只取successful_attempt_id |
| FR-15 | 0003旧库升级，含running与已有成功报告 | 成功报告继续可核验；旧running拒绝在线恢复，不补造进程证据 |
| FR-16 | 所有失败、恢复、重试路径 | 无新candidate/truth，当前空间服务指针不变，历史服务仍可读取 |
| FR-17 | 导入封存后DB失败及同键重入 | 暂不放行恢复；不可见dataset和孤立内容保留，待I4d专门验收 |

## 2 执行与证据

Windows进程试验必须启动真实父/子进程，并在可控故障门处执行强杀；mock仅用于补充CAS错误分支。使用临时数据根和独立受限PostgreSQL，不向既有项目库注入故障。升级试验先建0003数据库数据再升级，不能用直接create_all代替迁移。

每次记录代码/依赖指纹、Windows与Python版本、迁移版本、固定输入摘要、故障位置、进程身份及退出观察、状态与revision变化、attempt/fence、事件、目录摘要、CLI退出码及错误码。不得在证据中输出数据库凭据。

并发验证使用真实独立进程及PostgreSQL事务；通过屏障控制竞争点，断言持久状态和事件，不以某一线程先返回作为唯一依据。进程退出检查覆盖创建身份、等待完成及句柄关闭；清理前再次核对归属，仅清理本轮临时资源。

## 3 通过标准

I4a必须先通过FR-01至FR-05、FR-10至FR-12的进程证明；否则停止开放恢复入口，允许继续完善只读诊断。I4b/c完成余下任务用例、契约兼容与迁移检查，复跑既有测试、前端构建，并在浏览器核对多attempt诊断及成功报告。

验证记录应逐项标明通过、失败、未执行及平台限制，并给出原始日志路径。未运行的故障不能因正常流程测试通过而标记通过。FR-17在导入恢复实现前保持未完成，不能宣称I4整体完成。
