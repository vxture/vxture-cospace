# 地图场景入口与引擎选型

日期：2026-11-08。状态：设计及M1本机验证已推进；MapLibre 6.17.0与独立验证页已接入，生产入口尚未变更。新「空间服务—浏览器端」key已完成真实街道底图与中文注记加载；控制点对齐及生产接入未验收。

## 1. 产品定位

新增登录后的统一「场景入口」，首次进入工作区和工作中重选场景复用同一页面。登录前产品介绍页保持独立。入口负责查找、选中和进入场景；业务模块左侧继续承担能力导航；数据管理和语义本体继续为工作区共用支撑。

核心流程：登录并确认工作区 → 场景入口 → 选中场景 → 明确点击进入 → 场景业务工作面。有效业务深链直接打开原记录，不强制绕行入口；无有效目标的普通进入默认打开入口。

## 2. 引擎决策

2026-11-09 用户决策：地图供应商确定采用高德。后续正式地图接入使用高德官方 JS API，支持明暗底图；下文 MapLibre + 天地图为已完成的早期验证记录，不再作为生产推荐。当前先推进场景入口功能，供应商替换独立实施。高德 Web JS API 凭据、安全配置、坐标适配、商业授权及海外权限仍需完成接入核验。详见《地图暗色能力核对-2026-11-09》。

建议采用 MapLibre GL JS，React 组件直接封装原生引擎，首期二维、bearing=0、pitch=0，不显示三维开关。地图按路由懒加载；离开时销毁实例、事件和请求。现有 Three.js 场景三维工作面继续独立使用。

2026-11-08 查询 npm 官方注册信息：maplibre-gl 最新记录为 6.17.0、BSD-3-Clause，主页 https://maplibre.org/ 。这只是候选版本；实施时检查 Node/TypeScript/Vite 构建、浏览器兼容、worker打包及依赖审计后锁定确切版本，不直接按latest安装。

| 候选 | 判断 |
| --- | --- |
| MapLibre GL JS | 推荐。适合矢量/栅格底图、点位聚合和范围图层，后续可增加倾斜及建筑挤出，底图可按部署配置替换 |
| 高德 JS API | 中国大陆在线地址检索、POI及其服务生态为主要需求时可选；地图服务、坐标和凭据使用方式与供应商绑定 |
| Leaflet | 二维栅格点位入口可行，但本项目预期有矢量样式、范围及建筑表达，优先统一MapLibre路线 |
| CesiumJS | 全球地形、地球和大规模3D Tiles成为入口核心需求时另立专题；首期场景查找没有引入必要 |
| Mapbox GL JS | 需另核对当前商业许可与服务条件；本阶段没有使用其专有能力的明确需求 |

引擎开源许可与底图数据、样式、字体、卫星影像、地理编码服务许可分别核对。MapLibre可展示倾斜建筑，不意味着已有楼层选择、室内定位或全球三维能力；这些需要数据和单独设计。

## 3. 底图技术路线与上线门槛

用户已确认首批地理分布为「中国大陆为主，兼顾海外」。引擎采用MapLibre；国内优先验证天地图兼容服务，海外保留独立提供者配置。底图提供者通过部署配置指定，业务组件不写供应商URL或token；供应商尚需实测和授权核验，不提前宣布生产可用。

首期一个地图实例只使用一个明确的底图配置，国内/海外通过可见底图选项切换，不在不同坐标体系间拼接或按IP静默换源。地区配置与地图视野不限制用户授权场景列表，海外场景不会因当前使用国内底图而从列表消失。选中超出底图有效覆盖的场景时提示切换适用底图；未配置时继续支持列表进入。

两套配置共用场景位置schema与交互组件。各地图服务分别声明其覆盖、缩放、坐标和来源署名；国内服务是否具有足够海外覆盖由实测确定，不假定国内服务只覆盖大陆，也不假定它能满足全部海外需求。

- 中国大陆：优先评估有合法使用授权的国内地图服务（例如天地图兼容服务或企业已有地图服务），实测其可用产品、EPSG:3857瓦片、CORS、域名限制、配额、署名及服务条款。此处为候选，不表示已完成服务接入或授权核验。
- 海外：评估受支持的商业托管瓦片或企业自托管数据，保留来源署名；不默认使用OSM公共瓦片端点作为生产服务，不使用演示style作为生产保障。
- 私有园区/离线：可配置授权自托管瓦片；只有正式的更新、容量及运维需求确认后才增加瓦片服务，不为第一版立即部署全球地图数据库。

首期采用街道底图，不接卫星影像、外部地址搜索、浏览器定位和自动行政区归类。搜索只查本产品授权场景名称/编号/项目及已登记地址，避免把场景名称和业务详情发送到第三方地理编码服务。

每个提供者配置明确：provider_id、数据坐标系、瓦片投影、允许范围和缩放、style/瓦片来源、字体与sprite来源、署名、允许域名以及浏览器可见凭据方式。对栅格源明确XYZ/TMS/WMTS矩阵及行列规则，不把任意WMTS当XYZ模板使用。

不得直接把GCJ-02/BD-09瓦片叠到WGS84场景点位；EPSG:3857只是投影声明，不足以排除坐标偏移。若供应商要求特殊坐标，先明确数据来源与获准的适配方法，再单独验证；首期不编写猜测式坐标纠偏。

上线前完成目标网络实际访问、控制点对齐、授权与署名、配额、域名凭据、CORS、CSP及worker策略核验。服务端秘密不能传前端；浏览器key按供应商设计限制域名/权限，不能假装它是秘密。只放行实际需要的域名与worker资源，不关闭现有安全保护。

## 4. 页面布局与交互

桌面布局：产品顶栏；其下工作区与页面标题；左侧约320px结果列表；右侧地图占剩余区域；选中卡片位于地图内侧。尺寸服从现有DS间距、字体和组件，地图工具保持精简。

```text
┌ Vxture · CoSpace                  当前工作区       账户 ┐
│ 场景入口                    搜索名称/编号/项目/登记地址 │
│ 项目筛选   全部 / 已定位 / 位置待补充    当前结果数       │
├──────────────────┬────────────────────────────────────┤
│ 授权场景列表     │                                    │
│ 当前场景         │            二维地图                │
│ 场景名称/项目    │        点位 / 聚合 / 选中标记       │
│ 已定位或待补充   │                                    │
│ 发布记录概况     │     ┌ 选中场景 ──────────────────┐ │
│                  │     │ 项目、登记位置、发布概况   │ │
│ 无位置场景可进入 │     │ 当前场景提示   [进入场景]  │ │
│                  │     └────────────────────────────┘ │
└──────────────────┴────────────────────────────────────┘
```

地图与列表共享一个查询结果集和selected_space_id。点击标记/条目只选中，不切换业务上下文；点击聚合放大，完全同址在最大缩放时展示可选列表，不用伪造偏移表示不同位置。选中条目使点位可见，地图选中使列表定位对应条目，但拖动地图不自动筛掉列表。

首期不采用“地图移动即搜索”。筛选后才适配结果范围；用户手动探索后不因后台刷新反复飞回。零个定位点时提示“场景位置待补充”，地图可以显示配置的默认区域，但该中心不代表任何场景位置；无配置时保持空底图提示。

窄屏使用「列表 / 地图」切换，共享筛选和选中状态；地图选中后底部显示卡片。列表可完整完成选择，键盘和读屏无需操作canvas。聚合数和地图统计均来自当前授权结果。

首期卡片只展示已有可信元数据：名称、项目、登记位置状态、固定发布数量。选中后按权限按需读取已有流程摘要并显示观察时间；不得为所有场景逐个轮询完整流程。无权限或不可读的流程显示未知，不推断未完成。待可靠目录摘要接入后再开放按流程状态筛选。

新建场景复用已有入口和授权，可选补充位置，不把位置设为创建或进入的硬前置。位置编辑在场景配置中完成，入口卡片按权限提供“补充/编辑位置”。

## 5. 地理位置契约草案

新增可选geographic_location元数据，与模型坐标、输入坐标修订和成果质量分开存储。现有场景默认null，禁止根据样例名称或IFC site提示自动回填真实位置。

首期canonical地理锚点采用显式WGS84、GeoJSON Point、[longitude, latitude]顺序；字段包含人工标签/地址、来源方式、位置核对状态、更新时间、修订号。经纬度必须为有限数且在合法范围内；(0,0)不能充当缺省值。其他坐标体系不静默当作WGS84接收；来源坐标保留或明确拒绝，完成批准适配后才能建立canonical锚点。

位置核对只针对“地图登记位置”，不等同模型配准或工程精度验收。更新锚点不能修改模型矩阵、候选摘要、冻结发布或robot_ready状态。首期位置标签支持园区/楼栋/楼层描述，不因登记了楼层就声称具有室内三维定位。

授权读取复用/api/spaces目录边界，单场景位置写入复用场景配置的space.manage校验、CSRF和修订冲突规则；实施前核实已有存储模型并定义严格可选schema。撤权后清空对应点位、列表、卡片及选择状态；跨工作区清空全部缓存。位置和业务信息不嵌入第三方瓦片URL或style请求。底图请求仍会向服务商暴露客户端访问及视野范围，私有部署按需求使用自托管底图。

首期不引入空间数据库；小规模授权目录在客户端构建GeoJSON聚合源。场景分页时只聚合已加载范围并明确标注，不能当作全部授权场景总量。规模扩大后再按实测引入服务端授权bbox查询/聚合，不允许前端先取全局坐标再过滤权限。

## 6. 入口路由与重选契约

建议新增#scenes路由；不把现有#space三维预览含义改掉。顶部当前场景改为“场景名称 + 切换场景”入口，最终统一各工作面原生下拉选择；不另造一套场景目录数据源。

首次打开：有效深链照常打开；普通无目标进入场景入口。新建后的首次进入建议进入资料准备工作面，并展示已有流程引导；从场景入口普通进入默认到现有场景流程概览。实施前统一流程概览的确切落点，避免给尚未发布的场景直接打开空三维大屏。

重选打开时先通过现有runGuarded/NavigationGuard处理未保存修改，保留原工作面作为取消返回目标。取消恢复原精确记录；选择不同场景后只保留能力域及其合法tab，清除input/job/publication/artifact/batch/from/check等记录参数，复用并扩展sceneLinkFromHash白名单。

返回目标只允许站内已知路由和合法参数，不接受外部URL。选择同一场景可返回原精确记录，选择不同场景不得携带旧记录。浏览器前进后退仍走现有未保存保护机制。地图视野/搜索仅在当前工作区会话保留，不在localStorage保存敏感位置或业务详情。

共用数据管理/语义本体不强制要求场景。若从共用模块选择场景，只更新筛选或返回上下文；固定规则的id/version/sha可以按规则可读权限保留，旧场景的候选和发布引用必须清除并重新查询。独立固定发布大屏深链始终保持原发布身份，不因入口当前选择变化而替换。

## 7. 故障和性能

地图脚本、WebGL、样式、字体或瓦片失败时，列表、搜索、进入场景始终可用；显示重试和切换列表入口。不会把底图失败提示为“没有场景”，不会用示意图伪装可用地理底图。首期不建立全局离线缓存，授权数据不得通过通用service worker长期缓存。

实施验证覆盖1440px/390px、无位置、同址、无权限、空目录、无地图配置、地图故障、工作区切换、重新授权、有效深链、未保存修改及前进后退。以100/1000/10000个合成点位分别观察首载、交互与内存；10000仅为压力样本，不提前承诺支持规模。入口不得加载点云/模型或批量读取发布文件。
