# P12：场景进度与版本上下文

日期：2026-11-04。执行状态：**P12.1／P12.2／P12.3本机实现与验收通过**，见[P12验收记录](../validation/场景进度与版本上下文-P12-2026-11-04.md)。下文保留实施前的任务范围与验收标准；实际执行结果以上述记录为准。

前置：[P11验收](../validation/同场景资料更新与历史版本-P11-2026-11-04.md)。总计划：[业务技术流程任务批次与验收](业务技术流程任务批次与验收-v0.1.md)。

## 1. 当前判断

样本已跑通“场景资料 → 采集批次 → 固定模型 → 独立双视图 → 核对选择 → 固定发布 → 在线／离线使用”，也验证了同场景第二份不同资料、历史发布保留及显式回切。下一批重点是让工程师看懂并操作这些已有能力。

本次代码与文档检查发现：

1. `preview_workflow.py` 的流程以当前所选候选为锚点，正常结束后仍把“离线消费与恢复”作为下一步；服务不读取消费端，因此该步骤始终未核验，容易让服务端已完成的流程显得没有结束。
2. 当前工作候选、页面正在查看的固定发布、消费端实际启用版本是三个不同引用。多版本场景中，必须明确它们的关系。
3. P8已提供连续核对、固定交接和常用发布动作；P12应复用这些入口。流程详情包含大量工程记录，适合按需展开，页面首先应回答“现在是什么情况、接下来做什么”。
4. 六模块进度文档顶部仍有“P2—P5待推进”等旧结论，需要给出截至P11的统一快照。
5. P11后台浏览器验收出现过模拟会话确认窗口到期的503。需要验证恢复后的上下文保留；现有证据不足以认定真实平台认证存在相同缺陷。

## 2. 单一目标与边界

**进入一个场景，就能看清当前资料准备、工作候选、固定发布，以及下一步操作。**

继续采用 Workspace → 场景空间 → 多资料／批次／历史版本的归属；保留使用、构建、定义三类六模块。语义本体是共用定义，空间关联是具体场景实例；两者仍为纯几何流程的可选增强。

沿用现有保存记录、权限和发布门禁，摘要是只读投影，不引入第二套权威状态机、流程数据库或新顶级模块。摘要读取不得隐式预检、构建、选择、发布、导出离线包或探测消费机器。

## 3. 三类引用规则

| 引用 | 含义与来源 | 呈现及导航规则 |
| --- | --- | --- |
| 当前工作候选 | 已显式选择的候选，受选择修订及人工核对约束 | 展示候选标识、核对情况、匹配发布；新任务成功不自动替换 |
| 当前查看发布 | URL显式指定的固定发布；未指定时沿用当前入口既有规则 | 历史发布始终按自身资料、候选与双视图展示；与工作候选不同时给出简短说明，不重定向到新版 |
| 消费端启用版本 | 独立进程／设备保存的实际引用 | 服务端默认未知；下载、导出、查看发布都不能证明安装或激活 |

另保留“最近创建发布”的现有目录含义：它可能不匹配工作候选，也可能已暂停。不得把它改称默认启用版本，或在暂停时静默退回旧发布。新增展示名称不得伪造不存在的业务语义版本号。

## 4. 状态与下一步的设计

不使用单个百分比表达全场景。分别显示“当前工作进度”和“固定发布可用性”，这样新构建失败时，仍能说明历史固定版本可用。

| 保存记录情形 | 主要提示 | 主操作 |
| --- | --- | --- |
| 空场景 | 尚无资料 | 导入资料 |
| 已登记，但目标资料未预检或上次检查失败 | 资料待准备／需处理 | 查看对应资料与预检 |
| 目标资料准备完成、尚未提交 | 可以开始构建 | 进入带资料／批次上下文的构建流程 |
| 明确跟进的任务进行中 | 构建中，显示最近读取时间 | 查看该任务 |
| 明确跟进的任务失败或视图失败 | 构建需恢复／视图待恢复 | 进入该任务既有恢复入口 |
| 候选就绪但未核对选择 | 候选待核对 | 打开指定候选核对 |
| 当前候选已核对、尚无匹配发布 | 当前候选待发布；另列历史发布情况 | 交接该候选至态势服务 |
| 当前候选及匹配发布完整、分发启用 | 当前候选的服务端流程已完成 | 打开固定空间；查询、离线交付作为后续可选动作 |
| 目标发布已暂停 | 该发布暂停分发 | 查看分发管理；不自动恢复或换版 |
| 响应不可用、无权限或绑定异常 | 无法确认／无权访问／引用需处理 | 恢复读取或进入具体核查入口 |

补充规则：

- 对任务／候选的明确跟进来自现有路由上下文；没有明确跟进时，展示当前选择和其他任务概况，不任意挑选最新任务作为用户意图。
- 工作候选的完成结论必须基于已有核对、匹配发布和双视图完整性记录，不只看任务成功。实际操作时仍执行原门禁。
- 历史任务失败、旧资料停用不自动撤销既有固定发布。新一轮构建前仍须重新核验资料。
- 消费端状态持续标注“未读取消费端”，不计为服务端尚未完成。本体／关联缺项不进入必做步骤。
- 查看历史发布时，主要展示该发布状态；当前工作进度保留清楚标签，不能套用当前候选的结论。
- 摘要标明读取时间，属于请求时读取结果，不承诺跨库事务快照；引用变化时提示刷新或核对，不拼接互相矛盾的结论。
- 没有权限的工程信息不返回、不展示；摘要入口不得泄露资料、任务或原始路径。

## 5. 页面安排

保留全宽工作区、浮动侧栏、品牌淡渐变、现有DS字号及按钮规格。

| 模块 | 本批呈现调整 |
| --- | --- |
| 空间预览 | 保留场景与固定发布卡片；明确当前候选对应发布和历史发布，打开具体版本的新标签页 |
| 数据管理 | 以当前场景的资料准备为主；摘要链接到对应资料／批次，保留现有详情面板位置 |
| 构建中心 | 以明确任务／候选为主；显示与当前选择及匹配发布的关系，复用核对与恢复入口 |
| 态势服务 | 以当前查看的固定发布为主；区分当前候选匹配发布与历史发布，保留比较、查询及离线交付 |
| 语义本体 | 保留共用规则库与可选场景上下文，不增加几何发布前置要求 |
| 空间关联 | 保留具体场景与明确候选上下文，显示可选增强属性，不覆盖既有固定发布 |

共享摘要采用一段紧凑状态区：场景上下文、工作进度、发布情况及一个主操作；来源标识、摘要、历史检查和完整流程明细按需展开。各模块仅显示与职责有关的部分，不重复铺满六组卡片。

## 7. 验收矩阵

以下是待执行标准，不是已通过检查数量。

| 场景 | 必须观察到的结果 |
| --- | --- |
| 空场景与资料准备 | 无资料、未预检、失败、通过各有准确提示；摘要读取不会执行预检 |
| 构建进行中／失败／视图失败 | 指向明确任务和正确恢复入口；保留失败记录，不改变历史发布 |
| 候选就绪至发布 | 核对前后提示不同，发布交接固定候选，成功后显示服务端流程已完成 |
| 新候选未发布、旧发布可用 | 两种状态同时可见，不声称新候选已发布，也不阻断旧固定版本 |
| 查看历史发布 | 来源、候选、双视图与在线查询均属于该发布；返回后上下文保持 |
| 发布暂停 | 阻止该版本分发，保留管理历史，不自动打开旧发布 |
| 消费端未知、无本体／关联 | 服务端完成状态正确；不伪造机器人状态，不追加可选前置步骤 |
| 切换场景／Workspace及权限 | 不残留旧场景引用；查看者、工程师、管理员按现有权限展示与准入 |
| 网络失败／会话确认过期后恢复 | 错误不显示成空场景或无任务；恢复读取保留场景／任务／发布，不自动重复写入 |
| 并发引用变化／多次刷新 | 可检测到的不一致显示待刷新；不会自动选择最新候选或重新发布 |
| 布局与操作 | 1440px及390px无全局横向溢出；详情面板位于header下方，固定三维空间打开新标签页 |
| 只读与历史隔离 | 摘要读取前后业务记录不变；验收实际写操作仅在独立环境显式执行，原模型与发布摘要不变 |

验证方式：针对性后端单元／HTTP检查、TypeScript与Vite构建、浏览器连续操作与截图复核。复用P10／P11固定成果验证多版本；恢复／暂停等写操作使用独立验收环境，不为展示摘要再造一批算法成果。若无消费协议变化，沿用P11离线证据，不重复全套离线实验；若改变相关引用传递，补跑受影响的在线／离线一致性检查。

计划证据：`docs/validation/场景进度与版本上下文-P12-2026-11-04.md`、对应操作指南、`output/playwright/flow-batch-p12-acceptance.json`。实施时按实际执行日期命名并填写，不提前生成通过结果。
