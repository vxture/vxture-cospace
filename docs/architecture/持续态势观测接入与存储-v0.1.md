# 持续态势观测接入与存储 v0.1

日期：2026-11-17。SG5 的独立实现增量。当前实现门开闭观测的有界、单机、可重放持久化内核；尚未开放公网写入或接入厂家传感器。它不以设计门扇几何推导实时门状态，也不修改底图或本体。

## 1. 三类数据分别管理

静态底图描述空间几何、实体、关系及连接。IFC 结构声明保留其设计来源与未核验状态。本体绑定另行决定实体语义，不能由 IFC 类名自动冒充已完成绑定。

观测记录是某来源在某时刻对已绑定对象的报告，不是底图几何修订。当前只接受门的 `open`、`closed`、`partially_open`、`unknown`，不接受可通行、导航路径或作业策略。应用需要结合本体、实测几何和设备自身条件决定行动。

`opening_observations.py` 管契约、时效及纠正规则；`spatial_observation_store.py` 管 SQLite 事务与持久化。前者不依赖存储，后者不承担身份认证、场景授权或厂家签名验证。没有调用现有 synthetic 图校验器来冒充真实观测契约。

## 2. 上线前的真实调用链

1. 可信管理端从已经校验的场景目录建立观测登记。登记固定平台 issuer、组织、工作空间、场景、目录 SHA-256、门实体标识与允许上报的 producer。不能接受浏览器自行提交任意目录注册。
2. 接入网关校验厂家凭证或消息签名、重放保护、租户和场景权限，将已认证主体映射到登记的 producer。产品不自建商业订阅限制。
3. 网关核对来源时钟质量、证据对象及对象映射，限制报文大小和频率。厂家设备编号不自动成为底图实体 ID，旧目录的观测也不自动迁移至新目录。
4. 调用 `append(scope, report, authenticated_producer=…)`。`authenticated_producer` 必须来自步骤 2，不能从同一报文的 producer 字段复制后充当认证结果。数据库自动记录平台接收时间。
5. 服务查询先做场景授权，再调用 `resolve`。下游得到来源报告状态与固定查询游标，而不是平台担保的现场事实或通行判定。

当前已实现步骤 4、5 的内部能力、步骤 1 的不可变存储边界及步骤 5 的场景授权 HTTP 只读查询（含固定时间与序号回放）。真实网关、密钥配置、时钟质量和证据内容校验尚未接入；数据库内核及只读 HTTP 接口不能代替这些职责。工作台查询当前报告，历史回放供消费端显式调用，见[观测接入记录](../validation/态势底图SG5观测工作台接入.md)。

## 3. 契约

登记：`cospace.opening-observation-registration/0.1`。允许 `ifc_design_candidate` 或 `synthetic` 来源，最多 1,000 个门、64 个 producer；相同作用域登记不可覆盖。新增主体或来源需显式的新作用域版本设计，当前不支持原地修改登记。

报告：`cospace.opening-observation-report/0.1`。固定 event_id、producer、entity_id、operation、value、observed_at、valid_until、1–16 个证据摘要和可选 supersedes。客户端不能指定 received_at。时间必须 UTC，过期时间严格晚于观测时间；允许迟到、已经过期的报告留档，拒绝晚于服务器接收时间的未来报告。此拒绝策略不等于已经校准设备时钟。

作用域将 issuer、组织、工作空间、场景与目录摘要一起固定。相同实体 ID 出现在不同租户或不同目录中不会共享状态。登记仅固定引用，不验证对应目录内容；查询明确输出 `source_content_verified=false`、`evidence_content_verified=false`、`clock_quality_verified=false`、`real_release_ready=false`。

## 4. 幂等、纠正和历史

相同作用域、producer、event_id 的相同报告返回首次写入记录和首次接收时间。内容不同则拒绝，不能覆盖。SQLite `BEGIN IMMEDIATE` 将幂等检查、纠正检查和追加合为事务；并发重试只写入一次。普通读取使用只读连接，不因查询创建数据库。

纠正必须显式指向同一来源、同一实体、同一观测时间的已有报告。可纠正值、有效期或证据摘要；不允许借纠正替换身份或观测时刻。一个报告最多直接被纠正一次，后续纠正须接在纠正链末端；数据库唯一约束防止分叉。原记录永久保留。撤销使用 operation=retract、value=null，并显式指向已有报告；普通报告为 operation=assert，必须提供值。撤销后该来源的旧状态不会复活，独立返回 retracted。后续可在撤销链末端追加显式恢复报告，原撤销记录仍保留。

状态同时按 `as_of`（现场时间）、`known_at`（平台知晓时间）和 `through_sequence`（最高接收序号）筛选。纠正在平台收到之前不影响历史查询。用返回的接收序号再次查询，即使之后有同秒追加，也可固定原先结果；游标同时包含登记、规则版本、查询条件和已知记录摘要。

各来源只取该来源最新观测时刻；同刻不同值保留冲突。最新观测过期不会复活旧的长有效期值。多来源有效值不同也保留冲突，没有默认来源优先级。状态区分 unavailable、expired、retracted、unknown、conflict、reported；reported 仅表示有效报告一致，不表示已核实真实现场。

## 5. 容量与运维边界

文件名 `spatial-observations.sqlite3`，根目录由可信运行配置提供，禁止传入客户端路径。SQL 参数化。单作用域最多 5,000 条报告；到达预算后明确拒绝，历史不被静默清理。幂等重试仍可成功。`append_batch` 支持同来源 1–128 条报告在一个事务中追加，全部成功或全部回滚；批内可按顺序纠正前一条，整批重试仍返回首次记录。追加通过索引查询幂等键及纠正目标，不逐次反序列化全部历史；状态读取最多读取该作用域预算内记录。

当前是单机能力，没有部署迁移或改变生产目录。已接入[现有整站冷备份、恢复及观测领域完整性检查](../validation/态势底图SG5观测备份与恢复.md)，观测写入与 runtime 变更锁协作；恢复保留历史游标和序号高水位。生产调度、保留/加密策略、容量告警、归档与游标留存、schema 升级、并发压测及多节点方案仍需完成。没有容量或吞吐承诺，不作为高频遥测库。数据库及报告内容均不得进入 Git。

服务器时间回退时拒绝继续写入该作用域，避免接收顺序与知晓时间冲突。修复时钟后可重试；不改写过去的 received_at。不能凭已有这一检查声称时钟可信。

## 6. 与重构和发布的关系

门的观测变化只更新查询结果，不触发底图重构。涉及实体身份、几何或连接的描述变化，先形成候选和影响清单，独立复核后形成新的底图版本。跨版对象匹配只提出候选，不自动迁移报告。危险操作确认和正式发布审核继续使用既有业务流程。

SG3 未核实的单位、对齐、区域和连接，不通过登记观测补齐。SG4 授权发布与真实快照仍有独立验收项。SG5 的真实识别基准、厂家上报与真实局部更新验收尚未完成。

## 7. 本机验证

35 项日志、既有状态与交换专项通过，含并发重试、租户/目录隔离、来源绑定、纠正与撤销历史、批量原子回滚、过期不复活、未来时间与容量拒绝。输入 JSON Schema 由运行契约生成，保留在 contracts/schemas；时间先后、纠正引用等跨字段规则仍由服务端校验。

Windows/Python 3.14.3 一次合成试跑：1,000 条相同时刻门状态报告，逐条独立事务约 172.25 秒，重新打开查询约 86.09 ms。增加批量事务后，按每批 100 条、10 个事务写入约 2.03 秒，重新打开查询约 30.75 ms，数据库 839,680 字节。测试使用合成来源和固定接收时间，不含网络、鉴权、证据核验和生产磁盘条件；两轮运行存在缓存与环境差异，不能将倍数差直接视为生产加速承诺。完整原始输出仅留忽略目录 output/sg5。

## 8. 多对象一致读取

已增加[只读批量查询及整批回放](../validation/态势底图SG5观测一致批量读取.md)。resolve_many 以显式只读事务固定登记与日志，最多 128 个已登记对象共享时间/序号及记录摘要；单门 resolve 复用相同内核，原 cursor 算法不变。HTTP 批量入口沿用场景权限、会话和 CSRF，缺配置/对象则整批拒绝，不返回混合上下文或局部成功。

日常单门、批量与历史读取现与冷备份共用[作用域记录完整性校验](../validation/态势底图SG5观测运行完整性.md)：规范字节、索引/来源/对象绑定、接收顺序与纠正链异常统一按存储不可用拒绝（HTTP 503），不降级成正常或无报告。校验整个当前作用域后再筛选历史前缀，其他作用域不扫描；不是签名防篡改或自动修复。

可信调用方可使用[带证据内容核对的内部接入](证据内容核对与接入-v0.1.md)，在一次 append_batch 前核对全部实际文件；不新增 HTTP 写入口或来源认证。回执不持久化，原日志与状态查询继续标记证据含义未核实。
