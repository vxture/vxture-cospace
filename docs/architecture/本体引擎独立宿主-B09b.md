# 本体引擎独立宿主 B09b

安装 `vxture-ontology` 的 `0.1.0.dev2` wheel 即可独立运行编制 API。它只监听 `127.0.0.1`，不依赖 CoSpace、地图、场景或平台权益。CoSpace 原有部署、账号、路径与数据不变，独立产品工作台由 B09d 装配。

```text
uv build --wheel packages/ontology/kernel --out-dir output/ontology-dist
python -m pip install <生成的-wheel>
vxture-ontology-host serve --data-dir ./ontology-data --identity-config ./identity.json --port 8791
```

`identity.json` 是操作员管理的文件，必须位于数据目录之外。顶层 `profile` 为 `vxture.ontology-local-host/0.1`，`principals` 为数组；每条包含 `scope`、`actor`、`token_sha256`、`permissions`。为每位操作员单独生成 `secrets.token_urlsafe(32)`，配置记录其 UTF-8 SHA-256 小写十六进制摘要。原始令牌通过本地安全方式分发，调用时用 `Authorization: Bearer ...`，不要放进 URL、示例数据、命令历史或版本库。身份策略启动时读取，更新或撤销后重启。文件和数据目录使用操作者自己的文件权限；这个参考宿主用于本机联调，不作为公网服务。

| HTTP 路径 | 行为 |
| --- | --- |
| `GET /api/ontology-directory` | 查询可用候选及最新发布的目录视图；目录不是可整体导入的闭包。 |
| `GET /api/ontology-definitions` | 通过 `module_id` 读工作台；通过 `review_id` 读送审快照；通过 `module_id+version+sha256` 读准确的不可变定义和依赖。 |
| `POST /api/ontology-definitions` | 现有 save、validate、submit、decide、publish 命令，保留修订和幂等校验。 |
| `GET/POST /api/ontology-configuration/groups` | 单独管理预置、自建分组、启停和置顶、上移、下移、置底；不改变本体定义。 |

读取权为 `read`，私有草稿和送审还需 `read_private`；各写操作分别使用 `edit`、`submit`、`review`、`publish`；分组需要 `configure_groups`。审批者不能与送审者相同。作用域和操作者均由身份适配器解析，命令不得声明自己的身份。其他宿主可以为 `local_host.http.server` 提供自己的身份适配器，用经验证的身份返回 `Principal`；核心仍接受独立注入的权限和事务端口。没有新增统一登录、业务现场权限或账号系统。

独立宿主把编制状态、幂等回执和分组配置存于同一份 `ontology-host.sqlite3`。备份使用 SQLite 一致性快照，可以在本机宿主运行时执行。恢复只接受由此宿主生成的可信快照，复制到全新目录并检查数据库格式与完整性，拒绝覆盖当前状态。身份配置、令牌和运行配置不包含在备份中；恢复时由操作员独立选择配置。

```text
vxture-ontology-host backup --data-dir ./ontology-data --output-dir ./ontology-backup
vxture-ontology-host restore --backup-dir ./ontology-backup --data-dir ./ontology-recovered
vxture-ontology-host serve --data-dir ./ontology-recovered --identity-config ./identity.json --port 8791
```

验收用独立 wheel 从空目录启动，完成保存与送审、停启服务后继续审批和发布、升版后读取旧定义；另验证在线备份、恢复待审与已发布状态、分组顺序与身份文件隔离。CoSpace 使用相同的两个 SQLite 适配器，但继续沿用原数据库文件和分区，不要求迁移。
