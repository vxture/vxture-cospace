# 开发进展复盘与P19：RGB-D资料预览与构建来源联动

日期：2026-11-05。状态：用户批准后，P19.1—P19.3已完成本机实施与验收。以下保留原规划，执行结论见第7节。

## 1. 当前结论

样本主线已经贯通：**场景空间 → 登记资料 → 构建固定模型 → 独立派生两类视图 → 核对选择 → 固定发布 → 在线／离线消费**。同场景多资料、历史版本、失败恢复及重启也已有本机证据。后续按实际操作断点补齐，完成情况不换算为产品百分比。

P18补齐真实RGB-D工作进程的逐帧记录、全屏跟随及源时间回放。办公室60帧资料中57帧使用已有估计位姿参与构建，3帧未参与；最终56,637点与同输入原模型一致。217项后端、35项过程客户端、123项浏览器／HTTP、7项离线汇总及前端编译通过，另外保留原预览和静态展示回归。实际重启951个业务索引文件摘要不变。各类计数范围独立，不累加为统一测试总数。

证据：[P18验收](../validation/逐帧构建过程可视化-P18-2026-11-05.md)、[机器汇总](../../output/playwright/flow-batch-p18-acceptance.json)。本轮核对这些既有记录，未重跑P18测试。

## 2. 下一批选择依据

数据管理的`InputPreview`目前只开放PLY，其他路线明确显示未提供原资料预览。`input_facts`已经给出RGB-D来源清单、已有位姿、时间和适配器标定事实；`nyu_rgbd`已有严格PNM解码与明确的深度解释；P18已经保存源图像摘要及逐帧位姿。这些基础可以复用。

当前操作断点是：用户在构建前看不到RGB-D实际内容，构建后也不能从当前过程帧直接核对原始画面。P19建议补齐：**构建前看懂资料，构建中／回放时能查到对应来源**。

| 候选方向 | 本轮安排 | 理由 |
| --- | --- | --- |
| RGB-D资料预览与来源联动 | 建议P19 | 补齐现有路线，沿用办公室样本和P18证据即可验收 |
| 坐标／单位等关键解释纠正 | 后续优先候选 | 需要新解释与历史引用规则，适合单独完成最小闭环 |
| 空间关联画面点选、本体编辑 | 后续按业务用例推进 | 是定义层的独立工作，不作为几何构建前置条件 |
| 更多格式、多资料融合和实时采集 | 获取明确路线后安排 | 分别涉及新解析器、处理算法及设备条件 |
| 真实Vxture接入 | 外部配置具备后独立验收 | 仍需真实客户端、账户及Workspace环境 |

P17曾将关键解释纠正列为后续优先候选；本次依据P18新增的真实过程证据，将原资料与过程联动排在其前。DM09并未因此视为完成。

## 3. 业务操作与页面

### 3.1 构建前：数据管理查看资料

沿用header下方的页面右侧详情栏，在“内容预览”中按需打开“查看RGB-D”。空间、资料及已有详情位置不变。较大查看面使用按需放大视图，关闭回到原资料。

- 默认并列彩色图与深度伪彩图，窄屏上下排列；保留各自传感器画幅，不把未对齐图像直接叠加。
- 同一个帧游标控制两张图；显示当前帧／资料帧数、相对源时间、RGB与深度配对时差及已有位姿是否提供。
- 深度图使用明确、固定的米制色标和独立无效掩码；不可用像素保持无效，不涂成零距离或空闲。
- 可展开已有估计相机轨迹，标明首深度相机局部坐标及轴方向；没有重力依据时不称“俯视平面”。轨迹不等于导航路线或地面真值。
- 构建前只说明“有已有位姿／无已有位姿”。它表示路线可用条件，不能冒充某次任务实际处理状态。
- “用于构建”复用现有交接和实时预检；观看预览不保存审核通过状态。

原资料60帧与位姿覆盖57帧必须分别展示。资料尚未构建时也可查看，不能强制先产生任务。

### 3.2 构建中／回放：当前帧查看来源

保留用户认可的全视口纯底图和紧凑悬浮控件。增加一个按需“源画面”入口，默认关闭；打开后展示当前过程帧绑定的彩色／深度画面与源时间，关闭恢复完整画布。

联动使用P18记录的源帧标识及图像摘要，不凭滑块位置猜测原始序号。过程帧、accepted序号和原清单序号的映射显式保存或验证；参与／未参与及原因取自指定任务的记录。源帧请求尚未完成时清空或覆盖旧帧并显示加载状态，不能把上一帧图像标成新时间。

源文件缺失时提示“源画面不可用”；已验证的P18过程及独立固定发布仍按自身依赖读取。源画面不可用不等于已冻结模型损坏。

新来源接口要求`data.manage`，P18过程要求`build.run`，两项分别判定；只有构建权限不自动获得原图访问权。新入口依据能力和授权展示，直接请求执行同样检查。

## 4. 数据与接口设计

P19增加只读显示响应，不产生新资料实体、持久预览任务或模型版本。原报告、已有位姿和图像仍是固定来源，显示PNG不成为构建输入。

| 内容 | 设计及绑定 | 核验范围 |
| --- | --- | --- |
| RGB-D资料目录JSON | 新profile `cospace.rgbd-input-preview/0.1`；场景／资料ID、report及tracking摘要、帧映射、配对时差、位姿覆盖、局部坐标及限制 | 登记归属、两个清单摘要、数量、引用、有限刚体位姿和现有适配约束 |
| 单帧显示JSON | 场景／资料／源帧标识、两个原成员摘要、显示规则版本、尺寸、色标、有效性说明及两张PNG | 被请求的原图字节大小、摘要、严格解码和绑定；不宣称已复核所有图像 |
| 深度显示 | 复用NYU原始小端PGM解释和现有公式／有效范围；固定色标，最近邻缩小，失效掩码随图保留 | 深度码不是毫米值；禁止直接对原整数着色后标成米；伪彩图仅供查看 |
| 轨迹 | 已有`prefix_T_anchor_camera`及其固定摘要 | 无位姿的3帧不外推；未知UTC及场景对齐状态保留 |
| 过程联动 | P18指定任务的帧标识、源摘要与P19响应交叉核对 | 两端来源不一致时拒绝联动；不修改冻结索引 |

拟采用`GET /api/inputs/{input_id}/rgbd-preview?space_id=…`和单帧子资源`…/rgbd-preview/frame?space_id=…&frame_index=…`。精确字段、Schema和错误码在P19.1落定，沿用能力声明；旧服务无声明时显示当前支持范围。

读取策略及首版预算：

1. 先确认当前Workspace、场景、资料及`data.manage`，再读取清单和负载。不接受路径、任意成员名、变换或提高预算参数；拒绝多余／重复参数及越界帧。
2. 保持现有适配器最多500帧、每个PNM原成员最多2,000,000字节和640×480严格布局。清单使用独立有界读取，不因为查看一帧而重新解码全部120张图。
3. 资料目录JSON最多1MiB；单帧显示最多320×240，包含两张PNG的JSON编码后最多2MiB。PNG可作为受限data内容返回，拒绝任意MIME／SVG／外部URL。预算在P19.1以最坏情况样本确认，超过即明确拒绝。
4. 按需单帧请求，不预取整段原图；客户端最多一个在途帧请求，拖动时取消／合并中间请求，仅提交最后游标。后端解码在线程池执行，不增加常驻转码worker或磁盘缩略图库。
5. 响应`no-store`；客户端只保留当前帧，换资料、场景、权限失败或解绑时清空图像并取消请求。元数据与图像提交到画面前再次比较绑定及请求代次。
6. 预览检验所选成员；完整预检和构建仍按原规则核验全部必需内容。缺少可验证源时间的历史资料按帧序浏览并显示时间未知，不补造时钟。

## 5. 执行小批与验收

| 小批 | 交付 | 完成判据 |
| --- | --- | --- |
| P19.1 只读来源与格式 | 严格目录／单帧读取、深度显示规则、Schema、预算、授权与能力声明 | 原图与清单摘要一致；小端／无效码／有效范围及固定色标正确；60／57覆盖可复核；越界、缺失、篡改、非法位姿、预算、角色及跨场景拒绝；读取不启动构建、不写预检／选择／发布 |
| P19.2 页面与联动 | 数据管理RGB-D查看、已有轨迹、全屏构建按需源画面 | 资料未构建也可查看；两图与当前源帧对应；前后定位、快速拖动、迟到响应、换场景、关闭清理、窄屏及旧能力降级通过；源文件缺失保留独立过程回放；原画布默认布局保持 |
| P19.3 连续业务验收 | 原办公室场景新任务至固定发布／消费、回归、重启及文档 | 从资料核对转入指定输入真实构建；P18过程与原图摘要对应；两类视图固定同一模型；在线与独立禁网消费一致；实际重启恢复；原运行区和历史固定成果摘要不变 |

每小批通过后进入下一小批；保存测试名称、原始结果及必要截图，不预设通过数量。受控网络时序测试与实际worker过程证据分别报告。

### 关键验收场景

- 办公室原资料60帧全部可按索引查看；57帧具备已有估计位姿，其他帧显示真实缺项。某一任务处理失败后的部分范围不得与资料位姿覆盖混淆。
- 选择第N帧时，彩色、深度、配对时差、位姿标记与来源摘要属于同一明确配对；快速切换不混帧。全屏回拖不提前显示后续轨迹或沿用上一帧来源图。
- 原图被修改／丢失时相应查看失败；清单仍可读的其他帧能按其真实校验结果查看；构建准入继续阻断不完整输入。此测试使用独立故障副本。
- 原文件不变；同输入固定模型坐标、颜色和既有核心产物摘要保持，新增显示数据不参与模型计算。固定发布及离线包继续遵循自身清单，不承诺新旧整包字节相同。
- PLY本机准备及已登记点云预览、ROS单帧构建、旧RGB-D无过程任务、旧发布均回归。纯查看不会改变当前任务、候选选择或发布。
- 非资料角色、跨场景／Workspace及直接API拒绝；撤权后新请求拒绝并清空来源显示。共享屏幕上已见信息不等于可以追溯撤回。
- 有／无GPU均可查看两张图；轨迹不可用时保留图像和主流程。桌面与390宽无横向溢出。

实施使用独立运行副本；旧服务与业务记录保持。实际重启只作用于该批验证服务，记录前后业务文件摘要。离线消费继续针对固定模型及两类视图，不额外打包原图或P18过程分块。

## 6. 完成定义及后续

完成定义：**一个有权用户可以在数据管理中核对RGB-D资料，转入同场景构建，并在真实过程的某一帧查看对应原画面；后续核对、双视图、固定发布和消费仍走既有链路。**

DM11只新增“当前NYU RGB-D路线的图像／已有轨迹子项”，通用图像、轨迹、表格和额外格式仍保留待办。当前NYU内置标定和已有位姿可解释，不意味着通用配套资料管理DM10已经完成。精度继续`unverified`。

P19之后优先重新评估DM09关键坐标解释纠正；空间关联画面点选按具体对象标注用例独立推进。实时采集、SLAM调参、局部融合及生产身份联调分别保留其所需条件和验收范围。
