# 复核快照与观测上下文 v0.1

日期：2026-11-17。衔接固定复核快照与单作用域观测日志，提供可复查的组合读取上下文；不是已采用事实或正式发布协议。SG3 区域与连接标注、SG4 设计资料/本体提案和 SG5 有时效的来源报告仍各自保留语义与依据。

## 1. 解决的问题

仅记录观测 cursor 不能说明消费时采用哪版空间标注和本体映射；仅固定复核快照也不包含本次读取的观测截面。新的 context_cursor 同时绑定快照原始字节摘要、固定设计包与结构、场景/目录来源、对象选择与顺序、现场时间、平台知晓时间、最高接收序号、观测批游标和状态摘要。空间描述变更与来源报告变化都能被区分，不将类型映射调整误认为门状态变化。

复核快照保持不可变；实时报告不写回它。此组合只是“一起使用了这些固定描述和这个报告前缀”，不宣称数据库与文件跨存储事务，也不把报告变成现场事实。

## 2. 内部调用

`packages.service.ifc_review_observations.read_review_observations(journal, principal, snapshot_raw, query=..., design_package=..., expected_source=..., now=..., ontology_raw=...)`。

调用方必须先授权场景、固定快照/设计资料及本体的访问。principal 来自可信身份上下文；issuer、organization、workspace 与快照的 space/catalog 一起构成日志 scope，不接受查询指定租户或日志路径。没有新增 HTTP 路由、厂商写入口、凭证或平台会话请求。

query Schema：contracts/schemas/ifc-review-observation-query-v0.1.schema.json。必填 snapshot_sha256 与 1–128 个不重复 element_ids；所选对象必须是固定包中声明为 door 的对象。可选 replay 三项与既有观测回放一致：as_of、known_at、through_sequence（十进制字符串）。严格 UTC，不允许未来时间；缺省使用可信调用方给出的服务器 now。expected_context_cursor 可选，但使用它时必须同时提供 replay。

执行顺序：

1. 核对快照原始字节与外部可信摘要，重验整个固定资料包、标注和可选本体/类型提案；所有既有复核约束继续成立。
2. 根据固定门声明映射 element_id 到源实体 ID，不以名称或相似几何匹配。
3. 仅调用一次 resolve_many，在显式只读事务内固定整个 scope 的登记与有界日志，然后计算所选门状态。没有隐式登记、建库或逐门读取不同时间的行为。
4. 返回 `cospace.ifc-review-observation-context/0.1` 及 context_cursor；若指定预期游标，则精确比对整份上下文摘要，不一致明确拒绝。

响应只含固定来源、时间/序号、摘要游标和每门的状态摘要（值、最后上报时刻、有效/过期/撤销数量及原单门游标），不返回租户标识、producer 列表、原报告、证据摘要、路径或凭证。观测游标自身绑定 scope，故即使其他租户登记了同一目录和相同状态，也不能复用上下文游标。摘要不是认证令牌或签名。

## 3. 读取与回放

本地受控文件工具：

```text
python -m experiments.scripts.ifc_review_observations --snapshot <snapshot.json> --design-package <design.bin> --source <可信SourcePin.json> --query <query.json> --journal-root <日志根目录> --issuer <已知issuer> --organization <组织ID> --workspace <工作空间ID> --now <UTC时刻> --output <新上下文.json>
```

有本体映射的快照还需 --ontology。query 示例：

```json
{"snapshot_sha256":"<可信快照摘要>","element_ids":["e00002"]}
```

回放保留原快照、对象及顺序，并加入原结果的三项（sequence 转为字符串）：

```json
{"snapshot_sha256":"<原可信快照摘要>","element_ids":["e00002"],"replay":{"as_of":"2026-11-17T00:05:00Z","known_at":"2026-11-17T00:05:00Z","through_sequence":"1"},"expected_context_cursor":"<原结果context_cursor>"}
```

示例编号/序号须替换为实际固定包与响应，不能复制任意 cursor 建立信任。日志目录、来源与身份参数是有文件权限的本地操作者输入，此 CLI 不认证身份，不适合直接对外暴露。now 是显式复现实验条件，不认证时钟质量；线上内部调用应取服务器时钟。输出 exclusive create，拒绝覆盖。

后续同刻纠正/迟到报告不改变原固定序号回放。语义/区域变更即使状态摘要相同，也会改变 context_cursor；原 observation_cursor 可保持不变。改换快照后使用旧预期上下文会拒绝。日志、登记或固定资料丢失/损坏时无法回放，不缓存为正常或无报告。

## 4. 失败与边界

未登记 scope、未登记对象、非门、错误资料/快照/本体摘要、错误数据类别、重复或超预算对象、未来时刻、无效序号、上下文不一致都拒绝整批。已登记且无报告正常返回 unavailable；两者不能混同。底层 ObservationStorageUnavailable 原样传播，不转成无报告；未来 HTTP 接入必须沿用存储不可用 503 等既有错误区分。

最多 128 门、scope 最多 5,000 报告，超量需显式分批，多个批次不自动成为一个全局事务。复核快照/完整设计包核验有额外读取成本，本轮没有做缓存、生产并发或性能承诺。

alignment_verified、ontology_bound、evidence_content_verified、clock_quality_verified、real_release_ready 仍 false；未核实标注、设计声明和来源报告不是已核实事实。这里只读描述，不计算通行、路线或作业。SG3 真实核验、SG4 采用事实/正式发布、SG5 厂家/证据含义与真实变化验收仍独立推进。
