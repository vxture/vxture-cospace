# 开发进展复盘与P17：资料内容预览

## 1. 当前进展判断

主轴保持：Workspace → 一个物理场景对应一个场景空间 → 多份资料 → 多个历史模型 → 固定双视图及发布。

样本主流程已贯通：导入 → 检查整理 → 构建固定模型 → 派生双视图 → 核对选择 → 发布 → 在线／离线消费。P11完成同场景资料更新和历史版本；P12统一进度及上下文；P13完善说明和来源事实；P14接入严格PLY；P15收敛入口与构建交接；P16开放浏览器PLY准备。

|分类／模块|已实现的样本能力|仍需补齐|
|---|---|---|
|使用／空间预览|授权场景目录、固定版本、新标签全屏、双视图与历史切换|真实账户、现场数据及性能验收|
|使用／态势服务|核对发布、来源查询、在线查询、固定离线包、消费激活及重启恢复|正式部署、外部业务及实机接入|
|构建／数据管理|三条受控路线、浏览器PLY准备、说明与来源、预检、批次、版本与追溯|原资料内容预览、关键解释修订、更多配套与输入格式|

|定义／语义本体|固定小型规则包、版本、属性和关系约束校验|业务人员编辑、复杂约束及行业映射|

三类技术路线的含义仍不同：RGB-D利用已有位姿累积；ROS样本取首帧局部点云；PLY保持声明坐标进行规范化。三者流程都能运行，不代表均完成多帧SLAM或现场空间重建。

P16现有证据：301项后端、35项打包逻辑、181项浏览器、7项离线汇总以及前端构建通过。详见[P16验收](../validation/浏览器PLY资料准备-P16-2026-11-05.md)。这些是分范围检查结果，不是功能完成百分比或正式生产验收。

当前用户浏览的8779是P15运行副本；P16入口为[8780数据管理](http://127.0.0.1:8780/workbench/layout.html#data?space=space-0004d0e3c133f5fb&tab=inputs&input=input-9129e7b23b4d4ea6)。两个独立运行区同时保留，不能将旧端口页面当成P16缺少功能的证据。

## 2. 下一处业务断点及优先级

现在用户能检查资料结构和来源文字，但在准备弹窗和登记资料详情中还看不到点云内容；看到几何通常已进入构建后的成果。预检通过只能证明当前路线可处理，不能帮助用户及早识别选错文件、朝向不符或明显不相关的范围。

建议P17实现数据管理清单DM11的第一部分：**PLY资料轻量预览**。目标是在构建前看见所选资料的形态和数值范围，仍由用户判断是否属于当前物理场景。

|候选方向|安排建议|依据|
|---|---|---|
|资料内容预览|下一批P17|直接补齐已有入口的核对步骤，可用现有样本验收|
|坐标／单位等关键解释纠正|P17后的优先候选，另行设计|当前填错只能重新准备，需定义新记录及纠正引用，涉及历史影响|
|更多格式与多资料融合|取得明确样本及路线后安排|扩大支持面或新增处理算法，不能把多选文件等同融合|
|本体编辑与画面关联|按明确业务用例独立安排|当前几何主线可独立运行，定义能力继续保留扩展|
|真实平台与部署联调|外部条件具备后单独验收|需要真实客户端、Workspace绑定、账户和运行环境|

P17不增加Launcher入口、业务实体或持久预览任务，使用原数据管理、input_id及场景归属。精度优化仍后置。

## 3. 业务操作和页面

### 3.1 登记前：准备PLY

原文件 → 严格本机检查 → 显示点云预览与完整范围 → 填写／核对声明 → 原P16确认登记。

本机预览只依赖检查通过的文件，不要求先填完坐标和来源；打包登记仍要求P16完整声明及两次确认。文件检查、声明校验和包准备可拆为内部状态，用户无需创建额外记录。未知单位时显示“文件数值范围，单位待确认”；不能在用户确认前默认标成米。

预览区折叠为“查看点云”，按需展开。提供旋转、缩放、平移、适配全图及坐标轴；显示原始点数、显示点数、RGB／中性、完整数值边界。采用DS按钮、色彩、字号和状态提示；文件与声明核对仍为主要操作。

### 3.2 登记后：资料详情

沿用header下方的页面右侧详情栏，新增“内容预览”区；用户明确展开才请求。较大查看面使用页内对话框，关闭返回当前资料；不进入正式空间预览，不改变当前候选或发布。窄屏保留可达操作及滚动。

预览明确标注“资料预览”“显示抽样”“局部坐标／场景对齐未核验”。相机适配和绘制原点只影响显示，不改变点坐标、声明或原包。相机观察上方向为显示约定，不能推导未知的重力方向；不执行旋转纠正、去噪或坐标转换。

渲染不可用时仍显示点数、边界及说明，并保留原登记／构建流程。预览不是新的准入条件，不保存“看过即通过”的业务状态，也不代替预检。

## 4. 技术设计

### 4.1 本机解析及显示数据

- 继续使用P16严格PLY检查，统一产生预览抽样；不通过通用PLYLoader绕过现有布局约束。
- 完整点数和包络来自全量检查；只对显示点按原文件索引确定性等距抽样，最多10,000点。明确可能遗漏小物体，不把抽样范围替代完整范围。
- 原RGB按固定规则显示，无RGB采用DS中性色；原点云字节、坐标、来源收据及ZIP算法保持不变。
- 复用现有Three.js及OrbitControls；实现轻量资料画布，不把资料伪装成PublishedModel，也不为复用组件补造publication或智能体数据。
- 按需加载渲染模块，关闭／换文件／换资料／换场景后中止请求，销毁几何、材质、观察器和动画循环。处理空范围、单点、极端局部偏移和窄屏。

### 4.2 登记资料预览接口（已按第8节契约实现）

`GET /api/inputs/{input_id}/preview?space_id=…`，profile拟定`cospace.input-preview/0.1`，首版只支持`ply_pointcloud`。

响应包含明确space_id/input_id、格式、登记清单及点云摘要、原始点数、完整bounds、单位/frame/axes、颜色依据、抽样方法/上限/实际数量、点与颜色数组和限制说明。返回值允许声明字段，不包含服务器路径、凭据或任意文件定位。

固定最多10,000点、编码后最多2MiB；不接受任意路径、frame变换或客户端提高预算。能力响应新增可选预览声明；旧服务无能力则显示说明，不猜测端点支持。正式字段及错误码在P17.1落为Schema和契约。

权限沿现有资料facts使用`data.manage`及Workspace／场景／input归属核验；space.preview不授予原资料读取权限。先授权再读负载，不提供无认证回退；直接URL与UI一致。

服务端复用当前严格解析及登记绑定检查，核对真实清单、PLY、可选source.json后再抽样；使用线程池，避免在异步事件循环内解析文件。完整输入预算仍为32MiB/100万点；仅用户打开时执行，无后台轮询。响应`Cache-Control: no-store`，首版不保存预览文件、不新增缓存库。该预算限制单次读取与响应，不据此宣称多用户并发性能已验收。

源文件或收据变更／缺失时返回明确错误，清空旧画面；旧固定发布按自身完整性继续读取。停用／归档不因查看而恢复或赋予构建权，读取语义沿现有资料门禁。

客户端核对响应profile、场景、资料、摘要绑定、数量、有限数值、bounds、颜色和预算；不一致时不得绘制。旧三文件PLY与P16四文件包均支持；RGB-D、ROS显示当前路线暂未提供原资料预览，原构建入口保持可用。

## 7. 批准后的范围补充：构建过程可视化

用户在批准P17时明确提出构建过程应该可视化。补充复用已有build-stages记录，在构建流程显示真实模型冻结及人／智能体任务状态，并按需查看已完成阶段的几何。固定模型无需等双视图全部完成才可查看；未冻结或视图未成功时明确等待／失败／中断，保留原恢复入口。不显示虚构百分比、实时SLAM动画或不存在的增量几何。

新增受build.run及场景／候选归属保护的只读阶段预览接口，验证固定模型、任务及产物摘要。预览请求不poll、launch或compose工作；调度仍沿现有任务读取。人视图核验实际PLY产物后展示同源固定点云，智能体显示实际agent.npz表面单元。该画面为阶段产物预览，不伪装为已发布空间。

P17.1加入阶段产物绑定、未就绪／失败／篡改、跨场景和不推进worker测试；P17.2加入构建流程画布、运行中刷新不卸载已打开画面及两类视图切换；P17.3加入真实构建完成、阶段预览、发布和离线验收。预览保持按需读取，避免轮询重复解码几何。

## 8. 执行结论

2026-11-05 三小批均已实现并验收：252项后端、38项预览前端校验、35项P16打包兼容、165项浏览器、7项离线汇总及编译通过；19项阶段专项复测与后端重叠不重复累计。真实 OS1 资料→封存批次→模型冻结→独立双视图→核对发布→下载→三个禁网消费进程通过；RGB-D／ROS真实构建回归通过。

已验证：某路视图运行／失败／中断不阻止完成阶段读取；预览不 poll；旧响应不落图；轮询保留画布；旧能力不请求；无GPU保留业务；跨场景与查看者拒绝；实际重启805个索引文件摘要不变。原源及历史成果保持，浏览器ZIP与P16逐字节一致，显示抽样不参与构建。页面状态注入仅作UI稳定性测试，真实阶段与worker另有独立验收。
