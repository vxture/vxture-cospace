# 数据与本体最小工作面设计 v0.1

日期：2026-10-26。已完成首批只读实现，见[验证记录](../validation/数据与本体核对验证-2026-10-26.md)及[投影契约](../../contracts/schemas/release-inspection-v0.1.md)。以下保留设计边界；接口提案已按该契约落地，受控导入等后续项尚未实现。

## 目标与落位

内部交付工程师从已选固定发布追到已登记来源、本体类型和对象约束，识别缺失与不一致。服务负责组织读取，data负责资料完整性和引用校验，ontology负责类型、属性和实例规则；工作台负责呈现，不成为第二套资料库或本体定义源。

本轮沿用packages/data、packages/ontology、packages/service与apps/workbench。独立部署平台待实际容量、权限和协作需求确定，当前不拆成额外进程。spatial保持空间模型职责；agent和human仍是派生消费表达。

## 固定发布核对页面

| 工作面 | 首批内容 | 边界 |
|---|---|---|
| 数据管理 | 逻辑路径、资料角色、字节数、SHA256、登记/校验时点、合成标记、缺失情况 | 仅列已登记清单；不将原始输入缺失当作已采集 |
| 语义本体 | 本体ID与版本、类型ID、属性约束、对象ID、类型引用和实例校验结论 | 当前小型规则包；无自动推断或行业本体兼容承诺 |
| 对象关联 | 对象锚点、空间坐标系、所属固定真值版本、已有证据引用 | 没有关联证据则显式为空，不补造归属或外形 |

状态分开表达：结构/引用校验通过、资料使用条件待确认、真实质量未验证。不能用一个“通过”覆盖许可、现场质量和产品适用性。

## 接口提案

拟增加GET /scenes/{scene_id}/releases/{release_id}/data和/ontology，统一返回scene_id、release_id、truth_version_id、package_sha256及data_kind。界面要求与所选固定发布逐项一致；响应不能携带宿主绝对路径、数据库凭据或任意文件访问能力。

data.items使用逻辑路径和规范角色，展示登记时声明与登记校验结果，明确observed_at或registered_at；无法确定时返回缺失，不用本次读取时刻冒充校验时刻。原始包清单与本体内容目前未全部进入持久快照，下一实现需保存已校验原文与其引用信息，不能回读可变源目录冒充历史快照。

ontology响应带规范包定义及实例校验摘要。已通过的实例结论必须可由固定规则和对象快照重新计算；错误定位到对象及字段。不允许只展示缓存的“passed”标签而失去对应规则版本。

旧快照缺少新增内容时返回明确的capability_unavailable类错误；不覆盖已有发布。使用新发布ID登记扩展快照，保留旧版本追溯。模式版本及兼容测试在编码前一并落入契约。

当前合成服务撤回按整包保守门禁处理：上述内容读取也在事务中检查撤回，410后清除当前工作面内容。元数据历史追溯保留；下一阶段再审定独立能力撤回和审计授权，不在界面自行绕开门禁。

## 验证与后续顺序

1. 固定清单与本体进入持久快照，验证摘要绑定、深拷贝和旧快照行为。
2. 同源只读接口及工作台页面；切换发布清空旧内容，404/409/410/503不展示为合格或空白资料。
3. 合成包验证篡改文件、未知类型、缺失必填属性及撤回后读取失败。
4. 浏览器核对同一发布的资料、本体、对象与空间视图引用一致。
5. 在此基础上设计受控导入、任务记录和构建产物登记；真实数据使用条件、传感和独立校核继续按P1准备。

本增量的验收是“可核对固定发布的数据和语义来源”。文件上传、在线本体编辑、任务调度、多人协作、生产权限与真实构建放到后续逐步实现。
