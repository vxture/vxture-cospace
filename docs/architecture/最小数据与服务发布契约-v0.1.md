# 最小数据与服务发布契约

版本：v0.1\
日期：2026-10-26\
状态：P2实现输入草案，尚未实现服务或通过消费验证\
依据：[总体模型](真值与两类视图总体模型设计-v0.1.md)、[首版验收矩阵](首版用途与验收矩阵-v0.1.md)

## 1 本轮范围

将“真值＋两套派生视图，即是服务”落实为可检查的清单关系。先约束身份、坐标、来源、质量和版本，不提前确定点云编码、空间索引、数据库或网络协议。下列字段是逻辑契约，后续JSON Schema与接口实现需以样例验证后固化。

首个样例采用普通设备间及相连走廊的合成空间，用于验证引用、发布和查询行为。样例全链路标记`synthetic`，不能进入真实场景的正式发布通道，也不构成精度或重定位能力证明。

## 2 共用约束

| 内容 | 最小约束 |
|---|---|
| 契约版本 | `schema_version`明确解释规则；不支持的版本拒绝处理 |
| 身份 | `scene_id`标识场景；每类版本ID在场景内唯一，正式引用同时携带场景ID |
| 时间 | 采用带时区的时间；区分观测、构建、校核与发布时间，不以文件修改时间替代 |
| 数据来源 | `data_kind`区分真实采集与合成样例；派生必须沿用来源类别 |
| 内容校验 | 被引用文件含相对路径、字节数、媒体类型及SHA256；路径限定在交付包内，不允许越界读取 |
| 缺失信息 | 待定用显式状态及原因表达，不用0、空字符串或任意默认值伪装已知 |
| 不可变性 | 正式版本的清单和内容不覆盖；内容变化生成新版本 |
| 引用 | 正式依赖固定版本及清单摘要；不能使用latest或构建工作目录作为依赖 |

摘要用于确认内容一致，不等于来源可信或质量通过。观测证据可独立存储及受限访问，清单须能追溯其身份、保留状态与检查结论，不要求将全部原始日志随视图交付。

## 3 坐标契约

每个真值版本引用一个固定的坐标定义，至少给出`frame_id`、米制长度、右手系、X/Y/Z轴向及原点说明。首个合成样例使用X沿走廊、Y向左、Z向上；真实工程坐标另行确认，不能直接套用样例。

变换统一用`T_target_source`表示将source坐标映射到target坐标，列向量约定为`p_target = T_target_source · p_source`。发布变换时声明源、目标坐标系、4×4矩阵及适用范围；旋转须为有效刚体旋转。没有外部基准时不输出伪造的地理坐标。

首个样例中两类视图均直接使用真值坐标。未来采用局部坐标或分块原点时，必须提供到真值坐标的确定变换。坐标定义不匹配属于契约错误，不通过临时平移对齐静默修正。

## 4 三类版本清单

### 4.1 真值清单

| 逻辑字段 | 含义 |
|---|---|
| `truth_version_id` | 该场景内不可变真值版本身份 |
| `parent_truth_version_id` | 可选父版本；初版显式为空 |
| `frame`、`target_scope` | 坐标定义与验收目标范围；范围不能仅由已有几何反推 |
| `geometry`、`coverage`、`objects` | 权威几何、覆盖证据表达与空间对象的固定内容引用 |
| `ontology_ref` | 含语义实例时必需：固定本体包身份、版本及摘要；离线交付包含解释所需快照 |
| `quality` | 质量声明、评估范围、允许用途、限制和未决项 |
| `provenance` | 原始观测、实现、配置、构建及独立校核记录的固定引用 |
| `adoption_record` | 采用对象的摘要、审核结论及责任记录 |

构建候选具有独立身份；缺必要校核或审核时保留为候选，不能通过改文件名成为正式真值。合成样例单独记录样例检查结论，不伪造现场独立校核或人员签署。

空间对象至少包含稳定`object_id`、类型、几何锚定、确认状态和可选外部资产引用。对象身份不同于版本身份；对象的修改需随新真值版本发布。

对象类型引用固定本体内的稳定类型ID，不用显示名称充当身份。资料清单与本体包规范在后续契约增量中补齐，见[数据管理与语义本体平台规划](数据管理与语义本体平台规划-v0.1.md)；不能由目录登记成功推断真值或语义校验通过。

### 4.2 视图实例清单

| 逻辑字段 | 含义 |
|---|---|
| `view_version_id`、`view_kind` | 实例版本身份；种类为human或machine |
| `source_truth` | 场景、真值版本及真值清单摘要 |
| `derivation` | 派生实现、配置及可选能力模型和规则的固定引用 |
| `frame`、`scope` | 坐标解释、空间范围及分辨率等表达条件 |
| `artifacts` | 可读取产物及其校验信息 |
| `capabilities`、`limitations` | 已验证能力及表达损失；存在文件不代表该能力可声明 |
| `validation` | 与来源一致性、表达损失及消费检查的记录 |

机器视图的空间查询与重定位能力分别声明。即使空间查询验证通过，未做独立序列试验也不能声明重定位已验证。人视图的浏览与量测能力同样分开。

### 4.3 服务发布清单

| 逻辑字段 | 含义 |
|---|---|
| `release_id` | 一次不可变发布组合身份 |
| `source_truth` | 一个固定真值及其清单摘要 |
| `views` | 固定视图实例及摘要；所有实例必须引用同一真值 |
| `capabilities` | 本发布实际提供的用途、范围、视图与限制 |
| `readiness_record` | 引用、内容、坐标、来源类别及能力检查结论 |

完整产品样例至少包含一个人视图和一个机器视图。部分能力发布须明确其范围，不能因为凑齐两份文件就声称两类视图均具备全部产品能力。

## 5 发布、有效性与读取

发布前校验所有固定引用、摘要、空间与坐标关系、来源类别及所声明能力的验证记录。拒绝悬空引用、混用真值、合成与真实来源混入，以及未验证能力被标记为就绪。发布检查由受控流程执行，不能仅相信提交清单内的`passed`字段。

当前发布指针与版本内容分开存储。切换先完整校验新发布，再以预期旧指针为条件原子更新；竞争写入返回冲突。失败时保留原指针，不留下半套可读取组合。

读取方首次解析当前指针后，获得固定`release_id`及清单摘要；后续查询、分页与产物读取均携带该身份。一次读取会话不能因当前指针改变而隐式换版本。服务回应始终携带场景、发布、真值及相关视图身份。

限制与撤回采用追加记录，引用被影响版本、能力、范围、原因和生效时间。服务每次能力调用检查当前有效性；固定历史版本不自动绕过撤回。追溯接口可返回历史清单及后续限制，不能将历史可查等同仍可消费。回退发布也必须重新检查其当前有效性。

## 6 最小查询语义

首个样例实现发布清单解析、对象身份查询和有限范围的空间状态查询；人视图先提供可读取几何与质量图层的固定引用。HTTP路径、分页编码和几何文件格式在实现增量中确定，不在本轮引入微服务边界。

空间查询请求显式给出场景、发布版本、坐标系及位置或范围。状态区分occupied、observed_free与unknown；unknown带未观测、冲突或退化等原因。只有具备观测依据才能返回observed_free，不能以无点或文件缺块推断空闲。

目标范围外单独返回out_of_scope；数据损坏、未授权、版本不支持、引用缺失及能力被撤回返回服务错误。对存在且可用的版本，目标对象不存在可返回not_found；不能把依赖丢失误报为对象不存在。批量查询出现局部失败时明确每项结果及整体完整性，不填充默认空闲。

## 7 下一个可运行增量与验收

| 样例 | 应有结果 |
|---|---|
| 同一合成真值派生两类视图，完整清单发布 | 可解析固定组合与对象、坐标、质量引用 |
| 机器视图引用另一真值 | 发布拒绝并定位冲突引用 |
| 产物字节改变但摘要未更新 | 发布或读取校验失败，不返回空间状态 |
| 当前指针在两次分页之间切换 | 已固定发布的读取保持同一组合 |
| 同一区域分别提供空闲、占据和未观测证据 | 查询保持三态，不把未知降为可通行 |
| 撤回当前版本的某项能力 | 后续能力调用拒绝，历史内容与撤回原因仍可追溯 |
| 未验证的重定位能力或合成成果进入正式通道 | 发布拒绝，并说明所缺验证或来源条件 |

先形成可运行的本地清单校验器、合成包及查询样例，再决定存储与接口实现。该增量验证模型约束，不关闭P1算法可行性、P3真实构建或P4实际消费的验收项。
