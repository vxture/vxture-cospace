# 本体模块宿主集成 B09e

当前仅维护 CoSpace 内的正式本体工作台。独立性由内核、公共界面组件、明确契约和可注入适配器保证。

## 调用与数据归属

```text
CoSpace 本体页面 → CoSpace 业务 API → 宿主适配器 → DefinitionWorkbench / DefinitionAuthoring
空间关联与服务交付 → 固定本体引用及依赖闭包
```

`packages/service/ontology_definition_workbench.py` 绑定平台验证后的身份、工作区作用域和授权策略，注入 `SQLiteAuthoringPort`。界面通过 CoSpace 业务 API 读取和操作，用户使用原平台登录。

`@vxture/ontology-ui` 继续接收调用方注入的客户端，不导入平台路由、身份、地图或场景。查看、编辑、审批及发布沿用 CoSpace 的业务流程，系统分组仍在配置管理中。

| 数据 | 归属 |
| --- | --- |
| 定义草稿、送审、审批、固定发布和依赖 | 同一个 CoSpace 宿主管理的本体存储。 |
| 目录归组和顺序 | 原目录与系统配置存储。 |
| 场景实例、属性值、现场依据、几何和采用修订 | CoSpace 消费侧。 |
| 身份与权限 | 平台登录及 CoSpace 服务端授权；不新增本体账号。 |

不新增第二份定义库或同步机制。版本升级由消费方显式选择，已有发布保持原来的精确版本与摘要。

## 导航与流程约束

沿用已确认的[业务与配置边界及导航框架](语义本体业务与配置边界及导航框架-v0.1.md)。正式入口是「公共资源 → 语义本体」，当前侧栏为「本体资源 → 全部本体 / 通用核心 / 领域本体」。资源分组及本体条目在内容区组织，分组配置归 CoSpace 配置管理。业务记录导航须等对应查询能力具备后再开放。

查看、编辑、校验、送审、审批和发布属于所选本体的对象操作，不得变成全局菜单或第二套分类导航。模块解耦、宿主替换或新批次规划均须继承此约束，不能因为更换外壳重新设计信息架构。

导航数据与资源链接统一定义于 `ontology-navigation-contract.ts`，桌面侧栏与移动端抽屉使用同一份数据。前端回归检查资源入口、详情链接的资源范围及对象编制工作面的挂载位置；验收还须检查实际页面，功能流程通过不能代替导航验收。

## 保留与撤下

保留 `kernel` 的纯定义、实例校验、版本编制和交换能力，公共 UI，以及 `vxture_ontology.adapters` 中按需注入的持久化实现。wheel 和文件 CLI 是模块分发、离线校验与隔离验证工具，不构成独立平台。

撤下独立浏览器应用、本机令牌/HTTP 服务、专属 UI 构建与发行包，以及依赖这套外壳的验收脚本。包级验收直接注入存储，验证草稿、独立审批、发布、持久化及旧版本读取；CoSpace HTTP 回归验证真实业务入口。

## 兼容与回退

CoSpace 的 `ontology-authoring.sqlite3`、`ontology-group-configuration.sqlite3`、目录及场景实例文件名和表结构不变，不需要数据迁移。CoSpace 原来的适配器导入路径继续可用，内部实现移至 `kernel/adapters`。

原本机独立演示的 `ontology-host.sqlite3` 属于合成验收数据，不自动导入 CoSpace，不覆盖业务数据。旧演示文件可保留供核对，但不作为当前入口或发行物继续维护。

代码回退使用正常版本回退流程；由于 CoSpace 数据格式未改变，无需反向数据迁移。生产发布仍按 GitHub 检查、镜像构建和 production 人工审批执行。

只有出现第二个实际产品或独立交付需求，才重新评估服务化和身份适配；它们不是当前必做后续批次。
