# 园区供配电语义 B08a

2026-11-24。首批交付供配电 `electrical@0.2.0` 预置草案、一个制造园区合成样例和定义审批至固定交付的回归。供配电定义面向各类园区；场景设备编号、坐标、铭牌和单线图记录归场景实例持有。本批不改变通用核心、其他领域模块、导航、权限或交付格式。

| 要回答的问题 | 定义与约束 | 验收反例 |
| --- | --- | --- |
| 对象是什么，铭牌额定值是什么？ | 电气设备是物理对象，细分配电柜、配电变压器、用电设备。额定电压用 V、额定电流用 A；规格未知时留空，有值要同时保留量纲和录入依据。 | kV 原样写入 V 字段、负额定值、把实时量测填作额定值；前两项由契约校验，第三项由专业人员判断。 |
| 哪个端口归哪台设备，哪些端口资料显示已接线？ | 设备到端口的归属有方向；接线仅在两个端口之间，可双向读取其含义。端口身份可独立于空间点锚。 | 配电房不能充当端口；端口归属和设备邻近均不能推出接线。 |
| 哪台设备按资料直接馈供到哪里？ | `documented_feed` 从变压器或配电柜指向配电柜或用电设备；明确依据、方向和有效期。只交付显式映射的原始关系。 | 用电设备不能仅凭反转记录成为供电端；邻近、同属系统或端口接线不自动生成馈供声明。 |

行业对照采用 buildingSMART IFC 4.3 分支的固定资料：[IfcDistributionPort](https://github.com/buildingSMART/IFC4.3.x-development/blob/0f1c7acb287740d7d40e2d0021c216a9cdf638ab/docs/schemas/shared/IfcSharedBldgServiceElements/Entities/IfcDistributionPort.md)、[IfcRelConnectsPorts](https://github.com/buildingSMART/IFC4.3.x-development/blob/0f1c7acb287740d7d40e2d0021c216a9cdf638ab/docs/schemas/core/IfcProductExtension/Entities/IfcRelConnectsPorts.md)、[IfcTransformer](https://github.com/buildingSMART/IFC4.3.x-development/blob/0f1c7acb287740d7d40e2d0021c216a9cdf638ab/docs/schemas/domain/IfcElectricalDomain/Entities/IfcTransformer.md)。借鉴设备、端口和连接分开表达；现有 IFC 导入不自动生成本批语义，亦不宣称 IFC 等价或电气规范符合性。

旧 `supplies` 定义保持原义和端点；新增关系使用不同标识。新增铭牌属性都是可选，不为缺资料对象填默认值。已发布的 0.1.0、其场景关联及交付闭包保持固定。在无发布记录的工作区可从预置草案编制；已有发布记录时可用独立内核命令 `python -m packages.ontology.kernel --module electrical` 导出 0.2.0 与核心闭包，与最新工作区发布对比，保留现场扩展并核对版本和固定依赖，再通过现有编制保存接口提交新草稿。不得以预置覆盖现有工作区的草案或发布。采用前仍须发布精确的核心依赖，由不同人员提交与审批，再为目标候选显式选择固定版本。

本批以现有校验器检查必需属性、数值下限、V/A 与量纲、关系方向和端点、有效期与依据记录。端口唯一归属、回路重复或闭环、标准适用性仍需专业审核或独立规则；不推断当前带电、实时负荷、保护定值或停电影响。线上若采用，须先取得可追溯的项目资料和专业人员确认；本次测试审批仅验证流程。

一次只推进一个领域。B08b 消防，B08c 给排水，B08d 环境与运维分开验收，随后按专业资料充足程度确定发布范围。跨领域验证仍复用三类园区基线；B09 独立产品化不纳入本批。
