# 开源算法对照验证方案

版本：v0.1\
日期：2026-10-26\
状态：P1试验方案草案，已实现输入预检工具，尚未完成运行验证或执行算法

## 1 验证目标与结论边界

依据[首版用途与验收矩阵](首版用途与验收矩阵-v0.1.md)及[数据采集与独立校核需求](数据采集与独立校核需求-v0.1.md)，比较能够支持设备间及相连走廊的开源构建路线，识别输入、质量、资源、授权和集成风险。

首轮结论应回答：哪条路线在什么数据条件下可以产生可校核几何，哪些能力还需回环、配准或覆盖表达补充，以及这些成果是否可派生机器重定位参照。算法能出图不等于真值成立，也不等于服务可用。

本方案列出候选及核验步骤。第一轮核验结果见[算法数据与运行环境核验记录](算法数据与运行环境核验记录-2026-10-26.md)，已保存两主仓库固定提交的说明、LICENSE及依赖声明，完整传递依赖和实际分发条件仍需审查。尚未部署算法或取得测试结果。

## 2 候选与比较层次

| 候选线索 | 在本轮中的角色 | 需要核验的关键前提 |
|---|---|---|
| FAST-LIO2相关实现 | 激光惯性轨迹与局部几何候选 | 具体仓库、支持雷达、点时间、外参、初始化、回环是否由额外组件承担 |
| LIO-SAM相关实现 | 带后端优化的建图候选 | 具体仓库、IMU前提、扫描结构与字段、初始化、回环配置与依赖 |
| Point-LIO相关实现 | 条件替补候选 | 输入适配、时钟、计算开销、已有两路线是否暴露必要替补需求 |
| Open3D、PCL等 | 离线对照与配准工具候选 | 具体操作、参数、许可及依赖，不将同名库当作完整建图路线 |

优先核验FAST-LIO2与LIO-SAM两条线索。若资料无法满足两者前提，不虚构ring、逐点时间或IMU观测使其“公平对比”；先记录不兼容，再选择适合资料的替补或另组数据。

对照分两层：第一层比较算法原生输出；第二层比较满足首版产物要求的完整路线。可以给不同算法补充必要后处理，但必须分别记录组件、计算量及结果，不能把有回环与无回环差异隐藏为同一功能。

首轮最多维持两条主路线，遇到输入不适配、授权不可接受或质量明显不满足时按证据替换，避免同时集成大量候选。

## 3 技术与授权预检

### 3.1 仓库核验

每条候选记录官方来源、提交摘要、维护状态、构建说明、输入要求、输出坐标、算法及数据限制。直接依赖、传递依赖、示例数据和可选模块分别登记。

许可证检查至少覆盖商业使用、修改、分发、源代码义务、版权及NOTICE、依赖组合、专利或附加条件、再授权及客户交付方式。首批内部服务使用与后续向机器人厂商分发软件的路径分别评估。

审查结论分为证据已核验、需进一步解释、当前分发路径不接受。未取得许可证据的组件不进入对外交付基线。独立进程、容器或动态链接均不自动消除许可义务。

### 3.2 输入适配核验

以一份短日志检查解码、单位、轴向、IMU重力约定、逐点时间、采样间隔、同步和外参。适配转换保存原始来源和参数，不能为了让算法运行而推测未知数据。

适配结果分别标记原生支持、可解释转换、缺必要字段或未验证。输入不合格先解决采集或选型，不用后处理改善画面掩盖。

## 4 对照试验步骤

| 编号 | 试验 | 执行与记录 | 完成依据 |
|---|---|---|---|
| E01 | 输入及运行预检 | 同一短序列、指定环境、固定代码和参数，记录初始化与日志 | 两路线分别明确可运行或不适配的原因 |
| E02 | 原生输出对照 | 固定开发集，记录轨迹、几何、失败区、耗时与资源 | 产物可解释，不能只提交截图 |
| E03 | 完整构建路线对照 | 加入各自必要的回环、配准和后处理，分别登记依赖与成本 | 独立几何检查、接缝和全局漂移结果可比较 |
| E04 | 重复及失败条件 | 独立轮次或重复执行，检查普通走廊、遮挡、短时丢帧等适用因素 | 稳定性和错误可检出，明确数据缺失与算法失败区别 |
| E05 | 机器消费预验证 | 用冻结参照及独立序列运行选定定位实现 | 查询和定位可评估，失败时区分构建、表达及定位问题 |
| E06 | 保留集与真实场景复核 | 冻结参数后检查保留序列及独立参考 | 支持或否定首版条件内的技术路线，指出剩余验证项 |

只有公共数据时，E03至E06按现有参考和序列能支持的范围执行，不给出真实现场达标结论。真实独立资料到位后补测。

## 5 比较方法与指标

| 方面 | 对照指标 | 解释限制 |
|---|---|---|
| 轨迹 | 初始化、有效时段、参考位置姿态误差、漂移与重定位失败 | 标明有无参考、对齐方式、是否优化尺度和使用了哪些点 |
| 几何 | 独立检查点、已知尺寸、重复结构错配、接缝及局部形变 | 配准残差低不能单独证明绝对正确 |
| 覆盖 | 目标区域及对象的观测、未知和遮挡情况 | 点数多或模型表面连续不代表覆盖完整 |
| 质量诊断 | 是否报告退化、异常、初始化失败与输入问题 | 算法原生分数不跨路线直接比较 |
| 运行资源 | 总耗时、数据时长、CPU、GPU及内存峰值 | 同硬件及并发条件，离线与实时目标分开 |
| 重复性 | 重复运行数值差异与独立采集结果 | 同日志复跑与重新采集的重复性分开 |
| 集成成本 | 输入适配、可维护性、后处理与依赖复杂度 | 不能只以帧率排序 |
| 消费效果 | 机器视图派生损失、局部读取及独立定位表现 | 定位实现固定或明确差异，不归因于单一建图算法 |

精度和定位阈值由用途确定，正式测试前冻结；尚未确定时报告观测值及其条件，不给“通过”结论。几何评估中的坐标对齐只使用指定控制点，不能用全部独立检查点拟合后评估自身误差。

不同路线输出密度、坐标或后端能力不同，先声明可比对象。必要的降采样和对齐统一记录；处理前后结果均保留，避免通过评估预处理抹平算法差异。

## 6 构建与重定位分开选型

建图路线输出真值候选，定位路线消费机器视图，两者并不要求使用同一算法。首轮可评估明确初始范围的scan-to-map方案；具体实现和许可证需单独审查。

定位试验固定真值、视图、实现、参数及初始化条件，使用独立序列和参考，记录位置姿态误差、收敛、错误接受及资源。没有可靠参考时仅报告辅助现象，不凭匹配残差宣称定位准确。

如果某路线需要专用关键帧或特征，判断其是否应属于机器视图的可选派生成果。不能让正式服务隐式依赖构建工作目录或未归档的算法内部状态。

## 7 输出与选型判定

每次试验保留输入资料登记、实现摘要、参数、运行环境、命令或脚本、输出清单、诊断与评估结果。结果可复跑，允许数值非确定性但应说明其影响。

| 结论 | 判定依据 | 后续处理 |
|---|---|---|
| 暂定主路线 | 已有证据支持当前用途，输入及许可路径可解释 | 接入P3，继续真实场景和消费复核 |
| 备选路线 | 条件可满足，但有待解决风险或当前成本较高 | 保留可复跑试验，不同时建设全部产品集成 |
| 暂缓或排除 | 输入不适配、许可路径不可接受、关键质量失败 | 记录事实和重审条件 |
| 证据不足 | 缺真实资料、独立基准或测试条件 | 列出待补资料，不转述成达标 |

最终选型不以单一分数决定。必要条件先过关，再比较质量、消费效果、成本与维护风险。首版候选实现及传递依赖在正式分发前重新核验。

## 8 第一批执行清单

1. 核验两个主候选的官方仓库、输入前提和许可证据。
2. 核验公共数据候选，选择一份与候选路线相容的短序列。
3. 用试验资料登记模板形成首份真实记录，不能保留未经说明的关键空值。
4. 确认可用Linux运行环境和资源，编制最小复跑脚本后执行E01。
5. 按结果安排E02及必要替补，再请求对应真实采集和独立校核资料。

已完成第一轮官方资料和本机环境核验，保存说明与许可快照；尚未下载算法源码或原始日志、部署算法环境、安装依赖或执行评测。后续以核验记录中的依赖和数据条件为当前状态。
