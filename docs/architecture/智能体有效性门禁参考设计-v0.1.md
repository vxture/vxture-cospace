# 智能体有效性门禁参考设计

日期：2026-10-27。状态：R2b首批合成实验，位于experiments/scripts/validity_probe.py；不是正式信任链或机器人授权。

第二批已增加[测试委托与故障门禁补充](智能体密钥委托与故障门禁补充-v0.1.md)，下述首批故障和并发限制以该补充为准；真实授权边界不变。

依据：[可信分发总体设计](智能体可信分发与离线有效性设计-v0.1.md)。本轮不修改R0/R1默认CLI、安装或激活接口，新增GuardedSession仅作为显式实验封装，不能声称原R1会话自动获得门禁。

## 状态及原子性

ValidityStore使用独立validity-test.sqlite3，显式bootstrap只创建新文件，不覆盖已有状态；常规打开使用mode=rw，缺库或坏库不重建。测试公钥及Policy摘要绑定初始化上下文，配置变化拒绝；第二批支持外部加载单层测试根委托，尚无信任版本升级或设备恢复协议。

状态键为部署、场景、包摘要，完整binding另行固定。保存内容证明、最新状态JWS、绑定的grant及累积撤回能力集合。每次写入先通过R2a原始字节验签及角色/来源/受众核对，再用BEGIN IMMEDIATE事务比较序号。同序号同payload摘要幂等，不刷新期限；同序号不同摘要拒绝，低序号拒绝。epoch必须等于显式测试Policy配置，不允许消息自行换代。

更高状态清除旧grant，新的grant必须匹配状态payload原字节摘要、epoch/sequence及Policy摘要；修改旧grant延长时限要求先新状态。撤回集合持久保留，即使后续快照省略该能力也不能重新放行；显式重新allowed会被拒绝。

数据库提交前异常不返回已接受。第二批在验签后、事务前写入并fsync未确认写入标记，正常提交后删除本次标记；遗留标记使其他对象及重新打开对象返回storage_error。尚无解除接口；标记创建前写入即失败时仅当前对象锁存，物理断电及恶意回滚未防护。细节见第二批补充。

## 合成时间接口

IntervalClock接收测试时间锚(boot、counter、UTC earliest/latest)和计数回调，不从普通墙钟推断可信UTC。计数回退或boot变化后本对象永久unknown，需新的受控时间锚。新对象无锚也unknown。计数包含休眠且速率误差可控是调用方假设，本轮未验证Windows真实时钟或建立网络nonce时间锚。

判定取grant、状态、测试密钥有效期及离线限制的最严格交集，离线截止从已签status.issued_at起算。nbf可包含，exp到达即拒绝；时间区间跨边界返回unknown。同消息重传、安装和重开会话不延长期限。Policy中的示例秒数仅用于测试，不是产品默认。

## 查询门禁

每次判定重新读取数据库快照并验签已保存消息；检查内容存在、能力状态、撤回、grant绑定及时间条件。缺状态或可信时间返回unknown；expired/revoked不伪装为空间unknown。成功只返回simulated_allowed=true，仍固定authorized=false和robot_ready=false。

GuardedSession从实际R1文件后端读取活动包及快照，核对完整binding后打开；每次query重新调用门禁。内容版本保持固定，最新撤回仍影响旧会话。结果带状态序号、时间区间及deadline，查询失败不返回空间值。

并发顺序边界是数据库状态快照读取。撤回提交之后开始的新判定不可使用旧状态；已读取旧快照的在途查询可能随后返回，无法追回。第二批已用双线程、独立连接与屏障验证该交错，尚无跨进程查询屏障或动作执行门禁，不提升为全部SS-02通过。
