# 固定复核缺项报告 v0.1

## 用途与边界

`assess_review_gaps` 将同一固定复核快照中的待办按 SG3、SG4、SG5 组织，回答“资料填到了哪里、还缺什么输入”。它不是新的验收流程，也不是正式发布准入凭证。调用方必须先授权场景、来源、本体与本地证据目录；本轮不新增 HTTP 接口或改变生产发布。

先用既有检查器完整核对快照、来源固定值、设计包全部成员、标注引用及本体提案，再生成诊断。损坏资料拒绝，不当作“待补充”。报告含快照、设计包、结构、坐标系及来源摘要，`report_sha256` 是去掉该字段后整个报告的规范 JSON 摘要。相同字节与相同证据检查结果可复现；不加入运行时钟或绝对路径。

## 三批如何使用

| 批次 | 可直接继续处理的输入缺口 | 报告不能核定的内容 |
|---|---|---|
| SG3 | 区域数量；逐门缺失的 side_a / side_b；逐楼梯缺失的 lower / upper；连接证据引用是否为空；未用于端点的区域；证据内容状态 | 点云单位及真实对齐、现场区域覆盖、真实连接、资产身份 |
| SG4 | 未提供映射或仅有类型提案；逐来源实体的未映射编号；提案数量 | 事实采用、本体实例采用、授权发布、生产性能与失败验收 |
| SG5 | 同一固定来源声明的门编号，可交给既有观测上下文查询 | 厂家身份、来源时钟/证据、真实上报、真实变化及局部更新验收 |

连接的 `annotation_complete` 沿用现有标注校验结果，仅指两个合法端点及证据引用齐备，不证明端点落在真实门口。未关联连接的区域不等于不连通；未映射来源实体不等于每个都必须增加本体类型。区域数量大于零也不证明覆盖完整。零门、零连接不作为整批验收通过条件。

SG5 明确输出 `observations_not_assessed`：本报告不访问日志，不根据静态资料判断在线、开门或异常，也不把缺少观测理解为门关闭。需要报告状态时继续使用固定快照观测上下文读取，分别保留其时间、序号及游标。

`not_established_by_snapshot` 描述本契约无法建立的事实，不宣称这些事实在系统其他位置不存在，也不要求永久阻塞后续候选开发。正式采用和发布需要各自的授权、事实核验与验收记录；不能通过传入布尔值改变本报告结论。

## 证据检查

- 无引用：`no_references`，不因传入空证据目录产生“已核对”。
- 有引用、未传可信目录：`references_only`。
- 有引用及可信目录：核对全部引用，包括未使用证据的实际字节，输出 `bytes_checked` 及绑定快照摘要的既有核对回执。
- 文件缺失、摘要错误、链接或预算超限：整个请求失败，不输出部分成功报告。

`used_evidence_ids` 与 `unused_evidence_ids` 便于清理复核输入。字节正确不等于现场含义正确；原 IFC 不能借此成为当前门状态的证据。回执不保证后续留存、来源身份或恶意并发下的文件快照隔离。

## 命令行

```powershell
.venv/Scripts/python.exe -m experiments.scripts.ifc_review_gaps `
  --snapshot output/review.json --snapshot-sha256 <固定快照摘要> `
  --design-package output/design.bin --source output/source.json `
  --output output/gaps.json
```

映射快照须额外指定 `--ontology` 固定本体文件；可选 `--evidence-root` 由可信调用方指定，只读取 `<sha256>.bin`。命令独占创建输出，已有结果不覆盖。输出属于本地复核证据，不进入 Git。实现入口为 `packages/service/ifc_review_gaps.py`，不输出通行、路径或设备作业结论。
