# CoSpace 平台授权接入职责与实施记录

日期：2026-11-06。状态：本地代码收敛及完整回归已完成；未部署生产、未修改平台配置、未发布套餐。

依据：用户提供的[《产品接入通则》](https://claude.ai/artifact/54YtaMf3K7tPULZur29Vzf)，以及随后明确的本项目职责裁定：**席位、场景商业额度、存储容量等权益由平台决定；平台允许使用，产品就提供功能，不在产品另设数量门禁。** 本次裁定取代上一版计划中的本地数量限制方案。

## 1. 职责边界

| 事项 | 平台负责 | CoSpace 负责 |
| --- | --- | --- |
| 身份与 Workspace | 账户、组织、工作区、成员主数据及中央会话 | 验证身份并引用标识，按工作区隔离业务数据 |
| 订阅与权益 | 套餐、定价、下单、支付、续订、席位、容量、资源包和商业授权决定 | 读取平台授权结果并提供功能；用户点击后进入官网套餐页 |
| 业务数据权限 | 提供可信身份与工作区上下文 | 对具体场景、资料、构建和成果执行数据权限，防止跨空间访问 |
| 用量 | 统一资源规则与商业账本、扣减 | 按已发布接口报告自身真实业务事实；不复制钱包、不双计模型费用 |
| 技术运行 | 平台基础设施与公共接入 | 保留上传大小、磁盘、任务资源、并发和文件安全等技术保护 |
| 开通通知 | 开通关系真值、通知及对账接口 | 验签、幂等、拒绝倒序；对账使缓存失效，不凭通知自行授权场景 |

CoSpace 核心流程保持：Workspace → 场景空间 → 资料及历史版本 → 三维真值构建 → 双视图 → 发布与使用。一个具体场景一个场景空间。

## 2. 本地已实施

### 收回独立商业管理

- 删除 `ProductSeats`、`SeatChange` 和本地商业限额解析模块。
- 删除首次访问占席、释放／恢复席位、降配暂停业务的运行逻辑。
- 移除 `/api/product-seats` 的授权与处理入口，旧地址进入默认拒绝分支。
- 删除账户页席位管理组件及“查看成员席位”入口。
- 从场景创建流程删除 `scene.max` 数量比较及商业名额预留。创建幂等、工作区隔离、权限和异常恢复仍保留。
- 本地不再解析 -1、0 或缺失数量来建立另一套门禁；平台授权有效时均不因这些数量被本地拒绝。
- 上一轮未完成的独立存储准入代码已撤回，未引入本地容量钱包。

历史 `product-seats.sqlite3` 文件不再被业务读取或写入，保留既有审计数据与备份兼容性，不清空历史文件。删除实现不等于删除客户数据。

### 修正必要接入

- 订阅入口改为 `{COSPACE_WEBSITE_BASE_URL}/pricing?product=cospace`，默认官网为 `https://vxture.com`。不带 intent、workspace_id 或语言段，只由用户点击触发。
- C2 继续使用短期内存缓存和签名通知失效；没有权益持久副本，平台不可用时不绕过授权，保留用户中央会话。
- Webhook 仅要求通则规定的 `X-Vxture-Signature`。事件与投递身份取签名载荷，额外的未签名头不能决定事件身份。
- 接受四类通则事件，包含 `grant.invalidated`。保留 HMAC 原始字节验签、时间窗、重复签名头拒绝、投递幂等和 seq 处理。
- 新增 `ProvisioningTransport` 与 `ProvisioningReconciler`。专用 `provisioning:read` 换票不带用户、组织或工作区；仅分页读取本产品开通关系，不访问平台数据库。
- 正式服务组装在启动后扫描，并每 300 秒从第一页重新对账。失败后下一轮重试，401 最多刷新专用票一次；关停取消轮询。
- Webhook 与对账共用单调 seq。旧版本不覆盖新版本，pending 不是开通／撤销命令，缺行不代表删除，同 seq 冲突保留原状态并报告不可用。
- 仅持久化工作区／租户引用、开通状态与 seq，用于投递处理及缓存失效；它不是本地权益来源。对账不授予场景角色，不自动创建样例场景，不删除成果。

## 4. 后续边界

平台真实授权变化、开通通知及客户业务操作仍需部署后的联调证据；本地测试不等于生产验收。现有场景权限与来源配置属于业务数据访问管理，不是席位或容量管理。

真实存储占用上报和未来 AI 功能只按平台正式接口逐项接入，不增加本地收费、资源包、余额或成员管理。普通几何构建不伪造 AI 消耗，模型费用不重复上报。

三档仍是制单建议：全软件授权、成员 1／5／按合同、场景 3／10／按合同；容量、点数和价格待确认，由平台配置并发布。所有档位明确不包含地面采集处理工程。

平台生命周期：上线准备 → 发布已批准套餐 → 真实租户订阅并使用 → S2S／C2／C3 真实观测 → 转正式版。不以订阅验收阻塞套餐发布而形成循环前置。
