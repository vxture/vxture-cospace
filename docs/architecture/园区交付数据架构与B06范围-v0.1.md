# 园区交付数据架构与 B06 范围 v0.1

日期：2026-11-20。状态：设计草案，先于 B06 实现；不是已支持格式、成果类型或接口的承诺。生产 v0.11.0 已完成第二阶段空间关联消费，B06 尚未实施。

## 设计基准

系统级实体、身份/时间/版本、存储及服务边界见 [统一数据架构](空间态势服务统一数据架构-v0.1.md)。本文继续保留内容域及交付配置分析，B06实现以统一架构和责任边界共同约束。

产品责任优先遵循 [空间态势服务数据责任与交付边界](空间态势服务数据责任与交付边界-v0.1.md)。完整内容域用于架构分类；不属于本平台责任或尚无来源、未建设的能力不进入实际交付清单。机器人运行系统的数据需求不自动扩展本产品范围。

机器人消费需求另按定位、通行、避障、交通、任务与设施交互拆分，见 [行业对照与机器人数据需求](机器人消费数据需求与行业对照-v0.1.md)。B06 对象语义成果对应语义查询能力，不代表可导航或可执行任务；机器人自身能力与运行时观测不由静态交付包替代。

交付应由明确的数据成果及其依赖组成，而不是把运行数据库或整个场景目录压缩。先定义数据内容、空间图层、成果及交付契约，再实施固定实例消费。模型数据、本体定义、实例声明、业务事实、专业核实分别保留来源与状态。

本体的 L1 通用定义 / L2 行业场景定义 / L3 实例化继续成立；本文是宿主的数据架构，不重新划分本体层级，也不把数据目录、地图和交付引擎放入公共资源—语义本体。

## 三类概念

| 概念 | 含义 | 例子 |
| --- | --- | --- |
| 数据类型 | 内容的语义与结构；文件格式是另一个维度 | 点云、对象、关系、时序观测、规则、核验报告 |
| 数据图层 | 具有范围、空间参考、内容来源和展示/查询约定的可组合集合，可为栅格、矢量、三维表达或对象集合 | 建筑、设备、消防、管网、风险区域 |
| 数据成果 | 有身份、版本、范围、依赖、质量及不可变内容的可发布产物，可被在线或离线消费 | 某版园区设备图层、对象关系快照、巡检任务地图 |

图层不等于一个文件、导航分组或本体模块。一个图层可组合几何、对象、语义、业务观测；同一设备对象可在供配电与消防图层中出现而不复制成两个身份。纯定义、关系集和报告可以独立交付，不强迫它们成为地图图层。在线 API、瓦片服务、下载包是交付方式，不是新的基础事实。

## 数据内容域

| 内容域 | 数据类型与内容 | 固定依赖及边界 |
| --- | --- | --- |
| 来源与采集 | 点云、影像、RGB-D/LiDAR、IFC/BIM、CAD/GIS、台账导入、采集批次与许可 | 保留原始来源、采集时间、授权范围、处理血缘；不默认对外分发原始资料 |
| 空间基准与几何 | 坐标系、局部坐标框架、轴向、单位、高程基准、变换、覆盖范围；点/线/面/体、点云、网格、栅格 | 记录来源和精度；局部坐标合法交付，未经配准不承诺地理定位；不把某种存储格式当作唯一空间真值 |
| 对象与空间结构 | 园区、地块、道路、建筑、楼层、房间、设备、设施、区域的身份、几何引用与层次归属 | 对象身份与显示名称分离；跨模型/候选的同一对象须显式对照，当前不能只凭相同 object_id 猜测 |
| 语义定义 | L1/L2 概念、属性、关系、约束、规则、单位及固定依赖闭包 | 引用公共资源中已发布版本；固定模块身份、版本与摘要，依赖冲突不能择最新解决 |
| 实例与关系声明 | 对象的概念引用、显式类型值、有效期、空间/系统/连接/供给关系及依据 | 固定消费修订并绑定模型来源；区分声明与已核实事实；不自动将旧轻量类型规则升级为模块化定义 |
| 业务记录与观测 | 企业/资产/运维台账、工单、传感器时序、告警、业务绑定及外部标识 | 业务系统保留权威职责；可交付显式固定快照或有窗口的观测集，实时接入只描述接口能力，不将最新值混入旧版本 |
| 表达与计算 | 可视化点云/网格/瓦片、计算网格/占据或表面表达、索引、分区及专业分析派生成果 | 标明源成果、生成方法、分辨率、未知区及适用能力；表面观测不等于自由空间或可导航路线 |
| 证据、质量与血缘 | 模型点锚、人工依据、文档/照片引用、校验报告、专业审核、处理链、变更与验收依据 | 区分工程完整性、语义局部校验、专业审核、现场核实；依据引用不等于实际证据附件已交付 |

资产、道路、消防等是对象类别或业务主题，不应各自重新定义一套互不兼容的几何、身份、时间和版本体系。

## 图层组织

按用途提供预置图层模板；模板及图层目录由宿主维护，内容通过引用组合。后续可新建和编排，图层实例放在内容区清单，不增加按资源逐条堆积的导航。

| 图层类型 | 园区例子 | 主要内容 |
| --- | --- | --- |
| 参考底图与边界 | 园区边界、地块、地形、影像 | 空间参考、范围、底图数据或获准服务绑定 |
| 现状与设计表达 | 实景点云/网格、设计 BIM | 分别表达观测现状与设计意图，均携带时间和来源；不默认视作一致 |
| 空间结构 | 建筑、楼层、房间、道路、公共区域 | 对象层次与几何；层次关系不能仅由视觉重叠推断 |
| 设施与设备 | 电力、消防、给排水、暖通、环境设施 | 同一对象身份上的行业主题及显式实例属性 |
| 网络与拓扑 | 电气连接、供给链路、管网 | 有方向和端点的关系；拓扑连通与几何相交分开 |
| 运行与事件 | 设备状态、能耗、告警、工单、传感器 | 有效时刻或时间窗口，明确缓存和数据新鲜度；本期不新增实时系统 |
| 分析与任务 | 风险区、影响范围、巡检范围、任务地图 | 固定输入版本、规则/算法、时刻、结果边界与专业适用性 |

图层声明至少描述：图层身份/版本、数据内容类型、主题、对象或空间范围、坐标框架、时间范围、依赖成果、样式及查询能力、质量与访问分类。样式与数据分开版本化；样式变化不应改写对象事实。

## 成果与交付组织

建议采用“发布版本 → 成果目录 → 固定成果及依赖”的组织方式。同一发布可包含多个成果，同一不可变成果可被多个发布引用；交付包和在线接口消费同一成果清单。

| 成果类别 | 主要交付内容 | 当前与后续 |
| --- | --- | --- |
| 基础空间成果 | 指定范围的空间框架、几何及来源血缘 | 已有局部固定模型能力；统一地理成果归后续 |
| 对象语义成果 | 对象索引、固定实例修订、定义闭包、属性/关系、依据与校验范围 | B06 本批重点 |
| 专题图层成果 | 基于对象与语义组织的某个专业图层及其表达 | 数据架构预留，不在 B06 批量建设 |
| 计算与任务成果 | 计算表达、索引、分区、能力声明 | 沿用既有能力，不新增导航可行性承诺 |
| 业务或观测快照 | 某版台账绑定、限定时间窗口的状态/事件 | 仅沿用已有固定业务关联；新增实时/时序另排批次 |
| 质量与验收成果 | 工程校验、专业核查、现场验证及来源证明 | 按已发生的检查分别声明，未完成明确标识 |

交付方式可选：在线固定版本、离线完整包、分区/子集包、受控引用。完整包必须说明是相对哪个成果配置的完整；不能因为已有按钮名叫“完整交付”就声称包含原始数据、全部几何、实时数据或园区所有图层。

每个成果配置明确必需项、可选项、依赖闭包与能力。选入的成果缺失、不合法或依赖不满足时阻止该次采用；未选语义成果的旧发布仍按原合同成立。可选不等于读取失败后静默省略。

受控引用应声明是否随包携带、依赖外部系统、可离线读取及授权需求。若仅交付照片/报告引用而无内容，不得将证据附件标为完整。包内不放会话、令牌、密钥、运行数据库或宿主绝对路径；商业权益仍由平台负责，场景授权由宿主执行。

## 共同的版本与绑定元数据

成果与图层应分别具有：身份、schema/profile版本、内容修订/版本、场景与工作区范围、模型候选/模型摘要、对象命名空间与对照依据、坐标/单位/覆盖范围、有效时间与记录/生成时间、固定依赖、来源与处理参数、内容摘要/大小/媒体类型、校验结果及专业状态、访问分类、可离线性与缺失项。

schema版本、数据修订、发布版本和软件版本四者分开。记录时刻不能冒充有效时刻；交付时刻也不能使历史声明重新有效。多个内容域独立产生修订，但发布清单必须显式固定每一依赖，不能只有一个大版本号而隐含读取最新值。

内容摘要保障完整性，不自动授予访问权限。在线分发遵守现有暂停/退役/场景授权；已下载的合法副本不能靠在线暂停远程收回，交付政策须如实表达。

## 现状核对

现有 PreviewPublications 固定复制模型成员，模型可带 objects.json、旧轻量 ontology.json、business.json、relations.json。当前模块化本体消费另存在宿主 scene-ontology-links.sqlite3，发布尚未采用该修订；两种语义合同不能混同。

现有 preview_offline 完整包的基础成员为 publication.json、model.json、agent.npz 及 package.json，按模型声明增带旧语义/业务/关系成员。它不默认包含 spatial.npz、全部视觉表达、原始采集资料或真实园区全量成果。当前还有限定大小与数量，不因本设计而取消资源边界。

仓库另有 spatial-release 版本/质量检查合同，但不能直接等同正在运行的 preview publication；B06 需做兼容映射，不能借机无迁移替换全部发布体系。

## B06 的实施顺序与停止边界

1. B06a 数据合同：核对本设计，定义现有固定发布可选的对象语义成果配置、成员/元数据清单、版本绑定及缺失策略；明确现有对象、旧语义与新本体声明的职责。
2. B06b 固定采用：发布前显式选择消费修订，预检固定对象/定义闭包/属性/关系/依据及局部校验，冻结结果；拒绝最新值回退，幂等指纹包含所选修订及摘要。发布前复核候选与修订绑定。
3. B06c 同源消费：在线读取与离线包从相同发布成果读取；包内保存可验证的冻结定义/实例声明/模型与证据绑定。查询不再访问消费库最新修订或公共本体最新版本。旧发布不自动增补。
4. B06d 验收收口：覆盖升级/解除/修改后历史稳定、遗漏依赖/篡改阻断、授权和暂停/退役、包内外一致及回退兼容；独立安排上线审批。

B06 不新建原始数据仓库、统一 GIS 引擎、实时数据平台、全专业专题图库或分析引擎，不实现 B07 的地理配准。逻辑上预留各内容域，工程上只交付可选固定对象语义成果。实例采用条件为已定义的局部工程检查，专业核实缺失必须保留，不能将“允许交付该配置”解释为全园区专业验收通过。

实施入口沿用现有服务发布/离线交付；目录、图层编排与成果配置不塞进本体模块导航。当前仅形成此设计草案，尚未修改发布接口、交付包或 UI。
