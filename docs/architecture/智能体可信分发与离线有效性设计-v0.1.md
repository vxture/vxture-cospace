# 智能体可信分发与离线有效性设计

日期：2026-10-27。状态：R2设计草案，尚未实现签名、授权、同步或可信时间。现有R0/R1仍仅支持合成参考读取，robot_ready=false。

依据：[消费架构](智能体视图运行包与在线离线消费架构-v0.1.md)、[文件存储](智能体运行包文件存储与恢复设计-v0.1.md)、[决策](../decisions/ADR-004-智能体可信分发与离线有效性.md)。本设计使用已确认的FastAPI、独立文件存储和轻量SDK边界，不引入新的必需服务框架。

## 1 信任与责任

2026-10-27 R2b第四批形成[恢复日志协议](智能体恢复独占与提交日志协议-v0.1.md)和[ADR-005](../decisions/ADR-005-智能体恢复日志与维护独占.md)：后续独立v2保留完整消息、状态与receipt同事务、统一OS锁及代次防旧对象操作。本批仅结构核对通过，运行协议及旧库迁移未实施。

2026-10-27 R2b第二批新增[测试根委托与故障门禁补充](智能体密钥委托与故障门禁补充-v0.1.md)：单层测试委托、持久pending标记及线程双连接查询/撤回交错已验证。下一步只读故障核对和恢复条件设计；生产根轮换、可信时间和真实机器人授权仍未实现。以下首批进展保留为历史记录。

2026-10-27 R2b首批已验证[合成有效性门禁](智能体有效性门禁参考设计-v0.1.md)，包括持久状态序号、测试时间区间和旧会话撤回；未接入正式信任或原R1入口。设备时间、根委托、跨重启故障锁存与并发查询边界仍待验证。

2026-10-27 R2a首批已新增[合成测试证明契约](../../contracts/schemas/trust-proof-v0.1.md)及28项试验，见[验证](../validation/智能体测试证明验证-2026-10-27.md)。采用现有Node原生crypto作实验桥接；尚未选定生产密码库、实现根委托或实际有效性授权，以下仍是总体目标。

首版按“受信任设备操作系统、受控设备配置、外部介质和网络内容不可信”设计。防范文件替换、伪造来源、旧凭据重放、断点下载混包及误用过期能力。不宣称普通SQLite可以抵御设备管理员回滚整个磁盘；若设备需要抵御这一行为，必须补可信计数器、硬件或在线重新核验。

角色分离：离线根密钥管理设备信任策略；内容发布者签发包描述；有效性签发者依据受控发布及限制状态签发能力凭据；下载服务只传输固定字节；设备校验并执行使用限制。构建worker、前端和文件下载节点不持有效性签发私钥。签名说明来源与权限，不代替几何质量、独立定位或现场适用性验证。

初始信任根通过受控设备配置写入，不能从待安装包自带的公钥建立信任。设备可信配置含deployment_id、设备/组标识、根公钥、协议与算法允许列表、能力策略及时间要求。首批以单部署域为边界，跨企业互信通过显式根或委托配置扩展，不自动信任任意厂商证书。

## 2 三类签名对象

| 对象 | 绑定内容 | 解决的问题 |
|---|---|---|
| 内容证明 content_statement | deployment、scene、release/truth/view身份和摘要、运行包清单原始字节摘要、profile、data_kind、签发者及内容格式版本 | 文件来自授权发布者且没有换包 |
| 能力凭据 capability_grant | 包摘要、受众、能力/范围、profile、策略摘要、签发及起止时间、状态身份和序号、可离线条件 | 当前对象在何种条件下允许使用 |
| 状态证明 status_snapshot | 部署/状态身份、固定包摘要、epoch/sequence、完整能力状态、撤回原因、状态时刻；在线请求还绑定挑战nonce | 验证新鲜度和防止已知状态被旧介质覆盖 |

内容证明与包、凭据分离，续期不重发几何，也不把撤回状态写回不可变包。角色委托证书由根签名，限定公钥、kid、用途、部署、有效期和适用范围；内容签发权不推导有效性签发权。

每份能力状态以完整替换快照表达，首版不采用需要补齐历史链的增量事件。范围使用固定scope/profile摘要，不在首批支持任意几何求交；请求超出凭据范围或配置直接拒绝。未列能力一律不授权。能力凭据不是身份登录令牌，也不替代下载访问控制。

## 3 序号与防降级

状态键为(deployment_id, scene_id, package_sha256)。同一键的epoch/sequence由平台事务分配，sequence不复用；epoch仅通过根授权的恢复/换代流程递增，普通签发密钥不能自行提升。不同包或不同部署的序号不互相比较，避免一个高序号污染全部包。

每个客户端保存已接受最高状态元组及该快照摘要：更低拒绝；同元组同摘要可幂等使用，但不刷新新鲜度计时；同元组不同摘要视为签发冲突并拒绝。续期必须形成更高sequence的完整快照，再签发绑定该序号和摘要的grant，不以重复传输旧凭据延长离线时限。

客户端同时保存已见信任配置版本。新grant只在对应快照、信任版本及能力策略一致时授权。更新状态和信任高水位需要先原子持久化，再对外返回可用；写入失败返回storage_error，不能先执行再补记。

首批对发布撤回采用终止语义：已知撤回的包/能力不通过更高序号重新授权；恢复使用新发布/新包并重新审核。临时限制若未来需要可解除状态，应另行定义，不借valid覆盖revoked。

本地数据库丢失或无法确认高水位时，不从旧包重建“当前有效”，返回validity_unknown并要求可信重新引导。普通备份恢复可能带回旧高水位，受信任设备假设下也必须在恢复流程标记需重新同步；对恶意管理员回滚不作保证。

## 4 签名编码及密钥生命周期

首批验证候选为JWS Compact、Ed25519签名（JOSE alg=EdDSA并限定曲线Ed25519）；Python/C++库、许可、标准测试向量和目标CPU兼容仍需核验，当前不宣称算法库已经选定或实现。不自行编写密码算法。

签名覆盖JWS原始protected与payload编码，先验签再解释受限JSON；不将反序列化再序列化后的JSON当原签名消息。protected固定typ、alg、kid和协议版本；拒绝none、算法替换、重复JSON键、不支持的crit及非预期字段，不从jku/x5u等消息URL下载密钥。限制报文、嵌套与数组大小，验证器无隐式网络访问。

kid只用于已信任配置内选钥，不是信任证据。设备绑定deployment、audience、签发角色、授权范围和密钥有效期；当前信任策略已撤销的密钥不能因其历史签名仍能验过而继续授权。

私钥不进入运行包、仓库、日志或机器人。原型仅使用临时测试密钥，正式签发通过受控签名适配器；KMS/HSM或现场密钥保护方式在交付环境确定后评估。平台审核与签名操作分别留关联审计，但不能只凭操作者名称建立可信身份。

根委托轮换采用有版本的新信任包，可设置短期重叠并分别验证新旧委托范围；根轮换要求已有根授权的新根信任包或受控重新配置。根失陷无法靠该根的一条自签声明自证恢复，应走独立受控重新引导。离线设备无法立即获知密钥撤销，最长暴露期受委托期限、状态期限及离线策略共同约束。

## 5 时间与新鲜度

每项能力必须同时满足grant的nbf/exp、状态快照期限、委托期限、本地策略最大离线时长。实际允许窗口取这些限制中最严格的交集；下载、安装、重复导入旧介质和重开会话均不重置计时。nbf包含边界，exp到达即失效；不设置自动宽限期。

设备时间接口返回可信UTC区间[earliest, latest]及信任来源，而不是普通系统时钟一个数。只有earliest不早于nbf且latest严格早于exp及其他截止时间时才确认有效；区间跨越边界时返回validity_unknown，不猜测仍有效。

在线取得状态使用一次性随机nonce，绑定包、受众和当前请求。客户端用包含休眠时长的单调计时限制往返时间；签发者在读取受控状态后给出签名时间及误差预算。客户端根据经验证的签发时间、网络往返上限和误差建立保守时间区间，不信任下载服务的Date头。超时或重放nonce拒绝；具体时间同步与误差算法在R2b先做独立试验。

离线介质不能仅凭“有签名”确定刚刚签发，nonce也不能消除长时间携带延迟。没有受控可信UTC/安全时钟或可沿用的同启动周期时间锚时，可验证内容来源并存储，但不能把有期限的能力激活为有效。

同一启动周期内，已验证时间锚通过单调时间推进；时间源必须包含挂起/休眠，不满足时恢复唤醒后转unknown。重启后单调锚失效，除非目标设备有已验证的跨重启可信时间源；普通落盘时间或boot_id只能识别变化，不能证明时间正确。时钟回拨、时间源不可信或状态存储不可用均不静默延长期限。

离线最长可用时长及同步频率由用途与现场风险确定，本轮不填写未经确认的小时数。测试使用显式合成策略值，不能将其作为产品默认。

## 6 状态与会话门禁

| 判定状态 | 对外行为 |
|---|---|
| authorized | 包完整、信任/受众/范围匹配、状态与时间均满足，允许指定能力 |
| revoked/restricted | 拒绝受影响能力并返回原因；不自动切换旧包 |
| expired/not_yet_valid | 拒绝当前能力，不因重试下载延长期限 |
| validity_unknown | 缺可信时间、状态、高水位或存储不可确认，拒绝需要授权的能力 |
| invalid_proof | 签名、来源、绑定、协议或角色不匹配，拒绝采纳 |

内容安装就绪与使用授权分别存储：包可完整安装但尚未授权。安装、激活、打开会话及每次受限查询都有各自检查。会话固定的是内容版本，不能固定永久授权；接受更高撤回状态后，即使旧会话持有完整几何，也要拒绝后续受影响查询。

首批参考实现每次查询从本地有效性仓储取得最新已接受状态和时间判定；持久状态提交与查询判定的线性化顺序必须明确。大图高频场景再评估可失效的内存缓存，不能直接复用R1只读内存会话作为授权缓存。

线性化点定为本地有效性读取事务内的授权判定：撤回提交后开始判定的查询必须拒绝；此前已判定并在途的结果可能随后返回，不能追回已交付结果。结果应携带所用状态序号和判定时间，机器人集成层如要求更严格的执行门禁，需在动作提交前再检查，而非仅信任先前的空间查询结果。

查询结果区分空间unknown与授权失败。expired不能伪装成空间unknown或空闲；SDK只报告能力不可用及原因，机器狗/UAV集成层按约定执行停用、重新定位或其他任务处理，平台不擅自发送整机控制指令。

## 7 平台签发、同步与持久化

平台签发流程：鉴别请求者和受众 → 在场景/发布事务边界检查已采用版本、能力限制及撤回 → 产生固定状态与序号 → 将待签内容持久化 → 签名 → 返回证明。正式签发入口不得接受客户端传入passed或authorized作为依据。

签名进程与发布事务无法原子完成时，采用持久待签记录与固定内容摘要。签名完成后返回前重新检查所对应的状态仍可签发；若已有新撤回，不交付旧授权。并发撤回在签发检查之后发生，客户端仍可能短暂持有旧许可，窗口受新鲜度/离线期限约束；不宣称网络客户端能即时同步数据库撤回。

客户端流程：受限解析 → 验证受信任签发链/角色 → 核对来源与受众 → 验证挑战/时间或离线时间条件 → 比较状态高水位与终止撤回 → 原子存储状态/凭据 → 确认包完整 → 单独判断是否可激活。有效的撤回状态即使不具备grant也可限制既有使用；旧或过期的grant不能压过已接受撤回。

离线信任包更新由受控根授权流程处理，与普通数据包更新分开。密钥撤销/根更新必须经过适用的信任与版本检查，不能因网络中断就保持无限期信任。

在线与离线使用同一内容证明及绑定规则，传输层可用HTTPS和受控介质；TLS及登录保护访问，签名支持内容离线核验，互不替代。HTTP端点、设备认证和断点下载协议留待契约验证后实现，不把Next页面接口作为SDK的隐式协议。

## 8 兼容与增量

R0的agent-package/0.1仍为合成内容，source和validity字段不就地改成“已授权”。R2先新增独立的content/grant/status/trust契约及测试向量，再评估包升级；旧读取器必须拒绝不支持的必需可信特性。迁移不得使旧CLI成为新格式绕过有效性的入口。

R2a：建立逻辑契约的Schema、签名库选型与测试向量，纯本地验证签名、角色、绑定和状态冲突；只用测试密钥，不启用正式信任或网络服务。

R2b：实现参考有效性仓储、时间接口及会话门禁，验证撤回对旧会话生效、单调时限、重启unknown、持久化失败和防降级。先完成逻辑验证，再接入R1安装激活；保持synthetic。

R2c：实现有设备身份的在线状态挑战、可信下载与离线介质导入，验证故障重试、混包、弱网及签发/撤回竞争。R2d在目标设备上验证密钥配置、轮换、恢复与离线时钟，之后才讨论真实消费基线。

验收详见[清单](智能体可信分发与离线有效性验收清单-v0.1.md)。真实大图、物理断电、P1算法、P3构建和I4任务恢复仍各自验收，不能由可信签名替代。
