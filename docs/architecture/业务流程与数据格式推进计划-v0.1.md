# 业务流程与数据格式推进计划 v0.1

日期：2026-10-28。状态：设计与实验契约；不改变现有 synthetic 导入、发布或机器人有效性门禁。

## 1 决策基线

采用统一逻辑契约、用途化物理编码、外部标准适配器。权威性由版本、对象身份、坐标、证据和采用记录保证，不以单一文件格式保证。

| 环节 | 首版方向 | 后续适配与验证 |
|---|---|---|
| 观测 | 保留原生 ROS bag / MCAP / 厂商日志，统一清单描述 | 解码、逐点时间、IMU、同步与外参实际预检 |
| 点云 | 接收算法原生 PCD/PLY；成果按需评估 COPC | 不将 COPC 可读取等同机载运行可用 |
| 坐标 | 独立 frame 契约，局部米制右手系；控制与检查点明确分工 | 地理交换再确定水平/垂直基准、轴序及转换；局部 XYZ 不套 GeoJSON |
| 真值 | JSON 清单固定引用几何、覆盖、对象、质量、本体和证据 | USD 作为适配候选；未核验版本特性不进入冻结依据 |
| 语义 | JSON Schema 检查结构，版本化本体和实例映射 | OWL/RDFS、SHACL；IFC 与 IEC 61970/61968 按具体 Profile 映射 |
| 人视图 | GLB/glTF 与对象映射 | 大空间再验证 3D Tiles 分块、资源预算与质量表达 |
| 机视图 | 组件化运行包，固定 scope、frame、profile 与摘要 | 二维/三维占据、ESDF、定位参照和语义拓扑按用途组合 |
| 变更 | 领域操作与分块替换；固定基线、前置条件和独立验证 | JSON Patch 只用于适合的小型 JSON 内容 |
| 服务 | 固定发布读取、用途化时效与能力门禁 | OGC API 按实际对接范围提供适配，不声称已符合标准 |
| 事件与追溯 | 版本化事件和实体/活动/责任主体引用 | CloudEvents / AsyncAPI / PROV-O 映射 |

## 2 四条流程的事件骨架

| 流程 | 触发与输入 | 放行判据 | 输出事件 | 退化 / 未知 / 冲突 |
|---|---|---|---|---|
| 建图 | 需求确认；用途、目标范围、精度规程、观测及独立参考 | 预检→构建候选→语义确认→独立校核→采用→视图验证→发布 | candidate.created / candidate.accepted / release.published | 降低声明用途但须重审 / 证据不足保留候选 / 坐标或身份冲突隔离 |
| 增量 | 变化发现；固定基线、观测、领域变更集 | 独立验证、合并前置条件、派生影响检查 | change.proposed / truth.created / release.published | 限定区域 / 未确认变更不合并 / 基线竞争重新核对 |
| 消费 | 查询或订阅；版本、坐标、scope、用途及消费 Profile | 引用完整、能力可用、时效满足、范围匹配 | query.completed / consumption.refused | 明确限制 / unknown 带原因 / 证据冲突按用途拒答 |
| 对账追溯 | 复测或投诉；检查点、评估规程与历史版本 | 检查资料独立，误差口径与评估范围明确 | quality.assessed / capability.restricted / capability.released | 范围限制 / 缺独立证据不放行 / 暂停受影响能力并保留历史 |

这些为事件风暴输入，尚非 BPMN 可执行流程。BPMN 2.0 与 DMN 分别在流程边界、质量指标和审批角色确定后形成，不预设 A/B/C 数值。控制点用于拟合，独立检查点不得同时用于该轮拟合或调参。

## 3 顺序任务与验证门槛

| 编号 | 增量 | 依赖 | 交付与验收 |
|---|---|---|---|
| F01 | 观测资料清单 | 场景与用途基线 | Schema、合成样例、结构/时间/引用正反例；不伪造同步与标定 |
| F02 | 坐标与控制点 | F01 身份与引用 | frame、变换方向、控制/检查角色；拒绝反射、无效刚体变换及检查点参与拟合 |
| F03 | 质量、状态与场景配置 | F01/F02 | 三态与独立诊断原因；规程、评估范围、覆盖分母；配置 Schema 与边界测试 |
| F04 | 真值与双视图清单 | F03 | 固定输入输出、对象与本体映射、表达损失；跨文件身份/摘要负例 |
| F05 | 机视图编码 Profile | F04 | 分块原点、索引、编码、缺块语义、必需组件；离线样例和资源测量 |
| F06 | 消费与更新接口 | F03/F04/F05 | 请求/Profile 时效、历史读取、错误与局部完整性；领域变更集、事件和追溯映射 |

每项依次经历：设计草案→Schema/领域校验→合成验证→真实适配→接入验证。合成通过不等于真实准入、独立质量或产品验收完成。

首批 F01/F02 使用 `cospace.observation-input/0.1` 草案，见 contracts/schemas/observation-input-v0.1.md；不升级既有导入契约。真实日志解码、文件封存与算法预检继续依赖 P1 实际输入工作。
