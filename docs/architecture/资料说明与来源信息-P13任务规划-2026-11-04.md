# P13：资料说明与来源信息

日期：2026-11-04。状态：**P13.1／P13.2／P13.3本机实现与验收通过**，见[P13验收](../validation/资料说明与来源信息-P13-2026-11-04.md)及[8777操作](../guides/资料说明与来源信息P13运行.md)。下文保留实施前的范围与验收标准；实际结果以验收记录为准。

前置：[P12验收](../validation/场景进度与版本上下文-P12-2026-11-04.md)。总计划：[业务技术流程任务批次与验收](业务技术流程任务批次与验收-v0.1.md)。需求依据：[场景数据管理设计](场景数据管理设计-v0.2.md)的DM07、DM09、DM10及DM22。

## 1. 批次判断

P1—P12已完成现有两类样本的资料、批次、模型、双视图、核对、发布、在线与离线使用，以及同场景更新和历史回切。P12补齐场景进度和明确版本上下文。下一步处理数据管理的日常整理能力。

本次代码检查确认：

1. `PreviewInputs.register()`保存固定登记记录，名称也在其中；`resolve()`核验原始资料。准备摘要将任务的完整`input_binding`与登记记录比较。直接修改原记录的名称会影响引用一致性。
2. 资料详情已有预检、登记数量、来源及摘要，缺少资料名称、备注、用途的独立修订入口。
3. ROS1适配器已有`frame_id`、米单位、首帧与记录时间证据；NYU适配器已有轨迹及文件内时间线索。它们尚未形成统一、带来源的坐标与时间说明。字段存在不代表已知现场基准、UTC同步或精度。
4. 当前上传仅接受两类约定ZIP资料包。样本盘点未发现可直接选用的独立LAS／LAZ／PCD／PLY成品底图；已有派生PLY可以作为后续适配样本，但必须标明原始帧来源及局部性质。

因此，P13先完成资料日常整理与来源可读性；已有成果接入单独作为后续批次。继续保持一个实际场景一个场景空间，资料与版本归属于该空间。

## 2. 用户结果与页面

**进入场景的数据管理，能认清每份资料是什么、准备用来做什么、坐标与时间依据是什么，再沿现有入口进入构建。**

业务操作：选择场景 → 选择资料 → 查看或编辑说明 → 查看来源条件 → 预检 → 用于构建。

说明编辑为可选动作，不增加构建前的必填步骤。页面保留全宽布局、浮动侧栏、淡品牌渐变及DS；详情占据header下方的页面右侧。

| 页面位置 | 设计 |
| --- | --- |
| 资料列表 | 使用当前显示名；搜索覆盖名称、说明与稳定ID，保留格式及状态筛选 |
| 详情顶部 | 显示名、资料类型、简短用途；提供按权限出现的“编辑说明” |
| 资料说明 | 名称、备注、用途；保存后更新本场景目录与准备摘要 |
| 坐标与时间 | 紧凑展示单位、坐标系／frame、采集时间含义、配套资料及已知限制；缺项显示“未提供”或“未确认” |
| 技术来源与历史 | 按需展开原始登记名、稳定ID、证据来源、摘要、修订记录；避免默认铺满文件路径 |
| 预检与构建 | 沿用当前入口及门禁；编辑说明不代替预检 |

## 3. 数据边界

### 3.1 固定登记与可修订说明

固定登记记录继续作为构建输入依据。新增独立的资料说明记录，以`space_id + input_id`定位，并核验该资料实际属于该场景；Workspace归属从已授权场景解析。

拟定记录`cospace.input-description/0.1`：

| 字段 | 规则 |
| --- | --- |
| `space_id`、`input_id` | 稳定归属，服务端核验 |
| `revision` | 初始为0；每次实际变更递增，用`expected_revision`检测并发冲突 |
| `display_name` | 1—100字符，初始取原始登记名 |
| `description` | 0—500字符，备注 |
| `intended_use` | 0—500字符，自由说明，不作为路线、精度或机器人可用性的判据 |
| `history` | 修改前后值、修订、操作者、服务端UTC保存时刻、修改原因 |

复用现有SQLite修订保存方式和授权设施。无实际变化的重复保存返回原修订；冲突明确要求刷新，禁止覆盖另一人的修改。说明库读取故障显示错误；正常无记录才使用原始名称。已有资料首次读取不产生写入。

数据流：固定资料登记 → 原构建输入绑定；说明修订 → 目录及详情显示。两者通过稳定ID关联。

列表、准备摘要等业务响应增加独立的显示字段或说明对象，原固定`input_binding`保持其原内容。历史任务、批次、候选、发布与离线包中的名称保留当时值；如显示当前名称，必须另标“当前名称”。改名后再次登记相同包仍遵守既有去重规则。

### 3.2 坐标与时间事实

拟定只读说明`cospace.input-facts/0.1`，覆盖现有两类适配器。按字段记录`value`、已知／未知状态和`evidence_ref`，证据引用包含实际成员、字段及可用摘要；区分原始声明和处理路线的解释。

| 信息 | 首版提取原则 |
| --- | --- |
| 坐标 | 仅展示可从固定输入或明确适配规则确定的单位、frame及局部基准；明确其证据类型 |
| 时间 | 区分日志记录时刻、传感器header时刻、图像时间与登记时刻；保留原始数值及单位 |
| UTC／同步 | 仅在来源明确声明且有依据时显示；未知时保持未知，epoch形状的数值也不能自动证明UTC同步 |
| 配套资料 | 按实际固定包列出观测、已有轨迹、IMU／标定等存在情况，并注明当前路线实际使用什么 |
| 限制 | 激光路线仍是首帧局部、未配准；RGB-D路线使用已有轨迹；角色说明不代表实现多传感器融合 |

读取使用有上限的清单或已有检查证据，避免列表逐项完整解码大日志。区分“未记录”“源文件不可读”“证据与固定摘要不符”；无法确认时不能继续展示为已确认。落实时定义缓存及失效规则，并沿用提交构建时的实时校验。

本批只读呈现坐标和时间依据。用户修改名称、用途不会改变单位、矩阵、时钟映射或构建结果。关键解释的纠正需另立固定解释记录并重新构建，列为后续能力；DM09及DM10仅交付本节明确的子集。

### 3.3 接口与权限

拟新增：

- `GET /api/inputs/{id}/description?space_id=…`：读取当前说明及历史。
- `POST /api/inputs/{id}/description`：提交`space_id`、`expected_revision`、三个说明字段及修改原因。
- `GET /api/inputs/{id}/facts?space_id=…`：读取来源事实及缺项；不触发预检、任务或发布。

契约定稿随P13.1交付。复用`data.manage`管理权限；说明读取和技术事实同现有资料详情权限。操作者由验签会话确定，请求不接受客户端伪造的Workspace或操作者。仅有空间预览权限的用户继续通过固定发布浏览，不获得工程资料说明、路径或历史。

## 5. 验收矩阵

以下均为待执行标准。

| 用例 | 预期 |
| --- | --- |
| 旧资料首次读取 | 显示原名，说明修订为0，无写入副作用 |
| 名称／备注／用途保存 | 操作者和历史真实保存；刷新与服务重启后可恢复 |
| 取消、空名、超长与非法字段 | 取消无写入；非法请求拒绝并保留用户可纠正的输入 |
| 两窗口并发、相同内容重复保存 | 旧修订冲突；相同有效内容不产生额外修订 |
| 改名前后的预检与新构建 | 固定资料绑定仍一致；至少一份真实资料显式完成改名后的模型与双视图构建 |
| 相同上传包再次登记 | 复用原资料，不因当前显示名改变而新增或改写固定记录 |
| 历史发布和来源追溯 | 旧资料、任务、模型、双视图及发布摘要不变；固定发布仍可预览、查询 |
| 坐标／时间证据正常与缺项 | 两类样本如实呈现；局部坐标不强填EPSG，未知同步不变成UTC保证 |
| 文件丢失、摘要不符、说明库故障 | 错误和未知区分；不以旧事实冒充本次确认，也不把说明库故障当成未填写 |
| 跨场景、跨Workspace、查看者直接API | 服务端拒绝越权；页面不泄露旧场景的详情、说明或事实 |
| 慢响应、切换对象、会话恢复 | 旧请求不覆盖新对象；恢复后重新读取，写操作不自动重放 |
| 1440px及390px布局 | 无全局横向溢出；右侧详情在header下方，编辑按钮与输入遵循DS |

在独立运行区复用现有两类固定样本，保留原始工程和P12环境，记录修改前后文件摘要。说明写入及新构建仅在验收副本进行。若未改变固定发布、离线协议或引用传递，保留既有离线证据；如实施触及这些边界，补跑受影响的消费一致性检查。
