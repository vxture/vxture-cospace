# 智能体可信分发与离线有效性验收清单

日期：2026-10-27。状态：待实现、待执行，不是验证记录。依据：[设计](智能体可信分发与离线有效性设计-v0.1.md)。

| 编号 | 场景 | 必须满足 |
|---|---|---|
| TR-01 | 正常内容签名，改一字节清单或签名 | 原始签名向量通过，篡改拒绝；无网络取钥 |
| TR-02 | 包自带公钥、未知kid、none、算法替换或未知crit | 不建立新信任、不降级算法，明确拒绝 |
| TR-03 | 内容签发者尝试签grant，跨部署/场景/设备/组混用 | 角色及受众范围拒绝；合法签名不等于合法授权 |
| TR-04 | 包、release、truth、view、profile、scope摘要或data_kind换用 | 固定绑定不符拒绝，synthetic不得转正式 |
| TR-05 | 重复JSON键、超长报文、过深嵌套及未知版本 | 有界拒绝，不进入不受限解析或外部代码 |
| ST-01 | 同一状态键低序号重放 | 拒绝，不改变最高状态或刷新计时 |
| ST-02 | 同序号同摘要、同序号不同摘要 | 前者幂等，后者冲突；续期必须新序号 |
| ST-03 | 不同包的高序号、未经根授权的epoch增加 | 不污染其他状态键；普通签发者不能提升epoch |
| ST-04 | 已撤回后更高序号尝试授权，或回退到旧包 | 原撤回不解除，回退不能绕过有效性 |
| ST-05 | 写入高水位/凭据失败、数据库丢失、备份恢复 | 不先授权，返回unknown或storage_error并要求可信恢复 |
| TM-01 | nbf前、nbf、exp前、exp边界及时间区间跨界 | 边界一致，区间不确定时拒绝，不自动宽限 |
| TM-02 | grant、委托、快照及离线策略期限不一致 | 取最严格交集，下载/安装/重开会话不延长 |
| TM-03 | 在线nonce重放、响应延迟或挑战不匹配 | 超时/不匹配拒绝，不伪造新鲜度 |
| TM-04 | 离线旧介质重新导入、无可信时钟 | 不把收到时间当签发时间；仅存储内容不授予限时能力 |
| TM-05 | 时钟回拨、挂起唤醒、设备重启 | 无可靠时间延续时unknown，重启不重置离线预算 |
| SS-01 | 已打开会话后接收撤回或能力过期 | 内容版本保持固定，后续查询授权拒绝，不返回空间空闲/unknown |
| SS-02 | 多会话查询与撤回状态更新竞争 | 明确线性化边界，持久提交后新查询不得使用旧授权 |
| KY-01 | 委托过期、密钥撤销、合法轮换及旧信任包回放 | 权限和信任版本受约束；旧介质不恢复已撤销密钥 |
| KY-02 | 根轮换、根失陷、设备状态存储回滚 | 合法轮换按既有根授权；失陷/不可信回滚走独立受控引导，报告能力边界 |
| SY-01 | 签发待签记录后撤回、签名完成后撤回 | 返回前检查；不可交付已知失效许可；承认并测试已发许可离线窗口 |
| SY-02 | 断点下载混版本、缺块、部分凭据、网络失联 | 内容未齐不激活；状态更新不破坏旧内容；失联按期限判断 |
| CP-01 | 旧R0/R1工具处理新可信格式 | 不静默绕过必需门禁；旧合成样例仍明确robot_ready=false |

R2a先执行TR-01至TR-05与状态对象结构检查；R2b执行ST/TM/SS及本地持久化用例；R2c执行在线挑战、签发竞争和下载同步；R2d验证实际设备时间与密钥运维。跨阶段用例需在组合实现后重新验证，不能因Schema通过标记协议通过。

证据记录固定代码、依赖、测试密钥来源与指纹、签名消息原始字节、状态键/序号、时间源及误差预算、设备重启条件、调用结果与持久化状态。仅保留无真实授权的测试密钥，正式私钥和设备凭据不写入日志或仓库。

密码实现至少核对标准向量与负向输入，再做独立实现或目标语言互验；只签自己生成的消息再自行验证不足以证明互操作。时间测试采用可注入时钟验证边界，并在目标硬件补挂起/重启试验。并发采用真实事务和进程屏障，不只测试顺序调用。
