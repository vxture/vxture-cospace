# 智能体只读交付核对设计

日期：2026-10-27。独立合成诊断工具，experiments/scripts/delivery_audit.py。依据[文件会话组合设计](智能体恢复与文件会话组合设计-v0.1.md)。报告名称表示交付工程师的核对工作，不表示正式交付验收通过。

后续增量已实现[保存报告的只读工作台](交付核对工作台设计-v0.1.md)，不改变本扫描器或其报告格式。刷新仅重读文件，原观察时间仍未记录；下文保留本批扫描器设计边界。

## 输入与观察

输入已有FilePackages目录、已有user_version=3恢复日志目录，以及调用方明确指定的完整binding。binding包含scene/release/truth/view身份、包及关联摘要、profile和scope；不能只传场景自动猜测目标版本。输入只是核对目标，不建立外部信任。

先分别调用PackageAudit和RecoveryAudit，再以独立只读事务读取目标活动包和日志绑定。文件侧通过实际_load校验组件原字节，构造完整binding；日志侧只找与请求完整binding一致的states行，并观察content/status/grant是否非空。不输出证明正文，不验签、不判定撤回、不读取时钟、不重放历史。

报告含requested_binding、observed、components、findings。observed明确区分file_binding、journal_binding、active_revision和binding_match，journal_status使用proof_fields_present_unverified或proof_fields_missing，不使用valid/ready等表述。组件原报告保持原含义，PackageAudit的passed不能提升为交付或运行许可。

## 诊断及后续行动

| 原因 | 含义与后续 |
|---|---|
| observation_incomplete | 组件不可读、超限或格式不符；保留现场并核对组件诊断 |
| component_needs_attention | 文件安装残留、未决意图或活跃恢复等；进入独立受控核对流程 |
| file_binding_mismatch | 活动文件包与指定目标不同；重新确认目标，不能借用其他版本证明 |
| journal_binding_missing_or_ambiguous | 目标日志绑定不存在或不唯一；通过受控接收核对证明 |
| proof_fields_missing | 三类证明字段不全；字段齐备也须另过运行门禁 |
| file/journal_binding_unavailable | 目标组件损坏或无法关联；保留数据并诊断，不自动补建 |
| file/journal_observation_changed | 前后快照的活动版本或控制身份变化；重新生成报告 |

complete表示本次有界观察完成，并非“没有错误”；needs_attention表示有需处理的发现。两者可能同时为true。没有发现仍固定validity=not_evaluated、proofs_verified=false、history_verified=false、repair_authorized=false、authorized=false、robot_ready=false。

## 一致性与限额

全部SQL使用mode=ro及query_only；不构造FilePackages/RecoveryStore，不创建目录、数据库或锁，不改变mode、不装配维护权限。只读组件检查与目标关联分属不同快照，文件系统也可并发变化；附带前后版本比较只发现部分变化，不能证明没有ABA切换或跨库原子性。

limit为1至200，传给两组件审计；PackageAudit沿用现有小型合成文件限额，恢复审计与关联读取有SQLite长度/执行步数预算和limit+1边界。超限不输出自动清理名单。当前会审计目录内所有组件，其他场景故障也可能使整体needs_attention；目标关联单独列出，不把“其他故障”误说为目标已损坏。

只读报告不能绕过旧会话代次检查或撤回。未定义生产交付验收签章、操作身份、数据上传、自动修复或远程维护接口。原默认CLI及门禁实现不变。
