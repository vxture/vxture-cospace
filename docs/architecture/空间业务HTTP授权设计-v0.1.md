# 空间业务HTTP授权设计 v0.1

日期：2026-11-03。I3把既有平台RP身份和空间策略装配到真实样本工作台。六个业务模块、成果格式和固定发布流程不变。真实accounts客户端尚未配置，本轮以本地模拟身份源、独立样本副本验证。

## 1. 调用链

浏览器 → CoSpace同源RP → 当前平台会话与access token → 当前空间策略 → 保存记录归属 → 业务接口 → 原有成果生命周期门禁。

登录仍按yucer及平台契约实现：accounts决定会话，CoSpace使用独立client、自己的加密服务端会话和opaque Cookie。请求中的用户ID、角色、工作区或前端缓存均不作为身份。业务请求要求有效access token和仍有效的中央确认；GET不报告用户活动，也不为后台轮询延长中央会话。确认过期或平台暂不可用时拒绝业务调用，保留登录供重新确认。

`create_auth_app`仅在业务应用与`BusinessAccess`同时传入时启用`authorized_workbench`。认证入口与前端静态资源公开，业务采用显式路由清单；新增未知路由默认拒绝。路径歧义、点段、重复参数、重复JSON键均拒绝；非GET/HEAD须同源Origin及CSRF。未处理的auth前缀不能绕过检查落到内层默认模型静态目录。

角色仅对显式绑定的物理空间生效。先匹配已验签的issuer、active_org、active_workspace，再检查产品grant。平台`workspace:owner`只对该工作区明确绑定的空间具有产品管理员基线；org:owner、workspace:manager、裸owner/admin均不隐式升权。`space.manage`为后续管理能力保留，不代表已经开放空间创建接口。

本轮本体库是登录用户共享的固定规则包，可读与草稿校验；租户私有本体的编辑与隔离待单独设计。现有页面部分操作可能仍显示，是否可执行最终由服务端判定。

## 3. 资源归属及响应

空间和项目列表仅返回当前授权空间及其父项目。候选、资料、发布按服务器保存记录解析归属，核对空间和项目；body中引用的资料、候选、基线发布及批次也须属于同一授权空间。无权限请求在任务轮询、预检、生成离线包或读取几何之前拒绝；列表汇总内部仍可能读取全局记录元数据，输出先过滤授权范围。

预览许可允许`human.ply`、`views.js`及模型/对象/本体/业务/关系的展示数据。`agent.npz`、空间NPZ、离线ZIP和其余单文件导出要求`space.export`。能展示的几何本身可以被复制，角色分权不是浏览器数据防复制机制。内层无空间上下文的默认模型、根资产别名及未知路由均拒绝。

无身份返回401，无空间/能力或错误引用返回403，中央确认/凭据服务/策略暂不可用返回503。先授权、再检查分发状态：外部用户访问暂停发布仍403；授权用户访问暂停分发内容409，管理历史保留。HEAD、Range和条件请求执行同一准入规则。

## 4. 策略与撤权

`SpacePolicyStore`在独立runtime保存`space-policy.sqlite3`。完整策略与历史以同一事务写入；`expected_revision`冲突拒绝，必须记录actor、reason和UTC时间。actor是受信任主机操作者的声明，主机访问控制构成信任边界；浏览器不能提交策略替换权限。

每次业务请求重新读取策略快照，撤权无需重启，对下一次准入生效。已准入的在途请求和已下载副本不追溯撤回。策略缺失/损坏不回退缓存或匿名模式。会话和策略可跨本地进程恢复，当前SQLite与OS锁方案为单宿主实现，多主机部署另行设计。

## 5. 页面与运行隔离

授权页面只挂载真实授权空间卡片；账户区展示平台subject、组织和工作区，不以本机成员草稿作为权限。前端默认调用当前origin，防止8769页面意外访问8767无认证工程接口。全屏空间仍从卡片在新标签页打开，复用自己的RP会话；写调用注入同源CSRF。

8767保留原内部工程预览；8768保留I2独立登录验证；8769为I3受保护工作台。本轮演示8769使用明确标识的本地模拟平台和样本副本，不表示真实平台联调完成。原`var/nyu`的195个受管文件保持不变。生产入口须配置独立客户端、受控空间绑定和授予，不得将8767作为其匿名旁路开放。
