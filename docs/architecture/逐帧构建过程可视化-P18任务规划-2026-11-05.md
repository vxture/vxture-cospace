# 逐帧构建过程可视化：P18任务规划

日期：2026-11-05。状态：**经用户批准，P18.1—P18.3均已实施并验收。** 以下保留立项依据和原范围，执行结论见第9节。

## 1. 当前结论

单场景主线已经通过真实样本跑通：资料登记／批次 → 固定模型 → 人视图与智能体视图独立派生 → 核对选择 → 固定发布 → 在线／离线消费 → 同场景版本更新与回切。P17补齐资料及阶段成果预览，并按用户反馈增加独立全屏构建画布。

目前全屏画布在模型冻结后，按方位逐步显示已有静态点云。它是明确标注的扫描效果演示，尚未显示实际逐帧输入、相机移动和构建中间结果。下一批优先补齐这个具体断点，继续以流程贯通为目标。

不新增导航模块或业务层级。Workspace → 场景空间 → 资料／批次 → 构建任务 → 历史成果的归属继续沿用。

## 3. 样本依据与限制

优先使用已经登记的办公室RGB-D短序列，在**原办公室场景空间中创建新任务**，保留全部旧任务与发布。

- 场景：`space-d7a370b8107c30f7`；60帧资料：`input-3633f8094bc44604`。
- 原始帧清单：`var/nyu/office-0001a-short-001/report.json`，60对已接受RGB／深度帧。
- 已有位姿文件：`var/nyu/office-0001a-interior-0-002/comparison.json`，57个`prefix_T_anchor_camera`估计矩阵，且绑定上述清单摘要。
- 全60帧源时间跨度1.967172秒；前57帧跨度1.871161秒。样本较短，慢放必须显示倍率。
- 源时钟声明为`filename_time_unverified_utc`，适合计算相对时间，不足以声明UTC同步已验证。
- 既有构建使用前57帧，后3帧没有可用前缀位姿，不参与融合。历史同输入任务的固定模型为56,637点，此数字仅作既有结果参考。
- 位姿来自已有RGB-D估计实验，代表相机估计位置，不能称机器人实测轨迹或独立真值。

静态PLY路线没有帧时间与轨迹；当前ROS路线只提取单帧，也没有可用连续轨迹。这两条路线保留阶段预览／扫描演示，并明确能力差异。

### 代码中的实际断点

`experiments/scripts/build_nyu_flow_preview.py`已逐帧读取、核对源图像并按已有位姿累积点云，但仅在末尾保存固定模型。`spatial.npz`当前只有`points/colors`，没有逐帧归属和时间轴。末尾`np.unique`按体素排序，**最终点数组顺序不能当作采集顺序**。

因此，需由真实构建工作进程在处理时记录帧与新增点的对应，不能对最终点云重新排序来冒充逐帧构建。

## 4. 用户流程及页面

数据管理选择原场景资料 → 构建中心发起任务 → 新标签页全屏构建画布 → 跟随已保存的处理进展 → 完成后回放 → 返回原任务核对、发布。

保留用户认可的纯底图布局：全视口画布，无通用header、目录或内嵌卡片。仅保留紧凑悬浮控件。

1. 左上：场景、任务真实状态、当前模式“跟随构建”或“过程回放”。
2. 画布：实际处理帧带来的点云累积、估计相机标记／朝向与已走过的轨迹。轨迹在当前帧截止，不提前绘出后续路线。
3. 底部：播放／暂停、前后定位、速度及相对源时间；显示“已处理x／57帧，另3帧未参与”。帧覆盖与任务阶段分别呈现。
4. 跟随模式读取已落盘进展；用户拖动历史后进入回放，可明确返回最新。读取失败保留最后已验证画面并标注暂停更新，不假装任务继续推进。
5. 模型冻结后仍沿用原人视图／智能体视图任务状态及返回入口。回放完成不自动核对、选择或发布。

播放倍率只控制展示。短序列可慢放，不能把慢放时长写成实际采集或处理时长。未提供位姿的路线不展示设备标记；已有静态演示始终标明演示。

## 5. 最小数据设计

过程记录作为**现有构建任务的附属证据**，没有独立生命周期、审批或发布实体。首版采用JSON索引与不可变数值分块，内部复用NumPy存储，浏览器通过有界JSON接口读取；正式Schema和固定预算在P18.1实现时落定。

| 数据 | 必备内容 | 约束 |
| --- | --- | --- |
| 过程索引JSON | profile、场景／资料／任务ID、来源清单及位姿摘要、坐标／轴／单位、修订、已保存帧范围、结束状态、未参与原因、分块摘要与大小 | 原子替换；分块写完后才推进可读修订；不向客户端暴露本机路径 |
| 帧记录 | 原始帧索引、源文件标识及摘要引用、源深度时间微秒、相对时间、`T_anchor_camera`、本帧有效点／首次保留点数 | 按源顺序；位姿必须对应同一帧；零新增点的有效帧也须记录 |
| 几何分块 | 与最终固定模型一致的首次观测保留点、颜色及首次出现帧 | 保留现有体素首次取样语义；显示抽样不参与正式模型 |
| 处理记录 | 工作进程已保存帧数、UTC处理时刻、运行／完成／失败／中断状态及可读上限 | 来源为真实保存结果；读取接口不得启动、重试或推进构建 |
| 显示响应 | 明确任务绑定、修订、帧范围、抽样规则、实际点数、估计位姿与限制说明 | 沿用P17全局最多10,000显示点、单响应最多2MiB；全部请求／分块合并后仍受全局预算限制 |

三种时间分别保存：**源帧相对时间、工作进程处理时刻、播放器游标**。未知UTC同步状态不被修正为已验证；帧数进度不换算为整个建图任务的完成百分比。

首版通过已有轮询方式读取新修订，仅追加已核验分块；不引入消息队列、WebSocket或新的调度系统。接口受`build.run`及Workspace／场景／资料／任务归属检查，先授权后读取几何。摘要错误、越界、非有限数值、非法位姿或不一致修订应阻断显示。

过程记录失败或缺失要明确显示“过程记录不可用”，不得冒充完整回放。其对新任务是否允许冻结的处理须在P18.1固定为可测试规则；建议本批启用过程记录的RGB-D任务将记录完整性作为冻结前检查，失败仍沿用原任务恢复机制，不新增恢复状态机。

| 小批 | 交付 | 通过后再推进的验收条件 |
| --- | --- | --- |

| P18.2 全屏跟随与回放 | 复用P17画布，显示实际相机与累积过程；任务运行跟随，完成后定位回放 | 后续帧的点和轨迹不提前出现；回拖移除未来数据；暂停／速度／重播、轮询不重置、切任务迟到响应、窄屏、减少动态、无GPU及旧任务降级通过 |
| P18.3 连续业务验收 | 原场景新任务真实构建，衔接核对／双视图／固定发布／消费，更新手册 | 真实worker保存多个递增检查点及最终结果；刷新和实际重启恢复；双视图仍固定同一模型；在线及禁网消费一致；原任务／发布／源资料摘要不变 |

每小批完成都测试、记录证据，失败先修复；不预设通过数量，不累计相互重叠的回归成绩。

P18.3应区分两种证据：实际worker生成的递增过程记录，以及受控等待／故障注入的页面时序测试。正常构建不为动画故意延迟；若短样本运行过快而浏览器只读到完成状态，应如实记录，不能把事后回放写为浏览器实时观察到构建中间态。

旧任务没有过程记录时显示“此任务未记录逐帧过程”，原预览仍可用；需要真实过程则显式新建任务，不后台重跑或补写旧历史。中断过程只供查看已保存部分，不成为固定模型或发布。

## 7. 完成定义与范围控制

完成定义：**同一办公室场景的一次新构建，可以从实际资料帧追踪到估计相机位姿、增量点云、固定模型和两类视图，并沿既有流程发布消费；全屏画布读到的每一步均有对应保存记录。**

本批不扩展设备接入、在线SLAM、配准调参、环闭合、物理变化检测、局部增量、导航可通行推断、额外格式或本体编辑。样本仍按预录数据与已有估计位姿回放，质量维持`unverified`。

## 9. 批准后的执行结论

P18.1—P18.3完成：真实RGB-D工作进程保存逐帧来源／位姿／首次观测点与原子索引；全屏画布支持跟随、源时间回放和估计相机轨迹；旧任务和单帧路线保留明确演示边界。未增加业务层级。

接口实现收敛为有界的累计前缀快照：每次核验已保存分块后返回全局抽样，而非规划中的增量网络分块／客户端合并缓存。仍保留不可变全量过程分块、500帧／10,000显示点／2MiB限制及轮询修订；短样本先验证流程，差量传输后续按实测性能安排。

原办公室资料60帧中57帧完成构建，剩余3帧明确未参与。首次真实并发发现Windows索引替换短暂占用并保留失败任务；修复有界重试后，沿原恢复UI创建新任务`build-102ee3f007704dff`并成功。实际worker运行中读到多个递增帧前缀；最终56,637点的坐标、颜色及NPZ摘要均与同输入原模型一致。
