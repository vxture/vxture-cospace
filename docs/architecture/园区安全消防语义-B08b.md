# 园区安全消防语义 B08b

本批在公共资源中提供 `fire_safety@0.2.0` 预置草案，沿用核心 `0.1.0`。跨园区复用概念和关系；区划图、配置台账、告警原始记录、点锚及有效期由园区实例提供。

| 要回答的问题 | 定义与约束 | 反例 |
| --- | --- | --- |
| 设备安装在哪里？ | 探测器及手动火灾报警按钮是物理设备。安装位置沿用 `core:located_in`，可指向专业资料定义的防火分区。 | 点锚、近邻或视图重叠不能自动生成安装或配置声明。 |
| 资料将设备分配到哪个报警区？ | `assigned_alarm_zone` 指向由配置资料划定的报警分区。防火分区是另一类专业空间；没有明确的空间范围时，不将纯逻辑通道当空间分区。 | 将防火分区作为报警分区端点、用安装位置替代配置归属。 |
| 告警所指的来源设备是什么？ | `reported_source_device` 从告警记录指向日志明确标识的探测或触发设备。找不到可靠来源时留空。 | 将设备到报告的反向记录映射为来源声明；用告警确认实际火灾、起火位置或当前状态。 |

行业对照使用 buildingSMART 固定版本的 [IfcSensor](https://github.com/buildingSMART/IFC4.3.x-development/blob/0f1c7acb287740d7d40e2d0021c216a9cdf638ab/docs/schemas/domain/IfcBuildingControlsDomain/Entities/IfcSensor.md)、[IfcSpatialZone](https://github.com/buildingSMART/IFC4.3.x-development/blob/0f1c7acb287740d7d40e2d0021c216a9cdf638ab/docs/schemas/core/IfcProductExtension/Entities/IfcSpatialZone.md) 和 [IfcRelAssignsToGroup](https://github.com/buildingSMART/IFC4.3.x-development/blob/0f1c7acb287740d7d40e2d0021c216a9cdf638ab/docs/schemas/core/IfcKernel/Entities/IfcRelAssignsToGroup.md)。借鉴物理设备、空间区域和分组声明分离，导入不会自动生成消防关系；不宣称 IFC 等价。

现有发布及固定交付不迁移。使用 `python -m packages.ontology.kernel --module fire_safety` 导出草案和锁定的核心闭包，先与工作区既有定义核对，再按独立审批流程发布并显式选择版本。

[物流园区合成样例](../../examples/ontology/parks/logistics-fire-safety-b08b.json) 验证版本审批、独立配置与安装位置、告警来源及固定交付。错误端点和方向阻止采用；邻近关系保持未映射；固定告警来源仍是资料报告。防火合规、探测覆盖、人员疏散与事故认定不属于本批。
