# 空间服务域：功能与交互设计

状态：2026-11-10 已确认的产品方向；第一阶段界面与 DS 侧栏已实施，其余为待实施设计。

## 1. 定位与边界

一套空间态势，为多个同类或不同类的具身智能体共享使用。
主要使用者为接入空间服务的研发人员，以及通过接口消费空间态势的具身智能体。
本域的首要职责是监测、管理和保障在线服务能力；接入说明、成果交付、反馈配置和服务对象记录提供辅助支持。

- 离线交付与在线服务是平级独立链路。离线包导入不是在线服务的前置步骤。
- 在线服务允许先导入成果再连接平台，避免在线初始化传输较慢。
- 态势反馈是独立能力，不要求已消费在线服务，也不要求已获取平台成果。
- 服务对象仅登记服务关系、交付、接入与版本事实，不负责设备控制、任务调度或运维。
- 反馈核验、采纳、融合、空间更新、构建及发布属于生产域，不在本域设置处理流程。
- 订阅与商业权益由平台负责；本域校验租户、空间、实例及业务能力授权。

## 2. 信息架构

默认入口 `/services`；应用路由下采用 DS 左侧功能导航，不增加公开 HTML 文件。
模块路由可用 `?section=directory|offline|online|feedback|recipients` 定位，刷新与浏览器前进后退有效。

| 模块 | 主问题 | 主要内容 |
| --- | --- | --- |
| 服务目录 | 哪套空间态势可以使用？ | 空间概况、版本、可用能力、态势预览 |
| 离线交付 | 如何脱离平台使用成果？ | 获取成果、格式、校验、导入说明；后续增加交付登记与导入确认 |
| 在线服务 | 如何监测和保障共享服务？ | 接入配置状态、调用观测、拒绝诊断、版本分布、发布管理及接入说明 |
| 态势反馈 | 如何向平台提交观测？ | 接入配置、数据约定、接口接入、接收诊断 |
| 服务对象 | 服务了哪些具身智能体？ | 离线登记、在线身份绑定、空间关联、使用版本和接入事实 |

态势预览作为空间与版本的共用操作，不独立成一级模块。
全局页面与空间内页面共用同一事实来源，以空间或服务对象筛选进入，不另建两套台账。

## 3. 服务目录与空间详情

### 目录

一张卡片代表一个空间；同一空间的多种能力、多个版本不重复生成卡片。
使用发布的 ShellSidebarFrame / ShellSidebarNav 作为左侧功能导航，支持展开和收起；手机通过 DS Drawer 打开导航。右侧标题为当前模块名称，不保留横向页签与重复说明。
内容区随侧栏宽度响应：内容容器不足 560px 单列、560px 起两列、1000px 起三列，间距 24px，提供 DS 卡片/列表切换。

- Header：类型图标、空间名称、所属项目、当前版本可用状态。
- 内容：真实授权概览图（缺图时复用“我的场景”的 SceneCover 默认空间示意图）、两行说明、已授权能力。
- Footer：左侧为 ver: 版本号与 DS 版本菜单，菜单内展示版本数量、日期和状态；右侧为三点操作与主按钮。
- 服务目录主按钮“查看服务”；离线交付主按钮“获取成果”；在线服务主按钮“服务接入”。
- 三点菜单包含服务详情、离线交付、在线查询、态势预览；缺权限或版本不可用则禁用对应操作。
- 页头统计空间数，不把版本或接口数量当成空间数。
- 搜索只匹配当前查看版本及空间信息，提示“搜索空间、项目或当前版本”。

首次打开选择最新可用版本；没有可用版本时保留最新记录并显示不可用。
这个初始选择不代表平台声明“推荐版本”，也不代表任何智能体已使用。
首次选定后固定版本；刷新不得因发布新版本而静默切换。选中版本消失时停止相关操作，不替换为其他版本。
切换版本是显式动作；对应的预览、查询、成果获取、说明均使用该发布 ID。

### 空间详情

右侧 DS Drawer，展示空间、明确版本、发布时间、所属项目和当前授权能力。
相同版本的离线交付、在线查询、态势预览在抽屉中切换，能力以服务器授权为准。
后续扩展为服务概览、成果版本、离线交付、在线服务、态势反馈、关联对象六个空间内页签。

## 4. 离线交付

交付流：选择空间与版本 → 查看成果组成与兼容性 → 获取成果 → 登记交付对象 → 使用方确认导入。
登记对象可以在获取成果之前或之后完成，不应强制登记才能下载。

需要分别保存：

| 事实 | 来源与含义 |
| --- | --- |
| 成果获取 | 服务端接收获取请求，不直接等于完整传输成功 |
| 交付登记 | 人工记录向特定对象交付的版本与方式 |
| 导入确认 | 使用方确认导入，保存确认人、时间与来源 |
| 实际版本上报 | 在线对象主动报告实际应用版本，可与人工确认并存 |

不得将下载、交付登记或人工确认转换为实时设备状态。
一个交付批次可关联多个对象，但各实例分别保留导入确认与后续版本记录。
成果版本不可覆盖；替换为新版本时新增交付记录。

## 5. 在线服务

当前实施：使用全局已选空间，发布管理员查看近 24 小时已记录调用、历史结果、时效拒绝、请求拒绝、依赖异常、请求处理耗时 P95、版本分布及最近 20 条记录。前台每 30 秒刷新，也可手动刷新。
普通使用者继续使用已授权固定版本，不公开调用身份等运维信息。

`GET /api/service-monitor?space_id=...` 要求 `publication.manage`，每次按当前租户、工作区及空间校验。调用记录仅在服务票据、租户绑定与空间调用授权均通过后产生；无可信租户的攻击请求由基础设施日志承担，不进入租户仪表盘。
只记录时间、调用身份、发布 ID、结果码和处理耗时，不保存凭据、位置、请求体或返回内容。
SQLite 存储位于持久化 jobs 根目录的 `service-observations.sqlite3`，保留最多 7 天、全系统最多 100000 条；读写时清理，容量回收使用 SQLite 空闲页。
记录为尽力写入，写入失败不能使本可成功的业务请求失败。读失败返回 503，不显示虚假零值。
明确标识采集起点、容量截断及本进程已知写入失败。重启不补录缺失调用，此指标不作为完整审计或 SLA 可用率。

HTTP 200 的时效拒绝与返回历史结果分别统计，不称为实时可用或服务成功率。
请求耗时含服务内部校验和查询，不是设备端网络往返耗时；最近请求不表示设备在线。
配置就绪不等于端到端健康，界面使用“服务接入已配置”。发布暂停/退役继续通过既有服务发布模块执行，并保留原授权和审计。
接入授权为只读配置，本轮不新增凭据签发或客户端授权编辑器。告警规则、通知、SLA 和心跳监测需要独立协议与事实后再实施。

- 态势获取：固定版本元数据与按支持格式获取数据。
- 空间查询：固定版本、坐标参考系、请求范围与明确返回语义。
- 版本更新：发现新版本、查看变更、获取版本、报告应用结果。
- 接入诊断：身份、授权、协议、最近有效请求、错误原因。

“已发现、已获取、已应用”是不同事件，不从请求成功推断应用完成。
在线初始化支持直接获取，也支持离线成果导入后继续连接。
自动更新、增量更新、断点续传、心跳能力只有在对应协议落地后才能标为可用。

当前浏览器范围查询依赖用户会话，不是机器人认证方式。
已有 `/s2s/spaces/{space}/publications/{publication}/query` 使用平台服务票据，
仅在部署配置及空间授权齐备后可用；调用方身份不等同于单台智能体实例。
不复制浏览器 Cookie，也不在网页生成未接入平台的自建凭据。

## 6. 态势反馈

独立于在线服务，可仅开放反馈。观测提交者未必消费过平台成果。

| 子板块 | 内容 |
| --- | --- |
| 接入配置 | 空间是否开放、允许的服务对象、支持的方式与反馈范围 |
| 数据约定 | 数据类型、参考系、观测时间、来源、证据引用、关联版本要求 |
| 接口接入 | 地址、身份验证、协议、请求与返回示例、大小限制、重试与幂等 |
| 接收诊断 | 测试提交、接收编号、最近接收时间、错误原因 |

接口提交优先，批量文件及持续数据流按实际需求后续扩展；不同时暴露空配置。
观测事件至少绑定租户、空间、来源身份、事件 ID、观测时间和参考系。
差异型反馈须绑定比较基线版本；纯观测型反馈按数据约定允许无成果版本。
接收方必须验证事件范围与空间一致；不自动以在线服务权限授予反馈权限。
接收接口设计使用幂等事件标识与内容摘要，重试不产生重复事件；异步接收不等同于业务采纳。

只展示已接收、提交失败等技术结果。默认不放长日志和内部处理进度。
不展示待审核、已采纳、融合中、已更新等生产流程状态；新版本通过成果版本与更新能力提供。

## 7. 服务对象

### 数据分层

| 对象 | 最小字段与职责 |
| --- | --- |
| 服务对象实例 | 租户、对象 ID、名称、外部设备标识、类型、型号、所属组织、负责人 |
| 服务身份绑定 | 实例与平台调用身份的验证关系、绑定时间、有效状态；不得仅信任请求体中的设备 ID |
| 空间服务关系 | 对象、空间、允许的独立能力、关系有效状态 |
| 成果使用记录 | 空间、对象、版本、记录来源、确认或上报时间 |
| 接入事实 | 能力、最后请求、最后有效连接、明确协议的在线判定依据 |
| 交付记录 | 成果版本、对象、交付方式、确认记录；追加式保留历史 |

同一个对象关联多个空间，同一空间服务多个对象。
离线/在线不是永久设备分类：交付方式、在线连接、反馈接入分开记录。
类型用于分组与兼容描述，不继承实际使用版本，不与实例身份混用。
同一服务身份可能代理多台智能体；未验证实例绑定时只能展示调用身份，不能宣称已识别具体智能体。

### 列表与详情

列表：名称/标识、类型/型号、所属组织、关联空间数、已开放能力、最近接入。
详情：基本信息、关联空间、交付记录、在线服务接入、态势反馈接入。
空间关系中展示版本来源：人工确认/设备上报，均带时间。
没有心跳协议时仅展示“最近请求”，不标为在线；超时连接不等同于设备停机。
未知、未连接、未登记不能显示为零使用或故障。

操作：登记对象、关联空间、查看交付、查看接入、解除服务关联。
不提供设备启停、遥控、任务调度或运行维护。
身份与能力变更需服务端授权、审计；解除某能力不能隐式撤销其他独立能力。

## 8. 视觉与交互

沿用发布的 DS 15.0.1，而非另起组件体系。
标题 18/16/14px；正文与关键操作 14px；搜索、筛选、说明及次要操作 12px；紧凑 tag 10px。
使用 DS ShellSidebarFrame、ShellSidebarNav、SegmentedControl、NativeSelect、Input、Button、Drawer、DropdownMenu、StatusBadge；详情能力切换继续使用 DS Tabs。侧栏背景、宽度、行高、字体、图标和交互状态不自建覆盖。
保持控件 32px 节奏。页面不添加四个重复统计大卡片，也不把连接状态做成虚假仪表盘。
自建 CSS 仅用于空间概览、卡片分区、网格与响应式组合，字体和颜色使用 DS token。

## 9. 分期与验收

### 第一阶段（本次）

- 五个模块入口及独立说明，目录按空间聚合并显式选择版本。
- 可用的成果获取、查询、预览使用既有接口与授权，统一名称。
- 明确未开放反馈接入和服务对象登记，不使用模拟设备、状态、凭据或保存表单。
- 保留现有平台服务身份和 S2S 约束，不扩权。

### 第二阶段

- 优先交付上述在线服务运行概览、持久化调用观测、接入说明及发布管理联动。
- 下一步：结合正式在线调用验证，完善异常诊断、版本服务策略和保障规则。
- 服务对象登记、交付登记及逐实例导入确认作为后续辅助能力，可读可改权限分别校验，保留事实来源。

### 第三阶段

- 经验证的实例身份绑定、最近请求、协议明确的连接状态。
- 版本发现、获取与应用上报分别记录。
- 正式服务身份与对象关联，不以浏览器会话代替机器人身份。

### 第四阶段（可与第三阶段独立交付）

- 态势反馈数据契约、接收接口、幂等与预算、技术凭证及诊断。
- 生产域接收反馈事件；本域无处理工作流。

验收重点：一空间仅一条目录记录；跨能力固定同版；撤权和未知生命周期关闭消费；
刷新不自动换版；离线记录不伪装实时状态；反馈可独立于在线消费授权。
