# 版本编码与依赖快照设计

日期：2026-11-11
状态：设计已确认；本地已实现场景、资料、构建、发布和规则的持久化展示映射。完整资料接替链与关联集合修订仍待实现；线上迁移需随发布验证。

本文是资料、构建、关联、规则和发布的业务编码依据。界面现有日期加技术 ID 尾码的版本标签是过渡展示，不是本规则的实现。服务发布布局见[服务发布工作区](service-publication-workspace.md)。

实现范围、演示估算时间与迁移操作见[业务编号与演示时间迁移](../guides/业务编号与演示时间迁移.md)。未实现部分保留本设计作为后续约束，不凭现有记录猜测依赖关系。

## 编码与作用域

| 对象 | 示例 | 唯一范围 | 含义 |
| --- | --- | --- | --- |
| 场景 | S482731 | 产品系统内全局 | 稳定场景编号，跨组织不重复，不包含组织或商业信息 |
| 场景资料 | D01-V01 | 场景内 | 第 1 项资料的第 1 个内容版本 |
| 构建 | B01 | 场景内 | 第 1 次正式构建 |
| 空间关联 | 空间关联 · R03 | 场景的空间关联集合内 | 第 3 次有效保存修订 |
| 语义关联 | 语义关联 · R05 | 场景的语义关联集合内 | 第 5 次有效保存修订 |
| 本体／语义规则 | O01-V02 | 产品规则目录内 | 第 1 套规则的第 2 个正式内容版本 |
| 基本信息 | 基本信息 · R04 | 场景基本信息内 | 第 4 次有效保存修订 |
| 服务发布 | B01-P02 | 场景内，P 在所属 B 下递增 | 第 1 次构建的第 2 次固定发布 |

S 为场景，D 为资料，B 为构建，O 为本体规则，V 为内容版本，R 为维护修订，P 为发布。V 是可被明确选用的正式内容版本；R 是持续维护信息的保存记录。不同类别的 R 不共享计数，不能单独显示一个无对象名称的 R 编号。

除场景号外，数字从 1 开始，所有对象序号、内容版本、修订和发布序号统一至少两位：D01-V01、B01、O01-V02、R03、B01-P02。两位是最小显示宽度，不是容量上限：B99 后为 B100，V99、R99、P99 同样自然扩展，不截断或回绕。场景号固定为 S 加六位随机数字，详见下节。编号不按日期重置、不回收、不因排序或删除改变。允许存在空号，不把连续无空号作为正确性要求。

场景内部使用短码；跨场景引用使用 S482731/B01-P02、S482731/D01-V02。规则使用 O01-V02，其权限仍按实际目录授权检查，编号不授予访问权。日期、环境、状态单独展示，不写入版本号。

## 场景随机编号

场景展示编号格式为 `Sdddddd`，其中六位数字由服务端使用安全随机源在 000000～999999 中生成并补齐前导零，例如 S482731、S003817。它不表达创建顺序，不从 UUID 截取，不在客户端生成。现有技术 ID 继续作为主键。

场景创建时以全局唯一约束写入编号；发生唯一冲突后重新随机生成并重试。仅执行“先查询再写入”不能保证并发唯一，必须以存储层唯一约束为准。重复创建请求用幂等键返回同一场景，不能因重试分配多个场景号。历史迁移使用同一随机分配与去重机制，保留已确认映射。

编号创建后不变，删除场景也保留已用编号占位，不复用。六位空间共 100 万个编号；容量监测及有限次数冲突重试必须纳入实现。重试耗尽时明确失败，不循环无上限、不返回重复编号。接近容量上限时需另行设计扩位迁移，不能悄悄改变六位规则。随机编号不替代访问权限校验。

## 时间记录与组合展示

时间由服务端记录，和业务编码分字段保存。编号不嵌入日期，避免同一天多次操作、跨日构建和时区转换造成歧义。界面组合显示短版本号与对应业务时间，时间始终包含年份。

| 对象 | 主要时间 | 组合展示示例 |
| --- | --- | --- |
| 场景 | 创建时间；详情另列更新时间 | S482731 · 创建于 2026-11-11 09:20 |
| 资料版本 | 该内容版本登记时间 | D01-V02 · 2026-11-11 09:25 |
| 构建 | 构建创建时间；另列开始、完成时间与耗时 | B01 · 创建于 2026-11-11 09:30 |
| 关联／基本信息修订 | 该次修订保存时间 | 空间关联 R03 · 更新于 2026-11-11 10:10 |
| 正式规则版本 | 正式版本生成时间 | O01-V02 · 2026-11-11 10:15 |
| 发布 | 固定快照成功创建时间 | B01-P02 · 发布于 2026-11-11 10:30 |

以上均为格式示例。页面主标题只保留短编码和状态，时间放在第二行；选择器第一行编码，第二行时间与状态；表格使用独立时间列。跨场景复制引用为 S482731/B01-P02，时间可附带说明，但不参与标识解析或唯一性判断。

接口使用带时区的 ISO 8601 时间，存储统一 UTC，页面按产品时区设置转换，本地工作台默认 Asia/Shanghai。详情、导出及审计显示秒与时区；紧凑页面显示到分钟，完整时间可在详情查看。缺失时间显示“未记录”，不得用更新时间、迁移时间或发布时间代替构建完成时间。耗时根据真实起止事件计算，与显示版本号无关。

## 分配与变更

| 事件 | 处理 |
| --- | --- |
| 新建场景／资料／规则对象 | 服务端分配稳定对象编号 |
| 上传或替换同项资料内容 | D 不变，新增不可变 V；独立资料使用新 D |
| 修改资料名称或备注 | 记录编辑历史，不增加文件内容 V |
| 编辑构建草稿 | 不占正式 B；保留原草稿技术 ID |
| 服务端接受正式构建 | 分配 B 并固定输入版本、参数和执行依据 |
| 构建失败或取消 | 保留 B；再次正式构建使用新 B |
| 同一次构建内部执行尝试 | 使用 attempt 技术记录，不重复分配 B；输入或执行依据变化必须新建 B |
| 保存基本信息、空间关联、语义关联 | 有实际变更才增加对应 R；保存时支持并发修订检查 |
| 发布规则草稿 | 生成新的正式 V，不覆盖旧 V |
| 成功创建发布快照 | 在所属 B 下分配 P，绑定依赖清单 |
| 暂停、恢复、退役、下载 | 只新增状态或操作记录，版本不变 |

无变化保存与重复请求不能产生额外版本。同一幂等请求返回同一记录；显式创建新的发布快照才分配新 P。时间先后不能替代依赖绑定。

三类成果随 B 管理，不各自引入人工业务版本。单独派生保留产物 ID、派生修订、算法与摘要；不得覆写已发布引用。模型内容或构建输入变化形成新 B；同一模型下新的关联、规则或信息快照可以形成新的 P。

## 发布依赖与不变性

示例仅解释结构，不表示已有记录：

```text
S482731/B01-P02
├─ 构建 B01
│  ├─ 资料 D01-V02、D02-V01
│  └─ 输入清单、参数、算法／镜像版本、三类产物及摘要
├─ 空间关联 R03
├─ 语义关联 R05
├─ 本体规则 O01-V02
└─ 基本信息 R04 的快照
```

发布清单同时记录可读业务编码、真实技术 ID、确切修订、内容摘要及创建时间。编码是引用的可读标签，技术 ID 与摘要承担实际绑定与完整性校验。历史版本不读取当前最新版关联来冒充发布内容。

此规则不改变[构建任务与候选边界](../decisions/ADR-002-构建任务与候选边界.md)：B 表示正式构建记录，候选保留自身 ID 和审核状态。关联修订后，如现有实现要求生成新的不可变候选并重新核对，应继续该过程；不得直接拼接未经核对的最新关联。后续需显式记录候选与 B 的映射，不能把 candidate_id 字符串直接当成 B。

发布仍校验选定候选、预期修订、授权和依赖完整性。资料版本、本体规则、关联或基本信息已修改，不自动改写历史构建和发布。当前基本信息修改也不自动形成新 P，只有用户创建新发布时才固定新快照。

离线包继承发布号，另记录完整／分区规格、范围、包格式版本与摘要。包格式版本是技术协议版本，不与业务 V、P 混用。检查、操作、交付和下载使用记录 ID 与时间；消费端显式记录其采用的固定发布，不因新 P 出现而自动切换。

## 服务端与接口约束

- 编码由服务端分配并持久保存，前端不能按列表序号、时间、UUID 尾码或记录数量生成正式编码。
- 分配与业务记录采用事务或可恢复的原子提交；以作用域和序号建立唯一约束，并处理并发与幂等键。仅预留编号但提交失败可以留下空号。
- B、P、V、R 的序号采用数值字段，按数值排序；格式化不改变其含义。
- 现有 ID、URL、文件路径和外部绑定继续有效。接口增量提供对象编码、数值序号、完整展示码、来源构建映射及依赖快照，不用展示码替换原主键。
- 数据未补号时显示“历史记录 · 技术 ID”，明确为过渡状态；不得展示推测的 B 或 P。
- 本体规则已有版本字段与新 V 的对应关系必须保存映射，不能静默改变已发布规则版本或外部协议版本。

## 历史迁移

1. 先盘点场景、资料版本接替链、构建任务、候选、规则和发布之间的真实引用，输出迁移预览与缺失项。
2. 有可信创建时间的记录按创建时间排序，同时间用稳定技术 ID 决定次序。无可靠时间的记录单列审核，不推断业务先后。
3. 场景和对象补稳定编号；构建与候选映射核实后补 B，再按来源 B 补 P。资料接替链不明确时不得合并成同一 D 的多个 V。
4. 保存不可变旧 ID → 新编码映射。迁移完成后重复执行不重新编号，递增序号计数器从已分配最大值继续；场景随机号继续按全局占位去重。
5. 历史没有修订链的关联或基本信息显示“历史快照”；不补造过去的 R。下一次真实变更开始记录修订，并保留历史快照引用。
6. 先在副本演练并核对记录数、引用、摘要与回滚。补号映射不得改写既有签名文件或交付包；旧包通过外部映射解析，新包增量携带业务编码。

## 页面展示与验收

构建标题、版本选择和来源链接使用 B01；发布标题、选择、交付与消费引用统一使用 B01-P02。资料主列保留名称，邻近显示 V02，D 与完整引用在详情可复制。基本信息和关联默认显示最近更新时间，详情展示具名修订。所有业务日期包括年份，并按既定时区显示。

验收应覆盖：六位随机场景号冲突重试与全局唯一约束、删除后不复用、随机号容量与重试耗尽处理、时间时区转换和缺失值、并发创建唯一性、重复请求不增号、失败与取消不回收、内部 attempt 不误增 B、关联修改后旧发布不变、跨场景同短码不串用、超位数递增、历史补号可重复执行、旧链接和旧离线包继续可用。接口未提供持久化编码前，不将纯前端格式调整宣称为版本规则已落地。
