# 多智能体共用三维球

日期：2026-11-11。首版 SDK：0.1.0；CesiumJS：1.147.0。

## 架构与部署

采用“客户端共用引擎 + CoSpace 集中空间服务”。每个智能体界面在自己的浏览器中
渲染，复用 `packages/globe-sdk`，不为每个智能体部署一套三维后端或 GPU 串流实例。
CoSpace 继续在 worker02 `/srv/md0/cospace` 的现有镜像中部署。worker01 保留平台
管理职责。现有平台登录、订阅检查、场景授权和 S2S 服务调用继续使用原链路。

深度集成使用 SDK；轻量查看使用同实现的固定发布版本嵌入页。SDK 提供原生与 React
入口、相机指令、场景定位、按智能体区分的点/线图层及选择回调，不包含业务页面或登录。
SDK 是供 Vite 等打包器消费的 TypeScript 源码包，当前由仓库本地依赖接入，尚未发布 npm。
接口与接入示例见 [SDK README](../../packages/globe-sdk/README.md)。

AMap 仍负责二维地图，Cesium 负责真三维球，Three.js 继续负责未配准项目模型预览。
本轮不改地图设置入口、两列面板、原偏好键及用户选择。

## 数据与版本

统一 `/api/globe/config` 输出无密钥的影像、地形、资源路径及版本配置。
场景目录、发布内容继续由原授权 API 提供；私有数据不缓存为公共静态资源。
SDK 的 `spaceId + publicationId` 联合绑定保证不同发布图层不混用，数据授权由宿主
后端负责，不能依靠前端校验。外部智能体的服务令牌只保留在各自 BFF，沿用 S2S 授权。

嵌入页必须显式指定场景及发布版本，并再次调用当前发布预览 API 检查权限与分发生命周期。
无权访问、停用、撤回或缺失时拒绝展示，不替换为最新版。父页面仅可控制相机及定位
已绑定场景，不能发送令牌、任意数据地址、坐标或图层。消息校验协议、来源和窗口身份。

现有演示场景没有登记地理位置，因此不虚构场景落点。SDK 接收有效 WGS84 坐标；GCJ02
转换与模型配准仍待实施。当前嵌入页展示全球底图、地形及有坐标的场景标记，不表示
项目模型已经叠加到地球。真实外部智能体业务数据接入需在其产品中配置适配器。

## 运行配置

生产 Compose 可读取 worker02 `etc/globe.env`，缺省沿用当前 Esri 卫星影像与 ArcGIS
地形；不会自动扩大外部父页面授权。可选环境变量：

| 变量 | 含义 |
| --- | --- |
| `COSPACE_GLOBE_EMBED_ORIGINS` | JSON 精确 origin 数组，默认 `[]`，无通配符 |
| `COSPACE_GLOBE_IMAGERY_URL` | 公共 HTTPS 瓦片模板或同源路径，空值关闭 |
| `COSPACE_GLOBE_IMAGERY_CREDIT` | 供应商署名 |
| `COSPACE_GLOBE_TERRAIN_URL` | ArcGIS 地形服务地址，空值关闭 |

不允许在公共地址中携带账户、查询参数或令牌。跨域嵌入需先登记精确父源；浏览器
第三方 Cookie 受限时使用 SDK+BFF，不放宽当前 Cookie、CORS、CSRF 策略。
如需自有数据网关，仍由现有鉴权服务处理，不把凭据下发配置接口。

Cesium 静态资源随镜像打包，版本必须与引擎一致。首期保留现有服务提供者及署名，
依赖其可用性与使用条款；后续可按带宽及覆盖需求迁移合规对象存储/CDN，私有成果仍
需鉴权。无需目前引入独立瓦片集群或渲染集群。

## 发布

沿用 feature PR → 五项必需检查 → squash → release tag 构建镜像 → production
Environment 审核 → worker02 部署。源码及本地认证状态不直接上传服务器。

## 本地验证

生产构建与独立地图实验构建通过；57 项前端测试、93 项后端配置及业务授权相关测试
通过，生产依赖审计无已知漏洞。浏览器验证原地图设置、真实球体与全球地形、固定发布
嵌入握手及父页复位指令；错误发布版本的定位指令返回拒绝。尚未对真实外部智能体完成
产品级集成，未执行生产部署。
