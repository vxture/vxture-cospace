## 1. 架构决策

当前目标是解决园区模型必须完整下载后才能展示的问题，让用户先看到真实三维内容，随后按视野细化，并在需要时进入精确工程作业。

采用“成熟底座、业务集成、进阶优化”三个职责层次：

1. 成熟底座采用已有的大型点云转换工具和渲染引擎，负责层级读取、LOD、可见性选择、解码和渲染。当前园区点云默认采用 Potree 稳定版及经兼容验证的 PotreeConverter 稳定版。
2. CoSpace 负责固定模型版本、场景鉴权、坐标基准、工程选点、对象关联及发布流程。通过独立适配层接入底座，不重新实现一套通用点云引擎。
3. 进阶优化在成熟基线上增加作业区域优先、预算自适应等策略，通过开关与成熟基线对照。未达到提升门槛则保留基线运行，不拖延成熟版本发布。

“行业最成熟”在这里是选型和验收要求，不是未经验证的产品排名。不能只使用成熟格式，却把加载、调度、缓存全部自行重写后宣称已达到成熟水平；也不能仅接入成熟组件，就推定整个平台具有同等性能。

本次修订替代前稿中“以自有二进制分块和自研调度作为主线、标准格式以后再接”的安排。自有分块保留兼容用途；成熟路线从第一批选型及主查看器实施就开始使用。

范围仍聚焦空间模型显示能力。语义本体、原始成果、机器人运行数据分别保持独立，不新增业务导航。

## 2. 现状与问题依据

以下是 v0.13.7 的问题盘点。L01 已替换主浏览显示路径；L02 继续替换配准及空间关联的工程读取路径，不表示下表仍是所有当前页面的行为。

| 链路 | 当前行为 | 必须修正的结果 |
| --- | --- | --- |
| 主空间查看器 | real-space-data.ts 完整读取 human.ply 和 views.js，校验、解析后才返回 SceneData | 视觉浏览不等待完整模型或全部计算单元 |
| 画布挂载 | real-space.tsx 等待 SceneData 才创建画布 | 先初始化稳定画布，数据按需进入 |
| 解析与显存 | 主线程解析 PLY，并复制位置、颜色及计算表达 | 使用成熟二进制加载路径和解码 Worker，降低复制及主线程阻塞 |
| 小型核对预览 | 流读取后仍拼接整份 JSON；已有 1 万点、2 MiB 上限 | 保留轻量核对用途，不把它包装成大模型流式能力 |
| 资料分块工作区 | 已有 3 级 LOD、摘要、LRU，但串行读取、相机变化先清空 | 保留兼容入口及经验，不继续作为新主引擎扩建 |
| 大范围视图 | 当前 planner 超过 96 块或粗层超过 15 万点会拒绝显示 | 采用层级概览和按视野细化，在预算内持续有图 |
| 服务端 | PreviewModel 初始化会遍历校验源成员并读取 agent.npz；发布读取还可能重复校验 | 元数据和当前范围读取不得触发无关整模解码 |
| 复访 | 授权业务响应统一 no-store | 首版只承诺当前访问上下文中的内存复用 |

分别测量入口脚本、授权与元数据 TTFB、传输、校验/解码、GPU 上传、第一个真实交互帧。后端预处理和前端显示都纳入链路，避免只改下载进度条。

## 3. 成熟基线的明确选型

### 3.1 按数据类型使用成熟路线

| 数据类型 | 默认路线 | 本轮边界 |
| --- | --- | --- |
| 当前园区点云 | Potree 稳定渲染器 + 兼容稳定版 PotreeConverter，采用其原生八叉树派生与加载机制 | 第一版交付主线，先完成真实生产样本闭环 |
| 建筑网格、倾斜摄影、BIM 显示派生 | 3D Tiles 1.1 + glTF，复用现有 Cesium 生态 | 保留适配接口，按需求后续接入，不作为点云首版前置条件 |
| 点云存储与交换 | 保留原始成果；COPC 1.0 作为后续可选标准化派生/读取路线 | 只有实际 reader、解码、Range、精度验证通过后才启用，不假定 Potree 任意版本直接支持 COPC |
| 地理底图与地球场景 | 继续使用现有 MapLibre/Cesium 能力 | 共享坐标基准和固定配准结果 |
| 既有私有二进制分块 | 兼容适配器 | 不作为长期唯一格式，不重建新的通用引擎 |

Potree 是成熟开源实现及其公开格式生态，不等同于 OGC 标准。3D Tiles 是空间组织规范，glTF 是内容格式，COPC 是点云组织格式；三者不能混称为同一个加载引擎。I3S 作为成熟行业参照和未来互操作方向，本版不同时建设多个等价后端。

PotreeConverter 的 2.x 路线可将派生组织为少量文件并按层级/字节范围读取。因此“不全部下载”不要求“把模型拆成数万个小文件”。真正必要的是空间索引、多精度组织、可按需寻址和支持该组织的成熟加载器。

### 3.2 稳定版本与集成边界

实施前锁定渲染器、转换器、解码器的兼容版本、提交摘要、构建产物摘要与许可证清单。官方 develop 分支和 README 用于调研，不能直接作为生产版本锁。首版采用已验证的 WebGL 路线，不把实验性 WebGPU 重写当作成熟保障。

现有工程画布使用 Three.js 0.187.0 / three/webgpu；Potree 与其自带或依赖的 Three.js 版本不能默认混用：

- 通过独立 PointCloudEngineAdapter 管理引擎生命周期、相机、坐标变换、选择事件与资源释放。
- 渲染实现可替换；同一视口只启用一个主渲染器，不在同一个场景中混放不同版本的 Three 对象。
- 引擎资源按需加载并隔离依赖，不为接入点云整体降级平台 Three，也不全站切换到 Cesium。
- 保留现有业务页面、DS 组件与状态管理；采用自有操作界面，不直接引入整套第三方查看器菜单和导航。
- 如果确需独立运行环境，仍通过受控桥接传递相机、选点和版本状态；不能绕过现有会话授权。

转换器是否支持现有 PLY 的字段、精度及颜色，在选型实验中实际核验；需要中间 LAS 时，明确 scale、offset、属性及重排规则，并检查量化误差。原始 PLY 始终保留，格式转换不能静默丢失工程来源。

若默认组合不满足硬性要求，只在本次选型中转向有完整转换与渲染链路的成熟替代方案，例如 Cesium + 3D Tiles 点云内容；必须先证明替代链路通过同样门槛。不能为赶发布改成自研引擎并沿用“成熟基线”结论。

### 4.1 原始成果、显示派生、精确查询分离

| 数据 | 职责 | 读取方式 |
| --- | --- | --- |
| 固定原始成果 | 原始精度、固定发布及离线交付的依据 | 后端计算或用户明确下载 |
| 原生显示派生 | 用成熟格式提供层级、多精度、颜色及必要显示属性 | 按视野、层级或范围读取 |
| 业务引用清单 | 绑定固定模型、派生入口、坐标契约和访问上下文 | 轻量入口 |
| 来源与完整性侧索引 | 派生器版本、源摘要、文件/范围摘要、完成状态 | 发布验证及实际读取时使用 |
| 对象索引 | 对象 ID、锚点、类型和详情引用 | 目录分页，详情按需 |
| 精确查询索引 | 在固定原始成果中定位局部原始点/几何要素 | 工程作业按需 |
| 计算表达 | 智能体表面单元等计算数据 | 用户主动切换或计算时读取 |

显示派生可重新生成，不覆盖源成果，不修改已有发布文件。新派生按“源摘要 + 转换器及参数版本”去重，完整验证后原子标记就绪。历史成果异步补建，浏览请求不临时转换整模。

### 4.2 业务清单保持轻量

业务清单只负责业务契约：schema 版本、固定模型/发布引用、源摘要、派生 ID、provider 与格式版本、原生 metadata/tileset 入口、坐标转换引用、来源与完整性索引引用、精确查询能力。

原生格式已经定义的八叉树、包围体、层级误差和节点偏移直接使用，业务清单不复制第二份层级结构。计算单元中心、全部对象详情、完整点数组都不进入首屏清单。

元数据入口目标不超过 50 KiB；更深层级与大对象目录按原生机制或分页读取。该值是待验证的入口预算，不要求所有成熟格式都改造成同一种私有文件结构。

## 5. 成熟引擎与 CoSpace 的职责

| 能力 | 负责方 | 原则 |
| --- | --- | --- |
| 空间层级遍历、可见性、原生 LOD | 成熟引擎 | 按其格式和推荐机制运行 |
| 网络队列、解码、几何缓存、渲染 | 成熟引擎及其原生扩展点 | 先调优成熟实现，不另设相互争抢的通用调度器 |
| 授权请求、固定版本绑定、范围完整性 | CoSpace 分发与适配层 | 所有读取都处于现有场景权限边界 |
| 业务页面、加载状态、诊断埋点 | CoSpace | 多页面共享同一能力契约 |
| 坐标基准、原始点查询、工程确认 | CoSpace 工程服务 | 与显示 LOD 分离 |
| 作业区域优先与设备策略 | 后续可关闭策略 | 优先通过成熟 API 提示；无有效扩展点则不强行侵入内核 |

首版需要实际验收的运行行为：

- 首屏不依赖完整 human.ply、agent.npz 或 views.js 中的全部计算单元。
- 全景入口优先建立可交互概览；已知目标对象入口优先目标区域及必需祖先；小模型可直接显示。不存在所有入口必须等全局根层完成的统一前置条件。
- 相机变化后保留同版本可用画面，按引擎机制细化；局部缺块不清空整个模型。父层保留或增量显示须遵循原生替换/增量语义，避免重复叠加。
- 通过成熟引擎配置限制网络、解码、GPU 上传及内存占用。首批用真实设备确定点数、字节和并发预算，不把旧有 15 万点或“并发 4”当作永久标准。
- 采用原生 Worker/解码器；补充校验时使用 Worker 和 transferable 数据，避免在主线程增加全量校验与复制。
- 视口变化不会反复下载仍有效的在途资源，旧模型请求不能写入新模型。引擎若不满足，必须修正适配或更换成熟组合后再发布。
- 页面切换和卸载正确释放监听、Worker、几何、纹理及 GPU 资源。不得只清空 React 状态而保留引擎实例。
- 浏览器能力不足时降低有界显示预算或明确提示；旧整包入口仅作已知小模型的显式兼容路径，不称为流式加载回退。

## 6. 服务端、Range 与缓存

### 6.1 移出整模前置工作

热路径拆为“鉴权与固定版本确认 → 小元数据 → 实际请求范围”，不构造无关的完整 PreviewModel 或计算单元。

构建及发布入库时执行全量校验，并建立可追溯的就绪记录。运行时依赖受控只读成果、摘要绑定与可靠失效机制读取可信元数据；不能只用文件名、mtime 或 TTL 代替完整性。

实际读取的资源/范围仍须完整性验证。若采用摘要侧索引，沿用原生节点范围或固定字节验证区间；范围不对齐时按验证区间有界读取后截取，不为一次 Range 重新哈希整包。端到端验证方式属于第一批选型门槛，不能为适配第三方引擎取消现有校验要求。

### 6.2 Range 是第一版基础条件

Potree 原生少文件路线可能依赖范围读取，必须一起打通应用服务、反向代理及实际生产域名：

- 正确处理 Range、206、Content-Range、Content-Length 和不可满足范围的 416。
- 严格检查资源归属、固定版本及范围边界；普通读取与 Range 读取执行相同授权。
- 保持字节偏移对应固定表示，不对已编码范围资源进行破坏偏移的动态重压缩。
- 配置每次及并发范围的服务预算，避免无界读入内存；请求取消后正确释放流。
- 跨域时仅开放确需来源及响应头；首版优先同源授权读取，不把受保护资源变成公开 URL。
- 通过网络证据确认实际返回 206。代理若将 Range 悄悄改成 200 整文件，不算完成。

HTTP 流读取、断点续传或 CDN 都不能单独解决空间按需读取。即使源文件只有一个，也必须具备空间索引和相应加载器。

### 6.3 分开处理业务缓存和公共静态缓存

第一版保留授权业务响应 no-store，仅使用受账户、组织、场景和版本约束的内存缓存；退出、撤权或上下文失效时清除对应资源。公开引擎静态资源继续采用现有内容哈希缓存。

资源身份不可变，不代表资源可以 public 缓存。持久化私有分块缓存、Service Worker 和 CDN 鉴权属于后续独立事项，需验证隔离、重验证与撤权后才启用。首版不宣传跨会话“复访秒开”。

## 7. 精度与工程作业契约

地图精度继续独立于机器人定位精度。源测绘精度、坐标表示误差、LOD 采样稀疏程度、配准残差分别表达，不混成一个“精度”。

- 原始坐标、控制资料和配准结果保持来源精度。大坐标使用双精度变换与局部原点，再进入渲染坐标，不能直接把大地坐标塞入 Float32。
- 厘米级作业下，新增坐标编码及坐标往返误差目标为各轴不超过 1 mm；这是待验证的数值误差预算，不是宣称源地图具有毫米精度。LOD 采样不在该数值预算中，其几何偏差单独评估。
- 精确选点绑定模型摘要、源文件/要素引用及稳定原始 ID。转换会重排点序，LOD 数组下标、临时 GPU 索引和转换后点序不能直接作为原始 ID。
- 若转换器不能保留可靠来源映射，采用独立的原始精度空间索引：由显示点击给出候选区域/射线，在固定原始成果中查询，返回原始 ID 与原始坐标供确认。不能假设标准格式天然具有所需 ID。
- 粗层点击用于导航和候选定位；只有精确原始数据已就绪且查询结果明确时才能确认工程坐标。多个表面有歧义时让用户选择，不自动吸附到不明对象。
- 控制点、对象锚点和配准参数可独立读取，显示细化不得移动已确认锚点。残差继续依据原始控制资料计算。
- 工程确认记录所用模型版本和坐标变换版本。切换模型、变换或会话后拒绝沿用过期精确查询结果。

主浏览首版先证明显示转换和坐标往返正确，不把未完成的精确选点暴露给用户。下一版工程接入必须完成原始 ID、局部查询和确认门槛，再替换现有作业能力。

## 8. 用户体验与界面约束

进入页面先出现稳定的画布框架与版本信息，然后显示真实几何。封面、骨架屏和下载进度条不计为“模型可用”。

浏览状态采用“可浏览、当前视野细化中、当前视野已就绪”；工程状态另设“精确数据准备中、可确认”。局部视野完成不能叫“完整模型加载 100%”。

同版本局部失败保留可用内容，提示局部重试；会话失效、权限撤销或版本绑定失败时停止读取并清理不再有访问依据的内容。

继续使用公共内容容器和 DS token，保留底部安全区域。操作行与图标按钮保持 32px，辅助状态文字 12px；不增加多行解释头部、二次导航或调试卡片。正常页面把空间留给作业画布，性能统计进入诊断面板。

## 9. 领先性挑战：独立验证的进阶能力

层级流式、LOD、SSE、视野中心优先、相机运动裁剪、缓存预算和预取均已有成熟行业实现，不作为 CoSpace 创新点。语义、构件属性、高精度渲染和测量也不是独有能力。

领先性聚焦目标用户的实际任务：从园区模型进入指定对象、精确选点或配准核对，能否在相同显示质量与精度下更快、更稳定、更省资源。

| 挑战方向 | 设计假设 | 相对集成成熟基线的目标 |
| --- | --- | --- |
| 作业区域优先 | 用已知对象、控制点和编辑区域提示加载局部高精细数据，并保留必要上下文 | 目标区域达到精确作业就绪的 P75 时间减少至少 30% |
| 受约束的预算自适应 | 根据网络、解码积压、GPU 预算及交互状态调节成熟引擎公开参数 | 弱网移动后当前视野就绪的 P75 时间减少至少 20% |
| 无效传输治理 | 利用明确的作业目标和相机稳定状态，减少短期内无用读取，不追踪或猜测无关业务 | 标准路径中未使用传输字节减少至少 30%，同时真实就绪时间不变差 |
| 园区工程流程衔接 | 保留固定模型、对象、配准和服务版本上下文，减少重复打开和定位 | 同任务步骤、完成时间及错误率优于本产品成熟基线，逐项提供记录 |

以上都是挑战目标，尚无实测结果，也不宣称优于所有行业产品。精确作业优先加载属于现有思路的场景化优化，只有经过对照才可声明在所测任务上有优势。

采用功能开关，按同数据、同设备、同网络、同质量对照“策略关闭/开启”。至少在两种代表性园区及弱网条件下复现，达到对应提升目标，且优势的 95% 置信区间不跨越零，才进入默认启用评审；样本不足则继续收集。任一坐标正确性、权限或版本一致性退化直接停止启用。非目标场景的就绪时间、交互帧时间及峰值内存不允许出现超过 10% 的回退。

进阶策略异常时关闭策略回到同一个成熟引擎及数据版本，不回退到整模下载。首版不引入大模型实时决策、试验性渲染内核或全新空间格式。

## 10. 对照方法与发布门槛

### 10.1 区分四组结果

| 对照组 | 用途 |
| --- | --- |
| B0：现有 v0.13.7 | 测量当前问题，证明改造收益 |
| B1：成熟引擎参考页 | 在相同平台外壳、鉴权网关、原生派生和配置下，建立可复现参考 |
| B2：CoSpace 集成成熟基线 | 加入业务状态、版本及监测，进阶策略关闭；作为第一版交付 |
| B3：CoSpace 进阶策略 | 在 B2 上开启单项策略，用消融对照解释收益 |

同时保存成熟引擎默认配置和经过合理调优的配置，主比较使用适合该场景的调优结果。禁止故意压低对照预算、降低对照并发或拿弱配置当行业基线。

B1 与 B2 使用相同派生，以衡量集成成本；B0 与 B2 同源但允许不同显示组织。跨格式对比需匹配颜色、可见覆盖、采样密度/几何误差和工程精度，不能单纯比较点数或字节数。

### 10.2 指标必须反映可用性

- T_model：进入页面到首个真实、覆盖目标初始视野且可操作的三维帧。封面不计入。
- T_view：相机停止后，当前视野达到预设显示质量且稳定的时间。
- T_exact：发起工程操作后，目标区域原始精度数据、来源与坐标变换可核验并可确认的时间。
- 同时记录传输字节、未使用字节、TTFB、长任务、P95 帧时间、CPU 峰值、GPU 内存估算、失败恢复及转换耗时/派生体积。

T_exact 从工程接入批次开始验收；不能用 T_model 代替。未使用字节的操作性定义是：基准路径结束并等待 10 秒后仍未参与任何可见帧或精确查询的数据字节；局部使用按可观测的节点/范围粒度归类，所有组采用相同规则。

### 10.3 建议绝对目标与成熟基线门槛

以下是拟定验收目标，不是已经达到的成绩。L00 先固定测试硬件、样本、视口及画质，再锁定预算；若不满足，需记录瓶颈并修正实现或阶段范围，不能在结果出来后静默放宽门槛。

| 条件 | T_model 目标 |
| --- | --- |
| 20 Mbps / RTT 50 ms，引擎静态资源已缓存、业务数据冷 | P75 ≤ 2 秒 |
| 20 Mbps / RTT 50 ms，应用与业务全冷 | P75 ≤ 4 秒 |
| 5 Mbps / RTT 100 ms，全冷 | P75 ≤ 8 秒 |

拟定桌面档为 16 GB 内存、集成显卡笔记本、1920×1080、DPR 1；报告必须补充实际 CPU、GPU、浏览器版本。较窄视口另测，不用缩小窗口掩盖桌面负载。

B2 相对 B1 的 T_model、T_view 的 P75 额外开销不超过 max（B1 的 10%，200 ms）。交互目标为 P95 帧时间不超过 33.3 ms，持续测试内存受配置预算约束，资源淘汰后不随路径循环持续增长。若 B1 本身不满足绝对目标，仍需调整数据转换、配置或成熟组合，不能仅证明“不比参考页差”就发布。

上述门槛同时覆盖性能、工程正确性和故障行为：无整包前置依赖、同版本无闪空、无旧版本混入、无无限内存增长、无近似坐标误确认。权限与完整性检查不得因性能优化而减少。

### 10.4 样本与测试条件

- 当前 5 个生产场景及其固定版本；独立合成的百万、千万点及更大压力样本，明确标注非测绘成果。
- 开阔园区、密集厂房、细长设施/薄结构、大坐标和厘米控制点；以画质检查和可复现路径覆盖。
- 冷启动、引擎热/业务冷、当前会话内复用分别测量；同场景随机化测试顺序，每个组合至少 30 次，报告 P50/P75/P95 和置信区间。
- 固定初始相机与操作路径，覆盖持续拖动、快速跳转对象、视觉/计算切换、场景切换、连续开关页面。
- 测试缺失/损坏范围、错误 200 整包响应、416、网络中断、401/403、版本变化、撤权、派生未就绪及超预算。
- 使用服务端日志、浏览器网络记录和运行指标共同确认按需读取。生产样本性能和合成容量分开报告，不预先声称支持上亿点。

## 11. 按批次实施与发版

本计划使用 L00–L03 标识加载专项，避免与既有业务批次混淆。挑战研究不成为成熟基线版本的发布前置条件。

| 批次 | 内容 | 具体交付与退出条件 | 版本边界 |
| --- | --- | --- | --- |
| L00：成熟路线验证 | 锁版本与许可证；真实 PLY 转换；Potree 隔离集成；生产同构鉴权 Range；坐标往返；B0/B1 测量 | 可运行验证页、固定样本、配置与证据、选型决策、预算；默认组合不通过则验证成熟替代方案 | 技术验证，不新增业务导航，不单独宣称完成上线 |
| L01：主浏览成熟版 | 新构建及历史显示派生；主查看器适配；视觉/计算/对象解耦；服务端热路径；诊断与故障恢复 | 候选及固定发布按需显示，5 个生产场景覆盖，B2 通过绝对目标与成熟参照门槛；旧小模型兼容入口明确 | 第一版仅发布主空间浏览闭环 |
| L02：工程统一消费 | 地图配准、全屏编辑、空间关联接入；局部原始数据、稳定 ID 和确认门槛 | 精确作业、清单/图形联动、残差及历史锚点回归；可报告 T_exact | 下一版发布工程作业能力 |
| L03：领先性挑战 | 作业优先、受约束自适应、无效传输治理，分别做开关及对照 | 单项达到挑战与不退化门槛才启用，不通过保留成熟模式 | 独立迭代，不扩张前两版范围 |

网格/BIM、COPC 适配、持久化私有缓存和远端分发按真实需求另立批次。本专项不承担机器人消费协议、新本体功能或新模型重建算法。

L01 的“完成”要求主空间页不再等待完整 human.ply，也不等待计算表达，模型变大时相同视野不能触发全量传输。仅提供演示预览、第三方独立页面或加载进度条不算业务完成。

所有代码实施继续走 feature branch、PR、五项必需检查与发布镜像；部署等待 production reviewer。本文修订不触发生产变更。
