# 服务对象与具身智能体接入设计

日期：2026-11-13
状态：2026-11-13 第一期登记与空间关联已在本地实施，待发布；厂家身份、业务接入及使用事件仍待联调。实际登记契约见 `../../contracts/schemas/service-recipients-v0.1.md`，后文接口草案与后续分期不代表现有能力。

## 1 设计结论

在「空间服务 → 服务对象」增加主操作 **添加智能体**，用于登记无人机、机器狗及其他机器人，并建立其与空间服务的关系。

添加流程以设备形态为第一选择，以空间数据采集、空间服务使用为独立的接入用途。名称只是便于识别的显示信息。设备形态不预设用途、权限或作业适用性；同一台智能体可以在同一空间同时采集数据和使用服务，也可以在不同空间承担不同用途。

CoSpace 为外部作业提供空间数据接入、共享空间成果和使用记录。实际飞行、行走、巡检任务及设备安全由厂家或行业系统负责。本模块管理服务关系，不扩展为设备控制台或行业工单系统。

## 2 产品定义依据

依据仓库根目录《共享态势模型-产品定义与规划.docx》，下列章节直接影响本方案。这里使用原文章节定位，不推测页码。

| 原文章节 | 关键描述 | 设计落点 |
| --- | --- | --- |
| 产品定义 一句话 | 来自不同设备、不同时刻的传感器数据形成可共享底图，并以标准接口供机器人和业务系统消费 | 同时支持数据提供方与成果使用方，同一智能体可以兼任 |
| 边界约定 不做什么 | 无人机、机器狗、轮式底盘、固定站由行业方案选型；传感器由行业方案配置 | 设备形态与传感器分开描述；不绑定指定厂家或硬件 |
| 六大能力项 | 多源接入归一时间和坐标、入库前预检；产物是标准观测，不是地图 | 空间数据采集提交进入资料接入和预检，不直接变成已发布成果 |
| 三个契约面 | 南向接入；北向读取空间及提交观测反馈；平台发布、查询、对账与追溯 | 原始数据采集、空间服务使用、态势反馈分别承接，避免混为一个接口 |
| 产品验证 六个是 | 同一份底图按不同机器人平台产生不同通行判断 | 预留尺寸、运动方式等适用参数；仅登记形态不承诺可通行或实机可用 |
| 成本结构 | 建图侧和消费侧不要求同构，通过底图与坐标系对齐 | 数据采集与服务使用互不依赖，不要求服务使用设备具备建图传感器 |

## 3 术语与设备形态

### 界面术语

「空间采集」收敛为「空间数据采集」，明确采集的是点云、影像、轨迹和观测数据；「空间引用」改为「空间服务使用」，明确智能体通过在线或离线方式使用平台提供的底图、空间表达和查询能力。两者作为接入用途，可独立选择或同时选择。

这是结合产品定位选用的界面用语，不宣称是某项行业标准规定的术语。测绘与机器人领域常以数据采集、传感器数据接入描述输入侧，以地图使用、地图服务、查询或服务调用描述使用侧；具体词语取决于系统边界。「引用」更适合版本引用、对象引用、坐标参考等技术关系，容易让用户理解为关联操作，不能充分表达成果在端侧实际使用。

完整选项采用「空间数据采集」「空间服务使用」；在服务对象页面的紧凑标签中可简写「数据采集」「服务使用」。表单字段采用「接入用途」，不称为作业类型；服务使用方式采用「在线服务」「离线成果」。提示语采用「向平台提供空间观测数据，用于建图与更新」「使用共享空间底图与查询能力，支撑智能体作业」。

「空间感知」可能包含端侧识别、定位和环境理解，「自主作业」可能包含任务规划与运动控制，均不适合作为此处用途名称。「空间建图」只覆盖采集后的部分处理流程，也不用于替代数据采集。「空间数据消费」可用于技术文档描述消费端，面向用户时统一写服务使用。空间服务使用是离线成果与在线调用的上位概念，不应缩写为只覆盖在线接口的「服务调用」。

### 设备形态

添加面板首先展示六个形态选项，以轮廓图标配合文字。所有选项使用同一登记流程；图标不使用具体厂家产品外形。

| 设备形态 | 示例提示 | 形态代码 |
| --- | --- | --- |
| 飞行式 | 无人机 | `aerial` |
| 四足式 | 机器狗、四足机器人 | `quadruped` |
| 轮式 | 轮式机器人、移动底盘 | `wheeled` |
| 履带式 | 履带机器人 | `tracked` |
| 人形式 | 人形机器人 | `humanoid` |
| 其他形态 | 其他足式、复合移动等，补充说明 | `other` |

无人机、机器狗是帮助用户理解的例子；「机器人」覆盖多种形态，不与四足式、轮式等重复成为同一层级的选项。复合设备选择主要作业形态，附加运动方式记录在扩展参数中。固定站不混入本次移动智能体快捷选项，未来可按采集终端需求独立扩展。

以下信息分别保存：

- 设备形态：设备如何承载和移动，是列表分组与筛选依据。
- 显示名称：用户自定义，可修改，不承担唯一身份职责。
- 厂家、型号：辅助匹配适配器与兼容配置，不决定权限。
- 内部智能体 ID：系统生成且稳定，不随改名、换型号描述或关联空间变化。
- 外部设备标识：厂家实例 ID 或序列号；有厂家身份域时按「租户工作区、厂家身份域、外部 ID」防重复，单纯厂家显示名称不作为身份域。
- 接入用途：记录在每条空间关系上，可选择数据采集、服务使用或两者。

添加面板不要求用户填写长宽高、转弯半径、载荷、飞行包络等运动参数。后续确有机器人视图适配需求时，在详情的「适用参数」中配置带版本的配置档案；缺失参数显示未配置，不根据形态或名称推算。

## 4 接入用途

### 空间数据采集

界面说明：**向空间提供采集数据，用于建图或更新。**

可登记提供点云、影像、轨迹、定位及传感器观测等数据的意向能力，实际可接收的数据以已实现格式契约为准。对接后须携带空间、设备来源、采集时间、参考系、数据类型和内容摘要；相机内参、传感器外参、时间同步及位姿要求按具体格式补充。

采集内容进入已有资料接入、质量预检、构建和发布链路。接收成功不表示预检通过，也不表示底图已经更新。无基线版本的首次采集可以登记和提交；有基线时单独记录其发布 ID。

态势变化反馈继续进入「态势反馈」模块，反馈权限单独授予。勾选空间数据采集不自动开通反馈权限，使用空间服务的设备也不强制具备反馈能力。

### 空间服务使用

界面说明：**使用空间底图和查询服务，为定位、理解环境与作业提供依据。**

空间服务使用包括在线查询和离线成果使用，覆盖共享底图及其可计算表达。实际定位、路径规划、避障、飞控等能力取决于厂家系统和后续经过验证的空间能力，不因登记而获得承诺。

服务使用支持独立选择「在线服务」「离线成果」，两者均可选。每条在线配置、交付和应用记录绑定明确的成果版本；新发布不覆盖原记录。关系可在尚无发布时先登记为待配置，不能获取不存在的成果。

### 用途组合

| 用途选择 | 典型情况 | 不要求的前置条件 |
| --- | --- | --- |
| 仅空间数据采集 | 无人机提供建图资料 | 不要求先下载底图或绑定消费版本 |
| 仅空间服务使用 | 轮式机器人使用共享底图 | 不要求采集数据或具备建图传感器 |
| 数据采集与服务使用 | 机器狗使用底图作业，同时提供补测资料 | 两项能力分别授权、分别记录结果 |

以上均为示例，任意形态都能选择三种组合。用户选择的是用途；厂家声明的能力、已验证的适配能力、平台实际授权分别展示。

## 5 页面与添加流程

### 全局服务对象

路由继续使用 `/services?section=recipients`。内容改为智能体实例列表，一条记录代表一台设备，主按钮为「添加智能体」。

搜索支持名称、智能体 ID、外部设备标识、厂家和型号；筛选支持设备形态、接入用途、关联场景和接入配置状态。关联场景是此列表内的筛选，不新增页头场景选择器，也不复用现有代表场景服务详情的 `space` 参数。

列表列项：智能体名称与标识、设备形态、厂家与型号、关联场景、接入用途、接入配置、最近接入事实、操作。较长信息放详情，不把所有版本堆到总表。一条对象在不同场景用途不同时，总表显示用途汇总并标注「按场景配置」。

```text
服务对象                                      [添加智能体]
管理具身智能体的接入用途、服务关联与接入记录

[搜索智能体…] [设备形态] [接入用途] [关联场景] [接入配置]

智能体       设备形态   厂家/型号   关联场景   接入用途   接入配置   操作
巡检设备 01  四足式     待补充      2 个       采集 使用  待对接     查看
```

以上名称和记录仅为设计示意，实施时无真实记录即展示空态。

### 添加智能体

沿用 DS Drawer，桌面右侧打开，移动端使用适合窄屏的完整宽度。采用两步流程，避免把厂家参数和空间权限塞进一个长表单。

**第一步 设备信息**

1. 先选择设备形态，必填，默认不代选。
2. 填写显示名称，必填；可按形态给出可编辑建议，例如「四足智能体 01」。名称允许重复，列表通过标识区分。
3. 厂家、型号、外部设备标识、负责人为可选；其他形态须补充简短形态说明。组织与工作区归属来自当前授权上下文。
4. 下一步进入接入用途；可以返回修改，未保存内容保留。

**第二步 接入用途**

1. 选择当前有权关联的场景，可添加多行，每行一个场景。
2. 每行独立勾选「空间数据采集」「空间服务使用」，关联时至少选一项；不依据形态预选。
3. 选择服务使用时展示在线服务、离线成果偏好；允许暂不配置具体接入和版本，明确显示「服务使用方式待配置」。
4. 厂家对接只选择「稍后对接」或已有适配方案。本期默认稍后对接，不填写虚构地址或凭据。
5. 可选择「暂不关联空间」，仅保存设备登记。此时明确显示「未关联空间」。
6. 底部按钮为「上一步」「取消」「保存登记」。保存成功进入对象详情，提示「已登记，接入尚未验证」。

保存登记同时写入对象与选定用途关系，失败时整体回滚，避免显示登记完成而关系丢失。提交中防重复；服务端通过登记幂等键处理重复提交。重名可保存；已验证身份域中的重复外部标识提示查看已有对象。

### 单场景服务对象

沿用场景服务页的「服务对象」页签，仅显示当前场景的关系与对应用途。主操作为「关联智能体」，可搜索已登记对象，也可从选择面板进入「添加智能体」。新建流程预填当前场景，设备形态和用途仍需用户选择。

一个对象与同一空间只有一条有效关系；重复关联进入编辑。解除关系只终止当前场景服务，不删除对象与历史。撤销采集不得影响仍允许的服务使用，反之亦然。

关系是场景层数据，不受页头查看版本筛掉。列表按每条记录显示实际关联版本；如支持「仅查看当前版本记录」，须由用户显式切换。当前代码在版本缺失时会隐藏全部页签内容，实施时需让服务对象页签独立读取场景关系，使尚无成果或版本失效时仍能登记采集关系，并继续进行场景授权校验。

### 智能体详情

详情采用四个页签：

- 概况：形态、名称、标识、厂家型号、登记来源、配置状态。
- 关联空间：逐场景展示用途、关系状态、能力授权与配置缺项；可关联、编辑或解除关系。
- 接入配置：厂家适配方案、身份绑定、协议版本、兼容数据类型、验证结果；技术参数折叠展开。
- 使用记录：采集提交、在线查询、交付、导入确认及实际应用版本上报，各自显示时间与事实来源。

设置「编辑信息」「关联空间」等操作。首期不提供启动任务、起飞、返航、运动控制或设备启停按钮。

## 6 状态与事实来源

状态分开展示，不合并成一个容易误读的「正常」。

| 维度 | 建议显示 | 含义 |
| --- | --- | --- |
| 登记 | 已登记、已归档 | 管理记录是否有效 |
| 空间关系 | 有效、已解除 | 服务关系是否保留；有效不表示已授权接入 |
| 接入配置 | 待对接、待验证、验证通过、需关注 | 按适配方案和独立能力展示；验证通过须记录版本、范围和时间 |
| 能力授权 | 未授权、已授权、已撤销 | 服务端可执行的授权事实，与用户勾选用途分开 |
| 接入活动 | 最近有效请求、最近接收、暂无记录、实例未识别 | 接口观测；不表示设备在线或运行健康 |
| 成果使用 | 已登记交付、人工确认导入、设备上报应用 | 不同来源的独立事件，不互相推导 |

没有实例心跳协议时不显示在线率、在线台数或设备故障。一个调用身份代理多台设备时，没有经过验证的实例绑定，只展示调用身份级活动；不得把相同调用次数分配给每台设备。

配置验证不等于实机作业验收。当前在线查询仍存在观测时钟未核验、`robot_ready=false` 等约束，新增对象后继续保留，不能因选择某种设备形态而变为可实时作业。

## 7 最小数据设计

| 实体 | 主要字段 | 规则 |
| --- | --- | --- |
| 智能体实例 `agent` | 内部 ID、租户工作区、形态、形态说明、名称、厂家型号、外部设备标识、负责人、状态、修订号 | 名称可变，ID 稳定；登记不自动授予服务能力 |
| 空间关系 `agent_space_relation` | 智能体、空间、数据采集/服务使用用途、服务使用方式偏好、关系状态、修订号 | 多对多；每对象每空间一条有效关系；授权单独引用权威记录 |
| 接入绑定 `agent_binding` | 智能体、厂家身份域、适配器版本、可信调用身份、验证证据引用、能力范围、状态 | 未验证的外部 ID 不能作为请求归属依据 |
| 服务配置 `agent_service_profile` | 关系 ID、能力、数据契约或固定发布、参考系、兼容配置引用 | 采集可无基线；服务使用按配置或事件绑定固定发布，不在实例上设唯一全局版本 |
| 事实事件 `agent_service_event` | 对象或可信调用身份、空间、能力、事件类型、版本或批次、来源、时间、摘要、幂等键 | 追加式记录；观测时间和接收时间分别保存，保留未知值 |

凭据仅引用平台或服务端安全配置，不作为普通实例字段保存，不返回浏览器。运行数据和证据正文使用受控存储，记录持有引用和摘要；不入 Git。扩展参数使用明确版本的档案，避免任意键值成为主业务字段。

## 8 厂家对接的简化设计

统一方向为「厂家设备或厂家平台 → 厂家适配层 → CoSpace 空间契约」。可由设备直连，也可由厂家平台代理；两者在产品内仍映射到真实实例。适配层只转换身份、数据与协议，不承担 CoSpace 内的飞控或机器人调度。

### 管理接口草案

以下均为待实现接口名，正式路径和权限名在实现时与已有契约统一。

| 接口 | 用途 |
| --- | --- |
| `GET /api/service-recipients` | 按可见范围分页查询、搜索和筛选实例 |
| `POST /api/service-recipients` | 原子保存实例和可选接入用途关系，不隐式授予执行权限 |
| `GET /api/service-recipients/{id}` | 获取实例及有权查看的关系摘要 |
| `PATCH /api/service-recipients/{id}` | 带预期修订号修改基本信息 |
| `PUT /api/service-recipients/{id}/spaces/{space_id}` | 带预期修订号新增或修改用途关系 |
| `DELETE /api/service-recipients/{id}/spaces/{space_id}` | 解除关系，保留历史，并同步阻断该关系的后续能力调用 |

关系解除、能力撤销需要被执行端实际校验，不能只改页面状态。历史未绑定实例的 S2S 调用继续保留调用身份级管理；尚无可靠实例验证时，不承诺能够单独撤销代理身份下的一台设备。

### 业务接入契约草案

- 空间数据采集：预留提交批次清单、获取受控上传入口、完成提交、查询接收与预检结果的契约。大文件不塞进登记接口。首次仅接既有支持格式，不因选择设备形态扩大格式承诺。
- 空间服务使用：已有固定版本 S2S 查询路径 `/s2s/spaces/{space}/publications/{publication}/query` 继续使用，不破坏当前严格请求模型。实例识别在新版本适配协议或可信身份上下文中补充，不能直接往旧请求体加字段。
- 离线服务使用：复用已有成果获取、校验及导入流程，新增交付登记与确认事件。单台设备的导入和应用状态分别确认。
- 态势反馈：后续复用独立反馈契约，不将其伪装为空间数据采集接口的默认能力。
- 采集提交和应用确认采用事件 ID、摘要与幂等键；同 ID 同内容返回原结果，同 ID 异内容拒绝，防止重试制造重复事实。

每种厂家只需明确五项：实例如何证明身份、支持的数据格式、时间与坐标约定、可使用的空间能力、错误及重试方式。SDK、ROS/ROS 2、MAVLink、MQTT 等作为厂家侧候选接法，待厂家确定后选用，不在首期 UI 中宣称已支持。

身份沿用平台可信服务票据；实例归属须由已验证厂家适配器、受信设备身份或经验证的代理映射证明。请求体中的设备 ID 仅是声明，不是授权凭证。平台调用身份可对应多台实例，映射有效期和撤销语义需要在厂商联调时确认。

## 9 权限与异常交互

读实例、编辑登记、关联空间、修改能力授权分别校验。新增权限名待与平台约定；不复用发布管理权限默认授予设备身份管理能力。实例、空间、绑定和事件均按可信租户工作区隔离，关联空间还需校验该空间权限。

「保存登记」只保存资料和用途意向。真正开通采集或服务使用由已有平台身份及空间授权机制确认；后续若增加授权编辑操作，独立展示影响范围并留审计。订阅与商业权益仍归平台，本文不增加设备额度或商业计费限制。

列表读取失败显示不可读取及重试，不显示空清单；没有记录才展示「尚未添加智能体」。无可关联空间时允许先登记设备。无可用版本时服务使用配置保持待配置，采集关系仍可登记。修订冲突提示重新加载，禁止覆盖另一位管理员的修改。

厂家能力尚未接入时显示「待厂家对接」与已知缺项，允许保存登记，不展示假的接入测试成功。一个能力验证失败时，只标记该能力需关注，不把另一项已经验证的能力整体标为失败。

已归档实例阻止新增关系及服务调用，归档前需要处理仍有效的绑定和关系；历史记录继续可追溯。首期可以只提供解除关系，不提供删除或归档入口，避免身份撤销链路尚未完成时出现虚假停用。

## 10 视觉约定

沿用当前服务域发布的 DS 组件、字体与 token，使用 Button、Drawer、Tabs、Table、Input、NativeSelect、Checkbox、StatusBadge 和空态。设备形态选择块使用相同外形轮廓图标和选中边框，不使用品牌图或给每种设备设计不同管理页面。

空间数据采集、空间服务使用采用并列的双选项，各有一句用途说明；不要使用只能选一个的角色下拉框。接入技术细节默认折叠，主流程突出形态、场景和用途。

## 11 实施分期与验收

**第一期 登记与接入用途。** 实现真实持久化的列表、添加、详情、编辑与空间关系；接入默认待对接。提供设备形态、用途筛选，区分登记与授权。单场景页签复用同一数据源。此期不虚构接入、调用或作业状态。

**第二期 空间服务使用与厂家联调。** 选择一个实际厂家，完成实例身份验证、在线固定版本服务使用或离线交付确认。先明确代理实例归属与撤销，再展示逐实例使用事实。

**第三期 空间数据采集。** 根据实际厂家输出确定第一种格式，打通采集批次、受控提交、预检与生产资料关联。采集状态与建图发布状态分开。此期可按厂家条件与第二期并行推进，不要求先有在线服务使用。

设计验收场景：

1. 飞行式、四足式、轮式、履带式、人形式均可登记；改名不改变身份、用途或空间关系。
2. 同一形态分别选择仅采集、仅使用服务、两者都有，不触发隐藏限制或自动扩权。
3. 一台设备在场景 A 采集、场景 B 使用服务，场景内显示本场景用途，总表显示汇总。
4. 仅采集且空间尚无发布时仍能登记；仅使用服务不强制上传资料。
5. 新版本发布、切换页头版本不会改写设备实际使用版本或历史交付。
6. 撤销某场景的采集不影响仍获准的服务使用；解除关系后执行端拒绝后续调用，历史保留。
7. 未验证外部 ID 无法冒充实例；共享调用身份活动不被分配为每台设备活动。
8. 对接未完成、列表读取失败、没有记录、无权限分别呈现；登记成功不显示设备在线或作业就绪。

## 13 登记交互细化（2026-11-13）

工具栏统一为 32px 高。最左侧为卡片 / 列表切换，其后为结果数量；搜索、设备形态、接入用途、场景筛选、描边刷新及添加操作集中居右。搜索与下拉框限制宽度，中间弹性留白，窄屏允许换行。列表与卡片共用同一批查询记录，切换不重置筛选。

添加与完整编辑使用居中大对话框，桌面宽度上限 960px；详情查看保留抽屉。容器按任务复杂度选择：跨场景配置需要完整的注意力和横向空间，快速查看适合侧边抽屉。这里采用成熟的分步表单和渐进披露模式，不将某一种容器称为行业统一的“最新标准”。

第一步突出设备形态，六种形态使用图标与例子；设备名称由用户填写，不再自动以形态生成名称。其余登记字段为选填。第二步左侧列出可管理场景，点击即建立待配置关联，右侧只呈现当前场景的用途。已选场景显示“待选用途 / 已配置”，提供明确的移除关联操作。

两个用途并列多选，并通过“设备 → CoSpace”“CoSpace → 设备”说明信息流向。在线服务、离线成果只在选中空间服务使用后出现，标为选填；取消服务使用会清空对应方式。没有关联场景时显示“仅保存设备”；关联场景却未选用途时阻止提交并提示。底部操作固定，正文独立滚动，遮罩点击不关闭正在填写的表单。
