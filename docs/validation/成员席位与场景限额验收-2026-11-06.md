# 成员席位与场景限额验收

日期：2026-11-06。结果：**本地实现和自动化验收完成，尚未部署生产**。

> 后续纠偏：用户要求复用平台既有管理能力。本报告仅保留当时的实现与测试证据，不再作为推广独立席位管理的依据；该部分和场景商业数量门禁已从本地业务代码移除。根据用户最新裁定，产品读取平台授权结果，不建立本地席位、场景名额或容量门禁。以 [职责纠偏记录](../architecture/CoSpace平台接入职责纠偏-2026-11-06.md) 为准。

## 1. 完成内容

- `packages/lifecycle/product_quotas.py`：产品成员占席、释放／恢复、版本冲突检查及审计。数据保存在策略目录下的 `product-seats.sqlite3`。
- `packages/service/platform_business_http.py`：已启用订阅的人工业务请求，在原有授权之后执行席位门控；上传提交前重查。真实 C2 下发额度为唯一商业数字来源。
- `packages/lifecycle/workspace_scenes.py`：创建意图前和提交归属前检查 `scene.max`；按完整 Workspace 范围统计场景绑定和 prepared 意图，已有历史成果不增加名额。
- 账户页（`#account`，管理导航亦可进入）：查看占用；所有者填写原因后释放／恢复席位；普通成员仅看到自己的记录。
- 新建场景及业务全局提示：显示席位满额、席位已释放、场景满额及额度不可用的中文原因。
- 冷备份白名单纳入席位账本，恢复后占用、释放状态与审计记录保持一致。

全部功能授权与工程排除条款保持策划约定：**三档均不包含地面采集处理工程**。

## 2. 执行规则

1. 平台已验证的成员首次使用获授权的业务接口时占席，同一成员重复请求或再次登录不重复占用。所有者使用同样占席；退出登录不释放。
2. 仅查询席位、所有者调整席位不要求占席，避免降配超额或所有者主动释放后无法恢复。所有者可释放／恢复本 Workspace 已登记的成员，不能通过该接口给未知身份发放场景权限。
3. 被释放的成员不得刷新自动抢回；必须由所有者恢复。平台成员身份及场景权限继续在业务请求中验证。平台移除成员不会自动释放本地席位，所有者可清理残留占用。
4. 降配后若已占席数超过上限，业务接口拒绝访问；所有者仍可在管理入口释放多余席位。超额不会删除场景或历史成果。
5. `member.max` / `scene.max` 必须为明确、有限的非负整数。缺失、未知、负数（含无限哨兵）或非法值均不推导默认额度；0 表示不允许新增相应占用。Enterprise 也需平台下发合同具体数字。
6. 席位与场景锁均覆盖本机多线程／多进程。席位按 SQLite 写事务串行；场景复用现有进程文件锁及提交事务。当前为单主机存储部署，不宣称支持多主机同时写同一份本地目录。
7. 创建中断产生的 prepared 意图保留名额；同一请求可恢复。完整完成的创建重放不另占名额。取消／清理悬挂意图不在本批提供，不能手工删文件冒充完整清理。
8. 本机未启用订阅的工程预览维持独立模式。`/s2s/` 独立程序仍使用其服务授权与订阅规则，不消耗人工席位。

## 3. 本地管理接口

这两个入口属于 CoSpace 自身，不修改平台公共协议。

- `GET /api/product-seats`：受信会话和有效订阅必需，返回 Workspace 范围、limit、used、revision、can_manage、members；所有者可看该范围内全部记录，普通成员仅看自己。
- `POST /api/product-seats`：仅 Workspace 所有者，同源 Origin 与 CSRF 必需。请求：`{subject, active, expected_revision, reason}`；禁止客户端传入 Workspace / 组织 / issuer。版本变化返回 409，需刷新核对，不自动重放覆盖。
- 管理接口在额度超限时仍可使用，但订阅资格不可绕过；它不建立新身份或新场景授权。
- `POST /api/workspace-scenes`：沿用已有请求格式，客户端不得提交额度；服务端读取 C2 的 `scene.max`。

主要错误：`member_limit_reached`、`member_limit_reconciliation_required`、`product_seat_released`、`scene_limit_reached` 返回 409；无法确认有效限额返回 503 `product_quota_unavailable`。原有身份、订阅和场景权限错误继续独立判定。
