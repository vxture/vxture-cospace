# 智能体恢复状态机验证

日期：2026-10-27。J3独立Windows合成验证，依据[实现设计](../architecture/智能体恢复状态机实现-v0.1.md)。

新增30项专项实例通过，耗时101.93秒。Python 3.14.3、Windows，沿用J1原生文件锁和Node测试Ed25519适配，没有新依赖。本批修改J2仅增加独立存储版本和附加表的扩展点；原J2默认user_version仍为2，新RecoveryStore要求新建user_version=3，拒绝打开旧版。

全量本地回归246通过、6跳过、22个子用例通过，耗时290.24秒；跳过项没有本次验收证据，不推定PostgreSQL或实际设备全路径通过。三类证据场景的11条计划/凭据/结果另行通过Schema核对，八份源码摘要与当前文件一致。

| 覆盖 | 验证结果 |
|---|---|
| 撤回恢复 | 原消息、历史、计划、receipt与结果可核对；恢复后新对象仍revoked |
| 三次代次边界 | begin、resume、完成均推进；旧对象和恢复期间打开的对象拒绝，旧计划失效 |
| 计划字段改动 | store/context/generation/版本/前态摘要/未决集合摘要/目标摘要/items/授权标志任一改动，提交拒绝 |
| 实际集合变化 | 封存计划后增加合成未决项，重新对账拒绝旧计划，不写结果 |
| 原子回滚 | 逐项写入后和完成提交前的SQLite错误，使状态与receipt整体回滚，mode保持recovering |
| 多项回滚 | 通过显式SQL种入第二个未决项，第二项后失败时第一项也回滚；不是正常入口批量接收能力 |
| 完成响应丢失 | 重开读取原reconciled结果，重复应用和resume完成任务均拒绝 |
| 历史不可解释 | 缺未决消息、改签名并同步其摘要/引用、删历史receipt，均不能规划完成；故障注入显式去掉不可变触发器 |
| 期限与撤回 | 到期幂等恢复不续期；终止撤回不允许后续allowed；未决撤回自身冲突则阻断 |
| 重复恢复 | 新一轮可以重放前一次恢复生成的历史凭据，不丢失对账链 |
| 入口条件 | 无未决不开始、不同恢复ID不能抢占、未知ID不能resume；J2旧库不升级 |
| 五处独立进程退出 | begin提交后、plan提交后、item写后、完成提交前、完成提交后调用os._exit(77)，持久阶段和receipt与提交边界一致 |

计划及恢复结果使用已有交换Schema。独立子进程退出是进程内部立即退出，不是进程外强杀或物理断电；J1的外部强杀释放锁证据独立保留。本批未新做跨进程恢复竞争或真实机器人会话试验，不由旧对象模拟代次测试提升为机器人集成通过。

证据目录：[p2-recovery-state-001](../../experiments/runs/p2-recovery-state-001)，含[专项日志](../../experiments/runs/p2-recovery-state-001/focused.log)、[专项JUnit](../../experiments/runs/p2-recovery-state-001/focused.xml)、[全量日志](../../experiments/runs/p2-recovery-state-001/tests.log)、[全量JUnit](../../experiments/runs/p2-recovery-state-001/tests.xml)、[三类场景](../../experiments/runs/p2-recovery-state-001/scenario.json)及[环境与源码摘要](../../experiments/runs/p2-recovery-state-001/environment.json)。场景包括撤回完成、到期幂等、提交回滚；保存测试公钥及恢复记录，不保存随机私钥。

本地完整历史重放建立在实验库、事务和不可变约束完整的假设上；不是密码审计链或硬件防回滚。未实现角色权限系统、可信时间源、线上分发、v1/J2迁移、坏库恢复、日志裁剪、大规模性能或真实机器人运行。所有输出authorized=false、robot_ready=false。
