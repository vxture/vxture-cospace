## 样本与坐标处理

原文件：`D:\Work Space\SampleSpace\激光点云数据集\sum4re\Anoeta\Anoeta_HL2.laz`。LAS 解码后确认为 254,219 个有限 XYZ 点，全部保留，无抽样、无排除。原文件 823,330 字节，SHA256 为：

```text
221b9aabd4c49f3b963459039d1e7f99b036f8c80fb53ee0be8f71b253eee6d7
```

采用可逆局部化，避免原北向坐标超出现有输入边界：

```text
origin = [583107, 4794862, -2]
local = decoded_LAS_XYZ - origin
decoded_LAS_XYZ = local + origin
```

无旋转。局部范围约 `[0.496, 0.182, 0.435]` 至 `[81.941, 52.601, 10.988]`。float32 往返最大误差约 `3.7842e-6` 个假定米制单位，仅指转换数值误差，不是测量精度。转换后的 binary PLY 为 3,813,465 字节，SHA256：

```text
43165a75fff026f943aa4af608e14a8277301d4bd03a3c2458463802b0b04082
```

LAZ 的单位、CRS 和轴向含义没有可确认的声明。现有产品输入要求米制，本次**仅为隔离流程验收暂按米解释**，在输入说明、frame ID 和转换报告中保留该假设；未核验前不能作为正式交付。IFC 的米制声明不能证明 LAZ 单位，也未做点云与 IFC 对齐。

源 RGB 只有 5 种三元组，按 `floor(uint16/256)` 保留编码颜色；不做亮度归一化，不解释为照片纹理或已知语义分类。已有点云没有逐帧轨迹，本次不模拟机器人扫描或 SLAM。

预处理独立环境：Python 3.12.14、laspy 2.6.1、lazrs 0.7.0、NumPy 2.2.6。没有把这些库加入产品运行依赖。构建及消费使用仓库 `.venv`。原文件摘要在转换后、完整流程后再次核对，均未改变。

## 验收发现与修复

已有点云的缩略图曾按 RGB-D 相机透视投影处理：将场景 Z 当作相机深度、剔除 Z≤0.1 的点，且未按整个场景取景。Anoeta 实际图像几乎全黑。

本次将 `existing_pointcloud_candidate` 纳入已有的等轴投影与范围适配逻辑，完整场景留边显示。只改变缩略图取景，保留源坐标与编码颜色。新增回归覆盖负 Z、远离原点坐标、全场景取景、单点退化范围及文件不变；RGB-D 继续使用原投影。
