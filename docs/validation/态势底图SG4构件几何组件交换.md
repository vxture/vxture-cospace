# SG4 构件几何组件交换

日期：2026-11-17。接续结构声明快照交换，让应用取得来源固定、身份明确的完整 IFC 构件表面。未部署，未创建正式发布，未采用配准或本体绑定。

## 入口与边界

IFC 构件资料的结构声明区域，对已纳入结构提取且具有网格的当前构件显示“导出构件网格”。没有几何或不在结构声明中的构件不提供此入口。结构快照继续独立导出，几何按需逐构件读取，不把整个场景一次塞进概要响应。

`GET /api/scene-ifc/element-geometry?space_id=…&catalog_sha256=…&element_id=…` 复用 `association.edit` 场景授权。先鉴权，再核对可信配置、固定目录及原 IFC 的字节数/摘要，随后验证网格压缩成员预算、原始 NPZ 摘要、数组数量、三角索引和范围。使用完整提取网格，没有展示抽稀或自动重采样。

非法参数 422；未授权 401/403；缺失提取、来源改变、损坏或超预算 409。超预算不静默降采样。HEAD 同样核验并返回摘要，响应无正文；目前仍需计算完整导出，不承诺低成本。没有 POST 或文件路径参数。

响应 `application/octet-stream`，使用 `no-store`、`nosniff`；文件名和 `X-Content-SHA256` 包含准确下载字节摘要。构件编号只在该固定目录内有效，不作为跨版身份。

## 格式与预算

`cospace.ifc-element-geometry/0.1` 采用简单有界二进制，两个消费端均无需解析 NPZ：

| 顺序 | 内容 |
|---|---|
| 8 字节 | ASCII `CSIFCG01` |
| 4 字节 | 无符号小端整数，表示后续 JSON 头字节数 |
| JSON 头 | UTF-8、排序键、紧凑规范编码，最多 4096 字节 |
| 顶点数组 | 顶点数 × 3 个 float64 小端，XYZ，无额外变换 |
| 三角形数组 | 三角形数 × 3 个 uint32 小端，零起始顶点索引 |

单构件最多 200,000 顶点、400,000 三角形、10 MiB；不支持尾部附加内容。坐标有限且绝对值不超过 10,000,000。头 Schema 位于 `contracts/schemas/ifc-element-geometry-v0.1.schema.json`，二进制布局及跨字段校验由消费者另行执行。

头固定场景/目录/原 IFC 来源、对应结构快照字节摘要、GlobalId、目录构件编号、原 NPZ 声明摘要、IFC 坐标及米制单位、编码和数量。设计候选、未核验、未对齐、未绑定本体、不可作为真实发布的标记不可提升。没有设备通行性、导航路径、现场连接或门状态。

IFC 米制来自原提取，不证明点云单位或两者坐标关系。网格是来源的三角化表达，不保证水密、无重复面或现场精度；消费方不能据此将开放表面当作占据实体。原网格声明摘要仅供追溯，下载文件采用新的字节摘要，二者不同。

## 消费接入

1. 经可信分发取得结构快照、其准确 SHA-256 和独立核对的 source pin；不能复制文件自身的 source 来建立信任。
2. 明确选择结构快照中的 element_id，取得该构件组件及可信下载摘要。
3. Python 调用 `inspect_geometry_component(raw, expected_sha256=…, structure_raw=…, expected_structure_sha256=…, expected_source=…, expected_element=…)`，返回头、顶点和三角索引。
4. Node 从 `examples/scene-graph/consumers/read-ifc-geometry.mjs` 导入 `readGeometry(raw, structureRaw, {sha256, structureSha256, source, element})`，返回头、Float64Array 顶点、Uint32Array 索引和概要。仅依赖内置库，宿主负责可信下载、输入缓冲及界面，不接受 CLI 文件路径。

两个消费者都先独立验证结构文件，再核对组件准确字节、格式预算、规范头、来源/结构摘要、构件身份、坐标和索引。固定摘要来自同一可信服务有助于完整性检查，当前不提供数字签名。离线消费者没有原 IFC 或 NPZ，因此 `original_ifc_content_verified`、`original_mesh_content_verified` 始终 false；不能把声明中的摘要当作重验过原文件。
