日期：2026-11-15；实现 PR #78，基线 v0.7.40。

## 本地结果

- 前端全量 96 项测试通过，覆盖目录/概要复用、在途合并、全局与单 key 失效、旧响应拒绝、作用域隔离、服务端有效期和一次 CSRF 恢复。
- 平台登录、成员应用授权、场景概要相关 79 项通过；最终补充索引故障测试后，概要模块 15 项通过。
- TypeScript 与前端生产构建通过；依赖原有 use-client 构建提示保留。
- repository guardrails、严格 ruleset、diff 检查通过。精确暂存树与展开的 354 个归档成员使用 gitleaks 扫描，无凭证命中。

本地 Windows 固定测试场景概要直接读取 100 次：冷读 13.13ms，暖读中位数 3.14ms，暖读 p95 4.27ms。此结果仅衡量标量概要函数，不包含 HTTP、会话、平台授权、网络或生产负载，不用于声称线上总延迟。

Windows 完整回归有 test_agent_files.py::test_live_owner_recovery_blocked 失败：杀死子进程并等待退出后仍得到 owner_alive。该测试及 agent_files.py 未修改；保留失败证据，不调整锁保护以绕过测试。完整结果与 GitHub Linux 检查在 PR 验证记录中补充。

## 线上验收项

1. 有效会话及成员决定窗口内，多次切换板块、A→B→A 和重开抽屉：请求瀑布不应重复执行中央令牌交换与成员授权；目录和已缓存概要直接复用。
2. 过期后的第一个请求允许等待确认；并发业务读取共用确认与平台查询，不自动重放业务写入。
3. 平台撤权通知、30 秒决定期限、令牌轮换、退出、组织切换后，旧结果不能进入新作用域；场景 ACL 在后端每请求生效。
4. 比较 Server-Timing 的 rp_session、platform_gate、scene_summary 与 total，并单独记录到期尾延迟。嵌套片段不可相加。
5. 构建、候选选择、表达派生、发布、场景信息保存后，目录与概要更新；当前候选、最近构建标题固定且引用独立。

具体撤权窗口、配置 0 的严格模式、读模型重建及回退方式见 [架构说明](../40-frontend/business-read-latency-architecture.md)。本记录不代表已发布生产或已完成线上带身份验收。
