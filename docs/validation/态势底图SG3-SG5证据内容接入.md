日期：2026-11-17。实现与接入说明见[证据内容核对与接入](../architecture/证据内容核对与接入-v0.1.md)。本轮核对实际文件字节，不认证现场事实。

- SG3：配准复核和空间标注可选读取证据文件并输出绑定原输入的回执。软件测试验证健康文件、缺件、改写及原有核验标志保持；没有生成真实对应点或采用真实区域。
- SG4：Python 离线资料包消费者可选核对原 IFC 的实际字节及声明大小；既有组件完整性校验和默认 Python/Node 结果保持不变。
- SG5：新增可信内部接入方法，整批引用证据通过后才原子追加报告；缺件、摘要不符、错误纠正、来源不符或作用域/对象未登记均不部分写入。幂等重试仍核对当前证据。

## 既有资料试跑

沿用 Anoeta 和 Longyearbyen 已固定的 IFC 及离线包，复制原 IFC 到本轮独立本地证据目录并核对，不修改原文件。核对字节数分别为 4,207,262 / 1,516,258；原文件摘要与既有包一致。新消费者回执固定包摘要，original_ifc_content_verified=true；设计候选、未核实及正式可用状态没有升级。

两套固定设计目录共 7 / 22 扇门分别写入新建的独立合成观测库，证据引用本轮原 IFC 文件，作为**软件字节校验试验**。这份 IFC 不是现场门状态证据，报告值统一 unknown，不是厂家上报。整批只读取一份共享证据，之后追加缺失证据摘要的报告会拒绝，数据库字节保持不变。

Anoeta 另对旧 UI 测试标注的内存副本执行证据读取：用同一设计文件替换试验副本的摘要，只检验软件链路，不写回工作表，不作为真实区域证据；输出 confirmed_connections 仍为空。配准复核接入使用明确的合成控制点测试，不制造真实配准或单位依据。

脚本、证据副本、合成日志和回执仅留忽略目录 output/sg3-sg5/evidence-content-01；不进入 Git、不部署。
