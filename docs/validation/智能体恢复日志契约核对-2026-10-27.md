# 智能体恢复日志契约核对

日期：2026-10-27。范围：R2b第四批设计及结构检查，**不是恢复协议运行验收**。

本批形成[恢复独占与提交日志协议](../architecture/智能体恢复独占与提交日志协议-v0.1.md)、[实施与故障清单](../architecture/智能体恢复日志实施与验收清单-v0.1.md)及[恢复日志交换契约](../../contracts/schemas/recovery-journal-v0.1.md)。现有ValidityStore、审计器、R1工具及依赖锁未改动。

结构工具使用现有LiteralIntegerValidator及Draft202012Validator.check_schema，在Python 3.14.3执行：

```powershell
.venv/Scripts/python.exe -m experiments.scripts.check_recovery_contract
```

4个正例（intent、receipt、plan、result）及16个结构负例通过。负例涵盖未知字段、缺store_id、零/布尔/浮点代次、计数溢出、授权与机器人标志提升、非测试标志、错误摘要、超长token、未知记录/结果/阶段，以及空/超量计划。

证据见[report.json](../../experiments/runs/p2-recovery-contract-001/report.json)，固定Schema、样例和检查器的源码摘要。样例见[说明](../../examples/recovery-journal/README.md)：使用占位JWS和摘要，没有合法签名或实际事务关系；仅证明格式可表达，不能用于恢复或信任引导。

结构检查不计算真实摘要、不验证签名、不检查唯一intent约束、receipt链或计划CAS，不持OS锁，不执行提交或恢复。协议中的JL-01至JL-20全部保持待验证。本批未改运行实现，未重跑上一批178项本地回归；该历史结果不能计为本协议的测试覆盖。

下一批J1独立验证稳定OS锁、真实进程竞争/退出、存活者超时及旧代次对象拒绝，再进入J2事务日志。没有新增真实机器人授权或自动解除路径；authorized=false、robot_ready=false。
