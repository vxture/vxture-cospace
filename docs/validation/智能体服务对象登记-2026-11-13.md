# 智能体服务对象登记验收

日期：2026-11-13
范围：本地功能分支 `codex/embodied-agent-recipients`，未部署，未连接第三方设备。

## 实施结果

「空间服务 → 服务对象」已提供真实持久化登记、筛选分页、详情、修改及空间关联。主操作为「添加智能体」，单场景入口为「关联智能体」，可从已登记实例选择或新增。以设备形态作为首个必选项，支持飞行式、四足式、轮式、履带式、人形式及其他形态。

接入用途统一采用「空间数据采集」「空间服务使用」，按场景独立多选；服务使用方式可选在线服务、离线成果，也可稍后配置。未发布成果的场景仍可管理服务对象，页头明确显示暂无发布成果。

服务端按可信租户工作区隔离，新增 `recipient.read` / `recipient.manage` 权限。保存同时写入实例、空间用途、修订、操作者和前后快照，并支持请求幂等和并发冲突拒绝。仅看到部分关联场景的用户不能用不完整快照覆盖共享实例。未关联空间的登记仅供有管理能力的创建者及同工作区 owner 查看。

厂家接入统一显示待对接，外部设备标识只作人工登记，不建立可信实例身份，不授予业务调用权限，不生成在线状态、实际使用版本或虚构使用事件。登记接口没有改变现有严格 S2S 查询契约。

## 浏览器验证

使用隔离的本地认证测试环境和实际登记接口，测试记录、认证状态及截图保存在已忽略的本地目录，未写入产品种子数据。

1. 工作区尚无场景时，owner 可先登记四足智能体，保存后列表出现真实记录。
2. 新建无发布成果的场景，进入其服务对象页签，关联已登记智能体。
3. 同时勾选空间数据采集、空间服务使用，以及在线服务、离线成果；保存并刷新后配置保留。
4. 详情能查看设备形态、稳定 ID、空间关联、用途、登记时间和修订号；接入与使用记录明确未验证。
5. 修改显示名称后 ID 保持不变；取消采集用途不影响服务使用及其使用方式；采集用途筛选不再匹配该记录。
6. 桌面 1440px、手机 390px 检查列表、形态选择和抽屉。已修复窄屏抽屉超宽裁切和桌面筛选项错误占满整行的问题。

浏览器业务操作未见新增运行错误；控制台的 favicon 请求被既有访问门禁拒绝，未用于判断登记接口状态。

## 后续边界

后续需与真实厂家确认身份映射、支持格式、时间与坐标契约、数据提交及固定版本使用协议，并分别完成实机验证。当前解除空间关联仅改变登记关系，不声称能撤销某个共享代理身份下的具体设备；实际实例授权和撤销须随厂家绑定协议落地。
