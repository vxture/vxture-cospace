# N6 工作台综合验收与交付

日期：2026-11-08。基线：v0.2.0（main）＋N5 最终提交 `356ef77`；N6 分支 `codex/workbench-acceptance-n6`。本文记录本机候选验证，不代替生产部署成功或现场成果验收。

## 本批发现与修复

1. 有效确认缓存无法进入工作台。真实 RP 在中央 next_check_at 前返回 cached，N5 只接受 confirmed，模拟接口未发现此问题。本批增加服务端计算的 authority_ready：确认窗口有效且无重试错误时为 true；前端只接受明确有效的 cached。过期、不可用、登出与无字段缓存均保持阻断。GET 不续期、不检查中央；业务 API 仍逐请求核对权限与凭据。见平台会话契约及新增前后端回归。
2. 上传成功后误弹未保存提醒。回执清理后，弹窗关闭期间的 React 重渲染可能再次注册旧编辑。回执标记保持到编辑器恢复干净；上传与 PLY 准备完成后不再登记旧参数，新编辑重新启用保护。真实上传后可直接定位入库记录。

两项均属于 N5 交付阻断问题，N5 PR #26 不宜单独合并发布。本批阶段 PR 包含 N5 及这些修复，统一评审、squash merge，避免生产接收未经真实后端验证的独立 N5。

## 可复跑环境

先执行 `pnpm --dir apps/workbench build`，再在PowerShell创建全新仓库外输出路径（运行器拒绝仓库内路径及已存在目录）：

```powershell
$n6Output = Join-Path $env:TEMP ('cospace-n6-' + [guid]::NewGuid().ToString('N'))
uv run --frozen python tests/serve_workbench_acceptance.py --output $n6Output --port 18876
```

打开工具打印的loopback URL，通过模拟平台分别选择四类身份。输出根下的context.json包含合成场景与历史固定发布ID；upload/sample.zip为有效双点样本。按[操作指南](../guides/共用支撑与场景工作台操作指南.md)在新场景上传并完成闭环，历史场景用于多角色与版本隔离验证。浏览器切换角色应使用独立上下文／浏览器配置，标签页共享Cookie不能代表独立身份。

运行器仅用于测试，固定监听127.0.0.1，不提供生产认证选项。Ctrl+C关闭服务，保留输出便于排查；不得把该模拟平台、密钥或合成运行区部署到服务器。若本机端口被占用，选择另一个空闲loopback端口。

## 阶段交付边界

建议以 N5＋N6 汇总为下一阶段版本（建议 v0.3.0，正式标签待发布决定）。无需业务数据迁移；authority_ready为公共会话新增字段，前后端随同一镜像发布。旧版前端可忽略新增字段；回滚使用上一稳定镜像，不覆盖业务运行区。

完成阶段PR五项检查后具备代码候选交付资格。本批不合并、不创建tag、不部署。发布路径仍为squash merge → release tag按该提交构建镜像 → production Environment reviewer → worker02 `/srv/md0/cospace`。
