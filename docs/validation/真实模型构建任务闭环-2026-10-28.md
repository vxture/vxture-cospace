# 真实模型构建任务闭环

本轮优先流程，接通“发起构建→运行状态→新候选→双视图与候选查询”。不追加算法精度试验。

构建中心增加DS任务卡片、发起按钮和每2秒状态刷新。首版输入固定为NYU封存短序列和已有57帧位姿，不接任意磁盘路径，不重新运行里程计。每次生成独立build身份和输出目录，初始模型保持原样。

接口：GET /api/builds读取历史，POST /api/builds发起任务。单个本机服务实例一次运行一个子进程任务；已运行时返回409。任务状态写入job.json，完成后校验产物再暴露候选入口。运行结束/超时在任务列表轮询或下一次发起时收敛；120秒超时检查同样依赖服务轮询，不是独立后台看门狗。日志保留在任务目录。服务重启时未决记录标记interrupted，不自动接管或续跑旧子进程；本轮不是已有受控worker恢复系统的替代。

每个候选有独立URL `/candidates/{build-id}/`、清单接口和查询接口。候选页使用相对路径读取自己的模型及智能体载荷，避免浏览新候选时查询初始模型。候选不是正式发布，质量仍标记unverified，未知保持未知。

实际运行证据：`var/nyu/preview-builds/build-75bfff86f8a849fc/`，真实HTTP发起后从running变为succeeded；生成56,637个模型点、17,029个表面单元。已通过候选URL取清单、页面、离线示例并提交候选查询，返回模型ID与任务ID一致、state=surface_candidate。初始预览路径仍保留。状态完成时间是服务观测到进程退出的时间，不是精确算法完成时间。

验证：前端TypeScript/Vite构建通过；7项专项测试通过，覆盖既有查询/摘要行为、重启未决标记、缺输入拒绝、失败任务记录、候选未完成不开放及写入来源限制。POST接口供本机使用，允许8766/8767本机页面来源；未接生产认证。

Playwright已在构建中心看到实际成功任务、启用的发起按钮及打开新候选链接，并实际点击“发起构建”提交第二个任务；服务历史已出现第二条成功记录。首条任务通过真实HTTP发起，第二条通过页面按钮发起，分别保留独立目录。

入口：<http://127.0.0.1:8767/workbench/layout.html?revision=build-jobs-1#build>。本机模型服务运行方法不变，启动时自动配置固定输入和 `var/nyu/preview-builds` 任务目录。

下一步：候选列表与人工选择确认，把选中的候选接入“我的空间”，再贯通预览发布和固定版本消费。任务目前只能使用固定样例，尚无自助上传、在线采集、取消、自动重试或多进程协调。
