# L03 作业优先与预算策略

日期：2026-11-23。状态：工程实现及本地对照筛选已完成，生产发布另经五项检查与人工审核；默认 `baseline`。承接 v0.15.0 的渐进画布与原始点核验。本批交付可关闭、可复现的策略及共同路径修正，不以策略代码存在作为性能领先证据。

## 实现边界

| 能力 | 实现与约束 |
| --- | --- |
| 作业目标提示 | 公共工程画布把已选控制点/对象坐标随初始化传入；`task` 在首轮原生选择前定位；基线仍按既有 initialized 回调定位，最终相机与质量必须一致 |
| 预算自适应 | EWMA 记录同版本显示请求的字节、TTFB、完成时间；按网络、P95 帧时间和槽内待解码估计约束 2–6 个原生加载槽；运动中临时 250,000 点/60 px，静止恢复 500,000 点/30 px |
| 无效传输治理 | 运动中限制新读取槽为 1；页面隐藏、计算视图或几何关闭时冻结原生可见性选择，恢复后继续；同版本在途请求保留，不接管原生节点队列 |
| 开关与回退 | 服务端环境配置五种策略，未知/缺省回到基线；可选策略异常关闭该策略，保留引擎和固定模型；配置不写入派生或改变固定版本 ID |
| 度量 | 有界 8,192 个 Range 账本和 240 帧窗口；未使用/重复字节、完整性标志、P95 与最大帧间隔、最终节点/相机签名；长于一秒的前台卡顿保留，隐藏/恢复时重置间隔起点 |

共同修正：固定 Potree/tween 版本的全图定位使用零时长 tween，同一时钟刻度直接更新会发生 `0/0`，后续帧又覆盖初始作业点。现在适配全图后完成原生 tween，再接受明确目标；对照各组共用此修正。八次基线/目标策略交错重载的最终相机及可见节点一致，不将该缺陷修复计为策略收益。

坐标变换、原始点索引、查询/确认门槛、模型摘要及场景鉴权继续使用 L02 契约。权限/版本失效仍停止读取并清屏，局部数据异常保留画面并暂停，重试不能解除隐藏/计算视图的冻结条件。没有更改 vendor 引擎、原始成果、精确查询协议，也没有新增业务导航或调试卡片。

## 合成对照方法

Windows / Intel i5-10400 / 31.8 GiB / NVIDIA GT 1030（ANGLE D3D11）；系统 Chrome 157 headless，1920×1080 / DPR 1。这是筛选用实际机器，不替代方案中的 16 GB 集显目标硬件档。两份独立生成的百万点数据：网格厂房园区、狭长设施园区；均为合成数据，非测绘成果。固定原始文件与显示派生、相机、作业点、九次 180 ms 间隔的切换路径。CDP 模拟 5 Mbps / 100 ms、应用与业务全冷，跨组交错顺序，种子 9003。

先核验原始点 ID 及原始 double，再等待基线画质下的稳定节点；路径结束继续等待至少 10 秒后统计未使用字节。浏览器不同 realm 的单调时钟换算后再计算视野就绪时间。T_exact 只测已就绪索引上的按原始行查询，不把可浏览或稳定视野冒充精确查询完成。

筛选轮每个园区/策略 3 次，共 30 次。原定门槛是每个组合至少 30 次、95% 收益置信区间不跨零、非目标时间/帧时间/峰值内存不退化；筛选轮不能通过启用门槛。没有 GPU 峰值内存实测，缓存点数不代表完整显存。因此即使出现局部正向数据，也保持默认基线，不声明行业领先或生产 SLA。

### 筛选结果与启用决定

以下均为每格 3 次的描述性 P75，不能当成完整性能分位数或统计显著结论。T_view 从最后一次切换结束计时；未使用字节于路径结束至少 10 秒后统计。各组初始/最终相机、可见节点签名、点数和固定画质相同，30 次原始 ID/double 核验及账本完整性全部通过，重复传输字节均为零。

| 策略 | 网格 T_view（ms） | 网格未使用字节 | 狭长 T_view（ms） | 狭长未使用字节 |
| --- | ---: | ---: | ---: | ---: |
| baseline | 792.5 | 480,096 | 1,207.8 | 460,890 |
| task | 876.0 | 480,096 | 1,132.7 | 460,890 |
| adaptive | 950.7 | 480,096 | 1,534.9 | 668,736 |
| governance | 801.2 | 191,394 | 960.5 | 170,694 |
| combined | 968.9 | 191,394 | 960.0 | 170,694 |

治理策略的未使用字节在两种样本中分别减少约 60.1% / 63.0%；总 octree 传输 P75 仅分别减少约 11.7% / 28.6%，两者不能混称。网格视野时间约增加 1.1%，狭长约减少 20.5%，仍缺正式样本数、置信区间、峰值内存和生产代表性覆盖。

目标提示未呈现原始查询 P75 减少 30% 的证据：基线为 115.1 / 126.5 ms，目标策略为 126.4 / 127.0 ms。自适应策略的移动后就绪时间分别增加约 20.0% / 27.1%，未达到提升目标；组合策略也不能直接启用。各组路径内观测的 P95 帧间隔最高 17.8 ms，仅代表本轮合成条件。

决定：三项策略和组合全部保持默认关闭。保留治理作为后续单项候选；自适应方案须重新调优并重新对照，不能扩大到生产后再寻找收益。不因本轮失败降低门槛，也不扩张本次版本。共同定位修正、真实就绪状态、诊断和可复现工具独立交付。

### 复现

先按现有工具准备流程固定 PotreeConverter 2.1.5 与 Potree 1.8.2。以下根目录必须不存在，避免覆盖运行数据：

```powershell
.venv/Scripts/python.exe -m experiments.scripts.model_loading_lab --prepare --root var/l03-new-fixtures --converter <converter-path>
pnpm --dir apps/workbench exec vite build --outDir ../../var/progressive-l03-build
.venv/Scripts/python.exe -m experiments.scripts.model_loading_lab --root var/l03-new-fixtures --port 8794
```

使用 Playwright CLI 在专用会话 `l03-loading` 打开 `http://127.0.0.1:8794/loading-lab`，然后执行：

```powershell
.venv/Scripts/python.exe -m experiments.scripts.compare_model_loading --rounds 3 --output output/l03-new-comparison
.venv/Scripts/python.exe -m experiments.scripts.report_model_loading output/l03-new-comparison/results.json
```

对照脚本保存运行时哈希、顺序、条件及原始结果；结果目录必须是新的 `output/` 子目录。`--rounds 30` 可扩大每组样本，但完整启用仍须另补代表性生产场景、峰值内存、故障、质量和置信区间评审，脚本不自动启用策略。实验 HTTP 服务只绑定 loopback，实验策略查询只在专用 lab 路由可用，未接入生产业务路由。

实验服务使用准备数据时的固定派生和真实显示/精确查询接口。实验候选为明确无归属合成资料；没有放宽生产场景授权。原始证据、浏览器状态和生成数据保留在忽略目录，均不进入 Git。
