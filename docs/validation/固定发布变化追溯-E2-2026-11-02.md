# 固定发布变化追溯验证（E2）

日期：2026-11-02。归属“使用 → 态势服务”。本轮完成固定发布之间的只读比较，并追溯发布保存的候选核对记录；持续优先验证业务闭环。

## 实现结果

- 新增`POST /api/publication-comparisons`，显式指定同空间的基线与目标发布。读取发布快照，不跟随当前候选，也不依赖构建目录仍存在。
- 比较几何来源、表面单元、稳定ID对象及固定本体引用；坐标或网格不兼容时不计算单元增减。
- 双方发布绑定候选、模型清单及发布记录摘要，保留保存核对记录。检查目标核对基线是否与用户选择的基线模型相同，不将候选核对虚构为发布父子关系或认证审批。
- DS“版本比较”面板支持显式基线、对象前后值、核对说明、固定空间新标签页、来源与构建定位及JSON下载。更换基线、失败、绑定错误及迟到响应不会沿用旧结果。
- 更新项目进度、运行手册及独立[契约](../../contracts/schemas/preview-publication-changes-v0.1.md)。

## 边界及后续

这是保存证据的变化比较，不是现场变化检测、自动增量融合、版本合并或回滚。保存核对未经身份认证；摘要不等于签名。表面移除不表示空闲，标注变化不代表实体变化，未配准激光仍在传感器局部坐标；quality保持unverified，robot_ready保持false。尚无真实身份及空间ACL。

下一步由“数据管理”补空间成果目录与分类，将输入、候选、发布和离线包组织为可查询的成果脉络，再推进业务台账与对象关系。
