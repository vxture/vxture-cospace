# SG5 观测日志备份与恢复

日期：2026-11-17。修复现有整站冷备份与观测持久化之间的准入缺口：业务服务将日志写入 runtime/spatial-observations.sqlite3，但旧备份白名单不接受该文件，启用观测后会拒绝整站备份。本轮将该固定业务文件纳入既有 cospace.workbench-backup/0.1 冷备份流程，不新建并行备份体系，不部署或操作生产目录。

## 使用和运行边界

继续使用[现有运维指南](../guides/运行交接与备份恢复P23运行.md)中的 workbench_backup backup / verify / restore 命令、外部摘要收据和原路径恢复方式。备份需停止受管理服务及全部写入方，并取得服务锁、runtime 与 policy 变更锁。观测 register / append_batch 现与 runtime 变更锁协作，随后仍使用原 SQLite BEGIN IMMEDIATE 事务，保持幂等及批量原子性。读取路径不获取写锁、不因查询创建日志。

旧环境没有观测库时备份照常成功，不创建空库。存在日志时整个数据库按字节进入备份，包含登记、报告、纠正/撤销历史、原接收时间、租户/场景/目录作用域和 AUTOINCREMENT 序号高水位。不能把某租户的摘要导出冒充整库备份；备份可能含多租户业务信息，按私有运维资料保管，不放入 Git。

本轮没有热备份、在线导出接口、跨机迁移或覆盖恢复。恢复仍要求原路径为空且外部 ZIP 摘要可信；失败只清理本次暂存目录，不覆盖旧业务目录。包含新日志的备份需用支持本增量的软件恢复，旧版本会因未知成员拒绝。

## 两层完整性检查

备份和恢复暂存阶段除现有逐文件摘要及 SQLite quick_check 外，增加冷态观测领域校验：

- 数据库表、索引及 SQL 定义须匹配当前日志 schema，user_version 为 0；未知表、触发器或版本拒绝，不自行迁移。
- 登记和报告通过运行契约及规范字节检查，作用域摘要与登记一致；孤立报告拒绝。
- producer、event_id、supersedes 索引列须与报告内容一致；来源和对象必须在登记中。
- 序号为正整数，观测不得晚于接收时间，同作用域接收时间不回退。
- 纠正/撤销只能指向此前同来源、同对象、同观测时刻的报告，不允许分叉或悬空。
- 保留并检查 AUTOINCREMENT 高水位；它可以大于现有最大序号，恢复后不退回并复用旧序号。

WAL、SHM、journal 等边文件仍被拒绝，不绕过 checkpoint 要求。领域检查每库最多 1,000 个登记、100,000 条报告，每作用域最多 5,000 条；超过则拒绝完整备份/恢复，不仅检查前一部分。该预算属于当前冷态检查器，未改变日志写入的逐作用域上限，不是生产容量承诺；达到预算前需安排容量与归档方案。

standalone verify 仍核对容器/成员字节、布局及外部摘要，不解包执行领域校验；backup 在源目录执行领域检查，restore 在独占暂存区执行领域检查后才发布目标目录。内部 validate_observation_database 仅供冷态运维检查调用，调用方须先停止写入并持有现有锁，不作为在线健康接口。

这些校验能发现格式、引用和约束损坏，不证明原始记录从未被整体改写或删除，不是数字签名、厂家认证、设备时钟校准或证据内容核验。source/evidence/clock verified 及 real_release_ready 标记不会因备份恢复通过而变真。外部证据文件也不会仅凭日志中的摘要自动进入备份。

## 验证

新增专项覆盖：原字节保留、当前状态/纠正/撤销及固定历史 cursor 恢复一致、恢复后继续追加、跨组织作用域隔离、序号高水位 100 恢复后下一条为 101、空登记、旧环境无库兼容、写入与备份锁协作、边文件和校验预算拒绝。

损坏用例包含 SQLite quick_check 仍为 ok 但登记、索引列、对象、接收顺序、纠正目标、规范字节、序号或 schema 错误的情况。即使重新打包并提供新的 ZIP 和成员摘要，恢复暂存阶段仍会拒绝这类领域损坏，目标目录不会被公开。

本机另做一次自包含恢复演练：将 Anoeta、Longyearbyen 原有 IFC/目录/网格复制到新的本地运行样板，两个作用域登记 29 个门对象，写入 33 条合成报告，保存两组纠正前历史读取。原资料未修改；报告登记为 synthetic，不能进入真实 IFC 门观测业务查询。备份 ZIP 9,084,010 字节，恢复后文件树逐字节一致、29 个当前状态及两组历史结果/cursor 一致。原始包、数据和收据只保留忽略目录 output/sg5/observation-recovery-01。

相关观测备份/日志、整站备份和观测 HTTP 专项共 94 项通过。真实厂家上报、生产备份调度、加密/保留策略、schema 升级、容量告警、灾备 RPO/RTO 和多节点方案仍独立验收。
