# 三类六入口端到端流程验收（G1）

日期：2026-11-02。重点是内部交付流程；不追加建模精度实验。三类六入口保持不变，新增空间卡片“查看流程”，区分已实现能力与单个空间已保存记录。

## 实现与验收范围

只读`/api/workflow?space_id=`聚合当前空间阶段及下一步，明确绑定当前候选和具有相同候选ID、清单摘要的固定发布。新选择未发布不会借用历史发布。刷新失败和空间切换清除旧报告，阶段入口保留空间上下文，双视图固定发布在新标签页打开。

资料、构建、本体、关联、发布、预览、离线消费七阶段归入六模块。阶段记录不等于现场验收；没有对象、业务或关系是参考流程缺口，不新增发布强制门禁。消费端保持“未核验”，服务不因包已导出或能力存在而声称已激活。

固定发布核对单补齐业务、关系快照对照，并修正旧的“尚未持久化”缺口；同进程库对照与本批真实HTTP/独立消费进程验收分开描述。

契约见[参考流程v0.1](../../contracts/schemas/preview-workflow-v0.1.md)，操作及复跑见[指南](../guides/三类六入口流程验收运行.md)。

## 结论与下一步

两类已有输入的工程流程已可复跑。原空间展示自己的真实缺口，独立验收通过不意味着原空间关联已补齐；对象、台账和关系仍待现场核实，激光仍无配准，几何精度和完整度未验收。没有真实采集设备、用户身份/空间ACL、生产授权或机器人导航可用性结论。

下一步数据管理：设计并落地采集批次与成果生命周期，将批次、封存资料、构建尝试、候选、固定发布及停用保留关系串起来。保持主线为交付流程，不继续以精度实验扩展本批范围。
