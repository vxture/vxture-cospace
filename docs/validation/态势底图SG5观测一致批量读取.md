# SG5 观测一致批量读取

日期：2026-11-17。单门查询已有历史回放，但应用连续读取多个门时，每次都重新取服务器时间和日志，可能混入不同接收前缀。新增只读批量查询：一个请求固定服务器时刻、登记、日志快照与最高序号，再解析全部所选对象；查询不写入报告、不改变底图，也不新增页面或厂家凭证。

## 业务接入

`POST /api/scene-ifc/opening-observations`，JSON 示例：

```json
{
  "space_id": "space-1111111111111111",
  "catalog_sha256": "<固定目录摘要>",
  "element_ids": ["e00001", "e00002"]
}
```

示例编号和摘要需换成实际固定目录中的门。复用既有平台会话、association.edit 场景权限及 POST 的 Origin / X-CoSpace-CSRF 校验；先授权再访问结构和日志，不增加平台会话请求。它是业务工作台的会话接口，不是第三方设备无会话访问端点。不得将认证或 CSRF 值写入资料包。

请求 Schema：`contracts/schemas/ifc-opening-observation-batch-request-v0.1.schema.json`。只允许上述三项及可选 replay；每批 1–128 个不同 element_id，顺序保持，所有对象必须是同一固定目录中的门且已在相同观测作用域登记。登记包含但尚无报告返回 unavailable；缺少登记、未登记对象、非门、失效来源或不可用序号整批拒绝 409，不返回部分结果。未登录 401、无权限或 CSRF 不符 403、非法请求/URL 参数/未来回放时间 422、损坏存储 503。没有隐式登记或建库。

只有显式配置好来源的调用方才使用批量入口；现有单门 GET 仍保留未配置返回 configured=false 的行为。不能将批量 409 解释成“全场景无状态”或“正常”。POST 仅为有界列表载荷，不表示有写操作；GET/HEAD 不开放。

响应 profile `cospace.ifc-opening-observation-batch/0.1`，包含场景/目录、共同 as_of / known_at / through_sequence / cursor，以及按请求顺序返回的 states。每项只有 element_id、entity_id、status、value、最后接收时间 reported_at、有效/过期/撤销计数和单对象 cursor；不返回原报告、证据路径、producer 列表或租户 scope。响应 no-store。

所有对象共用相同登记摘要、筛选后记录摘要及时间/序号前缀；批游标绑定作用域、所选实体及顺序、规则和共同上下文，改变对象或顺序会改变批游标。单对象 cursor 沿用原算法，同条件下与单门接口逐字段一致。reported 仍只是来源报告一致，不是核实现场状态。

## 整批回放

在原请求中加入响应的三项，序号转换为十进制字符串：

```json
"replay": {
  "as_of": "2026-11-17T00:05:00Z",
  "known_at": "2026-11-17T00:05:00Z",
  "through_sequence": "2"
}
```

三项必须齐全，沿用[单门回放](态势底图SG5观测工作台接入.md)的严格 UTC / 非未来时间及序号规则。对象选择、目录、原始登记/报告保留且来源仍可访问时，后续同刻纠正或晚到撤销不会改变固定批次结果。cursor 是摘要，不是可替代请求条件或权限的令牌，也不是现场证据。

## 存储和一致性

日志新增 resolve_many(scope, entities, as_of, known_at, through_sequence)，单门 resolve 复用它。数据库使用只读连接和显式 BEGIN 读事务，登记及一次有界日志读取属于同一 SQLite 快照；离开事务后在内存计算各对象状态。并发写入可在事务后或 WAL 模式下并行提交，但不会混入本批数据。未改变生产 journal_mode，不把读事务换成写事务或运行变更锁。

共同记录摘要只计算一次，每对象仍按固定日志筛选并计算状态，因此复杂度最多约 128 × 5,000 条记录，不宣称全场景遥测性能或新增索引。不同作用域不能合为一批；1000 个登记对象需要分批，多个批次并非一个全局原子快照。可以在同一已知作用域沿用固定序号/时间查询其他对象，但需自行保留准确的请求和来源上下文。

source_content_verified / evidence_content_verified / clock_quality_verified / real_release_ready 均为 false；catalog_content_verified=true 仅说明现有 IFC 目录/来源内容核对通过。未接入真实厂家、时钟与证据核验，不产生通行、重构或作业决定。

## 验证

新增专项验证一次日志读取、单对象 cursor 兼容、对象顺序、128 项边界、无报告与未登记区别、整批拒绝、POST 授权/CSRF、错误参数和来源、损坏存储 503、固定重放。两个并发用例分别在取登记后由另一线程在 WAL 中提交修正，以及在第一个对象解析时追加修正，旧批仍保持原结果，新批才能看到修正；生产数据库模式没有因此改变。

本机使用两套既有 IFC 绑定，Anoeta 7 扇门、Longyearbyen 22 扇门注册到独立本地试验库并写入合成报告。批量摘要与相同上下文单门读取一致；在最后一门同刻追加修正后，固定整批重放与原响应完全一致，新查询正确返回 unknown。服务方法直接调用，未模拟生产身份或厂家认证；原资料和生产配置未改写。单次本机批量方法约 28.18 ms / 17.42 ms，包含结构内容核对，不含网络和平台授权，不是生产性能承诺。原始报告仅留忽略目录 output/sg5/consistent-batch-01。

SG5 读取一致性能力已补齐；真实厂家身份、时钟/证据与上报、真实变化及局部更新验收仍独立完成。SG3 现场对齐及 SG4 正式事实发布不因本接口通过而完成。
