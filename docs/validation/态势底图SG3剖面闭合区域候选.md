# SG3 剖面闭合区域候选

日期：2026-11-17。针对现有 IFC 没有 IfcSpace 的缺口，从已固定来源的墙剖面提取可复查的栅格闭合空隙。结果只是设计几何候选，不是房间、楼道、可用面积或现场事实；没有部署、采用空间实例或生成连接。

## 调用与结果

```text
python -m experiments.scripts.ifc_section_regions --ifc-root <固定IFC目录> --ifc-sha256 <目录摘要> --z=-4.2 --z=1.16 --resolution .1 --resolution .2 --output-dir <新目录>
```

输出 `regions.json` 和离线 `index.html`。根目录不可覆盖；来源、原 IFC 和所读网格沿用既有摘要校验。JSON 固定目录摘要、完整剖面摘要、坐标系、切面、算法版本和每次分辨率；嵌入原剖面供回查。候选的 `source_segment_indices` 指向该高度剖面的原始截线，其中保留源 GlobalId、类型和三角形索引。邻接来源只表示栅格相邻，不证明连续完整边界或实体语义。

每个候选保存栅格原点、分辨率、格子数、栅格面积、范围，以及 `[row, column_start, column_end_exclusive]` 行游程。格子 `(column,row)` 的原坐标范围为 `origin + resolution * ([column,row], [column+1,row+1])`。这不是精确矢量边界，不能把栅格面积当作建筑面积。候选编号只在一次切面/参数试验内有效；参数、来源或切面变化不继承身份，不执行跨版匹配。

图册浅蓝表示候选，深灰表示参与计算的墙截线，浅灰为其他参照。保持原坐标比例，悬停可查候选栅格面积及截线来源。没有外部资源，用户/来源文字经 HTML 转义，不将数据解释为脚本。

## 算法与边界

1. 复用三角网格与显式 source-Z 平面的求交结果。仅 `IfcWall` 截线作屏障；门、虚拟开口、楼板及楼梯段不参与封闭，避免用门扇姿态或开口实体制造房间。其他墙类型若未被既有提取器归入 IfcWall 不自动补入。
2. 网格原点按源坐标与分辨率的整数倍确定，四周留外部空格。用 supercover 标记截线经过及接触的格子；在格边标两侧，在格角标全部接触格。仅吸附 1e-9 格的数值舍入误差，不执行几何端点吸附或形态学补洞。
3. 对剩余格子做八邻接连通域。任何连接图像外边框的域为外部，排除后保留达到显式面积阈值的空隙，默认 1 m²。内外嵌套保留格子实际集合，不填满内部洞。
4. 邻接屏障格的八邻域用于列出可回查截线。不推断 IFC 楼层归属、高度区间、房间用途、本体类型或门两侧端点，不写入标注工作表和正式底图。

没有修补几何缝隙，**栅格本身仍会封住某些较小缝隙**，结果随网格分辨率、相位和方向变化。不同分辨率的一致也不能证明真实性。八邻接允许对角空隙连通，但不消除栅格偏差。墙体截线内部空腔、围合天井和错误模型也可能成为候选；打开的门洞会让多个实际房间和楼道连成一个域。零候选不等于没有空间，有候选不等于已识别房间。图册中大连通域和细长空隙正是需要人工核查的情况，不能通过调阈值把结果包装成准确房间数。

所有 assessment、alignment_verified、ontology_bound、real_release_ready 保持未核验/false；confirmed_spaces、confirmed_connections 为空。输出不是导航占据栅格，不提供净宽、通行性或作业策略。人工起草边界仍使用既有标注工作表，之后独立核对区域、依据和连接；算法候选不能充当现场核验证据。

## 预算与复现

每次最多 8 个高度、3 种分辨率；分辨率 0.02–0.5 m、面积阈值 0.01–10,000 m²。单切面最多 20,000 条输入截线，2,000,000 格、2,000,000 估计网格跨越工作量及实际累计线格、512 个候选、200,000 行游程。候选数量乘格子数最多 50,000,000，限制掩膜扫描。预算超过即拒绝，不截断候选或悄悄降分辨率。CLI JSON 最多 32 MiB；不是生产峰值内存或并发容量承诺。

真实资料只读实跑，面积阈值均 1 m²；高度为显式观察参数，不声明真实重力或楼层净高：

| 数据 / source Z (m) | 墙截线 | 0.1 m 候选数 | 0.2 m 候选数 |
|---|---:|---:|---:|
| Anoeta / -5.6 | 16 | 2 | 1 |
| Anoeta / -4.2 | 226 | 6 | 6 |
| Anoeta / 1.16 | 1,064 | 7 | 5 |
| Longyearbyen / 1.0 | 434 | 0 | 0 |
| Longyearbyen / 3.953 | 440 | 0 | 0 |

Anoeta 最低切面出现细长墙内空隙；上层切面存在经开口连接的大域，不能直接用于房间划分。Longyearbyen 两个切面没有闭合空隙；没有通过补洞或加入门/开口屏障强行制造结果。这次试验说明单独采用剖面闭合不适合作为自动空间实例的验收路线，后续仍需结合三维几何和人工复核。

原始结果只在忽略目录 `output/sg3/section-regions-02`、`output/sg3/section-regions-longyearbyen-01`，截图在 `output/playwright`，均不进入 Git。Anoeta 两类形状已浏览器检查；唯一控制台错误为本地静态服务缺少 favicon，不涉及脚本执行或外部数据请求。

专项回归覆盖闭合/漏口/分隔、嵌套洞、游程面积与坐标、原截线索引、格边/格角/逆序、较小缝隙的分辨率偏差、门/开口不封闭、参数/预算拒绝、原网格改写和 HTML 转义。SG3 的点云单位、真实配准、区域及连接仍未核实；没有把候选提取测试替代 SG3 验收。
