## 实现与输入

试验使用Python标准库，当前运行解释器为本机Codex附带Python。代码要求Python 3.10及以上，不代表服务端语言选型。

固定样例在[examples/indoor](../../examples/indoor/package.json)，包含本体、对象、合成真值、人视图、机器视图及发布清单共6个登记文件。样例由[scripts/build_sample.py](../../scripts/build_sample.py)确定性生成，元数据均为人工合成，无现场采集、几何、覆盖或独立校核。

执行命令：

```sh
python -m apps.cli.check_sample examples/indoor
python -m unittest discover -s tests -v
```

## 实际结果

样例校验passed=true，verified_files=6，real_release_ready=false。本体sample-indoor/0.1，真值truth-sample-001，视图human-sample-001及agent-sample-001，发布release-sample-001。

12个测试通过：正常包、混用真值、未知类型、缺必要属性、坐标不一致、本体版本不符、未验证定位声明、产物篡改、包外路径、真实发布通道、真实数据标签及重复JSON键。语义失败样例重新生成有效文件摘要，避免只测试哈希不符而绕过实际语义规则。

## 限制与下一步

当前是专用规则校验器；已补充试验子集的JSON Schema结构规范，本地检查器只支持该规范所使用的关键词，未由独立引擎交叉验证。契约说明见[试验契约](../../contracts/schemas/synthetic-bundle-v0.1.md)。本轮不具备真实发布、空间查询、撤回、当前指针或权限管理，不检验几何和重定位质量。文件摘要不是来源信任根，入口清单无签名。

数据管理与语义本体平台目前分别完成文件引用、本体类型及必要字符串属性的局部能力，未形成完整管理平台。

## 结构检查增量

已新增结构规范，固定对象拒绝缺失、未知字段及错误类型；数据大小拒绝布尔值和负数，摘要要求64位小写十六进制。对象锚点、目标范围和坐标轴有固定数组长度。动态本体和属性键按对应规则检查。

新增4个测试方法，包含12组错误结构、根类型、JSON Pointer转义及CLI错误输出与退出码。与原12个测试合计16个测试方法通过，正常样例仍返回passed=true和real_release_ready=false。结构诊断具有文件名与字段路径，语义和读取错误暂统一为validation_error。下一增量增加合成空间证据与三态查询，再考虑发布切换及撤回。
