# 空间资料来源 I5 验证

日期：2026-11-03。目标是补齐授权工作台数据登记缺口，并验证来源配置能进入真实构建流程。

## 实现

数据管理新增“资料来源”页。服务端审核的启动清单只提供来源ID、名称和格式给管理员选择；每个空间独立保存启用集合、修订和修改历史。工程师只读已启用项并登记，查看者和跨空间访问被拒绝。服务端每次登记重新检查最新来源配置、完整核验文件，再进入原登记目录。

来源配置使用SQLite事务CAS，旧修订与旧目录摘要返回409。来源同ID改指向或适配器，重启后旧许可失效等待确认；目录移除来源也不会自动回退。新资料冻结`registration_ref`，保留来源ID、配置修订、目录摘要和已验签actor，经既有`input_binding`传入真实候选。重复登记复用原记录，不覆盖名称、来源修订或操作者。

停用只阻止新的登记准入；已登记资料、候选、发布仍按自身生命周期执行，不级联停用。原目录JSON、既有模型和发布不改写。主界面继续使用DS组件，来源勾选使用DS Checkbox，未改已确认首页背景。

回归覆盖默认无许可、CAS并发、重启、无变化不增加历史、来源同ID改指向失效、管理员/工程师/查看者/跨空间、CSRF、禁止浏览器路径、重复来源ID与无效字段、源文件损坏、配置库损坏503、可选适配器缺失503，以及新登记的来源修订冻结。

HTTP在独立副本实际启用A空间激光来源、登记新输入并验证重复登记，管理员另为B空间启用RGB-D，工程师B实际登记。重启后配置与来源绑定恢复；停用A空间来源后登记409，但已登记输入仍能由真实子进程生成激光候选，候选保留原登记来源修订。再验证原输入/构建/发布文件摘要不变，并继续既有发布、暂停、撤权和重启流程。

浏览器从卡片进入数据管理，管理员启用、登记/复用、预检、停用，登记弹窗随许可更新。两个页面实际触发旧修订409并保留未保存选择/原因；重新读取显示最新值。工程师只见授权来源，无管理开关、保存按钮和历史，能新建RGB-D登记并预检；直接访问其它空间403。桌面和390px视口无横向溢出，DS Checkbox操作与保存补验通过。控制台含站点图标401/403/404/503和主动触发的拒绝请求，不以零错误作为验收结论。

首次真实激光登记暴露本机缺少锁定依赖`lz4`，已执行`uv sync --frozen --extra input --extra preview`补齐；加入适配器缺失的明确503响应后重新完整验证通过。早期回归一次受到Windows临时目录rename拒绝，复跑通过，上表仅统计最终成功记录。

## 边界

当前采用本地模拟平台，真实客户端仍待登记联调。启动清单是该服务实例可供管理员分配的可信目录，尚无逐来源的第二层分配ACL。空间许可按请求准入生效，不追溯中断已准入请求。仅验收单宿主单业务进程；不宣称多节点存储、跨进程登记去重、文件上传、实时采集设备或精度验收完成。
