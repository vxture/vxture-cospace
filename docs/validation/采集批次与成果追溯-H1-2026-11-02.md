# 采集批次与成果追溯（H1）

日期：2026-11-02。归属：构建 → 数据管理，联动构建中心、空间关联、态势服务及空间预览。本批是成果生命周期的首个可执行单元：采集组织批次，不表示资料/候选/发布各自生命周期全部完成。

## 实现范围

- 数据管理新增“采集批次”，支持创建、完整成员调整、预检封存、停用、恢复和操作历史。固定空间及批次可直接链接，不增加第七个Launcher入口。
- 批次按空间归属，区分导入样本与人工现场采集声明。封存时重新预检成员；封存后不可改成员，新增资料另建批次。元数据封存不等于文件系统写保护或现场验收。
- 构建提交显式携带批次ID与修订；整理中、停用、过期修订、不属于批次的资料均拒绝。已纳入批次的资料不能省略批次绕过；同一资料可在多个批次，须显式选择一个可用封存批次。
- SQLite保存当前记录与完整历史，同一事务CAS。构建准入持锁到任务记录/子进程启动步骤结束，与并发停用排序；停用不追溯取消已准入任务。
- job和model source固定保存batch_ref，语义、业务、关系候选继承，固定发布和离线包保留。旧成果不自动归批次，旧资料、模型和发布不迁移。
- 批次详情显示保存的构建尝试和发布索引，失败/中断保留；不是完整性核对。空间流程面板可从保存的批次来源定位资料，说明提交修订，不反写历史模型。

契约：[状态与接口](../../contracts/schemas/preview-batch-v0.1.md)、[JSON Schema](../../contracts/schemas/preview-batch-v0.1.schema.json)。操作及复跑：[指南](../guides/采集批次与成果追溯运行.md)。

## 原服务及剩余范围

恢复后原激光空间仍保留原候选、固定发布和待核实对象，未加入本批批次或测试语义；原195个文件摘要不变，原采集批次数据库和台账目录未创建。新页面能显示空批次入口，不自动组织旧资料。

后续H2先明确资料、候选、固定发布各自的停用/归档、引用影响和历史保留规则，再实现受控操作；当前没有成果删除、存储回收、发布撤回或消费端远程失效。批次停用只控制新的资料构建，不改变历史固定发布的有效性。真实身份/空间ACL、采集设备和生产机器人授权仍未接入。
