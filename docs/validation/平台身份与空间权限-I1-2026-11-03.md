# 平台身份与空间权限 I1

日期：2026-11-03。根据用户补充，认证以现有 Vxture 平台为权威，参考 yucer 接入。当前批次完成校验与授权基础，不重建账户体系。

## 已实现

- Python `joserfc==1.7.7` 校验 access token：固定 RS256、issuer/audience、kid、公钥强度、时间、tenant user、账号状态、组织/工作区和 scope 角色；不信任 token 给出的密钥地址。
- 空间策略：issuer/组织/工作区显式绑定物理空间；viewer、engineer、manager 分开；平台 workspace:owner 的产品管理基线仅适用于已绑定的当前工作区。
- 保存记录适配器：在访问输入、候选、发布之前核对权限，重新检查保存的 id、空间及项目归属。不启动构建、poll、读取几何或导出包。
- 策略 JSON Schema、接入设计、操作说明及页面进度同步更新。

## 验证结果

112项身份与空间权限专项通过。包含真实本地RSA签名、错误issuer/audience、时间/类型、缺少必要字段、id_token冒用、算法降级、恶意header、轮换与缓存、弱密钥和不可用JWKS；以及角色能力矩阵、多空间、跨用户/issuer/组织/工作区、owner基线、非法策略和保存归属伪造等分支。弱密钥负例产生两条预期的SecurityWarning。

相关回归合计171项通过，覆盖上述专项及空间归属、空间目录、固定发布分发、成果控制、流程状态和成果目录。日志 `var/platform-access-i1-regression.log`。前端TypeScript和生产构建通过，依赖仍有既有use-client打包提示。

实际样本只读工具 `experiments/scripts/verify_platform_access.py` 完成19项检查，读取原3空间、9发布；用临时本地签名身份验证允许的空间、拒绝其他用户/工作区、viewer无导出权限、旧无归属发布拒绝。前后195个受管文件摘要一致，并与H3c历史基线一致。合成策略写在新的验证output，没有安装为演示服务当前策略。

```powershell
.venv/Scripts/python.exe -X utf8 -m experiments.scripts.verify_platform_access --output var/validation/platform-access-i1-001
```

可复查证据在 `experiments/evidence/2026-11-03/platform-access-i1-001`，包含代码、测试、schema、依赖锁摘要、公开参考文件摘要、前后文件清单和日志。测试私钥、token、client secret均不落盘或拷入证据。工具不请求外部accounts，没有真实SSO联调结果。

## 接入边界与下一批

I1 尚未装配 RP 会话或 HTTP 权限门禁，当前8767服务仍为内部工程预览，目录不按真实登录用户过滤。这里不把本地签名校验或前端隐藏入口当成认证已经上线。

下一批 I2：按yucer的中央会话规则，接独立CoSpace客户端、PKCE/单次state/nonce、host-only Cookie、服务端token保存与单次刷新、`/oidc/session/status`查询、全局登出。I3：落地空间绑定/产品成员管理并覆盖所有读写/静态/下载路径；I4：隔离副本中做两个用户的真实HTTP正负验收。平台client注册参数与真实环境配置尚未联调，不使用yucer的客户端凭据代替。
