# 业务项目基础与场景关联 D01

日期：2026-11-24。范围：项目基础与历史映射后端；尚未增加数据管理项目页面、资源共享或跨项目使用功能。

## 已实现

新增 `WorkspaceProjects` 和受保护的 `/api/data-projects`，支持项目创建、更新、归档，场景关联、重新关联和解除关联，以及历史业务项目显式接纳。项目目录、场景关系和操作审计单独持久化于 `preview-directory/business-projects.sqlite3`，作用域来自服务端可信的发行方、组织和工作区。

关联记录不修改旧场景、输入、构建、候选和发布中的 `project_id`。默认技术目录不能直接转成业务项目，未明确关联的场景为待关联状态；项目关联不会新增任何场景访问权限。既有 `/api/projects`、`/api/spaces` 和 `/api/data-catalog` 保持兼容。

存储首次写入才创建，并纳入既有部署 checkpoint。回退保留此数据库和原来源文件；旧版本不识别新项目关系，不能删除关系库来“恢复”旧场景字段。当前没有发起生产部署。

## 验证

10 项新增项目测试通过，覆盖双项目双场景、历史来源文件字节不变、重启恢复、明确接纳旧项目、技术目录拒绝、同请求并发重放、不同请求修订竞争、重新关联、解除与归档、查询分页及跨发行方 / 组织 / 工作区隔离。另覆盖场景数量和历史的权限过滤、会话 / CSRF / Origin 校验、伪造身份拒绝、空白名称及原因拒绝和损坏库失败关闭。

项目、既有目录、场景创建、场景设置与空间权限联合回归首轮 129 项通过、1 项跳过。新增 checkpoint 恢复测试核对项目及操作历史在后续修改后仍可从快照读取；完整业务 API 及备份回归随本批继续执行，最终结果以 PR 必需检查为准。

本批不涉及页面改动，不把后端测试等同于 UI 或生产验收。下一批 D02 接入数据目录的项目选择和管理抽屉，并建立资源与版本目录。

接口详见[业务项目与场景关联契约](../../contracts/schemas/business-projects-v0.1.md)，整体批次见[平台数据管理与项目关联设计](../architecture/平台数据管理与项目关联设计-v0.3.md)。
