# SG5 观测运行完整性

日期：2026-11-17。修复日常读取与冷备份校验不一致的问题：SQLite 文件结构正常、单条报告符合 Schema，仍可能存在索引与文档不符、未登记来源/对象或断裂纠正链。此前这些逻辑损坏主要由冷备份发现，日常查询可能将其作为有效输入。现在运行读取与备份共用作用域记录校验。

## 接入行为

单门 GET、只读批量 POST 和显式历史回放，均先在既有只读事务内验证当前作用域的登记与完整有界日志，再筛选时间和序号、计算状态。保持单作用域最多 5,000 条、批量最多 128 个对象的现有限制，不增加平台鉴权往返或写入。

校验包括：登记作用域摘要、登记/报告规范字节（拒绝额外空白及重复 JSON 键）、正整数序号、观测不晚于接收、接收顺序不倒退；producer/event_id/supersedes 索引与报告一致；来源及对象已登记；纠正指向此前同来源、同对象、同观测时间的报告且不分叉。原始 Schema 与状态解析规则保持不变。

损坏统一抛出 ObservationStorageUnavailable，HTTP 返回 503、no-store 和通用 observation_storage_unavailable，不暴露报告或索引细节。它不是客户端 409，也不是 configured=false、unavailable 或正常状态。调用方应保留“读取失败”的含义，不缓存为业务状态。

幂等重试及纠正写入读取目标事件时，同样检查索引绑定；发现不一致即拒绝且不追加。没有为每次写入增加全日志扫描。备份命令将此存储异常按既有 backup_rejected / 退出码 2 输出，不打印未处理的 traceback，不生成可用备份。

## 范围与限制

当前作用域任何一条记录损坏，都会阻止该作用域的单对象、批量和历史读取；即使损坏位于查询前缀之后、或属于另一个对象，也不跳过它继续输出状态。修复前不保证历史回放可用。其他租户/目录作用域不会因本次查询被扫描或暴露。

这不是数字签名、防篡改账本或自动修复：一致地改写文档和索引未必能被发现。全库 Schema、孤立记录、总量和序号高水位检查仍由冷完整性审计承担。读取不会迁移或修复数据库；运维应隔离异常库并按既有冷恢复流程处理。未改变生产 journal_mode、部署或存储容量承诺。

## 验证

新增专项覆盖 13 类结构仍正常的逻辑损坏，逐一验证单门、批量及固定空前缀均返回 503，查询不修改数据库；并验证同作用域不能跳过其他对象损坏、其他作用域隔离、损坏事件的重试/纠正拒绝及 CLI 错误输出。既有并发快照、历史 cursor、纠正/撤销和备份恢复回归继续执行。

使用既有 Anoeta 7 扇、Longyearbyen 22 扇设计门的合成报告库副本，本轮新校验保持全部健康历史 cursor；仅在副本中破坏末条事件索引，固定历史批量读取拒绝且文件未改写。原库与原始资料不变。试验脚本、库及原始结果仅留忽略目录 output/sg5/live-integrity-01，不进入 Git。

这些是设计来源绑定的合成数据，不是真实厂家上报或现场状态证明。SG3 现场核验、SG4 正式事实发布与 SG5 真实来源、时钟/证据和变化验收仍待完成。
