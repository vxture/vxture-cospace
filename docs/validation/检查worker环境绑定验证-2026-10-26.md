# 检查worker环境绑定验证

日期：2026-10-26。状态：I4a实际检查worker的独立环境与进程试验通过；未接入生产任务运行器，未开放recover/retry。

## 方案与结果

在Windows 11、CPython 3.14.3下，直接使用基础解释器创建单个子进程，显式设置`__PYVENV_LAUNCHER__`指向当前虚拟环境的python.exe。CPython在同一进程内恢复虚拟环境路径，无需先启动venv redirector，因而可保留Job Object的active_process_limit=1。使用`-I`启动固定引导脚本，显式加入仓库导入路径；不接受外部PYTHONPATH来选择worker。

这依赖当前CPython的启动器行为，不作为跨版本通用保证。升级Python、改变venv布局或更换打包方式时必须重新验证；失败时拒绝执行，不放宽进程限制或静默退回普通Popen。

脚本：[probe_worker_environment.py](../../experiments/scripts/probe_worker_environment.py)。完整结果：[results.json](../../experiments/runs/p2-worker-env-001/results.json)。绑定记录包含基础解释器、pyvenv.cfg、uv.lock、引导脚本及进程探针的SHA-256，以及现有LocalRunner生成的代码/版本/依赖指纹。

| 用例 | 实际结果 |
|---|---|
| normal | 实际apps.worker.check.main执行成功，退出码0；报告绑定固定context，验证通过，无candidate或truth |
| kill_registered | 子进程已创建并登记、仍挂起时强杀监督进程；子进程退出，无报告 |
| kill_check | 实际worker.main进入检查入口后停在试验屏障，强杀监督进程；子进程退出，无报告 |
| missing_venv | 缺少虚拟环境绑定时拒绝，venv_prefix_mismatch，退出码3 |
| fingerprint_changed | 预期代码指纹改变时拒绝，runtime_fingerprint_mismatch，退出码3 |
| invalid_input | 实际worker拒绝非法合成包，退出码2，无报告 |
| poisoned_parent | 父环境设置恶意同名jsonschema模块路径和虚假数据库地址；二者均未传给worker，正常报告通过 |

7项通过。正常worker与原子创建返回的PID一致，依赖目录均位于仓库.venv/Lib/site-packages；观察到sys.prefix为项目venv、sys.base_prefix为C:/Python314。报告中的job、attempt、输入摘要与规格摘要匹配试验context；报告仍声明未执行SLAM、现场质量、重定位、采用和发布。

## 过程与边界

监督进程使用基础解释器直接启动，框架断言监督PID与Popen.pid相同。worker原子加入Job Object后挂起，框架先取得带创建时间核对的观察句柄，确认可观测后才继续；强杀通过本轮Popen句柄发起，退出确认使用进程句柄等待。

试验在实际worker的inspect_package调用处加入可控等待屏障，用来稳定触发运行阶段故障；屏障仅存在于实验脚本，不修改apps.worker.check。该用例不代表已经在大数据解析的任意指令位置做过强杀。

环境允许列表为SYSTEMROOT、WINDIR、PATH、TEMP、TMP，并显式加入venv启动绑定及Python开关。`-I`忽略Python环境配置；实际编码开关效果不作为本轮结论。工作目录与输入路径均由框架固定。此为受信任本机环境的可复现执行验证，不是操作系统沙箱。

本轮直接创建合成输入及试验context，没有运行导入登记、JobManager、数据库事务、产物封存或发布流程。校验报告仅是worker输出文件，不是已提交的可消费任务产物。日志管道、日志限额和超时机制尚未与新启动方式集成。

仍待验证：host/boot身份、旧进程身份未知时的拒绝、实际重启、执行代次CAS、持久事件、迁移、多attempt读取和导入恢复。缺失这些条件时不能宣称I4a整体通过或开放恢复。

## 复跑与清理

从仓库根目录运行，要求目标目录不存在，保留本轮证据：

```powershell
.venv/Scripts/python.exe experiments/scripts/probe_worker_environment.py --root experiments/runs/p2-worker-env-002
```

每项保留绑定、进程身份、环境核对、合成输入、错误及报告。失败路径终止本轮监督进程，关闭Job Object收束worker，并等待已观察到的子进程退出。未启动数据库、容器或HTTP服务，未创建长期后台进程。

下一增量可开始I4b的0004迁移及执行代次提交保护，同时补齐进程身份与实际运行器适配；恢复入口保持关闭，直至相应故障用例完整通过。
