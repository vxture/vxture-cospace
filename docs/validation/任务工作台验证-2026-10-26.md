# 任务工作台验证

日期：2026-10-26。I3只读任务消费增量；没有新增构建执行或真实质量能力。

## 实现与验证

托管API增加场景任务列表、详情、固定输入和检查报告GET接口，见[契约](../../contracts/schemas/job-reading-v0.1.md)。无HTTP任务写路由。COSPACE_DATA_ROOT配置固定存储根；未配置时明确503，不把无配置显示为空任务成功结果。

工作台提供分页列表、按ID读取、状态与修订、固定输入/规格摘要、配置与运行环境、attempt时间及诊断、状态事件、输入清单和成功报告。任务按scene单独核对，不要求读取或激活服务发布。UI明确“检查完成不表示真值已采用”，报告保留未执行SLAM、质量、重定位、采用和发布声明。

PostgreSQL18全量66个测试、22个子用例通过，无跳过，见[日志](../../experiments/runs/p2-jobview-001/tests.log)和[JUnit](../../experiments/runs/p2-jobview-001/tests.xml)。新增接口用例覆盖分页/空场景/限额、跨场景404、固定输入与规格摘要、成功及失败报告读取、产物篡改503、输入缺失503、未配置503和任务写路由拒绝。既有worker、CLI及并发回归同时通过。

TypeScript严格类型检查及Vite生产构建通过；主JS约267.6KB/gzip83.3KB，按需三维块810.2KB/gzip220.2KB。保留TanStack use client打包警告，见[构建日志](../../experiments/runs/p2-jobview-001/web-build.log)。

实际浏览器验证：

- 列表展示真实执行成功、排队、取消及人为注入的演示失败；演示失败使用demo_failure并明确并非实际超时。
- 读取成功任务、8份固定输入和已封存检查报告，版本/摘要对应同一job及dataset。
- 切换失败任务移除旧输入与报告，显示stage/code，报告按钮禁用。
- 修改任务ID立即清除旧详情，不存在任务返回404；切换场景重置工作面，空场景返回明确无任务。

截图见[报告](../../experiments/runs/p2-jobview-001/report.png)和[失败诊断](../../experiments/runs/p2-jobview-001/diagnostic.png)。演示使用独立临时PostgreSQL，仅本机绑定；源fixture经真实导入与worker产生成功产物，不用静态伪造成功页面。

## 边界及下一步

没有身份认证或项目权限；场景过滤不等于授权。任务读取不使用空间发布撤回门禁，因为工程追溯与消费有效性分别管理。原始日志、输入内容下载、运行/取消/恢复操作不对网络开放。

分页为offset实时列表，新增时可能移动；单次详情锁定任务行保证状态/attempt/events一致。任务工作台不自动轮询。历史状态与文件健康分开：文件损坏时详情仍可追溯，但读取输入或报告失败，不能静默展示旧内容或规则通过。

下一步I4：worker进程中断、人工核对恢复、attempt序号与受控重试；先完善故障恢复契约、进程身份及旧执行提交保护，再实现恢复入口。不以本次页面可用推导真实算法、候选采用或可恢复交付基线。
