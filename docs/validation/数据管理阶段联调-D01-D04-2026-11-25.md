# 数据管理 D01–D04 阶段联调

日期：2026-11-25。目标版本 v0.19.0。本记录覆盖现有数据管理批次的整体收口，生产状态另以发布流水线及公网验收为准。

## 真实后端整链

新增 test_data_management_acceptance.py，复用真实 HTTP 应用、SQLite 和冻结场景成果夹具。三个项目分别由来源管理者、接收工程师和未获授权的第三方访问，顺序完成：

1. 关联项目和场景，登记真实输入，读取包含输入 / 构建 / 候选 / 固定发布的处理链；独立参考文件没有虚构处理链。
2. A 上传基础资料 v1，仅授权 B；C 无权引用、下载或在目录看到该原件，B 的参考权限不能打开 A 的场景。
3. B 引用 v1；A 追加并共享 v2，B 仍固定 v1；B 比较并显式升级，保留引用身份、用途、场景及未应用坐标状态。两个版本下载字节分别核对。
4. 隐蔽接收引用及有效授权阻止归档；来源管理者只得到是否存在依赖，不得到不可见场景。撤销两个版本授权后，未解除引用仍阻止归档。
5. B 解除引用后 A 归档，目录可筛出归档项，追加被拒绝，两个历史版本仍可下载。SQLite backup 后重开核对归档状态、版本历史和升级审计。
6. 恢复不自动重新关联；全程逐文件比较输入目录及构建 / 固定发布目录字节，未被资料治理改写。

该整链及处理血缘、归档、版本、原件、共享专项共 73 项通过（213.87 秒）。首次试跑修正测试对引用状态字段的断言，正式专项全通过；没有以此修改业务契约。前端数据目录 / 共享 / 文件 / 血缘 / 升级 / 处理契约 19 项通过。TypeScript 与生产构建、repository guardrails 和 strict ruleset 检查通过。完整仓库回归、原生 IFC 与五项必需检查由 GitHub 对候选提交执行，不重复累加局部测试数量。
