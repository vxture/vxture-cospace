# 真实预览版本切换与历史复查

本批完成“新候选构建→确认候选→独立发布→下载新包→消费方主动切换→旧版复查”。继续使用冻结的NYU办公室样本及既有轨迹，不新增精度实验。

## 消费行为

新增 `packages/views/agent/preview_consumer.py`，作为单进程、本机预览消费参考实现：

1. 初始无活动发布，查询会话创建被拒绝。
2. 下载与发布均不改变消费方活动版本；显式调用 `activate` 才切换。
3. 激活先完整校验离线包，随后在锁内核对 `expected_revision` 并替换活动引用。失败保留当前版本；同一期望版本的并发激活只能一个成功。
4. 查询会话固定绑定创建时的模型、发布、包摘要和消费方修订号；新会话读取当前活动版本，旧会话继续查询旧模型。
5. 历史包可显式加载复查，此时消费方修订号仍递增。它不表示服务端撤回、生产运行回退或机器人运行授权。

查询响应沿用原离线查询字段，新增 `consumer_revision`、`package_sha256`。消费方修订号与候选选择修订号是两个独立计数，不能混用。

本次同源重建的几何摘要相同，候选与发布标识不同。本记录证明版本隔离和切换流程，不证明几何增量更新。两次发布及离线包均保留，未删除旧候选。

相关回归17项通过：原14项，新增3项覆盖显式切换及旧会话、失败保留、并发修订号竞争。新增代码未修改前端，本批未重复前端构建。

## 使用与复现

工作台“服务与交付”刷新记录后可见两次发布，并分别下载离线包：

`http://127.0.0.1:8767/workbench/layout.html?revision=update-1#delivery`

消费调用示例（将参数替换为各离线包信息中的值）：

```python
from packages.views.agent.preview_consumer import PreviewConsumer

consumer = PreviewConsumer()
old_session = consumer.activate(old_zip, old_publication, old_sha256, expected_revision=0)
new_session = consumer.activate(new_zip, new_publication, new_sha256, expected_revision=1)
old_result = old_session.query(point_m)
new_result = consumer.session().query(point_m)
```

完整验证命令：

```powershell
.venv/Scripts/python.exe -m experiments.scripts.verify_preview_update --previous preview-e4ba91f7869745c4 --output var/nyu/office-0001a-update-002
```

此命令会真实创建新构建、更新工作台候选选择并发布新快照；它不是只读命令。输出目录保存新旧离线包及核对结果。

## 实现边界与下一步

消费引用及修订号仅保存在内存中，进程重启后从无活动版本开始，需要显式加载。没有自动跟随最新发布，没有持久安装、跨进程消费锁、生产信任或设备调度。此前合成包的恢复/有效性实验未移植到真实预览包。

质量仍为 `unverified`、`robot_ready=false`，表面证据不表示自由空间。下一步将现有阶段状态、固定发布与消费验证结果汇总为一张端到端流程核对单，便于从工作台确认每步成果和剩余缺口。
