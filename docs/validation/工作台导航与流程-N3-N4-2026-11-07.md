# 工作台导航与流程 N3 / N4 验证

日期：2026-11-07。范围：合并 N1—N4 的阶段版本候选。本记录不证明已部署或现场成果质量已验收。

## 实现

- 功能入口改为“共用支撑”（数据管理、语义本体）和“场景工作”（构建中心、空间关联、发布与服务、空间预览）。六个稳定路由及原有记录 ID 保持兼容。
- 场景工作使用同一个上方选择器与场景读取 Hook，包含刷新和有权限时创建；不自动选择首场景。左栏为模块能力。移除六模块横栏，以及构建、关联、数据的重复横向子导航。
- 共用数据左栏按原始、过程、成果导航；共用本体左栏区分规则编制封存与固定版本校验。本体无场景可用；固定版本深链直接进入查看面。
- 四步流程只读投影：“资料准备 → 模型构建 → 核对确认 → 发布交付”。明确本次目标、当前步、待完成原因、可操作入口。资料、任务、当前候选、固定发布使用不同证据。
- 既有固定服务可用性独立显示；历史发布不套用当前候选；退役与暂停均禁用打开入口；本体关联可选，消费端启用状态保持未知。
- 将 N5 中本轮迁移必需的防丢保护提前：本体、批次成员、场景／来源设置、对象标注、台账绑定、对象关系、资料说明、区域参数使用未保存离开提醒和刷新关闭提醒。取消留在原 URL 和编辑面；不自动重放保存。构建及关联已访问视图保留挂载。

## 阶段发布建议

建议将 N1—N4 作为一次导航与流程阶段版本（建议版本号 v0.2.0，正式标签在发布时确定）。新版不搬迁历史资产、不改场景／候选／发布／本体标识，也不改变算法或消费协议。

上线前按仓库流程：精确暂存树及归档扫描 → feature PR → quality-gate / build / test-coverage / audit / gitleaks 五项检查 → squash merge → release tag 镜像构建 → production Environment reviewer → worker02。main push 不部署。不通过本机源码包绕过流程。

生产验收需覆盖真实平台工程师／查看者、真实场景权限、一次输入到固定发布流程、旧发布访问与暂停、版本深链、会话恢复，以及线上宽窄屏。消费端激活与现场质量仍由各自验收确认。

本轮不会把完整 N5 / N6 的全部后续扩展标成完成；本轮已迁移页面的防丢与必要回归纳入阶段发布门槛，剩余增强不作为已交付功能宣传。
