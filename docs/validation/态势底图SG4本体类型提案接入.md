# SG4 本体类型提案接入

日期：2026-11-17。将已有 IFC 类型映射能力接入授权工作台。目的：在保留源 IFC 声明的同时，明确某个固定本体版本和一组显式类型规则会产生哪些提案。未采用实例、未修改底图、未部署。

## 使用入口

IFC 构件资料 → 结构声明 → 本体类型提案。默认收起；只有结构读取成功才显示。用户展开后选择已封存本体版本，为实际出现的 IFC 类选择目标类型，未选择的类保留未映射。没有预选词表或按名称猜测规则，也不自动继承 IFC 父类规则。

选择版本后仅加载该固定 ID、版本、摘要对应的定义。点击“生成类型提案”才执行诊断。界面展示提案/未映射数量和当前构件的目标类型，允许导出包含全部实体和规则的 JSON。修改规则、切换本体、关闭表单或离开场景会取消请求并清理旧结果；诊断配置仅在本次表单会话有效，关闭不保存。

源结构、本体版本、映射规则、实例采用分别管理。IfcDoor → 某目标类型只是类型提案；不能确认门两侧空间、当前开闭状态、属性值、几何对应或通行性。原始类型和 GlobalId 始终保留。产品现有设备间词表不是通用建筑本体，使用前应检查其范围；本次不默认提供或登记新的建筑词表。

## 调用与授权

`POST /api/scene-ifc/type-proposals`，无查询参数；请求由严格契约 `TypeProposalRequest` 校验：

```json
{
  "space_id": "space-1111111111111111",
  "catalog_sha256": "<固定目录的64位SHA-256>",
  "mapping": {
    "profile": "cospace.ifc-ontology-mapping/0.1",
    "ontology_ref": {"ontology_id": "<已封存本体ID>", "version": "1.0.0", "sha256": "<固定定义摘要>"},
    "rules": [{"ifc_type": "IfcDoor", "target_type_id": "<本体中存在的类型ID>"}]
  }
}
```

示例中的尖括号内容需替换；它不是可直接执行的真实配置。1–100 条规则、每个 IFC 类最多一条，目标必须存在于所选本体，未知字段拒绝。定义及来源继续沿用现有字节和实体预算。

1. 沿用已登录会话、CSRF 保护与 `association.edit` 场景权限，授权先于来源读取。
2. 从可信运行配置读取该场景固定 IFC 目录，重验目录与原文件，构建固定结构声明快照；诊断不加载网格。
3. 从 `WorkspaceOntologies` 读取当前组织/工作空间可见的已封存版本。共享模板只读，其他工作空间私有本体不可读取；拒绝摘要或内容变化。
4. 对实际 IFC 类精确查规则，输出独立提案，不改源目录、实例、发布或本体定义。映射变化不要求重提取 IFC/几何。

响应 `no-store`。未登录 401、无权限/错工作空间 403；非法请求 422；固定来源、本体缺失或变化、目标类型/规则无效 409。错误不返回服务器路径。GET、HEAD 未开放此计算入口。

## 输出与后续接入

协议 `cospace.ifc-structure-type-proposals/0.1` 固定以下内容：

- source：场景、目录及原 IFC 来源；structure_sha256：准确结构快照字节摘要。
- mapping：完整映射规则和固定本体引用；mapping_sha256：规范规则文档摘要，不是本体或结构摘要。
- entities：源 GlobalId、目录内构件编号、实际 IFC 类、目标类型或 null，状态 proposed/unmapped；保留未映射实体。
- proposed_count/unmapped_count：由实体结果重算。
- data_kind=ifc_design_candidate、assessment=unverified；saved、instance_validated、relationships_mapped、ontology_bound、alignment_verified、real_release_ready 均为 false。

客户端核对场景、目录、本体固定引用、全部源实体、构件编号、IFC 类、规则目标及统计，不接受额外实体、重复结果或提升核验标记。结果中的摘要供固定引用和复现，不构成签名或现场事实证明。以后采用实例需另有固定修订、必填属性/关系校验、证据与审核流程；本入口没有“采用”按钮。

## 保存并复用映射配置

在本体类型提案中选择固定本体和规则后，可直接“导出映射配置”，无需先计算全部提案。文件使用 `cospace.ifc-type-mapping-file/0.1`，包含 `source`（`space_id` 和 `catalog_sha256`）及原有 `mapping`（固定本体 ID、版本、摘要和最多 100 条类型规则）。不包含实体列表、模型、现场数据或采用状态。规则顺序保持原样，使原 Mapping 文档摘要可复现。

“载入映射配置或旧提案”读取上述配置，也接受此前导出的 `cospace.ifc-structure-type-proposals/0.1`，但只取其来源绑定与映射输入。浏览器检查 UTF-8、8 MiB 字节上限、JSON 层级、重复键和规则格式，再通过现有接口重新读取当前工作空间可见的封存本体，核对精确版本、摘要及目标类型。源目录暂未命中的规则会单独标记，保留其值和顺序，不生成无来源实体。场景、目录或本体不一致，以及缺失目标类型，均拒绝载入；失败保留原表单与结果。

载入成功仅回填规则并清空旧结果；用户可修改后显式生成新提案。原文件不会上传，生成时只提交映射输入，服务端仍重新鉴权并验证固定目录、原 IFC 和封存本体。没有新增共享存储或发布流程，也不自动迁移到新版 IFC/本体。若确需跨版本复用，需先重新检查类型规则和影响，再显式配置，不能编辑摘要冒充原绑定。

## 验证

合成回归覆盖确定性、规则变化不改来源、无写入、缺失映射、重复规则/未知目标、版本与摘要不符、授权先于文件读取、不加载网格、来源替换、跨工作空间私有词表隔离及封存内容损坏。前端测试拒绝错误来源、错误规则、伪造数量及已采用/已核验标记。

真实 Anoeta 与 Longyearbyen 固定目录分别含 168、157 个结构实体。本机使用**临时测试词表与显式规则**生成 168、157 条提案，未映射均为 0；这只证明所有源类型均命中测试规则，不是语义准确率或合格建筑词表验收。临时词表未登记至产品本体库、未修改生产配置，也没有采用任何实例。带完整规则的结果保留在忽略目录 `output/sg4/structure-type-proposals-02`；另以隔离的本机规则库通过服务层重跑两份资料，结果保留在 `output/sg4/structure-type-proposals-service-01`，没有连接生产目录服务或模拟真实用户授权验收。

SG4 本增量补齐工作台类型提案入口，不完成正式事实发布。SG3 对齐、空间边界及连接核验，SG5 实际观测与局部更新仍保持独立验收。

映射复用增量在本机用既有 Anoeta 和 Longyearbyen 提案回放。两份文件各恢复 9 条原规则，无规则重排；服务层分别重新生成 168、157 条提案，完整响应与原报告相同。浏览器隔离页验证载入旧提案、重新生成、配置下载及错目录拒绝后保留原规则和结果。使用旧临时本体与测试响应，未连接生产会话、登记本体或采用实例；文件和报告只留在忽略目录。
