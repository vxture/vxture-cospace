# 智能体查询恢复跨进程验证

日期：2026-10-27。J4第二批，仅Windows合成文件会话与恢复日志。依据[组合设计](../architecture/智能体恢复与文件会话组合设计-v0.1.md)。本批新增实验屏障、子进程工具及验证，没有改动门禁、恢复或文件会话运行规则。

新增5项专项实例通过，耗时26.92秒。由独立子进程打开实际FilePackages和RecoverySession，父进程操作同一RecoveryStore，使用stdin/stdout握手明确屏障。子进程直接使用基础Python并装配既有虚拟环境依赖，握手PID必须与Popen.pid相同。测试不依赖任意等待时间推测阶段。

全量本地回归266通过、6跳过、22个子用例通过，耗时356.68秒。跳过项没有本次验收证据，不据此宣称PostgreSQL或真实设备全路径通过。两种在途场景的PID与响应顺序、七份源码摘要已另行核对。

| 场景 | 观察与结论 |
|---|---|
| 判定持锁时恢复竞争 | 子进程在读取门禁快照后暂停，父进程begin超时busy，不能先进入恢复事务；未决不存在也不能绕过锁。独立只读报告仍可观察，不授予恢复 |
| 查询持有者强杀 | 只强杀本测试创建并握手的子进程；锁释放后父进程可继续检查，得到no_pending_intent，证明达到语义检查而非仍busy |
| 查询先完成、随后恢复 | 原查询返回固定空间值，恢复后旧会话stale_generation，显式新开日志/会话可查询同内容 |
| 已过门禁的在途查询（幂等恢复） | 空间查询前暂停，父进程完成恢复后才释放；旧代次响应可返回，随后旧查询拒绝，新会话为新代次 |
| 已过门禁的在途查询（撤回恢复） | 同上，旧在途响应仍可返回；后续旧查询stale_generation，新会话无法打开 |
| resume组合 | 子进程旧会话在begin/resume后拒绝；完成后显式重开使用代次4 |

表内前两项由同一个测试实例验证，后续幂等/撤回为参数展开的两项，总数仍为5。锁屏障在ledger._decision_snapshot内；在途响应屏障在session.session.query调用处，位于ledger.decide成功之后。屏障只在子进程实验实例中装配，不修改产品代码。

证据：[目录](../../experiments/runs/p2-recovery-concurrency-001)、[全量日志](../../experiments/runs/p2-recovery-concurrency-001/tests.log)、[JUnit](../../experiments/runs/p2-recovery-concurrency-001/tests.xml)、[两种在途场景](../../experiments/runs/p2-recovery-concurrency-001/scenario.json)及[环境/源码摘要](../../experiments/runs/p2-recovery-concurrency-001/environment.json)。独立场景保存实际子进程PID、屏障、恢复结果、迟到响应、后续拒绝及新会话结果；不保存私钥。

从仓库根目录复跑：

```powershell
.venv/Scripts/python.exe -m pytest tests/test_recovery_concurrency.py -q --tb=short
.venv/Scripts/python.exe -m experiments.scripts.recovery_concurrency_evidence
```

证据程序使用临时库，固定输出目录会覆盖本次场景/环境文件。要保留另一轮证据，另存或调整输出目录。只有测试请求文件含合成公钥、策略和binding，不含私钥。

生效边界是门禁判定，不是HTTP响应发送或机器人动作提交。不能宣称“恢复完成之后收到的所有旧响应都无效而绝不会出现”；调用方须保留响应版本与代次，实际动作执行前仍需独立门禁。本批未实现机器人执行器、网络传输、真实设备时钟、生产维护权限或物理断电防护。全部结果authorized=false、robot_ready=false。
