# 真实双视图DS全屏接入 C

2026-11-02，完成C首批：从“我的空间”新标签页打开固定真实发布，在既有DS空间布局中浏览人视图、智能体表面视图及同一对象快照。NYU与OS1-16输入均已验证。本批仅改变读取与展示，不登记新资料、不构建、不切换工程候选、不创建发布。

## 入口与版本

工程空间卡片“打开空间”和空间交付列表“打开固定版本”指向：

```text
/workbench/layout.html?screen=space&preview=1&space=SPACE_ID&publication=PUBLICATION_ID#space
```

链接包含空间与发布ID，不绑定可变的当前候选。我的空间卡片在点击时采用目录中最近的固定发布；打开后不会自动跟随新发布。左上角可以显式换空间，右侧概览可以显式选历史发布，浏览器后退与刷新保留对应URL版本。跨空间错误发布引用拒绝，不退回示例模型。

旧独立发布页、候选构建预览和历史未关联记录保留；界面设计示例仍明确标识为示例。这些入口与真实空间发布入口分开。

## 同源显示

- 服务端读取固定发布并核对成员；浏览器再次核对human.ply和views.js的字节数及SHA256。
- 人视图使用完整固定PLY，NYU为56,637点，OS1-16为12,884点。旧NYU的views.js曾抽样到28,319点，新全屏界面不将该缩略点集作为完整人视图。
- 智能体视图读取同一发布的表面单元中心，NYU为17,029个，OS1-16为7,474个。只表达表面证据，没有自由空间或距离场。JSON赋值文件只解析数据，不执行脚本。
- 人/智能体视图和对象API的空间、模型、发布及规范几何摘要必须一致。对象坐标保留原frame，列表、画面锚点和属性共用对象ID；属性显示类型、坐标及模型点证据。
- Three.js按需加载，WebGPURenderer实际使用WebGPU；内建WebGL2兼容路径和设备丢失恢复尚未单独验收。

NYU按right/down/forward相机轴显示，OS1-16按sensor轴显示，未把两类资料强行变为同一项目坐标系。视角旋转、缩放、平移及复位只影响画面；工程数据保持原样。摘要核对用于绑定一致性，不代表可信签名或现场质量确认。

## 布局

使用DS背景、字体、按钮、Popover、Shell面板、Avatar、输入框与Switch。取消通用header，全屏画布；左上空间标题与右上操作/Avatar均32px。左侧对象列表和相邻属性、右侧空间概览使用既有图形收放手柄；左下只有小型几何/标注开关。没有实际范围证据时，不绘制虚构“未知区域”或默认自由空间图层。

对象列表可搜索名称、类型或ID。点击画面锚点或列表项打开同一属性并定位。切换空间/发布会清空旧几何、对象、搜索与视图状态；任何几何/对象绑定失败都会显示原因并清空画布，不显示半套结果。失败可重试。
