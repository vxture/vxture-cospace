# SG4 真实 IFC 结构摘要接入

日期：2026-11-17。本增量将 SG2 的真实设计资料声明接入现有业务工作台；它不将未核实设计资料发布为现场事实。

## 入口与数据流

工作台现有 IFC 构件资料区域增加“结构声明”。先读取场景已配置的构件目录，再以该目录的 SHA-256 请求 `GET /api/scene-ifc/structure?space_id=…&catalog_sha256=…`。结构请求复用既有会话与 `association.edit` 场景授权，不新增登录恢复或平台权限会话。当前授权仍在服务器执行，客户端目录不构成访问许可。

摘要按场景和目录摘要读取；切换构件只在已取得的实体、关系中筛选，不重新请求结构摘要。场景、目录摘要变化或用户主动重试会重新读取。离开时取消请求，防止旧响应覆盖。组件重新挂载仍会读取，没有声称永久缓存或服务端零 I/O。

展示楼层、门、楼梯和空间声明数量，并显示所选构件的原始组成、归属、开洞、填充及边界声明。关系端点可选择已有 IFC 构件，最多显示 20 条关系并说明总数。没有提供结构声明的旧目录明确显示“尚未提供”，不伪装为已完成空间建模。

## 来源与含义

响应协议为 `cospace.ifc-structure-view/0.1`；`data_kind=ifc_design_candidate`、`assessment=unverified`。`alignment_verified`、`ontology_bound`、`real_release_ready`、`geometry_integrity_checked` 均为 false；`confirmed_connections` 固定为空。IFC 的单位 `m` 仅描述 IFC 已提取几何，不证明点云单位或两者对齐。

实体保留源 GlobalId、实际 IFC 类型、提取类别、目录元素编号、名称和几何提取状态。类别统计从已验证实体重算。关系保留原始关系 ID 及两端引用，不从门、楼梯或空间边界声明推断现场两侧连接。源声明、本体关联、现场复核和机器人决策仍分别管理。

## 读取和失败边界

- 服务端先鉴权，再校验场景绑定、预期目录摘要、目录内容及原 IFC 来源摘要。
- 此请求不读取构件网格；`geometry_status=extracted` 只说明目录记录，网格字节与几何完整性在几何读取时另验。
- 元数据复用既有目录预算（8 MiB），结构实体最多 10,000、关系最多 20,000；检查重复身份、实体与源构件绑定、关系引用闭合及重复关系。
- 客户端核对响应场景、摘要、协议、未核验标记、元素编号、关系引用及重算统计，拒绝跨场景、错误摘要或伪造已确认标记。
- 未登录 401、无场景权限 403；重复查询参数在公共鉴权边界按 403 拒绝；其他非法参数 422；过期摘要、来源变化和损坏声明 409。响应使用 `no-store`，不返回服务器目录或网格路径。

## 实际验证

对本机固定 Anoeta SG2 目录读取：168 个结构实体、173 条声明关系；楼层 3、门 7、楼梯 2、楼梯段 6、开洞 59、墙 78、楼板 12、建筑 1，没有空间声明。单次本机读取约 44.35 ms，含目录与源摘要核验，不含网络、会话和 UI；不能作为生产性能承诺。数据、配置及运行输出均留在忽略目录。

后端覆盖鉴权先于存储、跨场景拒绝、旧摘要、来源修改、重复参数、畸形结构、旧目录兼容以及禁止加载网格。前端契约测试覆盖身份与标记绑定、断裂关系、重复实体和伪造统计。TypeScript 与生产前端构建通过。

## 后续验收

这完成真实资料的授权只读概要接入，不等于 SG4 整批完成。真实事实快照、授权发布与在线用途包、生产性能验收仍需各自的新契约和证据；既有 synthetic 协议不能通过修改 `data_kind` 充当真实发布协议。SG3 的单位、配准、区域和连接证据缺项继续保持未核验。
