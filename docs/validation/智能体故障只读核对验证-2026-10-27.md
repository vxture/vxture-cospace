# 智能体故障只读核对验证

日期：2026-10-27。R2b第三批合成验证，依据[故障核对与人工恢复条件](../architecture/智能体故障核对与人工恢复条件-v0.1.md)。

新增14项专项测试通过，覆盖只读命令及故障边界。执行环境Python 3.14.3、Windows；核对器自身不调用Node密码适配，也不加载外部信任配置。合成测试资料由已有测试签名工具生成。

全量本地回归178通过、6跳过、22个子用例通过，耗时109.95秒。本次跳过项未取得验收证据，不能据此称PostgreSQL或真实设备全路径通过。

| 验证场景 | 结果 |
|---|---|
| 库不存在 | 不创建目录、数据库或pending |
| 正常库只读核对 | 3类保留证明可观察；库与标记的文件字节集合不变 |
| 只读SQL及CLI | mode=ro；测试数据库授权器禁止写操作仍可完成；退出码0/2及JSON结果正确 |
| 摘要匹配 | 报告retained_digest_match；标记保留，原门禁继续storage_error |
| 提交失败 | 报告当前保留快照未匹配，不推断可清理 |
| 曾提交后被替换 | 同样可能未匹配，不能据此推断从未提交 |
| 写入者仍活跃 | 线程屏障保持事务未提交，审计可观察但不声明写入者已退出 |
| 坏库与文件侧条目 | 数据库观察不完整，pending仍列出database_unknown；不修改坏库 |
| 坏JSON、重复字段、异常名字、标记超限 | 不完整结果，保留原字节 |
| 状态/条目超限、危险路径拒绝 | 不完整结果，无恢复或清理授权；危险路径采用注入拒绝验证，非实际Windows链接验收 |

证据：[目录](../../experiments/runs/p2-validity-audit-001)、[测试日志](../../experiments/runs/p2-validity-audit-001/tests.log)、[JUnit](../../experiments/runs/p2-validity-audit-001/tests.xml)、[合成报告](../../experiments/runs/p2-validity-audit-001/scenario.json)及[环境与源码摘要](../../experiments/runs/p2-validity-audit-001/environment.json)。源码摘要覆盖核对器、门禁、证据生成器及专项测试；历史证据保持原位。

复跑说明见[运行手册](../guides/智能体故障只读核对运行.md)。合成证据同时保存正常库、已匹配标记与提交失败标记的核对结果，确认核对前后标记原字节不变。原R0/R1及ValidityStore写入行为均未改动。

报告不是密码验证、时间判断、全库完整性检查或恢复决定。数据库与文件系统不是统一快照；文件大小、SQL步数、行数均有限额。未实现维护独占、提交凭据、人工解除、信任迁移、可信时间、硬件防回滚或真实设备授权。所有输出固定authorized=false、robot_ready=false。

下一批先细化恢复独占、完整消息留存与提交凭据、状态对账契约，再实现恢复状态机。I4构建任务恢复及真实算法/构建验收保持独立未完成。
