# 智能体恢复与文件会话组合验证

日期：2026-10-27。J4首批独立Windows合成组合，依据[设计](../architecture/智能体恢复与文件会话组合设计-v0.1.md)。新增15项专项实例通过，耗时48.30秒。

全量本地回归261通过、6跳过、22个子用例通过，耗时330.74秒。跳过项没有本次验收证据，不推定PostgreSQL或实际机器人全路径通过。两条独立文件会话场景及七份源码摘要另行核对一致。

| 场景 | 结果 |
|---|---|
| 文件会话与幂等恢复 | 初始可查；未决拒绝；begin后旧会话stale_generation；完成后仍拒绝旧会话，新日志/新锚/新会话可查询同内容 |
| 截止不延长 | 新会话门禁deadline与旧会话一致，缺时间锚和到期均不能打开 |
| 撤回恢复 | 旧会话被代次拒绝，恢复完成的新会话仍无法打开，无空间值回退 |
| 完整绑定 | scene、scope、truth和package摘要换用均拒绝 |
| 活动版本 | 同包重激活不改变旧会话revision；真实不同内容切换后旧快照保持原结果，新会话不能使用旧binding，新包未获独立证明也不能打开 |
| 关闭行为及旧入口 | close后拒绝；v1 ValidityStore不能冒充RecoveryStore传入适配器 |
| 四阶段只读报告 | clean/pending/planned/reconciled元数据可见；审计前后库内全部文件字节保持不变，不输出token正文或授予恢复 |
| SQL/CLI只读 | 明确mode=ro，授权器拒绝SQL写操作仍可完成；CLI正常/待处理退出码0/2正确 |
| 缺库、坏库、超限、控制不一致 | 返回不完整报告，缺失目录不创建，不修复 |

专项首轮有一项测试错误地读取LocalSession内部不存在的revision属性，已改为检查公开query响应，再补真实内容切换测试后全部复跑通过。未因此修改既有运行会话实现。

独立证据包含幂等恢复和撤回恢复两种场景，实际使用FilePackages文件存储与RecoveryStore日志，保存前后响应和四阶段只读报告。见[p2-recovery-session-001](../../experiments/runs/p2-recovery-session-001)、[场景](../../experiments/runs/p2-recovery-session-001/scenario.json)、[环境及源码摘要](../../experiments/runs/p2-recovery-session-001/environment.json)、[全量日志](../../experiments/runs/p2-recovery-session-001/tests.log)和[JUnit](../../experiments/runs/p2-recovery-session-001/tests.xml)。不保存随机私钥。

本批验证顺序组合，没有会话查询与恢复并发屏障、跨进程会话/恢复、真实机器人动作或平台维护角色校验。审计只检查有界元数据，不做签名/历史重放/当前状态摘要验证；complete不能代表日志正确或设备可用。文件与日志两库无跨库原子激活，旧包撤回仍依赖其独立状态。

所有返回authorized=false、robot_ready=false。真实SDK、可信UTC、在线挑战、旧库迁移、物理断电、维护身份认证及I4构建恢复均未完成。下一批先补并发查询/恢复边界及跨进程组合证据，再接维护入口。复跑见[手册](../guides/智能体恢复与文件会话实验运行.md)。
