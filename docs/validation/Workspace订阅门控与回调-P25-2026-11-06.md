## 本批完成

1. 浏览器业务入口按已验签用户令牌中的 Workspace 检查权益，Workspace 所有者也不能绕过。场景角色仍独立检查。
2. CoSpace 服务端用用户 access token 做 OBO 换票，得到 audience=vxture 的短期票据，经内部入口请求 `GET /platform/entitlements`。程序消费使用 CoSpace 自身 service 换票，再与调用产品的场景权限相交。
3. C2 的 tier 和 bundled 是商业覆盖依据。当前浏览器功能要求 tier 为已知档位；程序数据访问允许 tier 或 bundled。未知档位／状态拒绝，平台不可用返回 503，不退回旧缓存。
4. 默认内存缓存 30 秒，上限 45 秒。签名通知更新 SQLite generation，当前进程和同目录其他进程下次请求重拉。上传提交前及程序结果交付前再检查。
5. `POST /api/webhooks/vxture` 支持 tenant.provisioned、tenant.deprovisioned、subscription_changed：原始请求体 HMAC、300 秒签名时差、头与正文一致、重复键／重复头／超大体拒绝、投递幂等、同 ID 异文冲突、生命周期 seq 防乱序、双密钥轮换。
6. 回执仅保存事件 ID、摘要、Workspace、类型、序号、时间和失效代数；不持久化权益或密钥。通知不产生场景授权、不删除历史数据、不代表初始化完成确认。尚未接入共享资产 grant.invalidated 或 provisioning ack。
7. 页面展示“未开通／需要续订／状态不可用”，用户主动进入 Console 订阅。开通后恢复工作台，后续业务请求发现撤销则隐藏业务视图，保留登录。
8. 生产身份源组装业务工作台时必须配置权益检查。8790 明确模拟环境保留原有流程；8791 真实认证入口仍不开放业务。

## 配置与运行

必需：`COSPACE_PLATFORM_API_URL`、`COSPACE_PLATFORM_WEBHOOK_SECRET`；API URL 是受信任内网 origin，无路径。HTTP 仅在明确开启 tailnet 标志且地址属于 100.64.0.0/10 时允许；公网生产使用受信任 TLS。可选旧密钥 `COSPACE_PLATFORM_WEBHOOK_PREVIOUS_SECRET` 用于短期轮换。

本机真实 C2 通过已确认的 tailnet 入口完成。当前 8791 使用 DPAPI 保存的**本地验签测试密钥**，尚未登记给平台；不能把本地接收器测试当成真实投递通过。所有 client secret、会话密钥、签名密钥及用户令牌不进入报告、Git 或业务备份。

新增业务备份允许文件 `policy/platform-events.sqlite3`，冷备份恢复保留回执及失效代数；进程缓存重启后为空，会重新读取权益。
