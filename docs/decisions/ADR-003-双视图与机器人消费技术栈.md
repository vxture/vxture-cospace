# ADR-003 双视图与机器人消费技术栈

日期：2026-10-26。状态：用户确认方向；迁移、SDK与专项选型待验证。

## 背景

产品采用真值加人视图、智能体视图及统一服务。机器人需要在线或离线获取轻量空间能力，工程师需要浏览、管理与追溯；两者不应依赖同一可视化运行时。用户确认复用既有TypeScript/React产品体系，保留扩展性。

只读核对vx-agent-yucer的package.json、pnpm锁文件、Next配置及部署文件：当前为Next.js 15.5.28 App Router、React 19.2.7、TypeScript 5.9.3、Tailwind 4.3.3及Vxture设计系统；服务端为Next Route Handlers/Server Actions，数据使用Prisma/PostgreSQL，会话相关使用Redis。上述是本地文件记录，不是最新版本或运行验收结论，未修改该项目。

## 决策

1. 人视图继续采用Three.js；UE5保留为仿真或高保真展示消费端，不作为机器人或平台必需依赖。若引入UE，重新核验受支持版本，不冻结早期5.0。
2. 管理前端方向统一到TypeScript、React、Next.js App Router和Vxture设计体系。当前CoSpace的Vite实现继续可运行；先验证共享组件、身份接入和三维客户端边界，再独立迁移。Next主版本及组件版本不因参考项目而直接冻结。
3. 空间管理、构建编排及发布API保留FastAPI；几何重计算与机器人端计算通过独立C++组件或算法进程承担。Next仅承担门户及必要BFF，不承载长建图任务。当前不新增NestJS服务。
4. NestJS作为未来管理控制层候选，只有业务复杂度、团队维护方式及迁移收益足够时重审；不为统一语言引入重复业务写入服务。Next不能直接写FastAPI拥有的领域表，认证接入也不能导致绕过领域规则。
5. PostgreSQL与不可变成果存储保留。每组表只有一个迁移规范源；未来引入Prisma时不得与SQLAlchemy/Alembic共同拥有相同表的结构迁移。
6. 机器人接收用途裁剪的运行包及轻量SDK；SDK不要求Node、浏览器、Python平台服务、PostgreSQL或UE。C++读取接口优先评估，ROS 2为可选适配，具体平台和性能待实测。

## 扩展边界与后果

智能体视图支持占用/距离/定位参照/拓扑/语义等组件，通过角色、编码版本及能力声明扩展，不提前绑定OctoMap、Voxblox或NDT实现。人视图独立演进，运行包不默认携带纹理与展示模型。

Three.js与Next的组合需要明确客户端渲染、按需加载和固定发布缓存；Next standalone需Node服务，不自动支持纯离线静态功能。设计体系复用需核验导出API、许可、依赖、主题及浏览器表现，不直接复制参考项目的Webpack补丁、Redis和数据库部署。

可信离线消费引入有效性、撤回滞后及时间信任问题，按[运行包架构](../architecture/智能体视图运行包与在线离线消费架构-v0.1.md)分批验证。首版不同时新增多种后端和多套SDK，避免扩展性变成提前部署所有组件。

重审条件：实测空间查询负载超过当前计算边界；机器人目标平台变化；大场景分块需求超过当前格式；管理业务或团队结构变化；仿真成为正式消费任务。每次用同条件性能、兼容与维护证据评估，不以框架热度决定迁移。
