# ADR-007：语义本体独立产品边界

日期：2026-11-20。状态：用户已确认公共资源定位及未来独立产品方向；本批实现独立定义内核与目录组件，旧编制/实例链路迁移仍待后续。

## 决策

语义本体位于“公共资源—语义本体”，同时按未来可独立沉淀的通用产品建设。产品拥有通用核心与领域定义、依赖、约束、规则及其版本治理；消费方拥有实例、几何、观测正文、现场证据和确认结果。三层是语义组织，第三层不意味着本体产品拥有所有业务实例数据。

依赖方向：CoSpace 宿主适配器 → 通用本体接口；通用本体内核与 UI 不反向依赖 CoSpace。宿主替换时允许更换认证、存储和 HTTP 适配器，不应重写概念、依赖解析或核心编制规则。

## 本批物理边界

| 单元 | 路径 | 可依赖内容 |
| --- | --- | --- |
| 独立定义内核 | `packages/ontology/kernel`，独立 Python 打包入口 | Python 标准库与随包定义资源 |
| 独立目录 UI | `packages/ontology-ui`，独立 npm 包入口 | React、公共设计系统、自身契约与注入客户端 |
| CoSpace HTTP 适配器 | `packages/service/ontology_library.py` 及业务 HTTP 边界 | 平台认证/权益检查、纯内核读取 |
| CoSpace UI 适配器 | `apps/workbench/src/layout/ontology-library-client.ts` | 宿主 endpoint、错误转换、组件客户端接口 |
| 场景消费方 | 现有 spatial、construction、lifecycle、views、service | 固定定义引用及显式契约；不得反写本体含义 |

内核不导入父目录旧模块。UI 不导入宿主路由、场景选择、平台会话或 endpoint；Shell 负责将其挂载到公共资源。目录读取不要求选择园区，不读取任务、模型、私有规则库或场景清单。平台认证和商业权益仍属于宿主边界，公共资源不表示匿名公开。

模块可独立打包，不等于已成为完整独立产品：本批未增加独立账号、独立服务或独立发布流水线，也未将私有草稿和正式版本切换到新契约。

## 逐步脱离历史耦合

现有 `workspace_authoring.py`、`preview_versions.py`、`scene_usage.py` 等保持兼容，明确归为宿主历史实现。其认证主体、文件布局、场景使用查询不能进入新内核。

后续抽取顺序：

1. 定义集合及纯校验接口稳定，建立仓库外安装与消费验证。
2. 定义编制用例改为接收显式作用域、actor 和存储端口；平台身份转换及权限判定留在宿主。
3. 将草稿保存、固定版本、审计、依赖仓库定义成接口，由宿主实现；保留并发修订与幂等行为。
4. 使用查询由消费方提供“引用位置”接口，本体产品不扫描园区存储。
5. UI 编制/比较组件只接收客户端契约；独立产品 Shell 可直接装配相同组件与内核。

旧模块迁移不能以移动文件代替契约隔离，不能让旧版本失去解释或修改授权边界。

## 验证要求

2026-11-20 B04a：新增纯编制用例 `kernel/authoring.py`，通过 `transaction(scope)` 存储端口和 `authorize(scope,actor,action)` 宿主授权函数工作。独立 wheel 不导入数据库；可替换的 SQLite 参考适配器放在 `packages/ontology/authoring_sqlite.py`，不进入纯内核依赖。该适配器仅接收注入目录和作用域，不依赖 CoSpace 身份或场景；HTTP/表单后续接入。见[编制与版本契约](../../contracts/schemas/ontology-authoring-v0.1.md)。

内核在隔离解释器和独立安装包中运行；UI 在不挂载 CoSpace 的页面上运行；HTTP 测试证明认证先于读取且不访问场景/私有规则库。依赖方向作为持续测试，新增功能不得破坏。后续引入第三方依赖须声明必要性及可替代边界。
