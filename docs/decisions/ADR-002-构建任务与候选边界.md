# ADR-002 构建任务与候选边界

日期：2026-10-26\
状态：确定下一实现增量的技术方向；实现与故障验证待完成

## 决策

首批采用PostgreSQL任务状态、固定输入清单、本地不可变文件存储和单任务worker；网络入口保持只读。先通过本机CLI完成导入和synthetic_check执行，再扩展工作台。执行器固定登记，参数受Schema约束，禁止用户提交任意命令。当前不增加外部队列或编排框架。

构建任务成功与正式真值采用分离。synthetic_check只产生报告；未来spatial_build才可产生待校核空间候选。正式采用、两类视图发布及服务切换仍由lifecycle控制，不能由任务状态触发隐式发布。

文件先封存、数据库后提交可见引用；承认两者无共同事务，通过不可见暂存、孤立内容核对和故障恢复处理失败。首批不提供自动过期抢占，防止旧执行与重试同时提交。自动恢复需以后补齐租约、隔离令牌及旧worker提交拒绝机制。

## 依据与影响

当前只有小型合成输入，真实算法环境及资源模型未验证；固定输入和产物血缘比引入分布式调度更早构成必要条件。现有PostgreSQL、Python和Alembic可承载首个闭环，不新增部署依赖。保留job与attempt身份，为后续独立算法进程和恢复留边界。

代价是首批单机、单任务执行，无高可用、运行中取消和自动恢复。应用只读访问约束不等于OS隔离；真实构建接入前必须验证进程树回收、资源限额与输入挂载边界。候选与真值分离要求后续明确审核采用接口，但能保留质量与发布责任。

## 重审条件

同时运行多个资源密集任务、多主机或GPU调度、断网离线交付、资源隔离不足、人工恢复成本过高时，重新比较成熟任务引擎或队列。重审按实际负载与恢复要求选择，不要求维持自建调度；输入快照、attempt、产物及采用边界必须保持。
