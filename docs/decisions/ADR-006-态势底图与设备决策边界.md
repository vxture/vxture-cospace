# ADR-006：态势底图与设备决策边界

日期：2026-11-16。状态：产品边界已由用户确认；技术设计待分批实现与验证。本决策修正旧文档中将设备通行代价、机体能力规则及导航结果纳入平台核心的表述，不改变现有运行协议。

## 决策

CoSpace 构建和服务态势底图，描述几何、语义、空间结构、连接关系以及带来源和时效的状态。应用结合具身智能体自身物理特性、任务和现场感知，判断能否通过、如何规划、如何接近及如何作业。

例如：平台描述楼层、楼道、楼梯、门、配电柜及其位置、形状、尺寸与关系；楼梯连接两层是底图事实，某设备能否上下楼不是底图事实。门洞、门扇与开关状态分别表达；空间连接不等同当前开放，更不等同设备可达。

1. 核心计算视图采用几何证据与语义空间图相结合的表达，不能以点锚列表或表面体素单独替代空间结构。
2. 对象有稳定身份，几何表示、属性、关系和状态分别版本化并绑定同一发布；未识别、未观测、未核实和过期必须能区分。
3. 通用几何距离、范围、截面与连接查询属于平台；机体适配代价图、导航图、路径、轨迹、接近位姿和控制属于下游应用。不得把接口出现“连接”解释成平台承诺通行。
4. 既有设备登记保留其接入和关联职责，不成为定义空间事实的前置条件。平台无需接受设备机体参数才能描述楼道或楼梯。
5. 占据、已观测空闲、距离场、定位参照作为按需求提供的组件，不要求所有底图全部生成；组件存在不构成导航或安全授权。
6. 应用提供的作业点、禁行区域与外部状态可以按独立来源关联保存；不得冒充实测几何，也不得自动适用于所有设备。
7. 同一态势底图可被多个能力不同的应用消费，不维护相互独立的设备专属权威空间事实。

## 影响与验收

来源结构、本体定义和场景实例分责：原始分类与声明关系随证据保留；本体维护通用类型与规则；独立映射绑定固定来源、本体版本和规则后生成候选。场景决定是否采用具体实例和关系。本体升级不回写来源或静默改变历史发布。

首批重点是两层空间中的楼层、房间/楼道、楼梯、门和配电柜：核对几何、身份、结构、连接、状态、来源与版本。导航或实机抵达可用于下游集成验证，不是平台功能成立的唯一判据。

现有 `machine` / `agent` 协议标识与 `robot_ready` 等字段不在本次文档变更中改写；旧预览成果保持原能力和未知语义。技术实现采用显式新版本及适配，不能把旧产物重新标为完整空间图。
