# ADR-005：智能体恢复日志与维护独占

日期：2026-10-27。状态：拟采用，待J1至J4验证；未实施迁移或恢复操作。

实施进展：J1锁、J2日志及J3恢复已取得独立合成证据，见[恢复实现](../architecture/智能体恢复状态机实现-v0.1.md)；J4运行包会话与维护权限尚待组合验证。恢复完成额外推进代次，防止恢复期间打开的对象继续使用。未迁移已有库或开放真实设备授权；以上初始状态保留为决策历史。

J4首批补充：[文件会话与只读审计](../architecture/智能体恢复与文件会话组合设计-v0.1.md)已完成顺序组合验证，维护角色矩阵只作设计；并发与跨进程组合、生产维护权限仍未实现。先前进展保留为历史。

当前有效性实验只保存最新证明，pending只保留消息摘要。它能阻断新查询，却不能证明历史消息是否曾提交，也不能在所有权不明时解除。需要为恢复提供完整消息和明确的提交边界。

后续独立ledger-v2采用单SQLite日志：准备事务保存消息原字节及intent，应用事务同时写状态和唯一receipt，恢复决定与解除recovering模式同事务完成。JSON导出只作证据，数据库之外的文件删除不参与v2放行判断。旧v1库及标记不自动迁移、不因v2恢复成功而解除。

首版所有消费判定、正常写入和恢复遵守同一稳定OS独占锁；恢复begin/resume增加持久generation，每次操作拒绝旧代次对象。该选择降低并发度，但先使所有权、提交和中断路径可验证。首版不做日志裁剪；达到限额时拒绝新写入。共享读锁、压缩/归档与设备迁移需各自补证据。

仅在最新状态里查摘要无法处理已被替换的历史提交；按TTL删标记无法确认写入者已退出；文件与数据库双权威会引入跨介质清理空窗，因此不作为v2恢复依据。内核锁也不提供恶意磁盘回滚或管理员文件替换防护，不引入此类承诺。

实施协议、比较条件和分批验收见[恢复独占与提交日志协议](../architecture/智能体恢复独占与提交日志协议-v0.1.md)。本决策不改变真值与双视图模型、现有门禁入口或真实机器人授权状态。
